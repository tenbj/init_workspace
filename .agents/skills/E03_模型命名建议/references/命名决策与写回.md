# 命名决策与写回

## 这项技能解决什么问题

- 用于只做“命名建议”的轻量模型标准化：输入一个标准库 Excel 和一个模型设计 Excel，复制出新的模型设计文档。
- 在模型设计文档的字段名列后新增 `推荐字段名` 和 `推荐依据`，按标准库和字段上下文给出建议、标准候选、命中层级和决策动作；表名默认取 A1，推荐表名与表名决策依据一起追加在 A1 原表名后。
- 从 v1.2.0 起，E03 不只要求“依据可见”，还要求“决策可控”：AI 必须给出具体推荐名，并明确 `rename / keep`；不得输出 `待确认` 或空候选。
- 从 v1.3.0 起，E03 增加可执行质量门禁：写回前必须校验字段/表名覆盖率、长 token 处理、决策字段完整性和依据完整性，并生成 `quality_report.md`。
- 从 v1.4.0 起，写回输出 Excel 时可同步复制标准库原始 sheet，并基于标准库模板生成 `标准规则库_建议` 与 `标准映射库_建议`，供人工评审后沉淀。
- 从 v1.5.0 起，`标准映射库_建议` 必须经过现有 `标准映射库` anti-join 和可复制性质量门禁：自动过滤已有标准、中文名冲突和词根冲突，只写入最终可直接复制进标准库的新词条。
- 推荐名必须遵守“最小改动优先、短词根优先、避免语义膨胀”：除标准库明确要求外，只修订明显不规范的词根、后缀、缩写或词序，不把短词扩写成更长短语。
- 从 v1.5.1 起，参考库表字段按层级处理：参考库表名规范化后以 `dwd_` 为前缀时才视为 DWD 表，字段命名以审核为主，推荐字段名尽量与参考字段名保持一致；只有参考字段名与标准库强规则、标准映射、合规词根、snake_case 或字段语义明显冲突时才重新设计。参考库表名不以 `dwd_` 为前缀时，字段命名完全按标准库和字段语义推荐，不把参考字段名作为保留或风格依据。
- 从 v1.5.2 起，同一 Excel 内优先按 `字段名/current_field_name` 复用已生成的 `推荐字段名`：`字段名` 相同的字段必须得到相同推荐。这里的 `字段名` 是模型设计当前字段名列，不是 `参考字段`。
- 适合快速评审命名，不生成 E01 那种完整运行目录、批次、评审清单和标准缺口沉淀。

## 先读哪些本地知识

- 先读用户给出的标准库 Excel 和模型设计 Excel；不要默认使用 E01 的运行目录协议。
- 需要字段识别、推荐 JSON 和 Excel 写回细节时，再读 `references/扩展说明.md`。

## 固定动作

1. 确认两个输入文件：标准库 Excel、模型设计 Excel；输出默认放在B04定位的output子项目目录，命名为 `{原文件名}_命名建议.xlsx`，不得覆盖原文件。
2. 运行 `scripts/model_naming_workbook.py extract` 抽取模型和标准库上下文；若脚本无法识别模板，再按 `references/扩展说明.md` 手动定位字段名列、备注列和字段行。
3. AI 先整体阅读 `context.json` 中的标准规则库、标准映射库和所有模型字段，再逐字段执行“术语识别 -> 同字段名一致性复用 -> DWD 参考字段判断 -> 标准规则/映射匹配 -> 候选生成 -> 长 token 复核 -> 当前名对比 -> 决策”；不要先看当前英文名是否顺眼再决定保留。
4. `recommendations.json` 可以由脚本辅助落盘，但字段/表名命名建议必须来自 AI 对本次 `context.json` 的逐字段语义判断。不得仅复用历史 run 的静态字段决策表；只有输入文件哈希、E03 版本、标准库内容和模型字段完全一致，且重新通过本轮质量门禁时，才可把历史决策作为参考。读取标准库时必须使用 `context.json` 中 `standard_sheets[*].records`，不得因为 `rows` 为空就判断标准库为空。若本轮发现可沉淀标准，应在 JSON 中补充 `standard_rule_suggestions` 或 `standard_mapping_suggestions`；`standard_mapping_suggestions` 只能包含当前 `标准映射库` 中不存在、且可直接复制进标准库的新词条，不得包含已有中文名称、已有标准词根或占位说明。
5. 每个字段必须先区分 `字段名/current_field_name`、`参考库表/reference_table` 和 `参考字段/reference_field`：`字段名` 是模型设计当前字段名列，`参考字段` 是来源表字段列，二者不是同一列。推荐顺序固定为：先按相同 `字段名` 复用本 Excel 已生成的 `推荐字段名`；若没有可复用结果，再判断 `参考库表` 是否为 `dwd_` 前缀且 `参考字段` 非空，满足时尽量推荐 `参考字段`；若仍未触发，再按标准库和字段语义推荐。`参考库表` 为空、为 ODS/`ods_` 或 `参考字段` 为空时，不能沿用参考字段，只能按相同 `字段名` 的既有推荐保持一致；找不到既有推荐时再走标准语义推荐。
6. 只有在“同字段名一致性复用”和“DWD 参考字段”都未触发时，才进入标准库强命中判断：如果字段语义命中标准映射库词条或标准规则，推荐名必须体现该标准词根/规则；若因冲突、不可信或多候选而不采用，也必须给出最负责任的具体候选名，并在中文依据中说明取舍风险，不得用 `待确认`、空候选或 `rule_only + keep` 绕过命中项。
7. 候选生成遵守一致性优先：同一 Excel 中相同 `字段名/current_field_name` 的第一条推荐确定后，后续相同 `字段名` 必须复用该 `推荐字段名`，并把 `standard_candidate_name` 同步写成该推荐名。只有没有同字段名既有推荐时，才继续按 DWD 参考字段或标准语义生成新候选。参考库表为 `dwd_` 前缀表且参考字段非空时，优先保留参考字段中已经合规的词根、顺序和缩写；其他参考库表或空参考字段不得因参考字段名存在而沿用其词根或顺序。
8. `代理主键` 且 `是否主键字段=是`、`是否业务主键=否`、参考字段为空时，优先推荐 `unique_key`；不要泛化为实体标识 `id`。
9. 推荐名或标准候选名中英文 token 超过 7 个字母且缺少标准缩写时，必须先生成短词根并体现在 `recommended_field_name` 和 `standard_candidate_name` 中，同时在依据中补充 `补充词根建议：建议新增 {中文词条}->{缩写词根}`；可在 JSON 中额外写 `term_root_suggestions`（新增字段）供后续沉淀。不得一边保留原长 token，一边只在依据里建议缩写。若确需保留长 token，必须不要写补充词根建议，并在 `long_token_exceptions`、`standard_long_tokens` 或依据中说明其为标准库明确允许的固定词根。
10. 每个字段推荐必须补充 `standard_candidate_name`、`match_level`、`decision`、`mapping_match`、`rule_match` 和 `recommendation_basis`；每个表名推荐必须补充 `table_standard_candidate_name`、`table_match_level`、`table_decision`、`table_mapping_match`、`table_rule_match` 和 `table_recommendation_basis`。
11. `mapping_match`、`rule_match`、`recommendation_basis` 和 `table_recommendation_basis` 必须使用中文正文；字段名、表名、标准词根、`rename/keep` 等结构值可以保留英文。
12. `recommendation_basis` 与 `table_recommendation_basis` 必须至少包含 `映射匹配：...` 与 `规则匹配：...`，并补充 `标准候选`、`匹配层级`、`决策`、必要时的 `保留/修订原因`。
13. 若未触发同字段名复用，且 `match_level` 为 `exact_field`、`exact_table` 或 `term`，标准候选名不同于当前命名时，必须推荐标准候选名；证据冲突时仍需输出具体候选名并说明取舍，不得直接保留当前名。已触发同字段名复用时，`recommended_field_name` 与 `standard_candidate_name` 必须同步为复用结果。
14. 将 AI 决策写成 `recommendations.json` 后运行 `scripts/model_naming_workbook.py write --standard-lib {标准库路径}`，脚本会先生成 `quality_report.md` 并执行硬校验；校验通过后才复制模型设计文档并写入 `推荐字段名` 与 `推荐依据` 列。质量门禁会校验同一 Excel 中相同 `字段名/current_field_name` 的 `推荐字段名` 必须完全一致；不一致时写回失败。推荐表名和表名推荐依据追加在 A1 原表名后，同时把标准库 sheet 与标准建议 sheet 写入输出 Excel。写回脚本必须对 `标准映射库_建议` 做过程校验：先生成建议初稿，再与当前 `标准映射库` 做 anti-join，自动过滤已存在词条、中文名冲突和词根冲突，只把最终可复制新增项写入建议 sheet。
15. 最终只向用户交付新的模型设计 Excel 路径和必要的 `quality_report.md` 路径；输出 Excel 内应包含模型建议、标准库原表、`标准规则库_建议` 和经过过滤校验的 `标准映射库_建议`。`quality_report.md` 必须包含“标准映射建议质量”，列出初稿数、已过滤已有标准数、冲突数、最终可复制新增数和无法写入项；若最终新增项仍有占位说明、缺少业务域/释义/适用场景/示例，写回必须失败。如证据不足，仍需给出具体推荐名，并在依据中写明 `映射匹配：未命中...`、`规则匹配：基于...作出的负责建议` 和取舍原因。

## 什么时候再读本 skill 的 references

- 不确定 Excel 模板识别、推荐依据优先级、JSON 结构、脚本参数或异常处理时，读 `references/扩展说明.md`。

## 边界

- 不覆盖原模型设计文档，不直接改写现有字段名；A1 原表名必须保留，只可追加推荐表名与表名推荐依据。
- 不生成完整审计 run 目录、不维护标准缺口清单、不做字段删除/保留落地；这些属于 E01。
- 不把标准库匹配写成硬编码规则库；语义判断由 AI 基于本次输入完成。
