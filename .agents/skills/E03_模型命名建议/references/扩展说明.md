# 模型命名建议执行细则

## 输入与输出

- 输入 1：标准库 Excel，来自用户本轮指定路径。
- 输入 2：模型设计 Excel，来自用户本轮指定路径。
- 输出：模型设计 Excel 的副本，默认 `{原文件名}_命名建议.xlsx`。
- 原文件只读；输出文件已存在时，优先加时间戳后缀，不静默覆盖。

## Excel 定位口径

- 表名默认读取每个模型 sheet 的 `A1` 单元格。
- 字段区优先在前 50 行查找字段名列，常见表头包括 `字段名`、`字段英文名`、`英文名`、`字段编码`。
- `字段名/current_field_name` 是模型设计 Excel 的当前字段名列；它不是 `参考字段/reference_field`。相同 `字段名` 在同一 Excel 的多个 sheet 中必须得到相同 `推荐字段名`。
- `参考字段/reference_field` 是来源表字段列，常见表头包括 `参考字段`、`参考字段名`、`来源字段`、`源字段`、`原字段`。只有 DWD 参考模式触发时，才可把它作为优先推荐依据。
- 参考库表名按字段行中的 `参考库表`、`参考表`、`来源表`、`源表`、`原表` 等列识别；若包含库名/schema 前缀，只取最后一段表名，并判断该表名是否以 `dwd_` 为前缀，大小写不敏感。参考库表为空、为 ODS/`ods_` 或参考字段为空时，不套用 DWD 表参考字段保留规则。
- 推荐列必须放在字段名列右侧，列名固定为 `推荐字段名`。
- 推荐依据列必须放在 `推荐字段名` 右侧，列名固定为 `推荐依据`。
- 推荐表名和表名推荐依据直接追加在 `A1` 原表名后，格式为 `推荐表名：xxx；表名推荐依据：...`；保留原 A1 内容，不覆盖原表名。

## AI 推荐过程

推荐不是先判断当前英文名是否合规，而是先按同一 Excel 内相同 `字段名/current_field_name` 复用已有推荐，再识别参考库表层级，最后做字段语义到标准库的匹配。

每个字段按固定顺序处理：

1. 读取并区分 `字段名/current_field_name`、`参考库表/reference_table`、`参考字段/reference_field`，以及字段中文名、字段描述、说明、备注、表名、sheet 名等语义来源。
2. 优先查同一 Excel 已处理字段：若已有相同 `字段名/current_field_name` 的 `推荐字段名`，当前字段必须复用该推荐名；这不是保留当前字段名，而是复用前序相同字段名的推荐结果。
3. 若没有同字段名既有推荐，再判断 DWD 参考模式：参考库表名规范化后以 `dwd_` 为前缀且参考字段非空时，本字段以审核参考字段为主，推荐名尽量保持参考字段名；只有与标准库强规则/强映射、字段语义、合规词根、snake_case 或长 token 规则冲突时才重新设计。
4. 若参考库表为空、为 ODS/`ods_`、参考字段为空，或参考库表不是 `dwd_` 前缀表，则不沿用参考字段；若同字段名没有既有推荐，进入标准库和语义推荐。
5. 阅读标准规则库和标准映射库，判断语义来源命中了哪些词条、词根、业务定义或规则；这是语义判断，可以包含近似命中、同义词、业务上下文和冲突判断。
6. 基于前序规则生成 `standard_candidate_name`，再与 `current_field_name` 对比。若本字段复用了同字段名既有推荐，`standard_candidate_name` 必须等于复用的推荐名。
7. 扫描推荐名和标准候选名中的英文 token；超过 7 个字母且不是标准库明确允许的固定词根时，必须将短词根体现在推荐名和标准候选名中，并补充词根建议；若继续保留长 token，只能用结构化例外说明。
8. 如果字段语义命中标准映射库或规则，而推荐名不采用该词根/规则，必须给出另一个具体候选名并在中文依据中说明取舍原因；不得写 `待确认`、空候选或 `rule_only + keep`。
9. `mapping_match` 必须用中文说明命中或未命中的标准库 sheet、行号/词条/词根和原因；`rule_match` 必须用中文说明同字段名一致性、词根组合、缩写、snake_case、币种/金额/费用后缀、参考库表层级、表上下文等规则判断。

`recommendations.json` 可以由脚本辅助落盘，但脚本只能承载 AI 对本次 `context.json` 的逐字段判断，不得以静态字段决策表替代语义理解。复用历史决策时，必须重新检查本次输入哈希、标准库内容、模型字段和 E03 版本，并通过 v1.5.2 质量门禁。

## 候选生成补充规则

按下面顺序生成候选，前序规则命中时不要被后序规则推翻：

1. 同字段名一致性优先：同一 Excel 内相同 `字段名/current_field_name` 已经有推荐结果时，后续同字段名必须复用该 `推荐字段名`，不再单独按参考字段或语义另起推荐。
2. DWD 表参考优先：没有同字段名既有推荐，且参考库表名规范化后以 `dwd_` 为前缀、参考字段名非空时，默认推荐参考字段名，以审核现有 DWD 表字段为主；只有强标准冲突、命名规则明显不合规或语义不符时才重新设计，并在依据中写明“DWD 表参考字段冲突”。
3. 空/ODS/空参考字段不沿用参考字段：参考库表为空、为 ODS/`ods_`、参考字段为空，或参考库表不是 `dwd_` 前缀表时，参考字段不作为保留依据；若没有同字段名既有推荐，按标准库和字段语义生成候选。
4. 标准库和语义推荐：前三条都没有可复用推荐时，才使用标准库明确给出的字段名、表名、固定词根或明确缩写；未命中标准时，基于字段中文名、描述、表上下文等语义负责推荐。
5. 代理主键特例：字段描述/中文名为 `代理主键`，且 `是否主键字段=是`、`是否业务主键=否`、参考字段为空时，优先 `unique_key`，不要改成 `id`。
6. 最小改动优先：没有标准强命中、没有同字段名既有推荐且没有可保留的 `dwd_` 参考字段时，以当前字段名为风格证据，只改明显不规范的 token，例如 `fee -> amt`、`date -> dt`、`commission -> comm`；保留已有合规的词根、词序和缩写。
7. 短词根优先：不要把短词无证据扩成更长短语，例如不要把 `manager` 扩成 `key_account_manager`，不要把 `over` 扩成 `over_capacity`，不要把 `long` 扩成 `long_term`。
8. 同类字段一致：一组字段已形成稳定前缀或词序时，优先沿用该组命名节奏，例如已有 `site_in_ad_*` 时，站外广告优先 `site_out_ad_*`，而不是另起 `offsite_ad_spend_*`。
9. 长 token 词根建议：推荐名或标准候选名中的英文 token 超过 7 个字母且没有标准缩写时，先把该 token 替换为短词根并写入 `recommended_field_name` 和 `standard_candidate_name`，再在 `recommendation_basis` 增加 `补充词根建议：建议新增 {中文词条}->{缩写词根}`，并可在 JSON 中额外写 `term_root_suggestions`（新增字段）。补充词根建议必须与推荐名中的实际词根一致；不得推荐 `adjustment_logistics_amt_usd` 的同时只在依据中写 `调整->adj、物流->logi`。若长 token 是标准库明确允许的固定词根，必须保留长 token 并在 `long_token_exceptions`、`standard_long_tokens` 或依据中说明标准来源，不写补充词根建议。`term_root_suggestions` 是长 token 复核线索，不等于最终新增标准；写回脚本会把它和现有 `标准映射库` 比对，只保留真正缺失且可复制的新标准建议。

最小改动示例：

```text
字段描述：大客户经理费(美元)
当前字段名：manager_fee_usd
规则：费用/金额类统一 fee -> amt，美元保留 usd
候选：manager_amt_usd
原因：manager 已能表达业务角色，标准库未明确要求 key_account_manager，避免语义膨胀。
```

```text
字段描述：长期仓储费(美元)
当前字段名：fba_long_fee_usd
规则：费用/金额类统一 fee -> amt，仓储语义补 storage
候选：fba_long_storage_amt_usd
原因：long 是当前字段的稳定短词根，不无证据扩写为 long_term。
```

强标准命中示例：

```text
字段描述：其他交易费用(美元)
当前字段名：other_transaction_fee_usd
标准映射：交易 -> tx；费用 -> fee
候选生成：其他 + tx + fee + usd => other_tx_fee_usd
决策：当前字段名不等于标准候选，decision=rename
```

不能因为 `other_transaction_fee_usd` 是可读英文且符合 snake_case 就保留；标准库已定义 `交易 -> tx` 时，`transaction` 不是本次标准候选。

## 决策可控口径

E03 v1.5.2 的目标不是让依据“看起来完整”，而是让每个命名推荐都能被机器检查，并把本轮真正缺失、可复制的标准补充建议随输出 Excel 一起沉淀：

- `standard_candidate_name` / `table_standard_candidate_name`：标准库映射或规则推导出的候选名；字段触发同字段名一致性复用时，必须等于复用的 `recommended_field_name`。
- `match_level` / `table_match_level`：只能写 `exact_field`、`exact_table`、`term`、`rule_only`、`none`。
- `decision` / `table_decision`：只能写 `rename`、`keep`。
- `keep_reason` / `table_keep_reason`：仅在 `keep` 时必填，用来说明为什么保留。
- `mapping_match` / `table_mapping_match`：标准库、别名、业务定义、主题域或历史命名映射结果。
- `rule_match` / `table_rule_match`：命名规则、词根拆分、缩写、snake_case、表主题/字段集合一致性等判断。

强命中规则：

- 未触发同字段名一致性复用时，字段 `match_level=exact_field` 或 `term`，且标准候选名不同于当前字段名时，必须 `decision=rename` 并推荐标准候选名。
- 已触发同字段名一致性复用时，字段 `recommended_field_name`、`standard_candidate_name` 和前序相同 `字段名/current_field_name` 的推荐结果必须一致。
- 表名 `table_match_level=exact_table` 或 `term`，且标准候选名不同于当前表名时，必须 `table_decision=rename` 并推荐标准候选名。
- 证据冲突或候选不唯一时，仍须选择最负责任的具体候选名，并在中文依据中写明取舍原因和风险；不得输出 `待确认`。
- 不允许因为模型文档已有 `字段名` 就保留原名；`字段名` 只能作为最小改动和同类字段风格证据，不是标准映射证据。
- 标准库抽取结果在 `context.json` 的 `standard_sheets[*].records` 中；不得因为 `standard_sheets[*].rows` 为空就判断标准库为空。如果 `records` 中标准规则库或标准映射库确实为空，不得声称“命中标准库第 N 行”；只能写 `映射匹配：标准库未抽取到可用行...`，并按规则推导给出候选。

v1.5.2 写回前会执行硬校验：

- recommendations 必须覆盖模型工作簿中所有识别到字段区的 sheet 和字段行。
- 同一模型工作簿中相同 `字段名/current_field_name` 的 `recommended_field_name` 必须一致。
- 每个模型 sheet 必须有表名推荐。
- 推荐名或标准候选名中超过 7 个字母的英文 token，必须已经由 `补充词根建议` / `term_root_suggestions` 给出的短词根替换；若仍保留长 token，必须有结构化长 token 例外说明。
- 校验通过时生成 `quality_report.md`；校验失败时仍生成报告并停止写回。
- `quality_report.md` 必须包含 `标准映射建议质量`：记录建议初稿数、已过滤已有标准数、中文名冲突数、词根冲突数、最终可复制新增数和无法写入项。最终新增项若缺少 `业务域/中文名称/标准词根/释义/适用场景/示例中文名称/示例`，或包含占位说明，质量门禁必须失败。

## 标准库同步与建议沉淀

写回时如提供 `--standard-lib`，输出 Excel 会追加复制标准库中的原始 sheet，并按原标准库模板创建：

- `标准规则库_建议`：使用 `标准规则库` 的表头结构，写入 AI 明确给出的 `standard_rule_suggestions` / `rule_suggestions`。
- `标准映射库_建议`：使用 `标准映射库` 的表头结构，写入 AI 明确给出的 `standard_mapping_suggestions` / `mapping_suggestions`，并参考字段级 `term_root_suggestions` 中的 `中文词条->缩写词根`。写回脚本必须先和当前 `标准映射库` 做 anti-join：已存在的 `(中文名称, 标准词根)` 不写入；中文名称已存在但词根不同、或词根已存在但中文名称不同的项视为冲突项，不写入最终建议 sheet，并写入质量报告。

建议 sheet 是评审稿，不直接覆盖标准库原表，但必须可以作为新增标准候选直接复制到标准库。AI 若发现可复用标准，应优先输出结构化建议，且不得输出 `待评审`、`本轮标准库为空` 等占位释义：

```json
{
  "standard_rule_suggestions": [
    {
      "作用对象": "字段名",
      "规则描述": "费用类字段在表达金额时优先使用 amt 词根，不保留 fee 后缀。",
      "示例": "logi_amt_usd"
    }
  ],
  "standard_mapping_suggestions": [
    {
      "业务域": "待评审",
      "中文名称": "卫星仓",
      "标准词根": "sat_wh",
      "释义": "卫星仓业务限定词根",
      "适用场景": "仓储、履约费用字段",
      "示例中文名称": "卫星仓处理费",
      "示例": "sat_wh_process_amt_usd"
    }
  ]
}
```

## 推荐依据

字段 `推荐依据` 与 A1 中的 `表名推荐依据` 必须显式包含以下内容：

- `映射匹配：{命中/近似命中/未命中 + 标准库 sheet、行号或标准字段/表名 + 命中原因}`
- `规则匹配：{命名规则、词根拆分、缩写、snake_case、表主题/字段集合一致性等判断}`
- `一致性判断：{同一 Excel 是否已有相同 字段名/current_field_name 的推荐；若有，说明复用的 sheet、row 和推荐字段名}`
- `参考判断：{参考库表规范化后是否为 dwd_ 前缀表；是时说明是否沿用参考字段；否时说明参考字段不参与推荐}`
- `标准候选：{标准库或规则推导出的候选名}`
- `匹配层级：{exact_field/exact_table/term/rule_only/none}`
- `决策：{rename/keep}`
- `保留/修订原因：{keep 时填写；证据冲突或候选不唯一时说明取舍}`
- `补充词根建议：{当英文 token 超过 7 个字母且无标准缩写时填写；建议新增中文词条和缩写词根，且该缩写词根必须出现在推荐字段名和标准候选名中}`

保留原名只允许在以下情况下出现：

- 标准候选名与当前命名一致，并且规则匹配也确认当前命名合规。
- 仅规则命中且没有更可靠标准候选，同时有清晰的保留原因。

不能写“沿用原字段”“保留原名”作为依据；这类内容最多只能作为当前状态描述或最小改动风格证据，不能作为标准映射证据。

当 `decision=keep` 时，依据必须证明标准候选名本身就是当前字段名，而不是证明当前字段名“看起来合理”。如果字段描述、字段中文名或表上下文命中了不同的标准词根，不能 keep，必须给出具体候选并说明为什么采用该候选。

## AI 决策 JSON

写回脚本接受下面的结构：

```json
{
  "sheets": [
    {
      "sheet": "实体Sheet名",
      "recommended_table_name": "ads_example_table",
      "table_standard_candidate_name": "ads_example_table",
      "table_match_level": "term",
      "table_decision": "rename",
      "table_mapping_match": "近似命中 标准库主题域 sheet 第 3 行 ads_example_table，业务主题一致",
      "table_rule_match": "符合 ads_主题_table 命名规则，使用 snake_case",
      "table_recommendation_basis": "映射匹配：近似命中 标准库主题域 sheet 第 3 行 ads_example_table，业务主题一致；规则匹配：符合 ads_主题_table 命名规则，使用 snake_case；标准候选：ads_example_table；匹配层级：term；决策：rename",
      "fields": [
        {
          "row": 8,
          "current_field_name": "原字段名",
          "field_description": "创建时间",
          "recommended_field_name": "created_time",
          "standard_candidate_name": "created_time",
          "match_level": "exact_field",
          "decision": "rename",
          "mapping_match": "命中 标准库公共字段 sheet 第 12 行 created_time，中文名与业务定义一致",
          "rule_match": "符合公共时间字段命名规则，使用 snake_case，后缀 time 表示时间点",
          "recommendation_basis": "映射匹配：命中 标准库公共字段 sheet 第 12 行 created_time，中文名与业务定义一致；规则匹配：符合公共时间字段命名规则，使用 snake_case，后缀 time 表示时间点；标准候选：created_time；匹配层级：exact_field；决策：rename"
        }
      ]
    }
  ]
}
```

允许在字段推荐中额外写 `field_description`、`mapping_terms_considered`、`semantic_reasoning`、`term_root_suggestions`、`long_token_exceptions`、`standard_long_tokens` 等辅助键；写回脚本会识别长 token 辅助键并忽略其他未知键，但不能省略上述必填决策键。`term_root_suggestions` 中 `中文词条->缩写词根` 的缩写词根必须出现在推荐字段名或标准候选名中；否则视为未采用建议。

字段推荐优先按 `row` 写回；没有 `row` 时按 `current_field_name` 匹配。`current_field_name` 不能作为标准映射证据；仅在推荐依据中明确标注为“最小改动/同类字段风格证据”时，才可用于保留词根、词序和缩写习惯。

写回前脚本会校验每条字段和表名推荐：最终写入的依据文本必须是中文正文，必须包含 `映射匹配` 和 `规则匹配`，不允许出现 `待确认`，并且推荐名、标准候选、命中层级、决策动作必须一致。同一 Excel 中相同 `字段名/current_field_name` 的 `推荐字段名` 必须一致。若标准强命中但推荐仍等于当前名、长 token 未替换为建议短词根且无例外说明、补充词根建议未体现在推荐名/标准候选中，或同字段名推荐不一致，写回会失败。

## 异常处理

- 标准库过大时，优先读取与表名、字段中文名、主题域相关的 sheet 或筛选后片段。
- 多个 sheet 都有 A1 和字段区时，逐 sheet 处理。
- 找不到字段名列时停止写回，报告需要用户确认字段列，不猜测整列。
- 模型设计是 `.xls` 时，先转换为 `.xlsx` 后再执行脚本。
