# C17_数仓质量治理编排

## 这项技能解决什么问题

- 非ODS按批次执行 C14 → C15一致性 → C11 → C15唯一性；ODS走同步统计节点与平台行数规则专用分支，集中管理证据。
- 从模型周期取最后配置时间加5分钟；真实运行后留截图，HTML默认最近批次并可筛选、点击查看。

## 先读哪些本地知识

- 必读 `references/执行编排.md`、`references/命令与状态.md`、`references/输出契约.md`。
- 按工作区标准定位B04子项目、恢复B08，修改前B02、收尾B03。实际子阶段先读C14、C15、C11，从注册表解析编号。

## 固定动作

0. 每个新批次或新的源码核验任务，先按 `references/最新源码准备.md` 更新 `input/data-assets`，记录同步时间、分支、远端及本地提交号，再读取完整加工SQL。同一批次固定使用该提交，传给C14/C11，不逐模型重复拉取。仓库为加工代码来源，平台同步语句只作可选部署比对；同步失败不得悄悄改用旧代码或平台SQL。
1. 定位治理台账；首次用scripts/govern.py的init初始化。保存清单原件，分配递增B编号，用batch登记；仅按用户明确范围跳过ODS。用户要求处理ODS时，执行 `references/ODS监控节点补齐.md` 专用分支：默认完成节点及指标配置、恢复上线，运行质量指标并查询新结果截图后返回；不默认额外启动DATAX/工作流验证新增节点，只有用户明确要求验证时才执行关联ETL运行分支。本边界仅限ODS，不继续套用下列非ODS第2—7步。单模型带教沿已有案例记录，不为导航或补配置而擅自扩展为整批治理。
2. 核验技术表身份，读取模型更新周期，用schedule推算并落盘。非每日或缺失周期标待处理，不退回固定08:00。
3. 执行C14，将有来源的SQL交给C15，查重、配置并全文回读；通知、周期和运行独立记录。
4. 执行C11；仅业务唯一键确认后生成唯一性SQL并调用C15，否则记“不适用”及原因。
5. 按授权仅运行目标一行，核实新记录；先收起左栏、关闭弹窗，截取目标与时间、结果同屏的列表PNG；数值另核对。
6. 按输出契约保存运行证据和截图元数据，用attach登记；每完成一模型即更新台账、HTML和B08。
7. 用verify验收截图，检查HTML筛选、缩略图与页内放大弹窗；交付批次报告及缺口。用户只要求一个案例时只验该案例，不补历史图。

## 什么时候再读本 skill 的 references

- 新任务开始、仓库更新、提交固定及平台源码来源边界：读最新源码准备.md。
- 恢复、跳过、无唯一键和浏览器缺失：读执行编排.md。
- ODS关联ETL、补统计节点、重新上线及同步行数质量指标：读ODS监控节点补齐.md。
- 初始化、登记、周期、截图参数和兼容：读命令与状态.md。
- 文件、截图内容和验收口径：读输出契约.md；结构导航见结构融合索引.md。

## 边界

- 不猜写接口、不重复建指标、不用历史正常冒充本次运行；禁止用报告截图或生成图替代平台画面。
- 缺截图不回退SQL已保存事实，但完整交付仍待留证；文件哈希验证不代替现场检查。
- 不创建后台定时任务，不擅自调整源模型启停，不私自增加通知收件人。用户授权ODS工作流补节点时，按专用流程临时下线并恢复原工作流及原定时状态；禁止删除工作流和任务节点。
- 周期是现场快照，后续执行重新读取；历史模型状态展示最新记录，截图按批次关联。
