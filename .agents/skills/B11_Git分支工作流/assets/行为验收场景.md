# 行为验收场景

| 场景 | 预期 |
|---|---|
| 工作区根目录本身有Git，目标在.agents | 识别根仓库；准备修改且在main时先建工作分支 |
| 根目录无Git，应用在任意名称子目录 | 从目标定位子仓库，不猜固定应用目录 |
| 根仓库中有独立嵌套仓库或子模块 | 使用目标最近的真实Git仓库，分开处理父仓库指针 |
| worktree的.git是文件 | Git识别到当前worktree，正常读分支 |
| 新文件的父目录尚不存在 | 从最近已存在父目录定位，保持目标路径用于后续创建 |
| 目标不在任何Git仓库 | 报告无仓库，继续可做的文件任务，不自动git init |
| detached HEAD需要实现 | 保留提交并先建专用分支 |
| 已有同任务分支与无关脏文件 | 复用分支，保护无关文件和暂存内容 |
| 纯文档修改 | 校验内容/链接，不硬跑npm测试 |
| 用户只说提交一版 | 仅本地提交，不推送、不合并、不发版 |
| 多远端且无upstream，用户要求推送 | 询问目标远端，不猜origin |
| 用户说OK，没有约定合并 | 记录验收状态，不自动合并 |
| 用户明确要求合并到目标分支 | 在授权范围内按仓库保护与策略合并，不重复索取已给授权 |
| PR工具不可用且基线有保护 | 不以本地fallback绕过保护 |
| 普通开发任务 | 按改动针对性验证，不自动执行B01 |
| 本骨架提交或合并，Git默认消息为英文 | 标题和正文改为中文；保留类型与代码标识；不自动改写既有历史 |
