# main 直接提交保护

本页落实既有 Git 任务标准和提交前强制门。禁止 main 直接提交；每次提交确认分支，工作分支提交后走 PR。

## 安装与核验

在目标仓库根目录运行：

```powershell
python .agents/skills/B11_Git分支工作流/scripts/install_branch_guard.py --repo . --check
python .agents/skills/B11_Git分支工作流/scripts/install_branch_guard.py --repo . --install
python .agents/skills/B11_Git分支工作流/scripts/install_branch_guard.py --repo . --check
```

首次缺少保护时安装；已经一致时保持原样。安装只针对目标仓库的公共 Git hooks 目录，不写全局配置、不覆盖第三方 hooks、不改变 core.hooksPath。发现自定义 hooksPath 或内容冲突时停止，先解决兼容，不绕过。运行态 hooks 不随 Git clone 自动安装，新克隆须安装后才能提交；linked worktree 共享保护。

## 拦截范围

- pre-commit：拒绝在 main、master、已知远端默认分支创建提交。
- prepare-commit-msg：同样检查分支，阻断跳过 pre-commit 的提交路径。
- pre-merge-commit：阻断在受保护分支本地创建 merge commit。
- pre-push：检查目标 ref，拒绝直接更新或删除远端受保护基线，即使当前位于工作分支。
- detached HEAD 不允许创建提交，先建立工作分支。
- hook 使用 Git 自带 shell 与 Git，无需 Python 常驻；Python 负责安装、检查和测试。

禁止为完成提交关闭或移走 hooks、使用 --no-verify、改 hooksPath 或用底层 Git 命令写引用。Git hooks 是客户端机制，不能声称能阻止任意修改 Git 配置的人；远端 main 同时要求 PR，并对管理员生效，防止未安装 hooks 的客户端直接推送。

## 本项目远端策略

main 必须通过 PR 更新，管理员同样受约束；禁止 force push 和删除。所需审批人数为 0，不新增第二位审核人要求；正常 PR 合并仍按用户已有授权执行。读回 GitHub 配置确认生效，不在真实 main 创建违规提交试探。

正式发布仍按 B09 核验合并结果；本页将检查前移到提交发生前，不能以“发布前会检查”替代。
