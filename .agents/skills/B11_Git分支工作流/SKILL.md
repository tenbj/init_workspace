# Git 分支工作流

## 这项技能解决什么问题

- 从本次目标文件定位真实 Git 仓库，适配根仓库、嵌套仓库、子模块、worktree 和无 Git 的工作区。
- 在受保护基线之外开展修改，保留用户已有工作，以当前仓库的检查和验收约定交付。
- 区分实现、提交、推送、验收、合并和发布；不绑定项目名、编程语言、包管理器或指定人员。

用户说“发布/正式发布”且对象明确时，读取 B09 的完整发布流程，不把它缩减为单次push或合并；本次新发布建工作分支，恢复同次发布沿用记录，按事项逐一提交后统一推送并保留分类合并。用户只要求commit、push或限定阶段时不扩展动作。

## 先读哪些本地知识

- 每次使用先读 `references/仓库定位与分支规则.md`，结合目标仓库的 AGENTS.md 和实际 Git 状态定位。
- 实现或检查前读 `references/校验与发布规则.md`；提交、推送或合并前读 `references/验收与合并流程.md`。
- 提交或合并前读取目标工作区的提交描述语言规则；本骨架统一约束见 `.agents/rules/version-control-rules.md`。
- 汇报时读 `references/输出契约.md`；迁入来源和适装边界见 `references/扩展说明.md`。

## 固定动作

1. 明确目标路径与本次动作，用 `scripts/inspect_repo.py --target <目标路径>` 做只读定位；多仓库分别处理。
2. 确认基线、当前分支、未提交内容和上游；即将修改且处于受保护基线时，先创建专用工作分支。只读任务不要求切分支。
3. 仅修改任务范围内的文件；保留已有脏改动和暂存内容，按目标仓库已有规则选择针对性检查。
4. 每次提交前重新确认分支，执行 `scripts/install_branch_guard.py --repo <仓库路径> --check`；禁止在 main 等受保护基线上创建任何本地提交。保护缺失时先按 `references/提交保护.md` 安装并复查，不能绕过。通过后按用户已有授权在工作分支提交和推送。
5. 向用户或其指定验收者提供变更、检查结果和验收入口。验收通过与合并、发布分别判定，不把一般性的“OK”解释为合并命令。
6. 仅在合并目标和授权明确后合并；沿用已确认的分支和分类提交，不将“继续发布合并”解释为允许改用 squash 或直接推送基线。用户要求保留分类提交时，按 `references/验收与合并流程.md` 执行 PR 合并核验，再交给 B09 发布。

## 什么时候再读本 skill 的 references

- 遇到多仓库、无 Git、脏工作区、detached HEAD、已有分支或基线不明确时，读仓库定位与分支规则。
- 需要选择测试、版本号、锁文件、文档或构建检查时，读校验与发布规则。
- 用户要求提交、推送、验收、合并、发布或清理分支时，读验收与合并流程。
- 维护本技能时，读 `references/结构融合索引.md`；需要复核典型场景时，读 `assets/行为验收场景.md`。

## 提交命名检查

生成消息及执行提交、合并或发布准备提交前，读取并执行 `.system/standards/Git版本控制标准.md` 的“提交命名”与“提交前核对”。命名规则和合格示例只在该标准维护，本 Skill 不另设口径。

## 边界

- 禁止从 main 直接提交。覆盖 commit/amend/cherry-pick/squash 后提交及本地 merge commit；发布、紧急修复、文档微调均须在工作分支完成。按 `.agents/rules/version-control-rules.md` 的提交前强制门执行，不能使用跳过 hook 或底层 Git 命令替代。

- 不在受保护基线上开始新实现；不为只读检查或单纯推送已存在提交而无故改写分支历史。
- 不自动初始化 Git，不猜远端或目标基线，不硬编码 origin、main、master、项目路径或人员。
- 不自动 reset、clean、stash、强推或删除分支；用户授权的具体操作按范围执行。
- 不提交无关内容、凭据、登录态或私密配置；已有授权足够时不重复询问。
- 不把验收通过自动升级成推送、合并、打标签或发布授权；目标仓库明确约定且用户已接受的流程除外。
- 不自动执行 B01，不强制使用某种语言的检查命令；无仓库时完成可做的工作并说明 Git 动作不适用。
