# 行为验收

| 场景 | 必须行为 |
|---|---|
| SQP 品牌新增 | cbebg/ads/dwd/规范表名/同名.sql；分支 DWD-SQP品牌视图；只提交加工 SQL |
| DWS 代码修改 | 分支按 B11 确认；提交消息按 `.system/standards/Git版本控制标准.md` 核对 |
| 选中 create SQL | 预检拒绝，不悄悄替换成猜测的文件 |
| 工作树有用户改动 | 保护原工作树，可用隔离 worktree；不自动 stash/reset/clean |
| 已推送且 MR 已建，通知失败 | 仅恢复 F05，不重复 commit/MR |
| MR 已合并 | 不发送“帮合并代码” |
| 暂存区混入其他文件 | 拒绝提交，不将其悄悄 unstage 或打包入提交 |
| CLI 不存在或权限不足 | 进入 F05 异常分支，绝不切换到 Codex 视觉/桌面消息 |
| 同名联系人/未知发信结果 | 交 F05 消歧/查询，不猜测收件人或盲目重发 |

创建本技能只执行离线校验，不再次提交原 SQP 模型或发送历史 MR 通知。


## 本次合入的命名与改名校验

发布输入必须包含 `naming_confirmation_file`；记录状态为confirmed，包含名称、层域、更新方式、频率、用户明确确认依据及日期，与正式SQL实际INSERT目标一致。加工SQL直接以语句开始；发现头注释回C18修改正式源并重验，不仅修改仓库副本。

明确改名时传 `previous_table`；仅允许已确认旧路径删除和新路径写入，原分支追加提交并复用MR，不强推。暂存内容必须与正式源一致。来源路径及默认人员不迁入，分支/提交仍遵循B11和当前Git标准。

用户明确追加收件人时，各人使用独立幂等请求ID及回执；本次追加不成为永久默认。MR创建、合并状态、通知各自记录，通知门遵循F05的当前通知规则。
