# 生成与验收流程

## 统一工程的分工

| 位置 | 保存内容 | 维护方式 |
| --- | --- | --- |
| 本技能 scripts/ | 校验、布局、生成、原生格式补充、复核记录、测试 | 所有报告共享，修复在这里进行 |
| 本技能 assets/ | theme.json 主题与 example.report.json 示例 | 统一视觉参数与输入示例 |
| 任务 inputs/report.json | 本次报告的结构、文字、数字和来源 | 模型研究后生成，用户也可以直接修改 |
| 任务根目录 | 最终 xlsx | 统一入口生成 |
| 任务 intermediates/ | 按运行编号分开的输入快照、布局规格、暂存 xlsx、逐页 PNG；.runtime 依赖链接 | 自动生成；不是另一份工程 |
| 任务 logs/ | 检查结果、运行状态、输入/主题/成品哈希、视觉复核记录 | 追溯使用的内容和检查结果 |

代码属于 Skill 内的公共脚本。作者库和 Node/Python 属于环境配套运行时；它们不是 MCP 中的业务生成器。MCP/命令工具只是发起执行的渠道。输入 JSON 可以独立迁移，生成不需要原来的临时脚本或旧工作簿。

旧报告的 intermediates 保留作为历史记录，不批量删除或改写。新任务只使用统一入口；旧报告需继续编辑时先提取为独立 report.json，核对后再接入。一次性迁移工具只是迁移记录，不成为日常生成依赖。

## 执行

1. 按内容结构设计完成六检，写好独立输入；数字、时点、条件、未知项和引用须完整。
2. 读取当前环境 spreadsheets 技能，调用 load_workspace_dependencies 定位配套 Node、Python 和作者库；按该技能要求执行使用标记。引擎不另行联网安装依赖。
3. 先校验再生成。以下为 PowerShell 示例；变量替换为本次环境和任务的实际路径，不将机器路径写进公共代码。

```powershell
$r01Node = '<配套 Node 可执行文件>'
$r01Skill = '<R01_汇报表格制作目录>'
$r01Task = '<outputs 下本任务目录>'
& $r01Node "$r01Skill/scripts/validate.mjs" "$r01Task/inputs/report.json"
& $r01Node "$r01Skill/scripts/generate.mjs" --input "$r01Task/inputs/report.json" --output-dir $r01Task --runtime-root '<配套 dependencies 目录>'
```

运行时也可用 `R01_RUNTIME_ROOT` 指定，未指定时尝试用户缓存中的标准配套路径。不同机器应使用环境返回的路径。脚本只在 intermediates/.runtime 下创建指向 node_modules 的链接，不修改依赖目录。

4. generate 调用 artifact-tool 写入数据、样式及合并，再由 Python 标准库补齐原生缩进、超链接、视图和打印设置。随后重新读取保存的 OOXML，逐格比对数据，检查日期/数字格式、页签、字体字号、重点、对齐、缩进、纵向合并、冻结和链接，再重新导入最终暂存文件逐页渲染。
5. 自动检查和渲染全部成功后才发布成品。已有同名文件默认拒绝；明确更新时追加 `--overwrite`。出错会非零退出，记录失败，保留原成品。目录有运行锁时拒绝并发写入；异常断电残留锁须确认无运行进程后才能清理。
6. 模型或人工实际查看全部 PNG，核对内容结构、字形、换行、截断、留白、边框和重点。模型需修正 report.json 或公共逻辑后重新生成，不能只修改预览。原生 indent 在某些渲染器里显示较弱，以保存后的原生属性检查与显示检查共同判断。
7. 全部预览已复核且无问题后，记录复核；这条命令不代替看图，也不自动判断视觉质量：

```powershell
& $r01Node "$r01Skill/scripts/review.mjs" '<本次 logs 中的 run.json 完整路径>' '逐页复核了哪些内容，以及修正或仍需说明的事项'
```

review 会核对成品哈希与运行记录相同，防止为已经变化的文件登记旧检查。自动成功状态为 automated_checks_passed；视觉复核另存 review.json，不将自动生成当作人工看图通过。

## 公共能力维护和自测

修改引擎后执行：

```powershell
& $r01Node --test "$r01Skill/scripts/tests/engine.test.mjs"
```

可设 `R01_TEST_OUTPUT` 指向任务验证目录保存测试产物，否则用系统临时目录。测试覆盖错误数据拒绝、丢失内容的合并防护、引用、版本、中文换行，以及真实导出/原生补充/重读/渲染、JSON 改动后重生成、数字与日期、等号文本、覆盖与失败保护。回归不能代替业务事实和逐页视觉复核。

公共逻辑变化后，用多页来源报告、多页方案比较、单页纵向分组三种已有案例复核；无需每次重新写生成脚本。更新技能展示版本并运行 A01 quick_validate；协议、主题或引擎发生兼容性变化时同步其技术版本。

## 当前范围

统一引擎用于新建内容型汇报或已转换为 JSON 的报告；不直接原位编辑任意旧 xlsx。现支持单页及一级多页、真实数值和日期、备注重点、标题横向合并、正文纵向共享格、独立来源表。复杂公式、图表、多级页签、标题以外的横向合并需扩展后再交付。能力不支持时明确报错或先扩展，不在任务下绕开公共引擎另造生成器。
