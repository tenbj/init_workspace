# 内容结构设计

用于从零组织汇报，或重构“格式没问题但内容不顺”的表格。先确定信息之间的关系，再选择表格、章节或页面表达。规则可迁移到其他内容载体，本技能仍以 Excel 汇报表为交付范围。

## 先形成最小内容骨架

在作者工作区明确：读者要理解或决定什么；每个模块回答什么问题；模块内按什么主轴分类；哪些是下级、属性或依据；按什么顺序阅读。简单任务用几行提纲即可，不强制另交规划文件或等待用户审批。

骨架确定后才编号和分配行列。已有材料的段落、附件顺序和收集时间只是输入组织方式，不自动成为最终目录。

## 六项能力

| 能力 | 要作出的判断 | 执行动作 |
| --- | --- | --- |
| 信息角色识别 | 这条信息在说明背景、事件、事实、判断、影响、建议，还是提供证据？ | 拆开混在同一句中的角色；保留事实状态和判断条件，不因相邻出现就并成一类 |
| 分类主轴选择 | 这一层究竟按对象、领域、阶段、问题还是其他标准划分？ | 为同级条目选择一个能解释全部条目的标准；无法归入者改为属性、总括或独立模块 |
| 层级关系建立 | 哪些是整体与局部、主干与属性、结论与依据？ | 下级须展开上级；时间、地区、责任、优先级等按任务放入字段，不让属性自动冒充一级主题 |
| 阅读顺序安排 | 读者理解下一部分前，需要先知道什么？ | 按理解依赖、时间、因果或决策步骤排序；概览可先给结论，明细仍应交代必要背景和过程 |
| 内容边界划分 | 哪些信息能用同一套字段表达，哪些需要独立阅读？ | 决定分列、拆行、分组、独立表或页签；字段体系或阅读任务改变时拆分，不靠合并掩盖冲突 |
| 结构完整性校验 | 是否混类、越级、跳步、重复、遗漏或无法追溯？ | 正向检查素材归属，再逆向检查结论依据；修正结构后才进行文字压缩与视觉验收 |

分类主轴在同一层、同一阅读任务内保持一致，不要求整个工作簿只能使用一种维度。例如，事件表按事件分组，影响表按影响领域分组，证据表按资料条目组织；概览按报告模块组织。这些不同阅读任务不应混成一组明细编号。

## 主干、属性与证据如何落位

- **总括结论**：放在概览或主表清楚的位置，不与组成它的事件、领域同级编号。是否需要概览页遵循现有页签规则。
- **主干分类**：形成第二列及其共享范围；同级项目应有相近粒度，不混用一个行业与该行业的某家企业。
- **属性信息**：放入必要业务列。同一对象涉及多个地区时，地区作为范围；只有读者需要逐地区比较时，地区才成为该表主轴。
- **下级事项**：分别拆行；共享信息仅在真实范围内分组。不要为了让行数一致而把不同数量的原因、影响与措施强行对应。
- **证据与限制**：来源支撑事实，事实支撑判断；数据缺口和适用条件紧邻受其影响的结论。独立证据表不能成为藏匿关键不确定性的地方。

分类存在交叉时，先明确各项覆盖范围。一个事实确实支撑多个领域，可以多处引用同一来源，但不能把同一损失重复累计。对没有证据的范围，保留明确缺口；不要为凑齐分类虚构事实。

## 阅读顺序按问题选择

| 阅读任务 | 可采用的明细顺序 | 选择理由 |
| --- | --- | --- |
| 事件与影响分析 | 事件过程 → 影响分析 → 应对建议 → 证据 | 先让读者知道发生了什么，再理解影响与行动 |
| 问题诊断 | 现状与证据 → 原因分析 → 对策 | 使解释建立在可核查的表现上 |
| 方案决策 | 目标与约束 → 同维度比较 → 建议与待决项 | 先统一选择标准，再展示差异与取舍 |
| 进度汇报 | 目标与当前结果 → 偏差与影响 → 下一步及支持 | 优先回答是否达成、偏离在哪里以及如何处理 |

这是推理顺序，不是必须建出的页签清单。建议可紧邻对应影响，少量证据可与事实同表；不用为了遵循顺序创造空章节。摘要先给结论与明细先交代过程可以同时成立。用户明确的顺序优先。

重排后同步概览条目、页签物理顺序、编号、页内标题、交叉引用及超链接。交付前以保存后的文件核对，不能仅在回复中表示赞同就声称已改好。

## 来源依据是独立的内容结构

多条来源需要分别说明出处、适用范围或支撑事实时，组织成有明确表头的独立证据表；需要独立核查，或用户明确要求时单独成页。主表尾部的小字列表不能替代这样的证据结构。只有简单单来源且无独立核查任务时，才可用紧邻事实的简短引用。

- 来源字段按实际需要选取：资料主题或标题、来源编码、发布机构、发布日期、支撑事实、原文链接、适用范围或限制；仍遵循编号、主干与备注的列规则，不为字段清单机械增列。
- 区分展示编号与引用编码。已有稳定引用编码时沿用；调整来源排序不应破坏引用关系。
- 一个来源可支撑多个事实，一个判断也可依赖多条来源。不为凑一一对应复制来源记录，不以链接数量代替证据质量。
- 事实表中的每个引用都能找到来源，来源表说明实际支撑的内容；不能只列网址而不交代依据关系。只收录实际使用的资料。
- 发布日期、事件时间、统计区间分别表达。旧公告不自动代表当前状态，预测不当作实测，个案不外推总体。

## 结构六检

1. **分类检**：只读同级名称，能否用同一个分类标准解释？是否混入总括、属性或下级实例？
2. **层级检**：下级是否真正展开上级？目录是否对应真实模块？是否有空层级或孤立条目？
3. **顺序检**：下一部分需要的前置信息是否已经交代？是否为了突出结论而打乱明细的理解路径？
4. **边界检**：每表是否回答清楚的问题、每列是否有稳定含义？独立证据是否被挤在页尾？
5. **覆盖检**：原始事实、数字、条件、未知项和请求是否都有去处？重复信息是否必要？交叉分类是否会导致重复累计？
6. **引用检**：从结论能否追到事实及来源？来源编码、时间口径和重排后的引用是否一致？

六检通过后再检查字号、颜色、合并和打印。结构问题不能靠改名、标红、增页或缩小字体来判定解决。用户已认可的视觉样式继续保留，除非结构变化确实要求局部适配。

## 从迭代中得到的反例与修正

| 暴露的问题 | 根因 | 可迁移的修正 |
| --- | --- | --- |
| 总体判断、若干台风、交通、区域重点、统计缺口平级编号 | 把材料清单当成分类体系 | 先识别角色；事件表按台风组织，影响表按领域组织，地区与缺口回到相关字段 |
| 来源在主表尾部连续铺开 | 把证据阅读误当作排版附注 | 建立独立证据结构，说明出处、支撑事实与限制，通过编码引用 |
| 已拆出事件表与影响表，仍先展示影响明细 | 完成分类后没有检查阅读依赖 | 概览先给结论；明细先过程、后影响，最后提供可查的证据 |
| 新版能渲染、格式统一就认为完成 | 只验收外观，没有验收内容关系 | 先做结构六检，再做原生格式与逐页视觉核查 |

这些例子用于训练判断，不固化台风名称、六个影响领域、四张工作表或某次列宽。新任务重新选择分类主轴与内容边界。
