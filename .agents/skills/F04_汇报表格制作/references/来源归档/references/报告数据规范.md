# 报告数据规范

## 用户自定义表头（引擎 1.2.0）

用户明确指定列名与顺序时，工作表设置 `columnPolicy: "custom"`，按用户要求提供 columns，无需增加编号和备注。省略时仍使用原默认列约束。首两列继续居中加粗，正文标红如需说明，可设置 `emphasisReasonKey` 指向实际承载原因的业务列；未指定则使用 remarks。可设置 `autoFilter: true` 启用表头筛选，此时禁止正文合并。长表预览自动按行分段，全部片段均需视觉复核，Excel 中仍保持同一张表。

模型负责研究、提炼、分类、排序与核对事实，最终将可见内容写成 UTF-8 JSON；脚本读取 JSON 后只做确定性的生成和检查，不联网、不调用模型、不生成业务结论。最小可运行示例见 [example.report.json](../assets/example.report.json)，校验实现以 [model.mjs](../scripts/lib/model.mjs) 为准。

## 数据对象

| 字段 | 含义 |
| --- | --- |
| schemaVersion | 当前支持 `1.0.0`；未知版本拒绝执行 |
| id / title | 报告标识和完整名称，均必填；页内显示标题由各 sheet 决定 |
| filename | `.xlsx` 文件名，不能含目录或路径字符 |
| asOf | 可选，`YYYY-MM-DD` 口径日期；作为元数据保存，不自动添加页尾。涉及阶段性统计时，同时在正文或备注中明确可见的截止日期和范围 |
| sheets | 按最终阅读顺序排列的工作表对象 |
| sources | 可选，唯一来源记录；有来源时必须有且仅有一张来源表 |

工作表包含 `id`、`name`、`role`、`columns`，可选 `title`、`titleMerge`、`rows`、`groups`。role 为 `overview`、`detail`、`comparison` 或 `sources`。单页不强制概览；当前引擎的多页协议采用一级明细：首表 `0 概览`，其后 `1 主题`、`2 主题` 等连续编号。需要多级下钻时，应扩展统一协议及检查，不能扁平化后声称满足原结构。

各页 title 默认等于 name。明细标题以页签名起始；概览标题包含“概览”。`titleMerge` 默认 `true`：合并B2至最右业务列第2行，文字在B2，居中且无边框，不为标题扩大正文列宽。用户明确禁止标题合并时设为 `false`，改用足够宽的单格标题。标题超过可用宽度时报错，需缩短而非缩小字号。此能力自引擎1.1.0提供，输入schemaVersion保持1.0.0。

columns 为 3–12 列，每列包含唯一 `key` 和可见 `label`，可选 `width`（8–85）、`align`（left / center）、`numberFormat`。首列必须为 `no / 编号`，末列为 `remarks / 备注`；第二列为内容主干。首两列自动居中加粗，不接受左对齐。

## 行、数值和引用

每行具有稳定且唯一的 `id` 与 `values`。values 的键对应 columns.key；值支持字符串、数值、布尔、null 或 `{ "type":"date", "value":"2026-09-09" }`。未知内容写明“待确认”，不适用留空；零必须写数值 `0`。日期用日期对象，数字单位用 numberFormat 或单独字段，不把数值预先拼成带单位字符串。

- `no` 使用“一、二、三”这样的中文序号值，不包含顿号。分组覆盖行的共享字段留空。
- `emphasis: ["request"]` 表示该业务字段标红，必须同时提供解释原因的 remarks；首两列和备注不允许作为重点字段。
- `formats: {"cost":"0\" 万元\""}` 为单个数值的显示格式；也可在列上指定 numberFormat。
- `refs: {"fact":["S1","S2"]}` 给文本事实关联来源，脚本追加 `[S1、S2]`。未知来源、重复来源 ID/URL、未使用的来源都会报错。
- 概览行必须提供 `targetSheetId`，与后续明细逐一对应且顺序一致；第二列值等于相应页签去掉数字前缀后的主题。
- `height` 可设置较大的最小行高；引擎仍会按文字估算行高。过长行超出 Excel 上限会报错，需拆行。

当前为内容型汇报协议，不接受公式字段；以 `=` 起始的字符串按普通文本保存。需要公式、图表、图片或新增原生功能时，扩展公共引擎及回归测试后再使用。未知字段一律报错，避免表面接收却未执行。

## 分组和来源

纵向共享格通过 `groups: [{"from":"row_a","to":"row_c","fields":["no","topic"]}]` 定义。起止值为行 ID，顺序按 rows；起点必须有内容，被覆盖单元格必须为空，不允许重叠，也不允许包含标红或引用字段。首两列一起分组且跨度相同。没有自由合并地址接口，避免覆盖内容或横向合并正文；标题合并由 `titleMerge` 单独控制。

sources 中每条记录包含 `id`、`topic`、`publisher`、`publishedAt`、`support`、`url`，可选 `limitations`。网址仅允许无登录凭证的 http(s) 链接。来源表 role 为 sources，不自行提供 rows/groups；其列顺序固定为：

`no / topic / code / publisher / date / support / url / remarks`

来源表自动生成可点击链接和真实日期，limitations 显示在备注中。链接有效性与事实支持关系仍须研究核验；引擎仅验证引用完整、协议安全和保存后的链接目标一致，不会声称已重新访问网页。
