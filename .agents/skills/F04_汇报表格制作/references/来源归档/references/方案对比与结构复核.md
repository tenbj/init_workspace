# 方案对比与结构复核

用于多方案选型的字段设计与口径复核。通用分类、层级、阅读顺序和证据边界统一先读[内容结构设计](内容结构设计.md)；本分册补充方案比较场景，不固定某个项目、三张表或某组单元格。

## 先分清信息承担的任务

| 信息 | 回答的问题 | 放置方式 |
| --- | --- | --- |
| 共同目标与约束 | 本轮要验证什么，有哪些边界？ | 目标、预算、权限范围等明确字段 |
| 待决事项 | 需要领导作出什么选择？ | 事项、已有依据、待决问题与影响 |
| 方案事实 | 相同维度下，各方案有哪些差异？ | 以维度为行、方案为列，或其他语义稳定的结构 |
| 项目组倾向 | 建议什么，在什么条件下成立？ | 建议与适用条件紧邻，保留尚未决议状态 |

同一张表能保持这些关系清楚时可以共页；需要切换字段含义时用独立表或页签。多页中的概览承担快速理解与定位，明细提供决策依据。不要把公共预算、建议或请求横向合并进 A/B/C 的方案列。

“概览—决策事项—方案比较”适合共同边界与方案依据需要分别阅读的会议。只有少量同类差异时，一张比较表即可；不为了套用示例扩成三页，也不默认把每个方案拆为一个 sheet。

## 比较前保留口径

- **费用**：区分新增费用、首年报价、实施费、后续年度服务费及未包含投入。已知报价低于预算，不代表完整投入已确认在预算内；缺失成本不能按零处理。未经提供，不增加评分、收益率或回收期。
- **周期**：保留估计方、配置或上线范围、起算条件、审批排除时间、人员是否落实以及是否承诺。数字相同单位不代表同一工作范围，不能仅凭周数推出确定上线日期。
- **能力**：区分已支持、声称支持但未用真实数据验证、可按需设计。不能把“可设计”写成“已具备”，也不能扩大原始功能声明。
- **承接**：区分团队可承接、排期已确认、维护责任已确定；任一项未落实都应按其具体状态表达。
- **建议**：条件会改变推荐时，条件必须跟随推荐出现，不能只留在另一页或小字备注中。领导待决事项不能写成已形成决议。

金额、人数、周期按数值存储，单位用适当格式表达；“新增”“首年”“估计方”“未包含项”等业务口径放在可见字段，不藏在长段自定义数字格式中。存在同一数值的多处概括时，核对引用一致性。

## 从本次迭代提炼的检查方法

| 暴露的问题 | 根因 | 改进后要检查什么 |
| --- | --- | --- |
| 为单页塞入所有内容 | 把版式偏好当成内容约束 | 页签是否分别承担真实阅读任务；是否保留用户明确的数量限制 |
| 方案列上方混入公共说明 | 表头与正文含义不一致，靠横向合并遮掩 | 每个方案格能否明确回答该方案在该维度的情况 |
| 用户难以修改 | 一个合并块承载多个字段或判断 | 能否独立修改一项费用、条件或状态，不必重排整表 |
| 每页重复项目名称 | 为填满页尾添加无新信息的标识 | 删除后是否影响理解；无影响即删除，并收紧打印范围 |
| 样式合格但结构仍乱 | 仅检查渲染与原生格式 | 先做内容关系检查，再做视觉与文件检查 |

复核时沿原始素材逐项定位最终表达：事实、数字、限定条件、未确认项和待决事项都有去处。然后逆向检查每个新增说明能否解释其用途，无法解释的装饰文字删去。

## 修改范围

反馈针对结构时，可以重组页签、字段和阅读顺序，先解决内容关系。反馈仅针对某处无效文字时，保留已确认结构，局部删除并复核受影响的显示和打印范围。复盘写入通用判断规则，不把测试报价、固定纸张、某次列宽或临时导出脚本变成默认模板。
