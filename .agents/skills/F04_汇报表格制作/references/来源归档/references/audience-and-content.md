# 读者、表头与文字提炼

## 先决定读者需要做什么

| 主要读者 / 使用目的 | 优先呈现 | 可选表头组合 | 下移到依据或明细 |
| --- | --- | --- | --- |
| 直属领导：争取支持 | 核心判断、业务影响、具体请求 | 议题 / 核心判断 / 影响 / 建议与支持 | 调查步骤、实现细节、重复背景 |
| 负责人：确认责任与安排 | 边界、产出、分工、需协调事项 | 事项 / 目标 / 分工 / 待协调 | 不影响资源安排的技术过程 |
| 跨团队会议：作出决定 | 分歧、选项差异、待决问题 | 决策事项 / 选项 / 影响 / 待确认 | 长篇过程复述 |
| 分析师与开发：核对规则 | 来源、粒度、计算与预期结果 | 规则项 / 当前 / 拟调整 / 验证点 | 泛化价值口号 |
| 领导：了解进展 | 已交付、偏差、下一步、需支持 | 事项 / 当前结果 / 风险 / 下一步 | 逐日流水账 |
| 会后执行：落实纪要 | 决议、动作、责任、时间 | 类别 / 结论或行动 / 责任人 / 时间 | 未形成结论的冗长讨论 |
| 字段/方案对比：判断变更 | 前后变化、原因与影响 | 对象 / 调整前 / 调整后 / 影响 | 重复的通用说明 |
| 多方案选型：选定路线 | 同一维度的方案差异、约束与未确认项 | 比较维度 / 方案 A / 方案 B / 方案 C | 共同目标与决策请求放入适用的独立表或页 |

上表仅列业务字段，不是完整表头。实际输出必须在最前增加“编号”，将业务内容主干放在第二列，并在最右增加“备注”；编号与层级细则见[输入与内容要求](输入与内容要求.md)。其余业务列按目的删除、换名或组合，不按职位机械套模板。主表面向领导时，“治理价值”“建议方向”“对团队影响”等语义相近的列不能反复说同一件事。

表头一般 2–6 字；确实影响理解时可稍长。把“目前有哪些需要进一步明确的问题”改为“待确认”。少用“方案需要回答什么”这类长问句表头，改为“建设内容”“产出”等与当前阅读目的对应的词。

## 怎样提炼到可以扫读

1. 判断一段话真正承担的角色：事实、判断、影响、建议或请求。拆开不同角色，不在每列重复整段。
2. 删铺垫：例如“针对目前这个情况，我们建议进一步”通常删为“建议”。是否能删“建议”取决于是否会混淆方案状态。
3. 删重复：表头已写“建议”，格内不反复写“建议采取”；主题已明确时省重复对象。
4. 保留具体名词和动作：用“补齐口径记录”代替“进一步推进口径管理相关工作”；用“业务确认、开发验证”代替长段协作说明。
5. 一个独立判断只表达一次。同一父项下的并列动作拆行；单条理由过长则继续提炼或转明细，不靠缩小字体解决。
6. 无证据的收益用预期方向，不编造百分比、返工天数、完成日期或责任人。不能将“返工可能增加”压缩成“必然延期”。
7. 补充文字应有独立信息作用。默认删除只重复项目名的页尾、复述主标题的副标题，以及“请关注”等没有原因的备注。必要的条件、来源与决策请求仍须保留。

读者情绪和作者诉求转换为业务表达。例如“领导不理解我的困难”不写进表；可转为“口径确认成本需纳入交付复盘”。“我希望开展治理”可写为“申请牵头梳理治理方案”，但不自动扩大为已获准的公司级实施。

## 提炼示例

| 原句 | 可用短句 / 拆行 | 不可丢失的含义 |
| --- | --- | --- |
| 三条线中，一条有资深分析师，一条有资深开发，当前问题更多在另一条线显现 | 父项：经验依赖；子行：资深分析师支撑一条线 / 资深开发支撑一条线 / 另一条线问题较集中 | 三条观察分别列，不推断其他线没有问题；是否有因果关系仍需验证 |
| 人员轮换或业务扩展时，可能重复发生确认、调整与返工 | 人员变化后，可能重复返工 | “可能”和触发条件保留；事实未证实时不写“将全面爆发” |
| 邀请资深同事梳理关键口径，核对已有文档与实际使用情况，将有效经验沉淀为共享规则 | 梳理关键口径 / 核对文档使用 / 沉淀共享规则 | 三个动作拆行，共享父项可选择纵向合并 |
| 希望给予支持，由我牵头梳理口径治理方案，分析与开发共同参与 | 牵头：我；协作：分析＋开发；本次请求：支持方案梳理 | 角色和请求分别表达，不写成已经任命 |
| 完成时间暂定本周，可能新增基础数据建设 | 时间：暂定本周；依赖：可能新增基础建设 | 待定时间和依赖分列/行，不压成“本周完成” |

例子只说明写法，不是所有汇报的业务内容。

方案选型的字段取舍、费用与周期口径、结构复核示例，见[方案对比与结构复核](方案对比与结构复核.md)。

## 输入不足时

主题、受众、目的与零散想法足以形成讨论稿。只有观点没有量化事实时，保留“观察”“待核实”等紧邻标记，提出少量证据需求，不填造实绩。若关键业务含义缺失，标明缺口，或只追问会改变判断的问题。
