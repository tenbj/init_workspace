# 重点、备注与分组

## 加粗用于结构，标红用于正文重点

逐页先判断读者最需要记住什么，再决定是否标红；不按关键词批量上色。

| 对象 | 固定表达 |
| --- | --- |
| 页内大标题、所有表头 | 加粗，具体配色和居中见视觉规范 |
| 正文首列编号、第二列内容主干 | 黑字加粗，水平与垂直居中 |
| 其余正文，包括中间业务列、数值、备注 | 常规字重，不以加粗强调 |
| 值得优先关注的正文信息 | 用真实红字 #C00000，不附加粗体，并在最右备注说明原因 |
| 普通事实、一般动作、未选为重点的判断 | 黑字常规字重 |

红色可用于重大风险、关键待决项、核心请求或必须优先执行的动作，不限定为负面问题。但一个普通“待确认”不自动值得标红；“我来牵头”也不能自动加粗或标红。

- 每页通常先选 1–3 处重点，这是帮助取舍而非配额。没有重点就不标红；不能为控数量隐藏真实严重问题。
- 优先强调决定判断的短语，避免整列或成片标红。若约四分之一正文都是红色，应重新审视主次。
- 标红内容必须有对应备注，解释“为什么需要优先注意”，不只写“重点”“请关注”，也不机械复述原句。多个红色点同处一行时，原因应能分别对应。
- 例：将“提前完成验证”标红，备注说明“避免现场等待影响演示节奏”；将“可能延期”标红，备注说明触发条件或关键依赖，不能编造影响。
- “可能返工”“建议试点”“暂定本周”标红时必须保留限定词。黑白打印也能凭文字理解状态与原因。
- 备注列只放必要原因或补充内容，其他行留空。备注不默认加粗或标红，不用它代替应在主表呈现的核心请求。
- 不使用红底大块铺色，不改变蓝色表头。原生富文本不可用时，将关键短语提炼为独立单元格设红字，不写 Markdown、HTML 标签冒充格式。

## 拆行与合并

默认不横向合并，页内大标题除外：标题默认合并第2行从B列至最右业务列的区域并居中，不包含左右留白列；表头与正文仍默认不横向合并。用户明确禁止包括标题在内的横向合并时，所有合并区域的起止列必须相同；禁止任何合并时，数量必须为零。用户明确指定的模板或新要求优先，但不能用合并覆盖不同字段的数据。

同一事项因列宽自然换行可留在一格；多个独立事项应拆成多行。纵向合并是可选表达，只用于真实共享的编号或内容，覆盖范围一致、锚点之外无数据。需要逐行维护时，优先使用独立行和明确标签；不把解除合并作为正常修改的前置步骤。

示例表头为“编号 / 议题 / 行动 / 作用 / 备注”：

| Excel 行 | B 编号 | C 议题 | D 行动 | E 作用 | F 备注 |
| --- | --- | --- | --- | --- | --- |
| 4 | 一 | 规则沉淀 | 梳理口径 | 明确业务定义 | |
| 5 | | | 验证样例 | 核对预期结果 | |
| 6 | | | 维护版本 | 支持后续复用 | |

若此处确需展示共享主干，可合并 `B4:B6` 和 `C4:C6`，编号和主干加粗居中；D、E 各保留三条独立明细、常规字重。若不合并，应补齐逐行标签，不以空白伪装共享关系。备注无内容留空，不写“合并区域”等解释文字。

- 只有真实对应的信息才放在同一子行，不能把三条原因与两条措施按行强配。
- 不同责任、期限、状态不得合并；合并前核对非锚点数据。长汇总项先提炼成短标签，不合并出大段文字盒。
- 正文对齐按整列统一。公共长说明优先提炼或放入适合它的字段，不跨业务列合并；确需同列纵向共享时，沿用该列的对齐与缩进。首两列共享主干始终居中。
- 编号与组内序号分别遵循[输入与内容要求](输入与内容要求.md)，不将“①②③”塞入同一格，不混写“编号：内容”。
- 缺失、留空与不适用的处理遵循输入分册。不得以重复破折号填满备注，也不能把真实未知清空。
- 用原生缩进、行高与列宽留白；不为值、日期、标识符添加首尾空格，不用空格或符号伪造对齐。
- 普通分析数据、持续录入台账不属于本技能的主要用途。若另有可操作数据页，不能为展示合并破坏筛选排序。
