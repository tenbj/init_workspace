# 输出契约

## 最终交付

- 最终件为可正常打开的 .xlsx，位于当前任务 outputs/<任务名>/ 下；用户指定位置时另存至指定位置。
- 工作表数量按阅读任务决定，不能把“优先单页”当成强制一个 sheet 或一张打印纸。多页时首表为 `0 概览`，后续采用 `1 主题`、`2 主题` 及按需子主题层级，不固定页数；用户明确数量限制优先。详见 [输入与内容要求](输入与内容要求.md)。
- 多页交付时，概览模块与一级页逐一对应；目录的第二列内容主干与直接下级页主题、编号顺序一致。不得增设“对应章节”“输入章节”等指引列。
- 每页按“编号 / 内容主干 / 必要业务列 / 备注”组织；首列用独立的中文大写序号，首两列正文居中加粗，其余正文不加粗。周期、日期等只在有依据时提供。
- 同级编号使用统一分类标准，主干与属性分开；明细按理解依赖排序，概览可先给结论。需独立核查的来源有独立表头、出处、支撑事实与引用关系，不堆在主表尾部；具体见[内容结构设计](内容结构设计.md)。
- 页内标题体现页签身份，副标题不重复；标题默认合并第2行业务表宽并居中、无框，全部表头居中白框。表头与正文默认不横向合并；具体规则见重点与视觉分册。
- 正文按整列统一对齐，左对齐一格缩进，右侧有可见留白；重要内容标红并在最右备注说明原因，无补充备注与不适用字段留空，未知仍明确写“待确认”等。
- 所有工作表默认冻结前三行，包括概览与短表，不额外冻结列。
- 不强制每页结论，不默认附加重复项目名或页尾标识；主判断和请求在主表可见。确有必要的元信息才保留，并与表格间隔一行。

## 中间件与日志

- 内容输入保存为 outputs/<任务名>/inputs/report.json；成品位于任务目录根部。统一代码留在本技能 scripts/，主题留在 assets/。
- intermediates/<运行编号>/ 保存输入快照、编译后的布局规格、暂存工作簿与各页预览；logs/ 保存自动检查、失败和人工/模型视觉复核记录。不同任务各有自己的运行文件，它们不是多份生成器。
- 不额外交付模板、脚本、预览图或多种工作簿版本，除非用户要求。
- 使用 scripts/generate.mjs --input <数据路径> --output-dir <任务目录>；脚本不写死业务路径。已有成品默认拒绝覆盖，确认需要更新时用 --overwrite；失败保留原成品。

## 验收与失败边界

- 使用 spreadsheets 的作者工具；逐张渲染新增或改变的展示区域，按 visual-and-qa.md 验收标题、全部表头、字体、配色、左右留白、边框、合并、重点及冻结设置。
- 检查公式（如有）、日期、数字及事实口径；不能把文本符号冒充真实加粗或红色字体。
- 结构验收在样式验收之前：通过分类、层级、顺序、边界、覆盖与引用六检；字段含义稳定，共同约束与方案事实未混用，原始条件和未知项完整。保存后的横向合并默认只允许标题B2至最右业务列第2行。用户禁止标题横向合并时，所有合并区域起止列必须相同；禁止所有合并时数量必须为零。
- 多页时检查首表名称与位置、编号层级、目录主干与直接下级页、页内标题和页签顺序；缺失概览或存在悬空模块时必须修正后交付。
- 修改既有表格时保留未授权变动的内容与格式，核对保存后的最终文件；文件被占用时另存可区分的新版本，不关闭用户正在使用的文件来强行覆盖。
- 用户指出内容结构问题时，先重审信息角色、分类、层级与阅读顺序，再调整页签和字段，保留已认可的视觉样式。确认并执行重排后，须检查保存文件的实际顺序、编号、标题与引用，不以口头认可代替落盘；仅要求删除无效页尾时，局部处理，不扩大为正文重设计。
- 未生成最终文件、存在未解决的数据丢失或布局问题时，不声称完成。
- 如缺少渲染能力，明确说明尚未完成视觉验收，不把结构检查描述成视觉通过。
- 最终回复提供最终工作簿链接，并简述必要的待确认内容或工具限制。
