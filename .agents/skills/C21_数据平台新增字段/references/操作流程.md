# 操作流程

## 1. 强制第一步：全量字段定义确认

操作开始必须先完成本节。可先只读查看代码、模型身份、已有字段和表结构，以形成准确清单；不得先打开新增表单、填写、生成DDL预览或执行，再补确认。

1. 一次列出本轮全部模型的所有待增字段，不只报数量或只给第一列。每行包含中文模型名、完整库表名、连接/引擎、环境、字段英文名、中文名、释义/来源口径、目标数据库完整类型（含字符长度、数值精度/小数位）、Nullable、默认值、物理主键、业务主键、分组、排序和备注。
2. 明示本轮范围：仅填不提交、提交指定字段或逐字段全部提交。无默认值、空分组和空备注也写明；排序可写“按平台末尾顺延”，不捏造序号。未知关键项标为待确认，不擅自选更大类型或套用其他模型。
3. 在对话中展示完整清单，询问是否按清单执行，并等待用户明确回复。未回复期间只能继续独立的只读核对；已登录、提供登录链接、代码已提交或笼统的“帮我加字段”不等于确认清单。
4. 用户明确确认后，记录清单版本/时间、确认回复及授权范围。若本会话已有明确确认的同一完整清单，引用并复用，不重复索要确认。
5. 后续新增模型/字段，或更改列名、类型/长度/精度、释义口径、NULL、默认值、主键、展示设置或执行范围，先展示变化前后并确认受影响项。未变部分的确认持续有效；已确认“末尾顺延”时序号顺延不算变更。用户明确指定某项改值即为该变更的确认，不再反问同一内容。
6. 恢复时核对清单、确认记录和已完成字段；缺少确认记录则停在本步骤，不从草稿反推授权。

### 接入与授权边界

先读当前页面及任务记录，识别模型身份、字段现状和本轮终点。用户说“新增字段”可以指打开表单，结合带教上下文判断；“先填不要提交”明确停在草稿；“提交A，再填B不要提交”意味着A完整提交、B只填草稿。

目标身份至少核对中文模型名、完整库表名、连接/引擎和环境。相似中文名、即将下线的旧模型、跨引擎同名表不能混用。默认沿现有模型关系导航，不先从资产表或新建模型入口绕行。

完整清单确认与提交范围授权都必须可复核。清单已明确确认后，不逐项重复询问已确定的类型、文案和提交范围；平台“确认执行”也不新增一轮用户授权。本Skill不要求MR已合并，不把新模型创建流程套给已有模型。

## 2. 已验证的平台路径

1. 每次浏览器操作前选中目标tab并置前（工具支持时使用bringToFront）。
2. 数据模型列表按完整表名搜索，点击目标行的中文模型名。
3. 进入“数据字段”，点击“字段管理”，进入该模型的字段列表。
4. 核对目标模型和字段是否已存在；第一节全量清单确认完成后，才点击“新增字段”。
5. 按字段清单填写并回读实际选中值。

平台图标可能不进入可访问性树。先读取最新快照，再通过可见DOM、悬浮提示确认入口。“新增字段”实测为提示文字对应的newlybuild图标；它只是定位线索，不能在页面未核对时盲点选择器。排除隐藏表格副本，避免同名入口误点。不固化UID或坐标。

## 3. 填写与逐个提交

表单包含字段分组、排序序号、Type、自动联动字段类型、字段原名、字段名、字段释义、Nullable、物理主键、业务主键、字段备注。

- Type从实际选项中选择；回读标签，区分int、Int32等不同选项。
- 字段原名是SQL列名，字段名是中文展示名，释义完整保留业务枚举与中文标点。
- 非主键字段：Nullable=是，两种主键标记均为否。主键情形参见字段定义分册。
- 排序采用现场有效值或用户明确值，不硬编码58/59，也不因示例序号与原字段不连续自行重排。
- 可选分组、备注没有要求时不编造；必填值缺失则问清。
- 仅填草稿：不点击“确定新增”，保留前台窗口，记录未提交。

已经获得提交授权时，执行完整的同一字段提交：

1. 点击“确定新增”。平台实测此步调用previewAddDdl，仅生成预览，不能视为新增成功。
2. “执行语句”弹窗会显示DDL和“代码文件”。核对DDL的库表、ADD COLUMN列名、类型、空约束语义、注释与当前字段一致，且没有额外删除/重建等动作。
3. 预览DDL只增加当前字段，下方代码文件可以包含多个计划新增字段。不能仅因这种显示差异再次要求用户授权，也不要删除其他计划字段或在此改写代码。
4. 在既有提交授权内点击“确认执行”。不得把二次确认当作第二次授权请求。只有DDL对象或动作越界、字段定义矛盾、平台显示新的额外执行行为等具体异常才停止询问。
5. 等待结果，检查业务响应（实测addOne返回code=200、msg=操作成功），再回读字段列表中的原名、类型、中文名、释义、Nullable和主键标记。
6. 完成当前字段后，再点击“新增字段”处理下一列。不用第二列定义覆盖第一列草稿，不合并为未演示的批量API。

观察到的接口名称仅用于读取UI已产生的网络证据，不构成直接拼接写入API的操作规范。DDL省略NULL字样不能单独证明非空；结合表单、引擎语义、回读证据判断，必要时只读核对实体定义。

## 4. 异常与恢复

| 现场 | 动作 |
|---|---|
| 用户只教下一点击 | 只到指定位置，不提前提交或换流程 |
| 点击后超时、断网、结果不明 | 不重复点击；先查业务响应和字段列表，必要时只读实体核验 |
| 同名字段已存在且定义一致 | 记录已存在/此前成功，跳过重复ADD |
| 同名但定义冲突 | 记录差异，询问处理；不擅自改类型或删除 |
| 两列中第一列已成功、第二列失败 | 保留第一列，记录逐字段状态，仅恢复第二列 |
| 浏览器卡死/崩溃 | 确认会话丢失后复用授权登录方式，重新导航；先查已保存列，再恢复未提交草稿 |
| 活跃草稿仍存在 | 不靠刷新、重开URL、返回或关闭来补证据 |
| 只有HTTP200、无业务成功证据 | 不能宣布完成；继续读取响应或列表 |

登录恢复先执行[共用规则](../../../rules/platform-modeling-rules.md#平台登录与环境恢复)，检查 `.envs` 已登记入口。授权链接的真实值仅保留在私有环境文件；日志、记忆、交付不保存accessKey、登录态、Cookie或请求头，只保留脱敏对象、结果、时间和必要响应字段。
