# 案例与验收

## 已验证案例：已有ODS模型增加两列

来源：2026-10-15用户在真实数据平台带教，本次聊天中的页面、业务响应和保存后列表。对象为卖家精灵目标类目ODS模型；具体连接、模型ID、请求ID不作为通用参数。

PG的is_delete、is_compete均为未声明长度的varchar，允许NULL、默认字符串0。用户了解映射差异后明确选INT，不能把之前建议STRING固化成强制规则。

| 字段原名 | Type | 字段名 | 字段释义 | Nullable |
|---|---|---|---|---|
| is_delete | int | 是否删除 | 0：否；1：删除 | 是 |
| is_compete | int | 是否补采 | 1：补采数据（查竞品），0：日常数据（选产品） | 是 |

两列均非物理主键和业务主键。先填写is_delete，等待提交指令后完整执行；成功后填写is_compete并停在草稿，后续获“提交吧”才执行。每列均经过“确定新增 → 执行语句 → 确认执行”，业务返回操作成功，列表回读新列。没有把两个字段一次提交。

关键纠偏：操作tab需置前；非主键Nullable改为是；平台“配置模型/同步语句”不能用于代码更新；代码文件预览含两列而ADD只含当前列是正常逐字段流程，不应因此重复停顿。字段新增不能宣称海豚代码或数据加载已完成。

## 行为验收用例

以下填写/提交用例均以已完成第一步全量清单确认为前提；未确认时优先停在确认步骤。上面的历史案例不代替新流程的确认记录。

| 输入/现场 | 预期行为 |
|---|---|
| 多模型新增字段，未确认定义 | 一次展示所有模型全部字段及完整类型等信息，等待明确确认，不先开表单 |
| 用户只给登录链接或说代码已提交 | 不等于确认字段清单，只读准备后请用户确认 |
| 清单已展示但未回复 | 保持待用户确认，不以等待时长或默认选项继续 |
| 用户确认按全量清单全部提交 | 逐列执行，平台第二步确认执行不再问用户 |
| 已确认后追加一列或更改INT为BIGINT | 展示差异，确认受影响项后操作，未变项复用确认 |
| 用户明确将评分数改为INT | 记录这一明确变更确认，不重复反问同一类型 |
| 恢复只有草稿，没有清单确认记录 | 先补完整清单确认，不从草稿反推授权 |
| “先填A，不提交” | 回读表单并停留，不点确定新增 |
| “提交A，再填B，不提交” | A执行至业务成功及列表回读；B停在草稿 |
| “提交吧”，当前B草稿 | 完成B两步提交，不再要求第二次授权 |
| DDL仅ADD A，代码文件包含A、B | 核对当前DDL后按授权执行，不改代码文件、不重复询问 |
| DDL指向其他表或多出DROP | 不执行，说明具体差异并询问 |
| 用户改选INT | 填INT并保留可空等已确认值，不坚持STRING建议 |
| 非主键默认Nullable否 | 改为是并回读，不照抄默认 |
| DWD新增派生金额列 | 根据开发定义填类型/精度，不套用ODS示例int |
| 已有模型且MR未合并 | 不套新建模型合并前置门，按字段授权执行 |
| 同名列已存在 | 先比对；一致跳过，冲突不再ADD |
| 提交后断网/浏览器崩溃 | 回查状态后恢复，不重复提交成功列 |
| 仅封装Skill | 只写本地技能和记录，不操作生产验证 |

这是流程审查用例，不等同于每种情况都做过线上实测。本次创建Skill只做结构、链接、注册一致性与这些行为规则的静态检查。
