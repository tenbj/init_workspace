# 架构与 ER 页面维护

H02 每次交付同时维护系统架构页面和可交互 ER 页面，包括首次开发、功能迭代、缺陷修复、数据迁移及部署方式调整。两个页面与源码、API、数据模型一起验收和打包。

## 交付形态

交付的是两个独立、可直接打开的 HTML 页面，不是两张 PNG/SVG 图片附件。沿用已有项目的成熟页面形式，系统架构页包含分层图、图例与说明，ER 页包含单画布模型、字段详情和交互。图片截图只作为验收证据，不能替代页面交付。已有项目直接维护现有页面，不为了套推荐目录而改路径或重做布局。

## 首次开发

1. 调用 D04 生成系统架构 HTML 页面，遵循其方法论与自包含 HTML/SVG 要求。
2. 调用 G02 生成可交互 ER HTML 页面，完整读取并执行其呈现、交互与真实浏览器验收标准。
3. 架构图依据实际实现标注组件职责、页面/API/MCP入口、调用和数据流向、存储与外部服务、部署边界；不要把规划能力画成已实现能力。
4. ER 图依据权威 DDL、迁移或 ORM 模型标注实际表、字段、PK/FK、唯一约束、可空性与基数；区分逻辑关联与物理外键。
5. 不使用关系数据库时仍交付 ER 图，准确表示真实持久化实体与逻辑关联，注明非关系存储；无持久化实体时明确说明实际情况，不捏造表或外键。
6. 推荐保存到 docs/diagrams/architecture.html、docs/diagrams/erd.html，可复用已有项目路径；每张图是可离线打开的独立 HTML，路径登记到合同 diagrams。
7. Skill 编号按工作区 SSOT 解析。依赖缺失或解析失败时报告具体问题，保留 draft，不以普通示意图冒充已执行 D04/G02。

## 每次更新

1. 为本轮生成新的 delivery_id，例如 UUID；在已有合同上增量更新，不重新运行 init 覆盖项目。
2. 读取现有两个页面及其生成源码，检查本次源码、接口、组件、部署、表结构、字段、约束、数据生命周期与关系的变动。
3. 涉及架构时按 D04 维护架构图；涉及模型时按 G02 维护 ER 图。同步生成器/模板及生成结果，避免下次构建回退。
4. 两个页面都必须本轮核对。确无语义影响时可保留图内容，但 maintenance 写 reviewed_unchanged，change_note 解释本次改动为何不影响该图；重新核对当前来源并生成本轮报告，不能沿用旧报告或只修改日期。
5. 以实际实现和最终数据模型收口。原型设计与实现不同时说明设计调整，并更新图中的边界、关系和字段。
6. 有授权且可连接实际数据库时，只读比对元数据；否则明确证据来自 DDL/迁移/ORM，不声称已核对在线数据库。
7. 验证完成后登记当前图与来源文件的 SHA256、本轮 delivery_id、维护方式及证据。来源选实际架构组成/模型文件，不得只选图本身或无关占位文件，不包含凭据。
8. 更新 README/交付说明中的两图入口，把 HTML、可复现生成材料、模型来源与验收证据纳入脱敏 ZIP，确认是本轮版本。

## 验收与阻断

- 架构图执行 D04 要求，真实浏览器检查标签、箭头、图例、文字边界、布局及离线访问，核对图中能力和边界与本轮代码一致。
- ER 图执行 G02 的结构校验、真实浏览器双态几何与关键交互验收；核对实体、字段和关系与本轮权威模型一致。
- 两图分别形成 JSON 证据，详细报告和截图可作为补充引用；通用合同字段见输出契约。
- validate_project.py 检查两图、声明技能、维护记录、来源及哈希、本轮标识和报告内容；不能替代真实语义和浏览器验收。
- 缺图、缺来源、哈希过期、报告失败/缺失/属于上一轮、两图与实现不一致时保持 draft；不能仅在 limits 中说明就算完成。
- H02 不复制 D04/G02 的绘图和几何细则，只负责调用、每轮维护和系统交付一致性。
