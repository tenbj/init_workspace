# 输出契约

本文件定义 H02 系统交付物和合同字段。

## 目录结构

推荐输出到独立项目目录，至少包含：

```text
project-contract.json
app/ 或 src/
static/ 或 web/
api/ 或后端入口
mcp/
data/
docs/
examples/
tests/
verification/
scripts/
dist/
```

可沿用既有项目结构，但必须能在合同中解释各类产物的位置。

## project-contract.json

合同必须存在，字段至少包括：

```json
{
  "status": "draft",
  "project_name": "项目名",
  "prototype": {
    "path": "源原型路径",
    "sha256": "源原型sha256"
  },
  "operations": [
    {
      "id": "submit_result",
      "method": "POST",
      "path": "/api/results",
      "mcp_tool": "submit_result",
      "python_example": "examples/submit_result.py"
    }
  ],
  "checks": [
    {
      "name": "mcp_list_tools",
      "status": "passed",
      "evidence": "verification/mcp-report.json"
    }
  ],
  "limits": [
    "本地试运行，不等同生产就绪"
  ]
}
```

字段规则：

- `status` 只能是 `draft` 或 `ready`。
- `prototype.sha256` 必须来自源原型，不得用改造后文件替代。
- `operations[]` 覆盖页面、API、MCP 和示例的核心操作。
- `mcp_tool` 可为 `null`，表示该 API 不暴露给 AI。
- `python_example` 指向可运行或可读的 Python 示例。
- `checks[]` 记录验证项、状态和证据路径。
- `limits[]` 必须写清本地试运行、mock、凭据、许可证、生产缺口等限制。

## 必备输出

- 真实系统页面
- 后端 API
- 数据库或持久化层
- MCP 服务
- 中文 API 文档
- 中文 AI 安装与工具决策指南
- HTML 示例
- Python 示例
- 依赖说明
- 启动、停止、状态检查命令
- 测试和验证报告
- CI 或最小检查脚本
- 许可证状态说明
- 脱敏 ZIP 项目包

## 状态判定

`draft`：

- 合同骨架已生成，但系统能力、文档或验证未齐。
- init 脚本生成后的默认状态必须是 `draft`。

`ready`：

- 源原型未修改。
- 必备输出齐全。
- `validate_project.py` 通过，或只剩用户接受的外部限制。
- 验证证据能区分 mock 与真实测试。
- ZIP 包完成脱敏。

## 最终回复

交付时必须说明：

- 源原型路径和是否保持未修改。
- 系统入口、API 入口和 MCP 入口。
- 运行了哪些测试和验证。
- ZIP 包路径。
- 剩余限制和是否生产就绪。
- 是否上传 GitHub：默认否。
- 许可证状态：默认未选择，除非用户明确指定。
