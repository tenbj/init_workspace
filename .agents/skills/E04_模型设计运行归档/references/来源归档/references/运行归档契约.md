# 模型设计运行归档契约

## 触发口径

E04 只在用户主动调用 E04 或明确要求“归档式运行 E03 模型命名建议”时使用。用户主动调用 E03 时，不自动创建 E04 run，不移动或复制输入，也不改变 E03 的默认输出目录。

## 运行目录

所有 E04 运行产物只允许落在目标 `output/` 子项目内。

默认目录结构：

```text
output/{模型设计标准化子项目}/
  03_代码程序_vX.Y.Z/
    runs/
      E04_yyyyMMdd_HHmm_{run-name}/
        00_inputs/
          source_archive/
          source_copy/
          input_manifest.json
        01_parse/
        03_ai_decisions/
        06_deliverables/
        run_context.json
        run_summary.md
```

选择规则：

- 优先使用 `output/` 下名称包含 `模型设计标准化` 的子项目；子项目名可带或不带版本号后缀。
- 优先把 run 放到该子项目的 `03_代码程序_v*/runs/` 下。
- 没有 `03_代码程序_v*` 时，E04 prepare 可在目标子项目内补齐 `03_代码程序_v0.0.0`。
- 若模型设计标准化子项目不存在，E04 prepare 必须以主题 `模型设计标准化` 在当前工作区 `output/` 下创建标准子项目。
- E04 自行创建的根子项目名必须为 `output/{NN}_模型设计标准化`，不得带 `_v{x.y.z}` 版本号后缀。
- E04 不人工猜编号；编号按 `output/` 当前最大编号自动递增生成。
- 用户显式给出的目标子项目路径不存在时，不得落到 `input/`、`.temp/` 或其他目录；只允许在当前工作区 `output/` 下创建或定位模型设计标准化子项目，E04 自行创建时不得加版本号后缀。

## 输入归档

`prepare` 默认使用 `move-or-copy`：

- 同卷输入优先移动到 `00_inputs/source_archive/`。
- 跨卷输入直接复制到 `00_inputs/source_copy/`。
- 移动失败时转复制，并在 manifest 中记录失败原因。
- 归档完成后，E04 调用链只能使用 effective path，不再使用原始输入路径。
- 每个输入都记录 `source_name`、`effective_path`、`storage_mode`、`sha256` 和 `size_bytes`。

## Prepare 命令

```powershell
python ".agents\skills\E04_模型设计运行归档\scripts\model_run_archive.py" prepare `
  --target-skill E03 `
  --run-name "应收单" `
  --input "standard_library=input\标准库.xlsx" `
  --input "model_design=input\应收单.xlsx" `
  --archive-mode move-or-copy
```

常用参数：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--target-skill` | 否 | 默认 `E03`，只记录目标稳定编号 |
| `--run-name` | 是 | 进入 run id 的业务名称 |
| `--input role=path` | 是 | 可重复；必须包含 `standard_library` 和 `model_design` |
| `--project-dir` | 否 | 指定模型设计标准化子项目路径 |
| `--archive-mode` | 否 | `move-or-copy`、`copy`、`move` |
| `--out` | 否 | prepare 结果 JSON 路径；相对路径按 run 目录解析，绝对路径必须位于 `output/` 下；默认 `01_parse/prepare_result.json` |

Prepare 输出 JSON 会给出 E03 需要的绝对路径：

- `standard_library_path`
- `model_design_path`
- `context_json_path`
- `recommendations_json_path`
- `deliverable_excel_path`
- `run_context_path`
- `run_summary_path`

## E03 调用协议

E04 prepare 后，按下列路径调用 E03：

```powershell
python ".agents\skills\{当前E03}\scripts\model_naming_workbook.py" extract `
  --standard-lib "{standard_library_path}" `
  --model "{model_design_path}" `
  --out "{context_json_path}"

python ".agents\skills\{当前E03}\scripts\model_naming_workbook.py" write `
  --model "{model_design_path}" `
  --standard-lib "{standard_library_path}" `
  --recommendations "{recommendations_json_path}" `
  --output "{deliverable_excel_path}"
```

`recommendations_json_path` 必须由 AI 按 E03 的 JSON 结构写入，E04 不负责生成命名建议。
AI 生成 `recommendations_json_path` 时必须遵守当前 E03 的推荐过程：先整体阅读标准规则库、标准映射库和模型字段，再逐字段按固定顺序推荐。第一，优先按同一 Excel 中相同 `字段名/current_field_name` 复用已有 `推荐字段名`，相同字段名必须推荐一致；这里的 `字段名` 不是 `参考字段`。第二，如果没有同字段名既有推荐，且参考库表名规范化后以 `dwd_` 为前缀、参考字段非空，则字段推荐以审核参考字段为主，推荐字段名尽量和参考字段名保持一致，只有参考字段名与标准强规则、标准映射、命名合规性或字段语义冲突时才重新设计并说明冲突点。第三，如果参考库表为空、为 ODS/`ods_`、参考字段为空，或参考库表不是 `dwd_` 前缀表，则不把参考字段名作为保留依据；无同字段名既有推荐时，完全按标准库和字段语义推荐。不得输出 `待确认`，推荐依据必须使用中文正文。若本轮发现可沉淀的规则或映射，应按 E03 v1.4.0 结构补充 `standard_rule_suggestions` / `standard_mapping_suggestions`，字段级 `term_root_suggestions` 会自动写入 `标准映射库_建议`。

## Finalize 命令

```powershell
python ".agents\skills\E04_模型设计运行归档\scripts\model_run_archive.py" finalize `
  --run-context "output\...\run_context.json" `
  --status completed `
  --deliverable "06_deliverables\应收单_命名建议.xlsx"
```

失败时使用：

```powershell
python ".agents\skills\E04_模型设计运行归档\scripts\model_run_archive.py" finalize `
  --run-context "output\...\run_context.json" `
  --status failed `
  --message "E03 写回失败：..."
```

## 状态约定

| 状态 | 含义 |
|------|------|
| `prepared` | run 目录和输入归档已完成，等待 E03 |
| `completed` | E03 交付物已生成并登记 |
| `failed` | 运行失败，摘要中必须记录原因 |

## 失败处理

- 找不到模型设计标准化子项目：自行创建无版本号后缀的标准子项目；若创建失败，再停止并返回失败原因。
- 输入文件不存在：停止，不猜测相近文件。
- 移动失败：`move-or-copy` 下转复制；`move` 下直接失败。
- 输出文件已存在：prepare 创建唯一 run id；write 阶段不得覆盖旧 run。
- E03 失败：保留 prepared run，执行 finalize failed，向用户返回 `run_summary.md`。
