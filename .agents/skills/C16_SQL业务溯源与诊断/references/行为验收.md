# 行为验收

仅在创建、维护和评估本Skill时使用，不是每次数据任务的额外关卡。

结构校验只能证明入口和文件完整。行为验收应给执行者Skill、真实请求与最少原始材料，隐藏预期答案和修复结论；以模拟数据或只读环境进行，不让测试写入生产。

## 场景选择

- 串值或缺值：从一个异常字段主动查到相关来源、关联、选行和最终展示，能发现相连的粒度问题。
- 另一类异常：例如订单金额重复，验证方法可迁移，不依赖某次ASIN案例的记忆。
- 正常数据或局部来源问答：能给简短准确答复，不扩大审计、不杜撰错误、不擅自修改。
- 业务规则有歧义或数据不可访问：区分事实和推断，继续独立工作并指出最小待确认项。

## 评价实际输出

1. 是否先识别这行的业务对象和用户要保证的结果？
2. 是否用真实可复查的值解释已证实的断点？
3. 是否主动核对会改变目标结论的相连环节，并给完整必要改法？
4. 是否保留候选与正确业务分区，避免用聚合、过滤或截断掩盖原因？
5. 是否始终沿同一案例说明，减少用户补问？
6. 是否尊重解释/修复/验收范围和业务不确定性，并避免越权操作？

评估者用预先记录的预期检查实际回答和产物，记录遗漏及误报；按暴露的问题迭代。不要只匹配关键词、标题数量或自评分。有限用例通过不等于保证以后一次发现所有问题。
