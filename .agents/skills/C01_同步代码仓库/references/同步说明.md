# 同步说明

## 目标仓库

- 只针对 `./input/data-assets` 生效
- 默认远端为 `origin`，默认分支为 `master`
- 当目标仓库不存在或目标目录为空时，默认从 `git@git.rabbitgoo.com:dw-dev/data-assets.git` 克隆到 `./input/data-assets`；也可用 `DATA_ASSETS_REPO_URL` 或 `--clone-url` 覆盖
- 同步策略是“远端覆盖本地”，不会保留本地冲突、未提交改动或未跟踪文件

## 直接命令

从项目根目录运行：

```powershell
python ./.agents/skills/C01_同步代码仓库/scripts/sync_authoritative_data_assets.py
```

只检查当前状态而不执行同步时：

```powershell
python ./.agents/skills/C01_同步代码仓库/scripts/sync_authoritative_data_assets.py --status-only
```

如果运行环境限制了 GitLab SSH 或网络，保持同一条相对路径命令，在允许联网的环境中重跑；不要改成绝对路径，也不要手工改写同步流程。

## 脚本执行顺序

1. 从脚本位置反推项目根目录，再定位 `./input/data-assets`
2. 如果目标仓库不存在，或目标目录存在但为空，则使用内置默认远端、环境变量或参数提供的 clone URL 执行 `git clone --origin origin --branch master <clone-url> input/data-assets`
3. 如果目标目录已存在但不是 Git 仓库且非空，则停止并报错，避免误删未知内容
4. 执行 `git remote set-url --push origin DISABLED`
5. 执行 `git fetch origin master`
6. 执行 `git reset --hard` 和 `git clean -fdx`
7. 执行 `git checkout -B master origin/master`
8. 再执行一次 `git reset --hard origin/master` 和 `git clean -fdx`
9. 输出远端配置、`git status --short --branch` 和最新提交摘要

## 成功判定

- `origin` 的 `(push)` 地址显示为 `DISABLED`
- `git status --short --branch` 显示 `## master...origin/master`
- 工作区没有残留改动

## 可选参数

- `--repo-relative`：覆盖默认仓库相对路径
- `--remote`：覆盖默认远端名，默认是 `origin`
- `--branch`：覆盖默认分支名，默认是 `master`
- `--clone-url`：目标仓库缺失时使用的克隆地址；默认是 `git@git.rabbitgoo.com:dw-dev/data-assets.git`，也可通过 `DATA_ASSETS_REPO_URL` 覆盖
- `--status-only`：只打印当前摘要，不执行抓取和覆盖
