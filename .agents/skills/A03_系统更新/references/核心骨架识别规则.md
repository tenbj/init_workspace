# 核心骨架识别规则

## 核心骨架范围

属于核心骨架的变更：

- 根入口：`AGENTS.md`、`CLAUDE.md`
- 执行层：`.agents/rules/`、`.agents/skills/`、`.claude/commands/`
- 系统标准：`.system/standards/`
- 机器可读注册表：`workspace-spec.json` 中的目录骨架、必备文件、Skill 注册表、初始化覆盖层、BOM 检查清单
- 人类可读标准：工作区骨架、命名规范、Skill 管理标准

不属于本 Skill 的范围：

- `output/` 下业务或研究成果
- `output/00_系统治理/03_代码程序/src` 初始化程序源码
- `output/00_系统治理/03_代码程序/src/templates` 初始化模板
- `dist/*.exe`、构建缓存、Release 附件
- GitHub 发布、tag、Release Notes 和公开 changelog

## 更新矩阵

| 发现的变更 | 更新 `.system` 的位置 |
|------|------|
| 新增、删除、升级 Skill | `workspace-spec.json` 的 `skillsManagement.registeredSkills`；`Skills管理标准.md` 映射表 |
| Skill 进入或退出初始化覆盖层 | `workspace-spec.json` 的 `overwriteLayer.skills` |
| `.ps1` 脚本需要 BOM 检查 | `workspace-spec.json` 的 `bomCheck.files` |
| 新增或删除 Rule | `workspace-spec.json` 的 `overwriteLayer.rules`；必要时更新骨架标准 |
| 根入口、必备文件或目录骨架变化 | `workspace-spec.json` 的 `requiredLayer`；必要时更新骨架标准 |
| 命名、历史、版本规则变化 | `工作区命名规范.md` |
| Skill 域、编号、注册和调用规则变化 | `Skills管理标准.md` |

## 执行顺序

1. 先运行检测脚本，拿到差异列表。
2. 将差异分为“应写入 `.system`”“只属于执行层实现”“需要 B09 处理 exe”三类。
3. 只对第一类修改 `.system/standards/`。
4. 检查 `workspace-spec.json` 和人类可读标准是否互相解释同一件事。
5. 如变更要求初始化工具同步，只记录“后续交给 B09”，不在本 Skill 中执行。

## 禁止项

- 不更新 `output/00_系统治理/03_代码程序/src/init_workspace.py`。
- 不同步 `src/templates/`。
- 不运行 `src/build.ps1`。
- 不生成、替换或重命名 exe。
- 不把 GitHub 发布流程塞进本 Skill。
