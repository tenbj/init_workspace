# 六参数与分段

## 参数契约

交付顺序固定：七列总览与范围确认 → 六参数全文 → 分段表 → 配置运行 → 验收回写。不要先给分段，或用注意事项替代用户已在等待的六参数。

只保留以下六项，不增加数据量、年份、批次号等工作流参数。分段清单是外部执行记录。

| 参数 | 内容与检查 |
|---|---|
| sql | 完整 CK SELECT；投影逐列对齐目标，含两个日期参数和经确认固定保护界限 |
| columns | writer 列清单；格式跟已验证模板一致，SPPR 为无外层方括号的双引号列名片段 |
| table | 目标表名；SPPR 模板连接已指定 cbebg，因此此值仅为表名，不带库前缀 |
| StartTime | YYYY-MM-DD；默认取 Doris 实际源没有而 CK 有的历史起点 |
| EndTime | YYYY-MM-DD；默认取上述历史终点，包含这一天 |
| preSql | 单源重建时为完整目标DELETE，带StartTime/EndTime及保护边界；同窗双源合并不能每个节点都DELETE，按下方专门方案设计 |

默认时间不等于本次运行时间，尤其默认 H 宽而当前缺口 G 窄时。每次启动显式输入分段时间。NULL 日期无法由普通日期范围选中，必须单独设计确认；不伪造日期参数来掩盖 NULL。

## 生成与校验

1. 读取目标 DDL、原日常 columns 与 CK 字段，建立 SELECT 表达式→别名→writer 列→Doris 类型的一对一表。列数、顺序、业务语义都要核对，不能只比较数量。
2. 用原表别名 src 引用日期过滤列，避免投影别名把字符串日期带入 WHERE。DateTime64 经当前 reader 的 JDBC 类型 1111 不被识别时，投影转字符串；过滤仍用原始类型列及相容常量。需要按目标精度/时区确认。
3. 原模板可复用时不改模板；只需要时间参数化就只改 WHERE。迁表时必须同步 sql、columns、table、preSql，不保留旧表残留。审计字段按目标约定处理，不任意为业务列补 NULL。
4. 保留普通可读 SQL 与平台录入参数两种文件。SPPR 已验证录入值采用一层字面反斜杠 u0027 表示单引号；它是本模板两层 Shell/JSON 链的已测方案，不是所有模板通用转义。用已成功实例版本和解析后的 SQL 验证，禁止反复加反斜杠猜测。
5. 检查 table 无前后空格、换行和不可见字符；发现则报出并修正参数，不把带尾空格值用于 writer URL。不要对整段 SQL 无差别 trim/替换转义。
6. 用目标日期做真实非零记录投影读取、列数检查和计数。LIMIT 0、常量测试或 JDBC 元数据通过不证明实际数据可读。校验日期首尾、NULL、超界和特殊日期。

### 历史字段演变与无损映射

- 两个CK字段拟合并到一个目标字段时，先确认业务等价，再在拟补全范围统计“两者均非空且不同、仅旧字段有值、仅新字段有值、均空”。冲突非0时列实际样例并等待裁决，不能直接用COALESCE藏掉冲突。NULL、空串、空格是否等价须按实际业务约定，不静默trim。BR的ASIN回填ChildAsin是本表已核实语义的案例，不是其他表的默认映射。
- 分别列出目标独有列和CK独有列：目标列缺来源时核对可空、默认值及新行/同键更新行为，说明拟填NULL、默认值或不写的结果；CK独有列不导入也须披露信息损失。不能声称所有字段完整迁移。FBA库存规划的LocalRemark和FulfillmentServiceAndPrograms仅为对应案例。

### 精准日期保护与分段一致

经用户确认的断档保留区间，应同时从sql和preSql实际作用范围中排除，并在分段表中断开；不能只靠手工分段避开，却让默认宽参数或重跑覆盖它。日期保护采用本表类型支持的表达式、括号和已验证转义，不新增第七个参数。每段不得与保护区间相交，核对相邻首尾日期避免少一天或重叠一天；修改保护条件后重新展示完整六参数。

例如FBA库存规划确认保留2023-12-01～27后，历史分段在11月30日结束、12月28日重启；固定保护也排除这27天。该例170条仅作说明，不可照搬到其他表。规划工具不证明Doris独有数据安全，用户保留区间和已批准的整窗重建仍须单独核验。

固定日期分界只能保护被条件约束的读写入口。日常参数默认较新，不等于人工历史重跑也有硬保护；若用户另行授权约束日常，取数与DELETE都需相同固定边界，并说明分界前源后来变化不再自动同步。仅授权补历史时不修改日常，也不宣称已经实施永久保护。同Id日期可能跨界时，核对唯一键写入会否更新窗口外记录，或明细模型会否留下重复版本。

SPPR DATETIME(3) 的闭区间写法为 `${StartTime}` 至 `${EndTime} 23:59:59.999`。其他精度需适配，不能漏掉微秒尾部。参数业务语义始终左右两天都包含；若底层采用次日零点前的实现，必须明确等价且校验，避免将用户 EndTime 当排除日。1925 日期用能表示该年的原始类型判断，不能用可能发生范围回绕的 toDate 转换冒充等价。

固定上限/下限应由本表确认结果生成，不把 2025-10-01 强行用于全部表。SPPR 样例 SELECT/preSql 都限制 `Date >= '2022-11-01' AND Date < '2025-10-01'`。preSql 非事务保护：后续失败仍可能已删。

## 按当前 Doris 缺口分段

### 同一时间窗同时保留CK与Doris源

在已确认双方保留口径、目标明细模型且该窗口内所有被删记录均能由两边重建时，可提出一个工作流中两个串行DataX节点：首节点preSql清理该窗后导入一侧，第二节点preSql使用经该模板验证的无写入语句（如SELECT 1）再导入另一侧。两节点分别复用对应reader的已成功模板，各自sql/columns/table/preSql，日期取同一组StartTime/EndTime，不新增第七个业务参数。

- 这属于需要先确认的混合保留方案，不自动修改日常工作流，也不把方案可行写成生产已验证。
- 单一reader不能仅通过日期参数同时读取两个独立数据源，不能把SQL Server的SELECT直接放入CK reader。
- 目标明细模型不自动去重。首节点成功、第二节点部分失败时，不能单独重跑/自动重试第二节点，否则重复追加；节点自动重试须关闭，恢复应先确认前次导入结束，再从首节点清理该窗并完整重跑两侧，或采用经确认的隔离暂存方案。
- 二者日常任务与补数同窗竞争时仍要协调；整窗删除与两次装载不具备原子性，中间会暂时不完整，用户不能接受时改用暂存后发布方案。
- preSql空字符串在上游插件可跳过不代表平台一定保留空参数，必须回读真实解析结果；无写入语句需验证当前插件支持，不能改成会误删的条件来绕过。
- 不需要变更模型的唯一键场景可另行评估按Id写入，但必须读取当前DDL确认，不能沿用历史DDL。不同Id并存不需要改成明细；选择明细后须重做重跑去重策略。

- 约 500 万行是本用户经验容量，不是系统硬保证；按本轮实测可下调。预算计 **整段 CK 实际读取/重写量**，不能只算缺口数。
- 优先跳过已经完整的日期，合并连续缺口日期，累计不超过预算；不把两个缺口之间大段完整历史包进 DELETE。
- 按当前 Doris 覆盖、分区、日分布设计，不机械按年切。重试前重查，因为之前可能已删或部分写入。
- 单日超过容量，或 NULL/同一天内部不能安全用两日期表达时，列为待专门方案；未经用户同意不新增 Id 等参数、不假装分成同一天多次运行即可。
- 每段列明预期读取、删除命中、写入和净新增，说明窗内每条被删记录都有重建来源。运行期间同窗日常同步会干扰时先安排避让，停调度需明确授权。
- 串行逐段运行，一段验收后再提交下一段，不提前批量点运行。

离线辅助 `scripts/plan_batches.py` 接收已核实的逐日键差异，不连接数据库，不证明数据安全或替代范围确认。输入与命令见脚本 docstring。它只合并连续缺口天，不推断源删除、不解决同键字段冲突。存在 blocked 时整份计划不能直接运行。
