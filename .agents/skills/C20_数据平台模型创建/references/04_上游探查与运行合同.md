# 上游探查与运行合同

## 时机与依赖

开发阶段准备，平台建模前复核；**必须在打开Merge Requests列表前**完成本模型必要的上游身份、调度、更新范围探查。不要到更新范围或血缘页才临时猜。中途接入缺资料按01分册保留原页补证据。

从已发布的最终加工SQL识别真实FROM/JOIN物理库表，展开CTE引用、去重；CTE名称和DELETE/INSERT目标引用不当上游。若真实SELECT读取目标表做历史合并，单独记录自依赖用途，不能机械删去所有同名引用。SQP无此自依赖。

## 每个上游需要什么证据

| 类别 | 必填内容 |
|---|---|
| 身份 | 完整库表、平台注册中文名、模型ID、完整树路径/来源类别、角色用途 |
| 调度 | 是否有定时、实际启停、时区、cron及对应批次、工作流/任务身份、核查时间 |
| 范围 | 更新方式、参数名/方向/类型/原始值、筛选时间字段/表达式、上下界包含性；确实无参数则说明 |
| 运行 | 可见最近运行的开始/结束/结果，区别于配置时间，不凭计划推断成功 |
| 来源 | 平台配置、调度器实际部署、运行记录分别注明；缺口、不适用或冲突及影响 |

已验证的查法：在数据模型列表按英文物理表名搜索，在结果或已发生的模型列表响应中核对`metadataDbName`、`metadataTableName`、`id`、`name`、`namePath`。同名跨库必须再核库名，不能取第一行。平台曾返回`cron`、`scheduleState`、`updateScopes`、`etlParams`、`projectCode`、`flowCode`、`taskCode`，这些是可用线索，现场字段可能变化。

本平台观察到列表接口路径`/prod-api/dap/marksetDataSet/pageList`，查询项`metadataTableName`；优先通过UI正常检索后只读其响应，不写死完整查询或认证。解析`updateScopes`和`etlParams`中的参数、同步SQL，与本地最终SQL对照。浏览器reqid仅当次工具标识，不能作为模型ID或跨会话证据入口。

再沿关联任务查海豚工作流定时启停及cron，核查近期运行。平台scheduleState与调度器不一致时如实记录，以实际调度器启停判断是否有效；不能因为页面模型待上线就推定无调度，也不能仅因scheduleState=1断言实际上线。

## 调度推导

- 定时已下线：本次时间推算直接忽略并记录理由，不删SQL依赖/血缘，不反复问是否忽略。
- 文件导入/人工维护/无定时：记录类型及证据，不虚构时间、不额外建定时；实时源不是任意一个小时任务，需结合实际可用性确认。
- **保留有效上游多批次节奏**，在对应批次比较需等待的最晚计划启动时间，再加5分钟；不是全天取一个最大值，也不是对所有上游时刻并集都新增一个下游批次。
- 以计划时间推算，实际完成记录用于解释可用性，不偷换成完成时间+5。计划+5不能保证上游已完成，不声称已设置依赖阻塞。
- 跨午夜正确进位并记录日期关系；混合周期或多源批次无法唯一对应时先说明候选与影响，再确认批次对应关系。
- SQP已确认：PG每天08/13/15/16/17/20，维表03:20已早于每批，故下游08:05/13:05/15:05/16:05/17:05/20:05；不额外03:25，不只20:05。

## 范围推导

同时读取上游实际参数和SQL筛选字段，再读取本模型触发时间表达式、来源优先级和重算范围。区分业务周期、创建时间、更新时间、入仓时间。结合补录/迟到/历史修改和多源窗口，明确下游为何取此范围；没有证据不默认昨天至今天，也不机械复制上游T-8。

日常参数合同必须含：参数名、方向、类型、动态表达式、日期格式/时区、偏移天数、两端边界、示例展开、实际筛选字段、重算粒度、已确认依据与缺口。首次加载另列真实全量范围和核查日期，仍使用同一加工SQL，不新建full_load.sql。

SQP上游按localcreatetime取T-8至T；下游CK按UpDateTime、PG按COALESCE(localupdatetime,localcreatetime,crawldate)确定变化scope，再两源整组重算，PG整行优先CK补缺。用户确认下游同取T-8至T（9个自然日），此为当前基线，不是已证明最短窗口。旧于上游创建窗口的历史修改可能根本未入ODS，下游加大窗口不能独自解决；维度映射单独变化也不触发此SQL，需针对性补跑。

将结论写入开发正式交付说明及交接模板；备注写已确定的计划及依据。此步骤的身份映射供血缘使用，调度和范围分别供两个菜单使用。参考SQP中的维表窗口尚未核实，要保留缺口，不能包装成“全上游已查齐”。
