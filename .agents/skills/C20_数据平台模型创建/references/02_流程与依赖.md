# 流程与依赖

## 全新创建顺序

| 阶段 | 必需输入/前置 | 操作与通过标准 | 去向 |
|---|---|---|---|
| S0 接入 | 用户目标、现场、交付路径 | 确定对象、授权终点及当前阶段 | 下一个未验收阶段 |
| S1 中文命名 | 规范表名、业务、手册、术语 | 操作前确定中文名及完整域路径，冲突有记录 | S2 |
| S2 合并门 | C19真实MR/路径/提交 | 确认目标MR已合并；未合并终止 | S3 |
| S3 上游探查 | 最终SQL直接依赖、平台登录 | 进入平台；查身份、有效调度和参数，形成确认的下游合同 | S4 |
| S4 一键建模 | S1–S3、模型查重 | 才打开MR列表，唯一匹配行，填新增表单 | S5 |
| S5 确定发布 | 名称、域路径、人员、备注正确 | 点击后取模型ID与成功结果；原地等待自动配置 | P1 |
| P1 发布信息 | 开发基本信息、发布相对路径 | 十项值回读，消除联动重置 | P2 |
| P2 同步语句 | 正确代码路径/已合并SQL | 拉取完成，非空且属于目标；不编辑/执行 | P3 |
| P3 字段信息 | 最终DDL/字段交付、首次确认 | 导出→填写/复用→导入→逐项回读，主键/排序键一致 | P4 |
| P4 建表语句 | P3通过、开发DDL、加工SQL | 默认生成优先，三方差异查清并统一 | P5 |
| P5 更新周期 | S3确认的计划及模型备注 | 时刻/时区正确，自动说明保留 | P6 |
| P6 更新范围 | 更新语义、代码参数、运行合同 | 全量检查后跳过；增量参数逐项一致 | P7 |
| P7 数据血缘 | 最终直接依赖及身份映射 | 自动集合核对，必要时补缺再回读 | P8 |
| P8 查询语句 | 当前目标库表 | 全表查询正确，空白才补 | P9 |
| P9 质量监控 | 确认的模型分层 | ODS内置同步行数校验开，其他关 | S6 |
| S6 确认创建 | P1–P9证据完整、授权覆盖 | 点击一次，核实业务响应、身份及实际状态 | 输出回执 |

“确定发布”建立模型记录并自动进入配置；“确认创建”保存整套配置。二者不能替代，成功提示不等于上线。用户指定只走某步即在该步停下；全流程已授权则依序执行，不逐步索要重复许可。

## 前序信息在哪产生、后续在哪使用

| 产生环节 | 稳定输出 | 消费环节 |
|---|---|---|
| C18设计 | 数据库、规范表名、中文名、域路径、连接、层级、更新语义、粒度 | S1、P1、P4、P8、P9 |
| C18最终SQL | 文件hash、直接依赖、参数名、筛选字段/边界、重算粒度 | S3、P2、P6、P7 |
| S3平台身份查询 | 库表→平台注册中文名→模型ID→完整树路径，证据时间 | P7搜索补录 |
| S3运行查询 | 上线状态、时区、批次、参数、时间字段；配置/部署证据区分 | S4备注、P5、P6 |
| C18+S3确认 | 下游批次、日常参数合同、首次加载参数、例外与缺口 | P5、P6、后续运行交接 |
| C18字段设计 | 六列可导入Excel、COMMENT、键、类型、DDL | P3、P4 |
| C19代码发布 | 相对路径、提交、MR、合并证据和核实时间 | S2、S4、P1、P2 |
| 各平台阶段 | 值回读、差异处理、当前状态、证据路径 | 下一步、中断恢复、S6 |

这些栏目在开发时准备，最晚S4之前复核；缺失写“待核实”并说明是否影响当前阶段，不把浏览器临时reqid当稳定交接。未知源窗口不能写全量。影响下游时间/窗口的未知项未解决前不能把合同记为已确认；不相关缺口可明确限定后继续。

## 改动后的重验依赖

- 目标库表/分层/域/更新策略变化：重验命名、MR代码匹配、发布信息及P2–P9；必要时回开发和代码发布。不能只改表单名称。
- SQL版本变化：直接依赖、触发字段、参数、字段输出可能变化；重验S3及P2–P8。
- 字段英文名/Type/顺序/COMMENT/主键变化：重验Excel、P3、P4、INSERT列与投影；影响SQL则回C18/C19。中文展示名单改也需Excel和P3唯一性校验，不擅改COMMENT。
- 上游调度/启用状态/范围变化：重新推导下游合同，更新备注、P5/P6；不自动改业务算法。
- 血缘补录只涉及漏掉且已证实的对象：补回P7并核对集合；若发现SQL依赖变了，则按SQL变更处理。
- 复用已通过的无关项，不因小改动从S1全部重做。
