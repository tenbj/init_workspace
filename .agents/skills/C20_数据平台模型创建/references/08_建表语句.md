# 建表语句

字段信息验收通过后，进入“建表语句”，**优先平台默认生成**。本步骤比对，不单独点击执行或另跑生产DDL。平台确认创建可能按自己的流程建立关联资源，记录实际响应，不预先声称未发生/已发生物理建表。

## 必须比对

1. 保存或读取平台默认DDL，与本次正式开发DDL比较目标库表、字段集合/顺序、类型长度精度、可空、COMMENT、键、分桶和属性。
2. 同时核对六列字段Excel以及实际加工SQL的INSERT列/最终SELECT映射。字段按名称对照，类型大小写和无意义空格可规范化比较；COMMENT含义、可空及精度不可忽略。
3. SQL必须显式列目标字段；INSERT列与SELECT投影顺序对应，不因平台将序号0审计字段排到物理末尾就误改业务Excel前三行。DDL顺序差异要解释并对齐交付，不能只比字段数量。
4. 出现Type、字段或注释差异，追查代码、字段信息、DDL至少一处的来源错误，定位后同步相应产物；**不能因平台默认优先而无条件用它覆盖错误字段类型**。

## 已确认的平台口径

- 分桶默认 **24**，平台实际不是24需核对并调整到已确认设计，不从旧稿携带其他数。
- 四个表级项以平台为准：`IF NOT EXISTS`、表级`COMMENT`、`replication_allocation`、`enable_unique_key_merge_on_write`。
- SQP平台无IF NOT EXISTS、无PROPERTIES，表COMMENT为“广告_SQP_品牌视图明细”；正式DDL已按平台原文同步。这只是本次平台输出，不等于以后所有表都必须删除这几个子句，也不等于已查证引擎隐式默认值。
- 主键/排序键按已确认模型，不能套用SQP唯一键给其他未核验模型。

差异结论至少包含“原值→平台值→依据→修改位置→重验结果”。更新正式开发DDL和字段交付时按备份规则执行。若需要改加工代码，则回C18/C19保证仓库发布版本一致，不在平台临时修代码绕过发布。确认三方一致后进入更新周期。
