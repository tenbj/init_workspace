# 更新周期与更新范围

## P5 更新周期

输入为上游探查已确认且写进模型备注/交付说明的下游计划。逐项设置平台年、月、日、周、时、分，核对时区及每个批次；界面自动生成说明要**保留原文**，只核对内容，不手工改写为更顺口的文字。说明与计划不一致时查配置，不覆盖说明掩盖错误。

SQP：年`*`、周`?`、月`*`、日`*`、时`8,13,15,16,17,20`、分`5`；响应cron为`0 5 8,13,15,16,17,20 * * ? *`。显示“8、13、15、16、17、20期间，每小时的第5分钟”符合每天六次05分。时区Asia/Shanghai。本例状态开关原本开启，未主动切换；其他模型需按已确认计划核对，不能由此推定开关等于已部署上线。

周期填写完成进入更新范围，不跳过。表名dd可以一天多批次，本例不因六次运行就强制改为hh。

## P6 更新范围

先读代码实际参数和开发交付合同。全量无范围参数：进入页面检查确无需要的时间参数后跳过，不为了凑表单加入StartTime/EndTime。若全量SQL实际含参数，按语义查清，不机械跳过。增量：核对日常运行频率和参数合同均已交付；只有首次加载日期或某天示例，不算日常默认值。

| 项目 | 填写规则 |
|---|---|
| 参数名 | 与SQL `${参数名}` 大小写完全一致，表单只填裸名，不填`${}` |
| 方向 | 输入参数为IN，按代码实际参数确认 |
| 类型 | 使用平台参数枚举，如VARCHAR；此处不是字段Excel Type，不强制小写 |
| 值 | 填完整调度宏`$[...]`，不加引号，不填T-8文字，不把`${StartTime}`填成值 |
| 日期格式 | yyyy-MM-dd，MM为月份；偏移量在格式后；按实际调度器语法验证 |
| 边界 | 与SQL筛选条件一致，明确闭/开区间、时区和示例展开 |

SQP已确认日常值：StartTime/IN/VARCHAR/`$[yyyy-MM-dd-8]`，EndTime/IN/VARCHAR/`$[yyyy-MM-dd]`。2026-10-10展开10-02至10-10，共9日，SQL>=10-02且<10-11。这是案例，不是通用默认。平台最初自带`$[last_day(yyyy-MM-dd)]`与`$[this_day(yyyy-MM-dd)]`，不代表开发合同；不要把调度器last_day误解为SQL月底函数。

首次加载单独从实际SQL筛选字段求全量时间范围，使用同一加工文件传实际参数。不得把旧核查日期的结束上界或扩大后的首次范围当日常默认。

输入后失焦并逐行回读：名称、方向、类型、原始值与实际参数集合一一匹配，无遗漏、拼写错、重复或额外参数。与交付不一致先查04分册推导依据并补正式交付，再填写；不能仅凭经验临时用昨天。完成后进入数据血缘。

宏语法变动或未识别表达式应以现场调度器文档/验证证据为准，禁止仅靠本案例硬套新语法。参数范围与计划启动时间是两种合同，均须交付。
