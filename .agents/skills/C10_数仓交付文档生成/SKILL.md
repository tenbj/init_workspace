# 数仓交付文档生成

## 这项技能解决什么问题

- 把目标模型 SQL 转换为字段清单、六维质量指标、数据自测和独立报告。
- 复用标准 Excel 模板，完成生产只读实测、实际结果回填与交付前校验。

## 先读哪些本地知识

- 先读 `references/本地适配说明.md`，确认路径、依赖及来源授权的适用范围。

- 必须先读 `references/交付流程.md` 和 `references/输入输出与环境.md`。
- 填字段页前读 `references/字段清单规范.md`。
- 设计质量 SQL 前读 `references/六维质量指标规范.md`。
- 执行生产自测与写报告前读 `references/生产自测与报告规范.md`。
- 使用脚本前读 `references/工作包与模板说明.md`。

## 固定动作

1. 锁定目标 SQL、目标表、环境文件和交付模板；修改既有交付件前执行 B02。
2. 解析 SQL 的输出字段、分支口径、上游来源、关联条件与加工逻辑，形成字段和测试工作包。
3. 按六维生成 DQC：完整性、唯一性、有效性、准确性、一致性、及时性；每条 SQL 最终只输出 `quality_value`，且大于 0 为异常。
4. 执行 C02 做生产只读验证，检查错误字段并记录最新业务日期、数据范围和实际结果；不得用推测值替代实测。
5. 用 `scripts/delivery_workbook.py` 基于 `assets/数仓模型交付文档模板.xlsx` 生成或更新 Excel，同时输出质量 SQL 和独立自测报告。
6. 运行脚本校验、逐条重跑落盘 DQC，并回读工作簿；确认无“待实测”、无旧模型残留、字段顺序与 SQL 一致后交付。

## 什么时候再读本 skill 的 references

- 不清楚完整交付顺序、返工点或验收门时，读 `references/交付流程.md`。
- 不清楚环境、SQL、模板与最终产物边界时，读 `references/输入输出与环境.md`。
- 字段存在多分支、代表字段或系统审计字段时，读 `references/字段清单规范.md`。
- 六维映射、业务阈值或 `quality_value` 写法不确定时，读 `references/六维质量指标规范.md`。
- 需要决定自测深度、报告结论或异常披露方式时，读 `references/生产自测与报告规范.md`。
- 需要自动生成 Excel 或编写 JSON 工作包时，读 `references/工作包与模板说明.md`。

## 边界

- 生产环境只允许通过 C02 查询；不得执行 DDL、DML 或修改生产数据。
- 环境凭据只从授权环境来源加载，不得打印、复制到产物或写入 Skill。
- Excel“阈值/标准”必须写业务条件，不能写 `quality_value=0；>0异常`；该约定只属于 SQL 接口。
- 指标名称固定为“质量维度-模型名称”，检查类型必须使用六维标准名称。
- 未执行生产查询时必须明确标注待实测；完成交付时不得保留“待实测”或虚构实际结果。
- 不因文档任务擅自修改正式 ETL SQL、表结构或调度配置；发现不一致时先披露并等待授权。
