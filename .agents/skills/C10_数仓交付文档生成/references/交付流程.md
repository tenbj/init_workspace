# 数仓交付文档完整流程

## 1. 锁定输入

1. 确认目标 SQL 是当前版本，记录路径、目标表和模型名称。
2. 确认 Excel 模板；默认使用 `assets/数仓模型交付文档模板.xlsx`。
3. 确认生产只读环境来源。环境存在但未加载时按 C02 规则加载，不复制凭据。
4. 读取目标表建表语句或字段类型信息；SQL SELECT 不能替代表结构类型。
5. 修改现有交付文档前执行 B02，避免覆盖用户版本。

## 2. 静态解析 SQL

按最终 INSERT/SELECT 输出顺序记录：

- 字段技术名、中文名、类型、释义。
- 每个 UNION 分支的来源表达式。
- 上游表、别名、关联键与过滤条件。
- 枚举常量、空值处理、聚合、窗口函数、除法与精度。
- 业务明细字段与代表字段是否分列。
- `unique_key` 的拼接维度、空值规则和哈希算法。

多分支同名字段必须在一行中分别写明各分支逻辑。

## 3. 填写 Excel

- `01_交付表清单`：模型、层级、目标表、调度、场景、来源、负责人和备注。
- `02_1模型名称-字段`：保持 SQL 输出顺序；审计字段序号 0，业务字段从 1 连续编号。
- `02_2模型名称-质量指标`：按完整性、唯一性、有效性、准确性、一致性、及时性六维组织。
- `02_3模型名称-数据自测`：覆盖源目标数量、主键、主要分支、派生指标、枚举和边界。

## 4. 设计并执行质量 SQL

1. 先写业务条件，再转换成异常集合 `dc`。
2. 每条 SQL 最后一段统一为 `SELECT COUNT(*) AS quality_value FROM dc;`。
3. 使用 C02 逐条执行，检查 `error` 并打印格式化结果。
4. 质量值大于 0 时运行诊断 SQL 定位异常，不能把异常改写为通过。
5. 准确性至少复算关键源字段和一个核心派生指标；一致性至少检查行数、唯一键数和双向键集合。

## 5. 生产自测

至少完成：最新分区和分支数量、源原始行与唯一键、双向键差异、主键公式、关键字段与派生指标复算、枚举/边界、调度 SLA。

## 6. 产出与回填

- Excel：字段、六维指标、SQL、实际结果和结论。
- SQL：全部 DQC 与诊断/自测 SQL。
- 报告：数据范围、六维结果、自测证据、异常、风险和验收结论。

## 7. 交付前质量门

- 字段技术名与 SQL 输出顺序完全一致。
- 六维名称、检查类型、业务阈值和 SQL 逻辑一一对应。
- 阈值列不含 `quality_value`；每条 SQL 最终包含 `quality_value`。
- 从落盘 SQL 原文逐条执行成功，而不是只执行临时版本。
- 实际结果无“待实测”，结论与数值一致。
- 工作簿可回读、ZIP 完整、筛选区域覆盖全部数据行。
- 不存在旧模型名称、字段、结果和模板残留。

## 8. 返工规则

- SQL 或主键修复后重跑全部六维 DQC，不沿用旧结果。
- 新增字段时同步更新 02_1 的顺序、释义、加工逻辑和来源。
- 检查类型调整时，不能只改名称；同步重组阈值、SQL、实际结果和报告。
- 生产代码与本地 SQL 不一致时，分别说明生产数据状态和代码资产状态。
