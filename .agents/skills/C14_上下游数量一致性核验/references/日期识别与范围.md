# 日期识别与范围

## 输入与取证

目标表名或加工 SQL 即可开始；优先从用户指定代码或工作区 input 材料补全目标库表、最终 SELECT、调度参数、字段类型及日期映射。记录代码来源与版本／哈希；本地代码是否与线上部署一致需如实说明。

数据名称固定为查询数据 `query_data` 和实体数据 `table_data`。

## 日期选择顺序

1. 阅读日期参数、过滤、写入分区和调用脚本，识别参数实际控制的日期字段；参数若只表示任务执行时间，不能直接视作业务日期。
2. 存在参数日期对应字段时，使用该字段及其在目标表中的映射，参数只限制相同核验范围。按记录日期分组，不能把区间参数当常量赋给全部记录。
3. 没有参数日期时，自行识别业务日期，优先报表／统计／交易／订单／事件日期。对象状态表可按对象语义选择创建时间或其他业务时间，并解释选择依据。
4. 全量更新（全量覆盖/重建）表没有业务日期时，使用其他可对应的非审计时间字段；按语义和两侧映射选择，不机械取第一个字段。2026-10-10用户最终补充明确：first_inserted_dt、etl_dt、last_updated_dt三个审计字段不视为“其他日期”，优先于此前泛指加工时间可用的表述。不得用这三个审计字段或审计NOW()制造日期分组。
5. 全量更新表排除上述审计字段后没有其他时间字段时，直接以完整加工SELECT的COUNT(*)与实体全表COUNT(*)比较，记录mode=whole_table；不虚构日期，不声称逐日核验。非全量表仍须确认相同范围/批次，无法解决的关键映射如实询问。

## 日期表达式

- 两侧分别提供明确的 DATE 类型表达式，输出别名 `check_date`。
- 使用原加工后的转换结果；核对秒／毫秒、字符串格式、时区和日界线，避免多做一次不同的时间转换。
- 若业务日期是多列推导值，保留其计算逻辑，不能只取其中一个字段。
- NULL 日期不丢弃；使用 Doris `<=>` 空安全关联并比较其分组数量。两侧NULL分组数量相同通过。

## 比较范围

### 超亿行模型（2026-10-10用户明确规则）

- 模型总量严格超过100,000,000行时，一致性监控只核验最近六个自然月的业务日期数据。先记录总量证据、时间和来源；不能把单批数据量或SQL返回行数当模型总量。
- 默认窗口下界为 `DATE_SUB(CURRENT_DATE(), INTERVAL 6 MONTH)`（含），上界为 `DATE_ADD(CURRENT_DATE(), INTERVAL 1 DAY)`（不含），包含运行当天。两侧按同一业务日期、时区、边界过滤并逐日比较，说明排除更早历史；不固定为180天或写死本次日期。
- 保持完整加工逻辑，过滤可安全下推时须证明不改变JOIN、窗口、聚合语义；审计字段不能替代业务日期。无可映射日期时记录实际问题，不伪造半年范围。
- 用户清理过ODS历史数据时记录事实来源，旧全历史差异不伪装为已修复；近半年重新配置、回读和执行后记录新的结果。
- 本规则只限制一致性范围，不自动缩小C11业务键核验或唯一性监控范围；大表主键查询按C11分批覆盖原范围。

| 写入方式 | 处理 |
|---|---|
| 全量覆盖 | 完整加工SELECT与目标全表；有业务日期优先业务日期，无业务日期用其他非审计时间按日比较；排除三个审计字段后无时间字段则整表COUNT(*)比较 |
| 分区覆盖 | 两侧限制同一分区范围，再按对应日期逐日比较 |
| 增量追加 | 先识别批次或业务日期范围，实体侧采用同范围；不对比累计全表 |
| 增量更新／合并 | 明确输入事件与当前实体行是否同一粒度；多次更新事件不能直接与落表记录计数相等，应披露不可直接对比的范围或另取业务上可比的重算结果 |

保持原 UNION、JOIN、过滤、聚合、窗口和原有去重。仅删除写入动作并包装最终 SELECT，不能为了通过新增DISTINCT或取最新。

参数范围内某天两侧都无记录时视为一致，不增加日历缺失异常。逐日模式中总量只可辅助；全量表排除三个审计字段后无时间字段的整表模式以总量为主核验。推荐在同步／加载完成的稳定窗口执行；独立查询不等同共同事务快照，当前重算不等于上次加载的上游历史快照。完整SELECT中的审计表达式仍原样保留，但不作为分组或过滤依据。

## 示例

- 报表SQL按report_date过滤：两侧按report_date逐日计数，不按etl_dt。
- 无参数的广告组状态表，creation_date确认为源端对象创建时间：可按DATE(creation_date)比较当前对象创建日分布，说明它不是历史每日快照。
- 若另一个模型的业务对象按支付日期产生，应选择支付日期；不能继承广告组例子的创建日期。
