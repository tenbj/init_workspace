# 字段与业务线

## 输入与优先级

用户通用规则（2026-09-30确认）：常规质量配置只选择 Doris 模型；只有用户明确指定修复某个 CK（Clickhouse）模型时才操作该 CK 目标。同一技术表同时存在 Doris 与 CK 时，直接根据现场数据库/连接定位 Doris，不再为这两种引擎重复询问。若 Doris 内仍有多个候选，再核对连接、库、域及模型身份；未找到 Doris 时不得自动退而选择 CK。此规则指治理目标模型，不限制核验 SQL 读取的真实上游来源。

## 同技术表多引擎：配置前身份核对门

此门必须实际执行并留证，不能仅在报告中声明“已核对”。

1. 精确检索技术表，搜索覆盖已上线、待上线、已归档等全部候选；枚举所有同表记录，记录平台中文名、引擎、连接/库、域、层级及可见标识。禁止取第一行，禁止因Doris待上线而改选已上线CK；筛选导致不可见不等于模型不存在。
2. 默认筛定Doris，从这一行打开发布信息和质量指标入口，回读技术表、连接/库及绑定代码路径；后续模型树选择和保存回读必须回到同一身份。无法直接取得平台ID时，保存唯一行及完整身份组合证据，不能编造ID。
3. 平台中文名以这一条Doris记录为准。DDL的COMMENT、仓库文件夹名、旧台账中文名都可能滞后，不能据它们选择平台模型或给指标命名。它们与平台名称不一致时分别记录来源，不静默覆盖证据。
4. SQL来源按C17/C14：常规固定仓库版本，旧表/代码/部署冲突按已确认规则取关联海豚真实SQL。平台绑定路径用于核对关系；登记旧表、实际写入新表分开记录，指标说明注明真实SQL目标，expected/actual仍绑定同一已核实平台模型。名称识别错不直接证明旧SQL用了CK；核对实际库、完整源码、版本及哈希后决定保留或重算。
5. 创建前、配置模型后、保存回读后都检查身份一致；expected/actual填相同的已核实目标。任何一项冲突时不得保存到另一个模型。

反例：同表`dwd_mkt_amz_xt_asin_info_ilu_dd`的“市场_亚马逊新兔子体”是CK，而“市场_产品指标_我司子体”是Doris。此例仅说明判别方法，未来仍以现场回读为准，不硬编码名称或ID。

## 识别错误后的恢复

主动承认识别错误、保留历史证据并纠正当前台账；随后沿原授权继续定位正确模型、重新查重、复核SQL、保存回读、通知/周期、运行与留图。用户要求做完时，不得只标记“待复核”后结束。若已写入错误模型，先核实实际误写范围和修正方案；不擅自删除旧指标或运行无关ETL。业务键不成立时按C11如实记不适用，不能为了完成配置而造键。

必要输入：技术表名、核验类型/指标命名、完整 SQL 或生成依据。平台默认本文所述数据中台。继承用户本任务中已确认的监控时间与要求；缺少监控时间且无可继承约定时在独立调度项询问一次，不阻止SQL已保存后的C15完成，可根据任务完成时间提出建议，但不能自行把案例的08:00设为全局规则。

一致性 SQL 缺失时先执行 C14，并保留其文件、返回字段与异常语义。默认 SQL 应返回单行单列数值 quality_value，0表示一致、正数表示不一致日期组数，平台异常条件“quality_value 大于 0”。其他质量类型按其真实 SQL 语义设置，不能套用一致性口径。

## 上级节点：固定三选一

用户通用规则：`数据质量 → {业务线}`，业务线只允许 `前端运营`、`市场&研发`、`后端供应链`。

AI 根据平台模型中文名与数据域自行判断并记录一句依据，正常情况不再要求用户选上级节点。优先看业务对象与用途，辅以模型中文名、数据域描述和已有目录归属；DWD/ODS/DWS 层级或 ads 等技术缩写本身不能决定业务线。

下表是判断启发，不是平台全部数据域的官方映射；证据冲突时继续查看模型说明/字段，仍无法确定再问用户。

| 业务线 | 业务对象与用途线索 | 防混淆 |
|---|---|---|
| 前端运营 | 广告投放、广告预算、店铺、平台销售、流量、转化、运营报表 | 广告投放+广告域已由用户确认属于此类，不能因“广告”就归市场 |
| 市场&研发 | 市场调研、竞品、选品、新品研发、产品设计、研发项目与测试 | 商品主数据可能跨业务线，按主要服务流程判断 |
| 后端供应链 | 采购、供应商、生产、仓储、库存、物流、履约、供应链成本 | “订单”不充分：销售经营分析和采购履约是不同用途 |

页面可能存在基础质量、业务质量等其他节点，不能因可选就替换上述规则。不存在目标父子节点时询问，不擅自新建目录。

## 配置映射

| 页面字段 | 要求 | 保存后证据 |
|---|---|---|
| 指标名称 | 一致性任务用 一致性-{现场模型中文名} | 完整名称一致 |
| 上级节点 | 数据质量 → 自动判断业务线 | 完整路径或父子树关系 |
| 归属角色/人员 | 继承模型真实归属；用户明确要求优先 | 已选值，不能只留下搜索文字 |
| 指标说明 | 写清目标表、对比范围、日期/粒度和异常含义 | 说明弹窗中的完整文本 |
| 通知实例（独立项） | 沿用用户要求选择钉钉-工作通知；不计入C15完成条件 | 保存后重开显示已选；未配置则单列待补齐 |
| 订阅人员/报表链接 | 按用户要求；未指定保留默认，不虚构 | 有要求才验收 |
| 监控状态 | 启用，除非用户明确要求禁用 | 保存后状态 |
| 数据连接 | 跨境电商，即 Doris 数仓 | 完整标签一致 |
| 数据模型 | 前一步查到的中文名及其对应技术表 | 名称+数据域+层级+技术表/现场标识交叉确认 |
| 规则 | 自定义；页面当前文案为“自定义策略” | 策略类型 |
| 异常条件 | C14默认 quality_value 大于0 | 字段、操作符、阈值 |
| 自定义内容 | 原始 SQL 全文 | 重新读取全文并比较 |
| 监控周期 | 使用任务已确认的周期并启用 | 页面说明、各字段、启用状态 |

通知实例独立于C15平台完成条件。用户要求配置时仍需完成并回读，但缺失仅记通知待补齐，不将平台阶段标为未完成。当前页面下拉存在“钉钉-工作通知”和“查看全部通知实例”；后者不能充当通知配置。选择组件可能是单选或多选，应以现场形态为准；目标值必须选中。设置通知与执行本指标可能触发其工作通知，属于用户调用本技能配置并执行的范围；不另外发送测试消息，也不擅自增加收件人。
