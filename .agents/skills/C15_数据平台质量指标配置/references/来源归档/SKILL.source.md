# 数据平台质量指标配置

## 这项技能解决什么问题

- 把质量核验 SQL 保存到正确模型的质量指标并回读确认，即完成C15平台阶段。钉钉通知、周期和运行结果独立记录，不阻挡平台完成。
- 默认处理一致性指标：`一致性-{平台模型中文名称}`。已有同模型同名指标按用户规则跳过。
- 新窗口、新会话都从现场重新定位，不能依赖上一轮窗口编号、元素编号或账号状态。

## 先读哪些本地知识

- 必读 `references/浏览器识别与恢复.md`、`references/字段与业务线.md`、`references/配置与执行流程.md`、`references/输出契约.md`。
- 根据工作区要求执行 B08；成果归属已有数仓质量项目，必要时用 B04 定位；修改 live 文件前执行 B02，收尾执行 B03。
- 一致性 SQL 缺失时调用 C14；已有 SQL 时读取原文件并确认输出语义。不得仅凭表名臆造加工逻辑。

## 固定动作

1. 确认目标技术表名、平台地址、SQL 来源及执行范围；继承本任务已确认的时间、负责人等信息，不重复询问。
2. 枚举浏览器页面，核对站点、路由、标题和登录状态；读取新快照后再定位当前控件。
3. 在模型列表精确查到技术表名，记录中文名、数据域、层级、归属角色与人员，确认唯一目标。
4. 从目标行“更多信息”的质量指标入口跳转；该入口曾为第四个可见图标，必须现场验证含义。新开窗口后重新枚举页面。
5. 检索目标指标并核对关联模型；存在则记录“已有，跳过”，不存在才新建；保存结果不确定时先查重，禁止再次盲建。
6. 自动选 `数据质量 → 前端运营 / 市场&研发 / 后端供应链` 之一；填写指标基础信息。
7. 配置数据连接 `跨境电商`、现场查到的模型、自定义策略、完整 SQL 和异常条件；保存后重新打开回读，确认SQL全文一致即登记C15已完成。
8. 钉钉通知与监控周期作为独立配置项，沿用已授权要求继续处理并分别记录状态；待补齐不回退C15完成状态。
9. 用户要求执行时继续仅勾选目标1行运行，核对新的监控时间与结果；运行状态独立于平台完成，不得省略已授权执行工作或伪造新结果。
10. 每个实际配置指标运行后，收起左栏并关闭弹窗，保存目标、时间、结果同屏的列表PNG；数值单独核对。保存截图路径及元数据，结果HTML显示缩略图并支持页内弹窗放大；完整规则见`references/运行截图留证.md`。
11. 保留证据，默认运行平台交付核验；通知/运行需要验收时分别核验，分开交付状态、SQL路径及截图状态。批量端到端交付由C17编排。

## 什么时候再读本 skill 的 references

- 切换窗口、元素不在快照里、页面变化或操作失败：读 `浏览器识别与恢复.md`。
- 业务线、同名模型、负责人、通知或时间有疑问：读 `字段与业务线.md`。
- 创建、配置、回读或运行未完成：读 `配置与执行流程.md` 的对应状态。
- 写证据与交付前：读 `输出契约.md`；能力结构见 `结构融合索引.md`。

## 边界

- 不把历史 pageId、UID、模型 ID、指标 ID、坐标和图标序号当作新会话定位依据。
- 不直接调用猜测的写接口，不绕过页面权限，不读取或落盘密码、Cookie、令牌。
- 钉钉通知沿用用户独立配置要求；不得因缺通知、周期或新运行结果将已保存SQL的C15标为未完成，也不擅自取消这些独立工作或增加订阅人员。
- “已保存”“操作成功”“历史正常”都不能单独证明本次执行正常。
- 正常和异常都是有效执行结果；禁止为了通过而放宽阈值、删改 SQL 或反复执行。
- 遇到无法识别、权限缺失或步骤不明，先做一次有依据的恢复，仍不明确就及时询问用户；保存进度并继续无依赖工作，不能卡死或直接宣告失败。
