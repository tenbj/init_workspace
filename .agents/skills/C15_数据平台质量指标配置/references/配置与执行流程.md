# 配置与执行流程

## S0：输入与模型定位

读取完整 SQL 文件，确定返回字段、异常条件和本任务监控周期。进入模型页面，在“搜索数据表”中输入技术表名，点击查询，等加载结束。精确核对目标表、中文名、数据域、层级、引擎、归属角色/人员；结果不唯一先消歧，不选第一个。必须执行“字段与业务线.md”的身份核对门，保存候选矩阵和所选Doris行证据；在此门通过前禁止使用DDL注释生成指标名。

从目标行右侧“更多信息”识别质量指标入口（曾为第四个可见图标），点击后重新枚举页面，确认质量指标页。记录模型身份，后面每次模型选择都回到这一证据。

## S1：查重

继承的“搜索数据模型”可能只是中文模糊过滤，需再填完整指标名称并查询。读取稳定结果，核对完整名称和关联技术模型。存在唯一同模型同名指标时按“存在则跳过”交付，默认不修改通知、周期或再执行；若用户明确要求对已有项执行/更新，再按授权执行相应步骤。

同名却关联不同模型、存在多个同名条目或部分创建未绑定模型时，应核对详情和先前 checkpoint，必要时请用户帮助，不能新建另一个同名指标。当前筛选可能掩盖未绑定记录：必要时清空模型筛选，按完整指标名全局查重，并排除分页遗漏。

## S2：新增基础指标

只有稳定查重未命中时点击右上角新增；核对“新增指标”弹窗。

1. 上级节点依次选数据质量、判断出的业务线；核对父子关系。
2. 填完整指标名，选择模型归属角色再选择归属人员；等待异步选项，搜索文本不等于选中。
3. 指标说明如为只读输入，打开其子弹窗填写并确定。
4. 通知实例按已授权要求选择钉钉-工作通知；等组件选中状态更新，核对完整标签和实际值再保存，“查看全部通知实例”等入口不是实例。不能点击后立即保存而写入旧值。重开回读确认持久化，缺失不回退平台SQL完成但须继续补齐已授权通知。
5. 核对监控启用，点击确定新增；等待成功反馈、弹窗关闭，再查询列表确认已创建。

创建成功后，新指标因尚未绑定模型可能被继承的模型筛选隐藏。清空该筛选，按指标名查询；若仍有旧列表状态可刷新质量页再查。不能因为“看不见”而重建。

## S3：配置监控

在精确目标行打开更多 → 配置监控，确认当前指标名或上下文。

1. 策略信息选择跨境电商，回读完整选中值。
2. 打开模型树，搜索中文名；核对数据连接 → 数据域 → 层级 → 模型路径，再用技术表或现场观察到的模型标识与 S0 核对。同名模型不能只按中文名选。
3. 选择自定义策略。C14一致性用 quality_value、大于、0；保留其他 SQL 的真实返回语义。
4. 打开自定义内容/策略内容编辑器，填完整 SQL 并确定；在正式保存前回读全文，保留核对证据。
5. 监控周期按已确认要求配置并独立记录；没有周期不阻挡已保存SQL的C15完成。如果页面保存本身要求某字段，处理该实际保存条件，不把未保存的SQL标为完成。切换选项卡后重新获取快照。
6. 每天08:00的案例字段为年 `*`、周 `?`、月 `*`、日 `*`、时 `8`、分 `0`，页面说明“每天8点整”。这是页面字段映射，不能当作通用六位 cron 字符串盲贴。按当前周期组件的语义输入与验证。
7. 保存并等待完成；记录 S3 checkpoint。

## S4：保存回读（C15平台完成门槛）

从列表重新打开详情或编辑配置，读取持久化后的值，而非仍未提交的表单：

- 指标名、上级节点、负责人、连接、模型身份、策略类型、异常条件；
- 通知实例单独回读，未选中记独立项待补齐；详情不展示时从编辑指标查看，取消退出，不为查看而再次保存；
- SQL 全文与本地文件仅标准化换行后相同，可用脚本核对；
- 监控周期的自然语言说明、字段值、启用状态与用户确认一致。

目标指标、模型和SQL保存全文回读无误，即标C15平台已完成。SQL未保存或不一致时修正并重新回读，不能标完成。通知、周期的未完成与运行失败单独登记，不回退平台状态；也不取消用户此前已要求的独立工作。

## S5：独立运行验证（按已授权要求继续）

关闭弹窗，记录目标行原“最新监控时间/最新结果”。清除遗留勾选，只勾选目标数据行；统计数据行的已选数应为1，不把表头全选框计入。分页/跨页选择要一并排除。

切换搜索后可见1行不代表总共只选了1行，组件可能保留上一指标勾选。确认框数量非1时取消，清除跨查询勾选；必要时在无未保存内容时刷新，重新精确搜索、单选并核对后提交。

找到列表右上方添加左侧的执行按钮，现场核对其提示/位置；点击后若出现“确定手动运行已选的1条指标监控？”则核对数量和目标后确认。数量不为1立即取消并修正选中范围。已获得配置并执行授权时，此界面确认可直接完成，无需再次询问用户权限。

记录提交时间。操作成功仅证明提交；随后刷新目标列表或查看监控历史，直到监控时间推进且结果属于本次运行。时间须不早于本次平台时钟下的提交时刻；若本机与平台时钟不一致，用平台执行记录/任务标识关联，不能调低时间要求来通过。

若恰逢定时任务或其他人执行，只有“时间变新”不足以归因手动执行，应查本次运行标识/日志。无法关联就记录待确认，不假定是本次结果。

正常：报告正常和新监控时间。异常：报告异常和新监控时间，保留详情；异常是成功执行得到的数据质量结论，不是操作失败。需要诊断时使用现成诊断 SQL，额外修复数据必须另有用户授权。

执行中、超时、无新时间：按浏览器恢复规则有界等待并提问，不能反复点击执行来试。未知状态如 SQL 报错要如实记录错误文本并处理具体原因。

## S6：交付与恢复

按输出契约保存证据并分别验收：平台完成/已有跳过/未完成，通知已配置/待补齐，运行正常/异常/未运行/待确认。默认脚本核验平台保存SQL；通知和运行使用独立选项。B08收尾应保留尚未完成的已授权独立事项，不因C15完成便宣称全部工作完成。
