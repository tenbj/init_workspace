# 发布前检查

## 必须通过

1. `git status --short` 已理解：
   - 相关改动已纳入本次发布
   - 无关用户改动不被误提交

2. 忽略规则有效：
   - `.Claude.json` 不入库
   - `.claude/settings.local.json` 不入库
   - `input/` 只保留必要占位
   - `.temp/` 只保留必要占位
   - `.history/` 不提交历史快照
   - `*.exe` 不作为普通 Git 文件提交

3. 敏感信息扫描通过：
   - token / key / secret
   - 内部 URL
   - 数据库连接信息
   - 用户本机路径和私有配置

4. 发布文档一致：
   - `CHANGELOG.md` 最新版本在顶部
   - Release Notes 与 changelog 不冲突
   - README 当前版本正确
   - tag、Release 标题、资产文件名一致

5. 构建和校验：
   - `output/00_系统治理/03_代码程序/src` 已通过 `scripts/update_init_program.ps1` 按本次发布目标更新
   - `.b09_update_manifest.json` 存在，且版本与 `src/build.ps1` 一致
   - 主要交付物已通过 `scripts/build_init_exe.ps1` 重新封装
   - `.b09_build_manifest.json` 存在，且记录了资产路径、大小和 SHA256
   - SHA256 已计算
   - B01 体检无 FAIL
   - 必要测试或自检已通过

## 建议命令

```powershell
git status --short
git diff --cached --name-only
git diff --cached
git grep -n -I -E "token|secret|password|api[_-]?key|BEGIN (RSA|OPENSSH|PRIVATE) KEY"
```

如仓库中允许二进制 Release 附件只通过 GitHub Release 上传，则发布前检查暂存区：

```powershell
git diff --cached --name-only | Select-String -Pattern '\\.exe$'
```

## 失败处理

- 检查失败时停止发布。
- 如果失败来自本轮改动，先修复并重新检查。
- 如果失败来自用户未说明的既有改动，只报告风险，不擅自删除或重置。
- 如果必须移除暂存项，先说明将移除哪个路径，再执行非破坏性取消暂存。
