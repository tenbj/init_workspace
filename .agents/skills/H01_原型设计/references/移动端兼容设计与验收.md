# 移动端兼容设计与验收

适用于 Web / mobile-web / cross-platform 原型。未给平台时默认 Web 响应式；明确仅桌面时用 desktop-only 并记录用户约束。规则来源于移动端系统实践，但不复制具体产品的主题、底部五标签或数据结构。

## 先设计信息层级，再选择布局

- 手机首屏优先露出主要任务及下一步，低频统计、说明、导出等移入次级入口。长列表保留滚动，不为了首屏强删必要信息。
- 手机导航选择与产品匹配的底部少量入口、顶部标签或菜单；不要把桌面侧栏缩成窄列。切换入口保持当前状态清晰和核心操作可达。
- 桌面多栏在窄屏改为单列、列表到详情或选择器到结果；用户不能同时看见的上下文用标题、返回路径或关联入口补回。
- 宽表格优先卡片或摘要到详情；复杂专业表格可在容器内滚动，但必须有提示并保证关键列/操作可达。月历可变为日期分组议程；这不是所有产品必须采用的形式。
- 同一业务状态、事件和校验由手机/桌面共享。只调整呈现层，避免两套写入逻辑、编号规则或存储造成漂移。

## 可点击、可读、可返回

- 手机关键操作及导航触达区域默认至少44×44 CSS px；原生勾选控件可以借完整关联标签提供触达区。字段正文默认16px，避免手机聚焦时放大。
- `meta viewport` 使用 device-width，禁止禁用缩放。栅格/弹性子项设置 min-width:0，长标题允许断行；禁止用 body overflow-x:hidden 掩盖宽度问题。
- 固定头部/底部为内容预留空间，并考虑 env(safe-area-inset-*)。不得遮住最后一项或提交按钮。检测中心点被覆盖只是自动筛查，还需人工检查滚动到底部。
- 窄屏复杂详情、长表单可用全屏 dialog，适配100dvh、滚动及安全区；短确认框可保留居中弹窗，不能强制所有 dialog 满屏。
- 打开子表单、取消、保存、返回必须验证父级状态与滚动上下文；保存失败保留草稿，失败与成功提示均可见。测试软件键盘、触摸拖动和 iOS 安全区时说明真实设备覆盖范围，桌面 Chromium 模拟不替代真机。
- 有真实接口时同步/离线/保存结果必须在手机可见；独立原型可以使用本地状态，但不能误写成服务端保存。后续系统交付保留移动渲染与事件，不让生成脚本截掉它。

## 机器合同与默认门

`create_package.py` 为新包生成 responsive-web-v1 能力声明与 `ui.schema.json.responsive`。默认视口360×844、390×844、430×844、1440×1000，700px只作为初始布局断点，可按内容调整。手机验收宽度保持三种，桌面可以增加4K等业务视口。

responsive 包括 mode、reason（桌面排除时）、mobile_breakpoint、layouts、viewports 和 scenarios。每个场景关联真实REQ ID，steps按顺序执行：click、fill、select、expect_visible、expect_text；selector定位当前可见页面/弹窗，必要时注明 #app/#modal 等范围，避免命中隐藏父弹窗或后台副本。

场景至少覆盖产品主要任务的完成路径。按实际功能补充：导航切换/筛选、长内容/空态、详情及子表单返回、保存错误/成功、固定导航下最后一项。模板只演示一个主操作，生成真实原型时必须替换场景；不得用模板场景冒充业务验收。

```powershell
python <H01目录>/scripts/create_package.py --output <能力包> --input <输入JSON>
python <H01目录>/scripts/check_responsive.py <能力包>
python <H01目录>/scripts/validate_package.py <能力包> --require-responsive
```

已有运行环境可复用 Playwright；缺少时在调用方环境安装 `pip install playwright` 并 `python -m playwright install chromium`，不要为单次原型修改系统全局配置。脚本仅启动包目录的回环HTTP服务，不连接生产系统；禁止把运行报告和截图留在Skill目录。

自动检查每个视口的页面溢出、手机触达区/输入字号、可见弹窗边界、关键控件遮挡、页面脚本错误，并运行全部声明场景。新包缺报告、报告失败或HTML/场景哈希变化都会阻止完整交付。旧ASOC包仍可用结构验证器检查，但H01当前工作流始终使用 --require-responsive，需补新合同和运行证据。

宽度必须对照声明的目标视口，而非只比较 scrollWidth 与 innerWidth：手机浏览器可能因宽内容扩大布局视口，两者一起变大导致误判。正反回归必须包含宽内容、过小触达区、固定栏遮挡及点击后不产生预期状态的反例。

报告还绑定验收脚本哈希，校验方法升级后旧报告也会失效。截图保存在 evaluation/responsive/；人工仍需评审信息层级、首屏任务是否够早、容器内横滑是否合理、软键盘及真机体验。自动通过不代表这些已验收。
