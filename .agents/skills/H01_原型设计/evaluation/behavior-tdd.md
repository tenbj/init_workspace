# 行为 TDD 记录

## RED

目标 Skill 不存在时，基线会退化为通用 Prompt 或单 HTML 交付，具体缺口：

- 没有稳定的必备产物、顺序和验收定义。
- 时间压力下会省略 UI/Interaction/API/Database 或 Evaluation。
- 没有 artifact manifest、跨文件 ID 和状态一致性。
- 容易把外部可视化或研发流程能力误当成完整原型设计。

## GREEN 合同

- 正向触发：产品原型、交互验证、产品到工程 AI 交接。
- 反向边界：图片编辑、纯文案、已有代码小改不触发。
- 正常流程：输入合同到八个核心产物，再生成通过的验证报告。
- 压力场景：只允许降低视觉精细度，不允许删除协议层。
- 独立性：不得依赖任何外部系列 Skill。

## 1.1.0 · 响应式能力增量

默认Web初始化即包含响应式合同和四视口核心操作场景；只在用户明确限定桌面时排除手机。入口及workflow强制先运行真实浏览器，再完成包校验。

新增可运行正反回归：默认Web、显式桌面、宽页面、过小触达区、固定遮挡、动作无效及旧报告。单元测试中的合成报告只验证验收门，真实浏览器报告另行验证，不能混称。

RED反例发现手机布局视口可被宽内容扩张，使scrollWidth与innerWidth比较误判。GREEN改为对照合同目标宽度，宽页面被拦截。旧ASOC合同仍支持基础结构校验；当前工作流要求新增响应式验收。
