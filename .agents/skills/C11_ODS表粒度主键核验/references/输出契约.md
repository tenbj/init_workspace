# 输出契约

## 默认交付

1. 核验报告：按 `assets/核验报告模板.md` 输出业务解读、粒度、业务主键、技术主键证据及结论；新增固定章节“唯一性检验 SQL 配置”。
2. 核验 SQL 和已有执行证据：保持本次核验范围与采样、全量、时间等证据限制。
3. 业务主键已确认且最小性核验完成时：默认输出 `<技术表名>_唯一性检验.sql`，并将同一份完整 SQL 放入报告。报告写明业务键、检查范围、指标名称、异常规则及执行状态。
4. 交付逐字段剔除的最小性证据表：剩余组合、范围、唯一性结果、重复反例或业务身份必要性依据、保留/删除决定与SQL路径。最终组合须再次全范围核验；未经此步不能把唯一候选标成最小业务键。

报告放在归属子项目的答疑或研究分类；SQL及查询结果放在该子项目 `03_代码程序/` 中的本模型目录。按 B04 定位子项目、B02 备份、B08 与 B03 收尾，不写入 input 或 Skill 目录保存业务运行产物。

## 唯一性配置生成

以 `assets/唯一性检验模板.sql` 为唯一模板源，保留用户确认的结构：dc中选择业务键及 `COUNT(*) AS cnt`，按业务键分组，`HAVING COUNT(*) > 1`，最终 `SELECT COUNT(*) AS quality_value FROM dc;`。

| 占位符 | 替换规则 |
|---|---|
| 业务主键字段列表 | C11已确认的真实业务键列，逗号分隔；SELECT与GROUP BY保持一致，不把报告中的加号连接展示直接复制为SQL |
| 目标库表 | 本次核验目标的完整库表标识；必要时按数据库标识符规则引用 |
| 检查范围 | 与业务键成立范围匹配的真实条件；全表为 `1 = 1`，有明确分区或业务范围时据实填写 |

不得遗留 `{{...}}` 或其他虚拟字段。业务键若依赖推导表达式，需完整展开核验时已确认的同一表达式，并保持SELECT与GROUP BY一致；不能把仅存在于报告中的推导别名当成实体列。

- 指标名称：`唯一性-模型名称`；质量维度：唯一性。
- 配置接口只输出一行一列 `quality_value`；`> 0`异常，`= 0`表示本次范围内未发现重复。
- `quality_value`是重复键组数；一组3行计1组。`cnt`是该组行数，只保留在dc内部，不加入最终配置结果。查看明细可使用相同dc后查询 `SELECT * FROM dc`。
- 不自动加入日期字段或技术ID使结果变唯一；全局键只查当日可能漏历史重复，范围不得擅自缩小。
- 按原字段或已确认表达式分组，不为方便而拼接字符串键。
- 只检验重复：空集返回0，NULL组合参与分组，单条空键不单独报错。非空、完整性与上游就绪另行检查，不在此模板混入。

## 业务主键未确认

业务主键为“无”、仅有候选键或证据不足时，报告的固定章节仍保留，并写“未生成：<具体原因>”。不冒用技术主键或取最新键，不输出带占位符的文件并标成可配置SQL；已有探索性核验SQL保留为证据。

## 执行状态与边界

- 输出SQL配置文件是C11的默认交付，不等于完成平台配置；平台操作按用户任务范围另行调用 C15。
- 有已授权且可用的生产只读核验环境时，通过 C02 执行最终SQL并保存结果；未执行时明确标“已生成、未执行”，不复用旧数字冒充本次结果。生成配置不额外要求访问平台。
- 已执行时记录时间、范围和实际 `quality_value`；执行失败记录失败原因，不标为通过。
- 目标按技术键归并时，目标无重复不证明写入前候选无重复，报告保留该限制。

## 交付自检

- 主键来自本次已确认结论，表与范围一致；报告与独立SQL正文一致。
- 存在 `cnt`、重复组筛选及单列 `quality_value`，未用SUM(cnt)改变计数含义。
- 已生成SQL无未替换占位符，链接可访问，状态不混淆生成、执行和平台配置。
