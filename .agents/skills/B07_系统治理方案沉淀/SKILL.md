# 系统治理方案沉淀

## 这项技能解决什么问题

- 把系统治理类问题沉淀为终版方案，避免过程稿、重评估记录和冗余选项混在一起。
- 适用于规则、Skill、脚本、目录、记忆、规范化、备份、SSOT 等工作区治理问题。
- 产出必须遵循 SSOT 与意图指向原则，收敛到最小可执行整改范围。

## 先读哪些本地知识

- 先读 `.system/standards/workspace-spec.json`，确认机器事实源。
- 再按问题类型读取 `.system/standards/*.md` 中对应的人类可读标准。
- 涉及 Skill 编号、注册、跨 Skill 引用或新建/修改 Skill 时，必须读 `.system/standards/Skills管理标准.md`。
- 涉及 output 文档落盘或 `目录.md` 维护时，必须读 `.agents/rules/direction-rules.md`。
- 写方案前读 `references/方案写作规范.md`；需要直接套结构时使用 `assets/系统治理方案终版模板.md`。

## 固定动作

1. 先界定问题背景：只交代现象、复核结论和为什么需要整改，不回放初版方案和重评估过程。
2. 识别 SSOT：区分机器事实源、人类可读标准、执行入口、过程记录，禁止把 output 方案反向当标准。
3. 按意图指向写整改项：用稳定编号表达动作意图，例如 `B01：补检查`；真实路径只作为具体落点。
4. 收敛最小整改范围：只列能闭环当前问题的骨架项，业务子项目具体修复由检查结果驱动。
5. 按终版结构输出：目标、问题背景、依据、最终判断、最小整改清单、不做事项、执行顺序、验收口径、结论。
6. 如需落盘，按 B02 先备份目标，再写入系统治理子项目，并同步 `目录.md`、`版本记录.md` 与 B03 记忆。

## 什么时候再读本 skill 的 references

- 每次产出系统治理方案时，都读 `references/方案写作规范.md`。
- 当用户要求模板化终版、重写既有方案或压缩冗余内容时，使用 `assets/系统治理方案终版模板.md`。

## 边界

- 不复述初版方案、重评估过程和无关历史。
- 不把业务子项目的逐项修复清单写进骨架整改范围，除非用户明确要求。
- 不把 output 中的方案、问答、研究文档当作标准源。
- 不为了显得完整而扩大整改范围；能闭环的问题只列最小闭环。
- 不要把稳定业务真相直接塞进 `SKILL.md`。
