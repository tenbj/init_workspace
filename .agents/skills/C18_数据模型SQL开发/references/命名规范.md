# 命名规范与依据

## 表名确认与改名的统一流程

核名、用户确认、发布交接和改名同步遵循工作区 `.agents/rules/model-sql-naming-rules.md`。正式交付前保存开发材料 `表名确认.json`；逐段列明库/层/域、业务过程及来源标签、更新方式和频率依据，保留用户明确确认原意及日期。交给C19时提供该记录路径，不能将“沿用既有目标”或机械复用ODS名称代替确认。

已确认的名称不重复询问；用户新纠正覆盖旧建议。改名要同步全部当前产物与生成器，保留旧回执真实哈希和源ODS名称；频率获用户确认后仍区分尚未部署的具体调度时间。

## 先查规范再命名

当前工作区依据（均相对工作区根目录）：

1. `input/权威资料/06 数据开发规范/03 数据资产建设-表规范_v1.0.md`：DWD 表命名及更新方式、频率。
2. `input/权威资料/0 数据规范/0. 数据开发规范与最佳实践.md`：标识符、视图、外表、脚本与表同名。
3. 原始表规范工作簿：`input/01 数据架构与标准/02 数据开发/03 数据资产建设-表规范.xlsx`。

先核对当前文件，不把本分册当成独立标准库。原文件缺失时查找对应权威规范；未找到则说明缺口，不编造已确认规范。规则与本次用户明确要求不一致时列出差异并遵循用户要求。

## 最终字段必须独立核名

表名与最终字段分别审核。开发或迁移模型时，按 E03 读取实际标准库及全部字段的中文含义、来源和计算表达式，形成逐字段建议与依据；记录标准库路径、哈希及旧名到新名映射。用户已要求落地字段修正时，同步实施，不把 E03 默认只提建议误当作再次确认要求。

- 保持原计算口径、类型和字段顺序，不等于必须保留原字段名。CamelCase 转小写只是格式步骤，不能替代语义审核。
- 数量、记录数、金额、天数分别按实际单位命名；旧名中的 Purchased/Unpaid/Quantity 等也可能与计算含义不符，必须回到来源与公式确认。
- 按 E03 区分当前字段和参考字段；合规 DWD 参考字段可作为沿用依据，DWS 来源已有名称不能直接照抄。涉及 DIM 同义属性和用户明确例外时，按下节优先级裁决，不能以“参考表不是 DWD”跳过 DIM 核名。
- 标准已定义的词根优先；新增短词根明确标为建议，不伪造标准命中。不把文本分类名称机械加上编码后缀，不在未转换数据时把文本标记改成布尔字段名。
- 修正后同时核对 CREATE 字段及排序/分布键、DELETE 范围键、INSERT 显式列、最终 SELECT 别名、字段 Excel、交付说明和生成器。中间 CTE 可保留旧别名用于溯源，但最终投影须规范。
- 保存改名前后差异，证明只改命名和格式时表达式不变。新文件没有重新执行数据库验证，就明确“离线检查通过”，不沿用旧哈希宣称本版实跑成功。
- 数据库或网络异常、用户暂停实跑时，复用已有证据完成离线修改并记录验证缺口，不重复连接。

## DIM 同义字段优先与人工命名例外

适用于新开发、迁移和修订模型的全部最终输出字段。字段命名按以下顺序裁决：

1. **用户最新明确的字段映射或命名例外**：在其指定模型和字段范围内执行，覆盖较早建议和默认 DIM 同名规则；已经确认的映射直接落地，不重复索要确认。
2. **实际 DIM 的同义字段名**：业务含义、属性角色和粒度一致时，沿用 DIM 中真实存在的完整字段名。不能另造缩写、同义词或另一套分类层级名，也不能为命中词根库把它改回其他名称。
3. **标准库与来源语义命名**：没有对应 DIM 属性的事实、审计或其他字段，继续按实际标准库、来源表达式、单位和业务含义核名；无标准命中才标为建议。多个 DIM 对同一语义命名不同且无法确定权威对象时，先查关联链路和适用范围，仍有歧义则列出差异再确认，不静默挑选。

### 先确认同义，分别判断名称与取值来源

- 查对应 DIM 的真实结构、字段说明和必要的加工来源；优先复用仍适用的已保存证据，按需通过 C03/C02 补证，保存表名、证据文件及核查日期。未查到不能宣称“与 DIM 一致”。
- 只有同义属性才沿用同名。相似字符串、部分样本相等、同一源表归属，都不能单独证明同义；单据编号与订单编号、长宽高与尺码、销售组织与供应商等须按实际业务角色区分。
- **字段命名与取值来源分别确认**：源字段按 DIM 同义名输出，不代表改为取 DIM 值。仅修正名称时保留已确认的来源表达式、类型、单位和口径；若需切换来源，另有口径依据并验证影响。
- 来源的版本编码与 DIM 的 SKU 编码等不同角色可以同时输出，分别命名；核查最终别名唯一性，不把不同值域合并成一个字段。用户要求不冗余某个 DIM 描述时，核对已有同义输出和来源，只删除明确的重复项，不据此推断删除其他源字段。

### 全字段复核与例外台账

用户指出任一命名问题，或提出“按 DIM 名称优先”时，检查**全部最终字段**，不只修改举例字段。开发材料保存逐字段对照，覆盖数必须等于最终字段数；每行至少列出来源表达式、原名、最终名、语义/角色、对应 DIM 字段与证据、采用理由。没有对应 DIM 的字段也须说明其属于事实、不同语义、键或审计等哪一类，不能漏审。

存在人工例外时，在模型开发材料单独维护 `字段命名例外.json` 或等价可回读表，至少记录：适用模型、源字段/表达式、相关 DIM 字段或默认建议、最终名称、用户确认依据及先后关系、例外原因。正式说明摘要引用该台账；无例外不强制造空文件。后续修订复用最新确认，历史建议保留为历史，不能重新覆盖当前映射。

规则优先级通用，具体字段映射只在确认范围内有效。不能把一个模型的 `ASIN`、`ProductNo` 等特殊映射变成所有模型的默认词根或永久例外；复用时重新核对业务含义和用户指令。

落地后同步 DDL、键及目标引用、DELETE 范围键、INSERT 列、最终 SELECT 别名、两份字段文档、交付说明和生成器；保存名称与表达式差异，区分离线一致性检查与最终版本实际执行证据。完整交付及验证边界仍按输出契约，不因改名省略检查，也不擅自新增数据清洗或切换维度关联键。

## DWD 结构

`业务域.dwd_数据域_{数据子域}_业务过程or实体_{自定义标签描述}_更新方式_更新频率`

花括号段为可选。库名不放进文件名；标识符使用小写字母、数字及下划线，字母开头。业务域、数据域和业务实体依据源模型、词根及用户口径确定，不凭前缀臆断。

| 更新方式 | 含义 | 判断依据 |
|---|---|---|
| ilu | 增量保留最新 | 仅更新受影响记录或范围，保留其他数据 |
| flu | 全量保留最新 | 每次替换全表最新结果 |
| ich | 增量保留历史 | 按变化保存历史版本或拉链 |
| fsn | 全量保留历史 | 定期保存全量历史切片 |

频率依据实际调度：`dd` 每日、`hh` 每小时、`2h` 每两小时、`30min` 每半小时、`mm` 每月、`rt` 实时。周报粒度不代表任务频率为周。不能仅因 SQL 有日期参数就判定 ilu；应检查目标写入语义。首次运行同一增量 SQL 覆盖全量不改变日常 ilu 分类。

实际数据库视图使用 `v_` 前缀；业务名称包含 `view` 不足以判定为数据库视图。外表后缀 `_fgn`。对象类型与 DDL 一起核对。

## 文件路径约定

- 加工 SQL：`{规范表名}/{规范表名}.sql`，规范表名不含库名。
- 不追加 `_delete_insert`、`_full_load`、`_final`、日期或版本号；更新策略在 SQL 中文注释和说明中表达。
- 建表作为单独交付角色，可在同目录使用 `create_{规范表名}.sql`。
- 修正名称时同步 CREATE、DELETE、INSERT、目标引用、目录、文件名、字段 Excel 和当前交付说明；生成器要能复现新名称。
- 历史原版和历史查询证据保留原貌；当前说明明确其属于历史，不能让旧名称重新进入正式交付。
