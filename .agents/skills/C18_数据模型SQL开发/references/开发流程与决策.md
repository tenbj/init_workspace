# 开发流程与决策

## 输入和溯源

收集目标对象、源表、参考加工、执行引擎、调度参数、粒度、业务键、来源优先级、单位、审计时间及交付要求。能从源码、DDL、已有确认和证据得到的信息不再反问。

先解释参考模型实际路径：源数据 → 时间范围 → 身份映射 → 字段对齐 → 冲突选择 → 目标写入。按实际依赖追溯到足以解释关键行为，避免遍历无关仓库。核对 JOIN 基数、过滤前后粒度及去重顺序，不只读最后 SELECT。

设计对齐表包含事项、现有逻辑、目标方案、证据、待确认项。更新策略、源优先级、跨年归属、比例单位、主键及审计语义等实质变化与用户确认；既有确认沿用。等待答复时继续独立查询和验证设计。

## 证据约束与最小表达式

设计 Doris 实体表前执行 [Doris实体表设计与实跑验收](Doris实体表设计与实跑验收.md)：先核验 INSERT 结果粒度与业务键，再选主键模型或有证据支持的明细模型；落实 decimal、文本、可空、MD5 和三个审计时间规范。

额外转换必须能回答：哪个字段、源类型、实际异常或契约、目标类型能否直接接收、为什么需要该表达式。

| 情况 | 原则 |
|---|---|
| 源类型与目标兼容 | 优先原值；不先一律 CAST AS STRING |
| 数值来自文本 | 明确转换、精度与舍入，验证实际引擎；建表约束不自动证明转换安全 |
| 未发现逗号或百分号 | 不默认增加去逗号、去百分号和重复正则 CASE |
| 实际空串 | 区分 NULL、空串、全空白；结合目标可空性和严格写入模式决定 NULLIF 等处理 |
| SELECT 转换成功 | 只证明查询语义；不能宣称严格 INSERT 或隐式赋值必然成功 |
| 比例 | 按来源契约统一单位；34 与 0.34 的映射须有依据，不用大小自动猜测单位 |
| 用户质疑必要性 | 复查真实样本、DDL及引擎行为，说明原动机和证据强弱，不迎合性推翻 |

真实案例附只读 SQL、统计口径、范围及原值。无结果如实写“本次范围未发现”。合成 `1,234`、`34%` 只验证假设，不能冒充源记录。必要时查询官方引擎文档并记录版本；引擎未知时不武断规定行为。

只保留帮助复用或阅读的 CTE，不为每个转换增一层。中文注释解释分段目的、参数和特殊业务判断，不逐行翻译 SQL。不修改引擎参数来掩盖数据问题。

## 多源合并与关键字段

- 分开确认字段结构以谁为准、同业务键冲突谁优先；整行优先与逐字段补空不同。
- 去重排序稳定且可解释；同时间冲突要明确决胜键，不随机取行。
- 身份映射检查历史、停用、未映射、一对多及大小写，防止关联放大。
- 业务键、技术唯一键、删除范围键分别定义；缺失身份或周期不能简单合成一个未知键。
- 哈希定义字段顺序、NULL、分隔和转义，避免简单拼接歧义。需要 scope_info 时展示实际哈希输入，验证 MD5(scope_info)=scope_key；不另造一套近似拼接。
- 日期按来源分别处理，不改写已确认保留的历史源值。
- 审计字段与写入行为一致；先删后写取 NOW 表示本次范围重写时间，不能声称保留历史首次时间。

## 增量先删后写

1. 源更新时间窗口决定受影响范围，DELETE 不重复整份指标清洗和宽表投影。
2. 同一表达式计算 scope，删除范围内全部旧行，包括已消失的排名或关键词。
3. 回读范围的完整有效源记录并重算，不只写窗口更新行而丢掉未更新成员。
4. 删除、写入使用相同参数、范围和稳定来源；空范围不删任何行。
5. 明确事务能力、失败重跑、并发约束；未验证原子性时说明两步可能有空窗。
6. 源物理删除、维度变化但无源更新时间事件能否触发范围，必须说明。

## 首次加载复用同一 SQL

逐源使用加工实际时间表达式查 MIN、MAX、NULL 数和记录数；使用 COALESCE 时不能用各列 MAX 代替。核对时区及闭区间/半开区间，与参数转换一致。

证明参数能触发全部应加载范围；NULL 时间记录可能随同范围其他记录覆盖，也可能完全遗漏，需用范围证据判断。仅有 MIN/MAX 不等于全量覆盖。

首次参数、核查日期、源表达式和覆盖结果写入说明；首次与日常共用加工 SQL，不另交 full_load.sql，不凭空增加运行模式参数。只有现有 SQL 确实无法覆盖且用户认可独立策略时才例外处理。历史上界不能永久作为未来首次上界。

## 验证和收敛

八类清单先设计后执行，区分合成输入/预期与真实结果。校验最终 SQL，不只测试独立公式。新旧比较采用同一来源快照、窗口、多重集，避免 DISTINCT 掩盖重复；运行时钟字段另验。

Doris 查询可执行性按实体表分册第5节验收：从当前正式文件提取完整查询，通过 C02 返回全部投影列，留存版本、日期范围、行列数与错误；仅 COUNT 或 EXPLAIN 不替代此步骤。

必要检查通过后不无故扩测。新变化、失败和未解决问题才触发额外检查。注释或命名变化可用词法等价和引用检查证明业务逻辑未变，明确未重跑生产写入。复用查询结果记录 SQL 哈希、时间和范围，不能给旧结果换新日期。
