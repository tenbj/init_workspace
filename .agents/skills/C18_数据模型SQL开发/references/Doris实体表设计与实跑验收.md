# Doris实体表设计与实跑验收

本分册固化本工作区用户确认的模型开发规范。适用于新建、迁移及重构 Doris 实体表；明确的用户要求优先。输入已存在的存量 DDL 不因本规范而自动获得变更授权。具体业务域、日期、键字段和核验行数仍须逐模型确定，不能照搬某次交付。

## 1. 先核验结果粒度，再选存储模型

1. 核验对象是拟交付 INSERT 后的完整查询结果，包含实际 JOIN、过滤、聚合及已确认去重；源表键唯一不代表结果键唯一。
2. 复用 C11 的证据方法：说明每行代表什么、候选业务键字段及含义，统计结果总行数、按候选键 GROUP BY 的组数、重复组数、键 NULL/空串/空白及冲突样例。这里应用到结果集，不改写 C11 对原始 ODS 表的结论。
3. 选择有业务解释且稳定的唯一组合。校验充分的日期范围和真实重复案例，不凭几行样例宣布全量唯一；网络不可用或用户暂停时记录“未验证”，不得默认改用明细模型。
4. 有唯一业务键时，以 `unique_key` 为实体主键，采用 `UNIQUE KEY(unique_key)` 主键模型。分别比较原结果行数、业务键组数、技术键去重数，要求一致；预期归并丢行数为 0。
5. 只有确认没有稳定唯一业务键、且主键模型会归并减少应保留的结果行时，才使用明细模型，并给出重复样例及预期丢行数。一个候选键失败不等于没有业务键；不能用额外 DISTINCT、随机值、ROW_NUMBER 或审计时间伪造业务唯一性。

模型结论、核验范围、业务键与技术键分别写入说明；已确认业务键按 C11 生成独立唯一性检验 SQL，生成或只读核验不代表部署或配置到平台。

## 2. 技术主键遵循现有代码惯例

先读取 input 中同域或同类模型的真实代码，记录参考文件和表达式。标准形式为：

```sql
md5(concat_ws('|', 业务键字段1, 业务键字段2, 业务键字段3)) as unique_key
```

- 固定业务键字段顺序，沿用已确认的原值口径；不擅自换 SHA256、JSON 编码、分隔符或自动清洗。MD5 的32位输出仍按主键文本规范声明 `varchar(255)`。
- 核验 NULL、空串、空白、字段内 `|` 及日期/数值的文本表示；考虑 CONCAT_WS 的 NULL 行为。不能把拼接不同含义的键或缺失身份默认为同一实体。
- 比较业务键组数、拼接值去重数、MD5 去重数及空键数，验证当前范围无编码归并；这不等于数学上保证所有未来哈希无碰撞。
- 若有分隔歧义或缺失键，先按业务和已有代码确定缺失处理或无歧义编码方案，并说明相对默认规则的差异；不能静默换算法掩盖问题。
- 三个审计时间不参与业务键、技术键或原业务结果 DISTINCT。

## 3. 类型、可空与最小转换

| 对象 | 规范 | 必要证据 |
|---|---|---|
| 小数 | 优先 `decimal(18,6)`，不因源为 DOUBLE 或聚合类型较宽就沿用 `double` / `decimal(38,6)` | 最终表达式范围、整数及小数精度、最大绝对值、转换前后 NULL 数和舍入差异 |
| 文本实体主键 | `varchar(255) NOT NULL` | 实际长度及非空；不截断键 |
| 其余文本 | `string NULL`，不用 `text` | DDL、Excel和说明使用同一类型 |
| 其他非主键字段 | 全部允许 NULL，包括业务键原字段、日期、数量、金额和审计时间 | 不能因当前样本无 NULL 就加 NOT NULL；业务键完整性另做质量核验 |
| 审计字段 | `datetime(3) NULL` | 三列名称、顺序、赋值口径一致 |

`decimal(18,6)` 不够时才依据实测范围或已确认业务容量采用更高精度，并解释原因；不能用“保险”替代画像。针对目标转换统计失败/溢出、新增 NULL、舍入影响和代表行。现有数据可容纳不代表未来永不超界；确需近似浮点的业务须给出明确依据。

最外层 SELECT 不机械地全字段 CAST。逐字段判断源表达式类型与目标是否一致、目标赋值是否安全：兼容且无需改变语义时直接输出；文本转数值、decimal 精度收敛或必要日期转换才显式转换。中间计算需要更高精度时保留，只在有依据的边界收敛；移除冗余 CAST 不等于删除全部 CAST。SELECT 成功不能替代实际 INSERT 类型赋值验证。

## 4. 三个审计时间

按现有模型代码补齐以下字段，同步 DDL、INSERT 显式列、最终 SELECT 与字段文档：

| 字段 | 类型 | 常用范围重写赋值 |
|---|---|---|
| first_inserted_dt | datetime(3) NULL | now() |
| etl_dt | datetime(3) NULL | now() |
| last_updated_dt | datetime(3) NULL | now() |

上述赋值用于已确认的 DELETE 后 INSERT 范围重写方案，表示本次重写时间，`first_inserted_dt` 也会重置，不能解释为保留历史首次入库时间。若业务要求保留首次时间，须设计并验证相应保留机制，不套用全部 NOW。以源创建/更新时间赋值也须有来源证据。运行时钟放在原业务去重之后，避免影响业务结果集合；核验审计字段非空及已约定的一致性，重跑比较业务列时排除预期变化的运行时间。

## 5. 必须验证最终文件的查询部分

1. 从当前正式加工 SQL 现场提取 INSERT 后完整 WITH/SELECT，不重新手抄一份近似查询；保证没有 DELETE、INSERT 或其他写语句，并替换全部参数为真实值。
2. 使用 C02 在目标 Doris 执行。至少选有数据的代表范围取回全部投影列的结果；合理控制日期和客户端行数上限，并记录是否触及上限。空结果只能证明本次空范围执行情况，不能替代字段值计算核验。
3. 核验返回字段数量、顺序、主键和审计字段；另按需要对完整业务范围做行数、业务键及类型画像。EXPLAIN、纯 COUNT 汇总、旧版回执或几列样例不能单独证明本版全部 SELECT 字段已执行成功。
4. 保存源文件路径、源文件及执行查询哈希、参数、执行时间、耗时、实际执行 SQL、行列数、错误及样例。说明是小样例、完整单日还是全范围；客户端追加 LIMIT 要如实记录，触及上限不得称完整取回。
5. 文件字节哈希与统一换行后的文本哈希分别标注，前后比较使用相同编码/换行口径。最终 SQL 有变化时判断旧证据是否适用；不能给旧结果换新日期或声称修改后的版本已实跑。
6. 用户明确暂停网络核验时停止重复连接，继续已授权离线工作，列明未验证项；用户随后要求实跑时按新请求恢复。必要核验通过后不无故重复执行。

只读 SELECT 成功证明所记录版本和范围的查询可执行，不等于 CREATE、DELETE、INSERT、严格写入、事务、权限或并发已经验证；交付 SQL 不构成生产写入授权。

## 6. 格式、命名与成套交付衔接

- SQL 零空白行，WITH 后续 CTE 逗号前置且注释在 CTE 名称行之前，详见输出契约。
- 表名和最终字段按 E03 及实际标准库核名；域缩写须有依据并能解释，不能把本次 `mfg` 或表名复制成其他模型默认域。
- 默认补齐 CREATE、加工 SQL、字段 Excel 和说明。“不考虑分区替换”不免除落表交付；有参数不自动等于增量，DELETE 与回写范围必须一致。
- 用户要求“新开一套、保留这套”时建立独立新交付目录，旧套原貌保留并用文件清单/哈希核对；新套生成器、文档、Excel和证据指向新路径。
- DDL、DELETE 范围键、INSERT 列表、SELECT 别名/顺序、类型、NULL、三个审计时间、Excel和说明同步检查。不得只修改 SQL 而留下旧文档或由生成器重新生成错误版本。
