# C18_数据模型SQL开发

## 这项技能解决什么问题

- 将模型需求、参考 SQL 和源数据转为可验证、可重跑的加工 SQL。
- 适用于多源合并、新旧数据衔接及已有模型重构；简单格式调整无需启动完整流程。
- 将正式交付与开发证据分开，首次加载和日常更新尽量共用一份参数化 SQL。

## 先读哪些本地知识

- 按工作区入口完成话题定位、进度记录及修改前备份。
- 开始设计先读 `references/开发流程与决策.md` 和 `references/命名规范.md`；命名依据回到其中列明的 input 原始规范。
- 开发 Doris 实体表时必读 `references/Doris实体表设计与实跑验收.md`；在选模型和编写 DDL 前落实结果粒度、业务键、类型、可空及审计规范。
- 设计验证前读 `references/八类验证清单.md`；交付前读 `references/输出契约.md`。
- 已有口径和证据优先复用，避免反复确认、重复查询及无关检查。
- 对接平台建模时必读 `references/平台建模交接.md`，开发阶段生成可导入六列字段文件、命名及上游/日常参数合同，平台执行路由 C20。

## 固定动作

1. 定位目标、源表、参考模型及运行引擎，核对表名、最终字段命名、更新语义和频率；按 E03 使用实际标准库逐字段审核，不能因迁移需保留公式就沿用旧字段名；加工路径固定为 `{规范表名}/{规范表名}.sql`。
2. 识别参考 SQL 主线，按实际依赖追溯粒度、关联、范围、去重及审计时间；先给出理解和差异再实现。
3. 同时设计验证清单与样例，标记真实证据、合成样例和未知项；按 C11 方法核验 INSERT 查询结果的粒度与业务键，先证明主键模型不丢行再定模型，不能只看源表主键；影响结果的口径与用户对齐。
4. 按证据选择最小必要转换，完成建表和参数化加工 SQL；SQL 中间说明、表及字段注释使用中文，文件中不留空白行，WITH/CTE 采用输出契约规定的逗号前置格式；同步 DDL、DELETE 键、INSERT 列表、最终 SELECT 别名和字段文档。
5. 核验删除与回写范围、源优先级、主键及字段一致性；从最终加工文件提取 INSERT 后的完整 WITH/SELECT，替换真实参数，通过 C02 实际执行并记录返回行列、错误、范围和文件哈希；首次参数按实际时间表达式求源全量范围并证明覆盖。
6. 按输出契约生成精简正式交付，运行本技能本地校验；记录执行过的验证和未覆盖项。
7. 同步交付说明、字段文档、任务状态与记忆，回复交付入口和关键限制。

## 边界

- Doris 实体表默认小数 `decimal(18,6)`；主键文本 `varchar(255)`、其余文本 `string`；仅实体主键 `NOT NULL`。已验证业务键生成 `md5(concat_ws('|', ...)) AS unique_key`，采用 `UNIQUE KEY(unique_key)`；明细模型必须有无唯一业务键且主键模型会丢行的证据。
- 参照现有模型补 `first_inserted_dt`、`etl_dt`、`last_updated_dt` 三个 `datetime(3) NULL` 审计字段并明确赋值含义；最外层不全字段 CAST，仅保留有类型或语义依据的必要转换。详细例外条件见实体表分册。
- 生产查询复用 C02，源 DDL 复用 C03；不自行新建生产连接或执行生产删写。必要沙盒写入按 C04 的授权和边界处理。
- 实体表选模型前按 C11 方法核验结果粒度；按需复用 C12/C16 溯源、C06/E05 字段文档；单 ODS 初稿可复用 C05/C07，额外报告按需调用 C10。
- 不把本次 CK/PG 优先级、报表年算法或除 100 规则当成通用默认值。
- 不因假设脏数据而增加清洗；不因用户质疑而删除有证据支持的必要处理。
- 生成 SQL 不等于授权执行生产 DDL/DML；未执行的检查不得写“通过”。
