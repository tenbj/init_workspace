# 环境与异常处理（条件触发）

本文件仅在相应异常出现时加载。正常发送复用已有工具、身份和网络；不要为了执行通知再次安装、扫码或更改 Clash。

| 条件 | 最小处理 |
|---|---|
| 找不到 dws | 检查调用方配置、PATH 和已知本机安装位置；不要搜集无关凭证。确实缺失才按官方发布安装并验证版本/校验和 |
| 命令/参数不支持 | 查看本机 help/schema；官方文档或版本确需更新时再升级，不盲目更换整个工具链 |
| 未登录或无法续期 | 先官方 profile/status 检查；使用正常刷新机制，刷新失效才发起一次登录并等人工授权 |
| 多组织/多账号 | 根据实际 profile list 精确选择，不能用另一组织凭证绕过资源权限 |
| 组织未开通 CLI/权限不足 | 说明管理员需开启的具体能力，等待已授权组织管理员处理；不扩大授权范围 |
| EOF/TLS/超时 | 区分网络与业务失败；只读 doctor 和代理规则/链路核对；结果不明时先保留发送状态，禁止重复消息 |
| 401 | 按认证问题处理，不用修改代理“修复”已撤销令牌 |
| 请求已接收但状态待定 | 继续查真实任务 ID，不重复 send |

## 本机配置与安装

工具入口允许明确 `--dws <可执行文件>` 或 PATH；如需要配置文件，保存在调用方已确认的本机私有位置，仅放可执行路径和 profile selector。不要在 Skill 写入令牌、代理凭据、私人账号 ID、固定用户目录或一次性运行端口。历史案例目录中的便携版只可作为当前机器发现线索，不作为通用依赖。

官方来源：[DingTalk Workspace CLI](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli)。安装时核对当前操作系统架构、发布版本及官方校验；不以本案例 v1.0.63 永久锁定“最新版”。版本变化时读取 help/schema，不猜参数。

使用官方安全凭证存储及刷新令牌。不能承诺永久授权：访问令牌可自动续期，刷新令牌仍有有效期，并可能被用户或组织撤销；失效后才需要再次授权。授权完成后继续原任务，不创建多组同时等待的授权流程。

## 示例组织A 与好友边界

本案例已验证：示例组织A 已开通 CLI，发信用户可向仅在示例组织B组织、但与本人是好友的正式联系人发送个人私聊；也已向测试联系人实际发送成功。这只是特定账号和好友关系的证据，不意味着拥有示例组织B组织通讯录或跨组织历史读取权限。不可因发送失败就申请所有组织消息读取或创建额外组织。

## 仅在网络异常且确需调整时处理 Clash

第一选择是只读检查；不要把改网络当作日常发消息的前置步骤。任何持久配置调整应有明确授权。若用户授权新配置测试，按以下最小流程：

1. 识别当前配置、原始源文件、增强项、实际主核心规则、DNS/TUN 和健康基线。完整配置可能有代理密码，备份存应用私有原目录，不复制到项目交付或日志。
2. 保留已验证可用的原配置，复制独立新配置，按实际端点增加精确规则。已出现的 CLI 域名包括 `login.dingtalk.com`、`mcp.dingtalk.com`、`aihub.dingtalk.com`、`mcp-gw.dingtalk.com`。这些是本案例证据，今后以实际 CLI 端点为准，不无限扩大 DOMAIN-SUFFIX。
3. 全量语义对比应只有授权规则变化；不顺便改内网 DNS、TUN 排除、默认代理、系统设置或证书校验。
4. 先独立核心验证：测试核心关闭 TUN、独立 localhost 端口，必要时绑定实际物理网卡避免现有 TUN 污染测试。CLI 代理变量仅用于该子进程，不覆盖全局环境。
5. 隔离验证应覆盖 GitLab 页面及仓库读取、Doris 连接/协议握手、钉钉已授权只读业务、OpenAI 入口；核对实际规则命中。Doris 握手不能冒充 SQL 查询，OpenAI 入口不能冒充账号登录成功。
6. 通过 Clash 正常本地导入流程加入新配置；在可接受切换网络的时机由用户正常切换，随后做真实主 TUN 验收。此技能不使用 Codex 视觉、鼠标、键盘或剪贴板自动化作为修复手段。
7. **禁止为了几条规则，直接向主核心 PUT 整份 payload 或覆盖当前生成配置。** 撤销只针对当前任务和匹配配置；如果用户同时切换了配置，停止恢复，先重新核对身份及差异，不能把旧备份覆盖到新选择上。

代理规则恢复、文件恢复、真实网络恢复分别留证。未切回实测不能声称 TUN 已恢复；没有故障瞬间证据，不能把 DNS 缓存或路由竞态猜测说成确定根因。

## 锁屏与输入设备

正常 dws CLI 不需要前台窗口、鼠标、键盘或剪贴板，进程已运行且机器联网时可在锁屏场景工作；睡眠、断网和失效授权仍会阻断。既有测试证明后台发信，不包含一次完整锁屏实测；需要锁屏验收时单独安排，并通过 CLI 回执验证，不绕过锁屏策略。
