# 工作区适配与避坑守则

本分册承载 `J01_HyperFrames视频制作` 针对当前工作区与 Windows 环境的专属约束；当上游英文 Skill 细则与本工作区制度冲突时，以本守则与工作区 SSOT 为准。

---

## 一、工作区落位与治理约束

1. **子项目归属（`B04`）**：
   - 开始制作新主题视频前，先定位已有子项目或通过 `B04` 创建对应子项目（如 `output/NN_<主题>/`）。
   - 具体视频工程统一创建在 `output/<子项目>/03_代码程序/<纯英文短名>/`（如 `promo-v1`），**禁止直接写入 `output/` 根目录**，也不要直接放进 `output/50_HyperFrames网页视频/03_代码程序/hyperframes` 源码仓内部。
   - 该目录属于 `03_代码程序/`，按 `workspace-spec.json` `backupPolicy` 免 `B02` 备份；但配套的剧本说明、复盘文档若写入 `01_问题答疑/` 或 `02_课题研究/`，修改前仍需按 `B02` 备份。
2. **凭据边界（`B12`）**：
   - 任何 API Key（如 `HEYGEN_API_KEY`、`GEMINI_API_KEY`）不得写入 `SKILL.md`、HTML 源码、记忆或报告；需持久化时按 `B12` 规范管理。
3. **进度与记忆（`B08` / `B03`）**：
   - 多步视频制作任务（编剧 → 素材 → 预览 → 渲染）必须在开始时建立 `B08` 任务进度，并在故事线确认、预览验收与最终出片前写 checkpoint；完成后通过 `B03` 沉淀摘要。

## 三、Windows 与中文视频实操避坑

1. **前置依赖核查**：
   - 必须具备 **Node.js `>= 22`**；
   - 本地 `render` 必须具备 **FFmpeg**（未安装时提示 `winget install Gyan.FFmpeg` 后重开终端，或临时改用 `npx hyperframes render --docker`）；
   - 若无头 Chrome 缺失，执行 `npx hyperframes browser ensure`。
2. **Apple Silicon（Mac MLX）工具在 Windows 不可用**：
   - 上游 `media-use` 文档提到的本地生成工具 **`mflux`（FLUX 生图）**、**`ltx-2-mlx`（本地生视频）**、**`parakeet-mlx`** 属于 Apple Silicon MLX 生态，在 Windows 上不能作为开箱即用的本地替代。
   - **Windows 本地替代策略**：画面优先用「代码原生动效 + 网页抓拍 + 用户自有素材 + 免费图库」；语音转写使用 Windows 支持的 `npx hyperframes models install parakeet` 或 whisper；中文免费配音优先用真人录音、免费 HeyGen 3 分钟额度或本机免 Key 的 Edge TTS 导出 MP3 后放入 `assets/`。
3. **中文语音转写参数红线**：
   - `npx hyperframes transcribe` 默认使用 `small.en` 模型，会**把中文语音强行翻译成英文**！
   - 处理中文语音必须显式传 `--model small --language zh`（或更大模型），并按中文无空格特点人工/脚本核对断句与简繁字形。
4. **PowerShell JSON 传参避坑**：
   - Windows PowerShell 直接传递内联 JSON（如 `--grading '{...}'`、`--vars '{...}'`）会被吞掉双引号导致报错。
   - 一律将 JSON 写入临时文件传入文件路径，或通过管道 `--grading -` 传入。
5. **遥测与隐私边界**：
   - 上游 `SKILL.md` 中的 `npx hyperframes events --skill=...` 与 `feedback` 属于官方使用量遥测；在本工作区中**默认跳过不静默上报**，除非用户主动允许。
