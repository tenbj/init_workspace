# 输出契约

本文件定义 `J01_HyperFrames视频制作` 在执行视频制作、编辑或复刻任务时的交付物、落点与验收底线。

---

## 一、输出物分类与标准落点

所有产物均落在通过 `B04` 定位的目标子项目内（设 `<PROJECT>` = `output/<子项目>/03_代码程序/<纯英文工程名>`）：

| 产物类别 | 标准路径 | 说明 |
|---|---|---|
| **最终件（成片）** | `<PROJECT>/out.mp4`（或用户指定的输出文件名） | 经 `render` 导出的确定性 MP4，需非空且时长/分辨率与根合成一致 |
| **最终件（可编辑工程）** | `<PROJECT>/index.html`、`compositions/*.html`、`assets/` | 明文 HTML 时间轴工程与冻结本地素材，支持后续人机继续局部微调 |
| **中间件（编剧与规格）** | `<PROJECT>/STORYLINES.md`、`SPEC.md`、`REVIEW.md` | 叙事片（>15s）的 3 套故事线、帧级规格与抽帧复审记录 |
| **中间件（质检截图）** | `<PROJECT>/.hyperframes/artifacts/snapshots/*.png` | `snapshot` 生成的关键帧验证图，供 AI 与用户视觉验收 |
| **中间件（素材台账与历史）** | `<PROJECT>/.media/manifest.jsonl`、`.hyperframes/` | 素材来源台账与可撤销编辑历史（禁止手工删除 `.hyperframes/`） |
| **说明文档（按需）** | `output/<子项目>/01_问题答疑/` 或 `02_课题研究/` | 如用户要求沉淀分镜文案、制作复盘或架构说明时落盘并同步 `目录.md` |

---

## 二、交付前必过验收清单

1. **静态与运行时检查**：`lint` 与 `check --json` 无未解决 `error`。
2. **视觉看图验收**：至少对每个核心场景中点执行 `snapshot` 并人工/AI 核验无文字截断、无黑屏、无元素错位。
3. **成片媒体核验**：若已执行 `render`，确认目标 `.mp4` 存在且文件非空；如有 `ffprobe`，核验实际时长、分辨率与音频轨存在。
4. **费用透明度**：如本轮涉及任何 L1 免费登录额度或 L2 付费积分操作，向用户如实汇报消耗路径。

---

## 三、最终回复必须说明

- 目标视频工程目录路径与最终成片路径（若停在预览阶段，给出 `preview` 本地访问地址）。
- 本轮使用了哪些上游子 Skill、采用了哪一层级素材资源（L0 零元本地 / L1 免费登录 / L2 授权付费）。
- `lint`、`check`、`snapshot` 与（如已渲染）成片校验结果。
- 后续如何微调（直接告诉 AI 改哪一秒/哪句话，或重新执行 `npx hyperframes preview`）。

---

## 四、失败边界

- 未定位到上游 `skills/` 包或缺少运行依赖（Node < 22 / 既无 FFmpeg 又未走 Docker/云端）时，明确报告阻塞点与修复命令，不得伪造渲染成功结果。
- `check --json` 存在未修 error 或成片未实际生成/为空文件时，不得宣称成片已交付。
- 不得把 API Key、登录凭据写入任何工程文件、日志或回复。
