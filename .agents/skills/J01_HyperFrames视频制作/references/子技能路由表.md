# 上游 HyperFrames 子技能路由表（方案 A 薄桥接）

> 本 Skill 采用「薄桥接入口 + 原样保真引用上游完整 `skills/`」架构。上游 9 个官方 Skill 合计 343 个文件、122 个可执行脚本，内部通过相对路径与 `hyperframes/scripts/plugin-cli.mjs` 强耦合，**必须保持上游原目录结构完整，不得拆散或改名**。

---

## 一、上游完整 `skills/` 目录解析顺序

执行任务前，按以下优先级定位 `<UPSTREAM_SKILLS>`：

1. **首选（本工作区已克隆的官方源码仓）**：
   `output/50_HyperFrames网页视频/03_代码程序/hyperframes/skills`
2. **备选（用户通过官方 CLI 全局安装的技能目录）**：
   运行 `npx hyperframes skills update` 后写入的用户级技能目录（如 `~/.agents/skills/`、`~/.claude/skills/` 中包含 `hyperframes/scripts/plugin-cli.mjs` 的目录）。
3. **缺失处理**：若上述位置均未找到 `<UPSTREAM_SKILLS>/hyperframes/SKILL.md` 与 `plugin-cli.mjs`，立即停止视频制作流程，提示用户任选其一恢复后继续：
   - 克隆仓库到子项目：`git clone https://github.com/heygen-com/hyperframes.git "output/50_HyperFrames网页视频/03_代码程序/hyperframes"`
   - 或全局安装官方核心技能：`npx hyperframes skills update`

### CLI 统一调用约定
上游文档中写到的 `npx hyperframes <command>`，在桥接模式下优先通过上游启动器在**目标视频工程目录**内执行（保持与上游 `CLI_FLOOR` 安全校验和版本策略一致）：
```powershell
node "<UPSTREAM_SKILLS>/hyperframes/scripts/plugin-cli.mjs" <command>
```
或直接在本机已安装 Node 22+ 的环境下于目标视频工程目录运行 `npx hyperframes <command>`。

### 上游版本升级方式
因为本 Skill 只做薄路由，升级上游能力无需修改本工作区核心骨架：
- 若使用源码仓：在 `output/50_HyperFrames网页视频/03_代码程序/hyperframes` 执行 `git pull`；
- 若使用全局安装：执行 `npx hyperframes skills update`。
