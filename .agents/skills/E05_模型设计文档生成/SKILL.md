# E05_模型设计文档生成

## 这项技能解决什么问题

- 已有SQL/DDL/加工程序：按实际实现补设计文档。
- 只有需求：先定业务过程、粒度、主键、指标与来源，输出可评审草案。
- 已有其他模板：按语义翻写成公司模型设计Excel，保留迁移对应关系。
- AI负责理解与设计；脚本负责读取、填充和结构校验，不以正则猜测代替SQL语义分析。

## 先读哪些本地知识

- 先读 `references/本地适配说明.md`，确认路径、依赖及来源授权的适用范围。

- 每次先读 `references/模板理解与字段规范.md`、`references/场景工作流.md`。
- 生成前读 `references/输入输出协议.md`、`references/输出契约.md`。
- 来源冲突、疑似复制残留或验收时读 `references/证据与验收.md`。
- 当前用户材料优先于示例；模板来自用户提供的品类市场趋势工作簿。

## 固定动作

1. 定位输入、模型范围、场景和目标模板；执行B04定位子项目，B08记进度；修改已有成果先执行B02。
2. Excel运行 `scripts/model_design.py inspect`，读相关页含隐藏、合并、公式、批注和图片；代码读取完整DDL、最终投影、CTE、JOIN、UNION、窗口、调度。
3. 先形成理解摘要与证据，厘清粒度、技术键和业务键、指标、来源分支、更新策略；只对阻断设计的分歧询问，其余明确列缺口。
4. 按协议生成 `model_design.json`；分别标记已确认、设计建议、待确认、存在冲突，并引用证据。多来源放同一字段mappings。
5. 运行 `scripts/model_design.py render --input <json> --output <xlsx> --report <json>`；默认使用 `assets/模型设计空白模板.xlsx`，不依赖原.temp文件。
6. 结构通过后做AI语义复核：字段覆盖、粒度与键、指标算法、全部来源分支、目录一致。失败先修复，有缺口以草案交付。
7. 交付Excel、理解与差异说明、缺口和校验结果；更新目录、B03记忆和B08状态。

## 什么时候再读本 skill 的 references

- 表头与多来源续行：`references/模板理解与字段规范.md`。
- 三种场景与其他Skill分工：`references/场景工作流.md`。
- JSON与脚本参数：`references/输入输出协议.md`。
- 样例陷阱与验收：`references/证据与验收.md`。
- 产物路径和交付状态：`references/输出契约.md`。
- 11项结构落点：`references/结构融合索引.md`。

## 边界

- 不执行DDL/DML，不自动修改源代码或原Excel；文档生成不等于开发、上线、生产验证。
- 不照搬示例表名、作者、日期、完成状态、截图、主键、业务阈值或AI公式。
- 代码补文档保留现状；改名和口径建议列差异，不伪装为已实现。
- 需求可给候选方案，不能虚构源表存在、代码已实现或验证通过。
- 翻写不能丢失额外语义，放备注/设计说明/翻写映射；映射不了列待确认。
- 结构校验不证明语义正确，必须AI复核，不依赖Excel执行=AI(...)生成最终内容。
