# 场景工作流

## 公共入口

确定目标模型、范围、材料、场景与目标模板。能从上下文推断的不重复问；核心对象/粒度/指标有不兼容解释时少量询问，同时继续独立读取。非阻断缺失显式保留，以草案交付。

本地材料为依据。需要DDL用C03；真实只读探查用C02/C11并遵守其执行方式，文档不强制查生产。命名评审可用E01/E03，交付质量报告用C10，用数说明用C13；不将任务扩大为开发上线。

## code：已有代码补文档

1. 确认引擎/方言、目标、代码版本；完整读DDL、INSERT目标列和SELECT位置、最终投影、调度；程序代码跟踪schema及写入参数。
2. 追踪CTE/别名/临时表至真实来源，拆JOIN类型/键/有效期、过滤、窗口排序/rn、去重、聚合、UNION ALL各分支及类型对齐。
3. 同版本DDL决定物理名、顺序、类型和Key，投影决定取值；两者不一致列冲突。SELECT *无schema时不能声称字段完整。
4. 写最终粒度、业务键、代理键、水位与历史策略；不能凭字段名推断键。CREATE存在不证明已建表/上线。
5. 指标写表达式、过滤、维度、去重、单位币种、窗口、分母、NULL/零规则。父体指标挂多子体行要注明不可直接求和。
6. 实现写主体，需求或旧文档差异另列。不得为了补文档改SQL或把建议当已实现。

## requirements：需求先行

1. 提取用数问题、对象、业务过程、维度、指标、周期、验收条件。
2. 先定一行再分层拆表，不能混合多个粒度；业务/技术键给候选和验证方法。
3. 复用已有来源和标准；无证据的源表不能说存在。候选名称/类型/来源标设计建议，未知填null。
4. 设计更新、迟到/补数、幂等、分区、历史、NULL、换算、JOIN基数；推荐实现明确未确认。
5. 无代码不是失败，K列可不适用或标建议伪SQL，不编造已实现逻辑。
6. 每项需求在表/字段/设计说明有落点，记录未覆盖项及影响；不得填开发已完成。

## rewrite：其他模板翻写

默认转成本公司模板；用户另指定目标模板则先读目标结构并实现适配，不把任意xlsx直接传默认渲染器。

1. 读所有相关页、隐藏、合并、多行表头、批注、公式缓存、图片和附件；Word/Markdown按章节定位。
2. 原列/单元格/章节→目标语义映射：英文名D、类型E、释义F、源列G、源表H、物理PK I、业务键J、转换K、约束L/设计说明。PK含义须核实。
3. 同名先辨别多来源、版本或不同模型，不按名称直接去重；保留分支条件。
4. nullability/default/索引/安全分级等无专列内容放备注或设计说明，长SQL保存完整附件。
5. migration逐项记录原位置、目标位置/语义、处理状态与解释；保留原文或精确定位。
6. 逻辑字段数和来源行分别核对，拆合/排除给原因；不得翻写时擅改类型、键和含义。

## 混合输入

分别判断意图与实现：实现看同版本DDL/代码/真实验证，意图看最新需求和确认，标准看本轮指定材料，示例不能覆盖事实。冲突保留双方位置、影响、建议；用户确认设计不代表代码已同步。
