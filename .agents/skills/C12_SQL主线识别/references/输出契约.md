# 输出契约

默认每次同时输出两个最终文件，位于本项目已定位的output子项目目录，不写output根目录：

- `<源名>_主线注释.sql`：开头用--写主线及逐节点动作，随后原样保留源SQL正文；不自动执行，源DDL/DML也不执行。
- `<源名>_主线识别.md`：主线在前，两列表格在后，表头依次为“主线节点”“代码动作”。多条独立语句分别成节。末尾记录来源文件和SHA256用于核验。

中间件：由模型读取代码并填写的JSON计划，记录source_sha256及analyses。其语义正确性由模型负责，脚本只校验结构、原文依据与输出。

```json
{
  "source_sha256": "源SQL原始字节的SHA256",
  "analyses": [{
    "name": "主查询",
    "flow": "读取明细 → 条件筛选",
    "nodes": [{
      "node": "读取明细",
      "action": "读取orders源记录",
      "evidence": [{"start_line": 1, "end_line": 3, "excerpt": "FROM orders"}]
    }, {
      "node": "条件筛选",
      "action": "保留status为paid的记录",
      "evidence": [{"start_line": 1, "end_line": 3, "excerpt": "WHERE status = 'paid'"}]
    }]
  }]
}
```

flow按模型判断显式填写，必须包含所有节点名；允许分支表示，不自动把节点列表强制串成线性链。行号是源SQL从1起的行号，excerpt须来自所指区间。短文本字段不得含换行；SQL脚本用统一--注释。既有SQL注释与优化器hint不改；源文件UTF-8 BOM仅在解码正文时去除，其他正文字符与换行不改。

命令：

```text
python scripts/render_mainline.py --source <源SQL> --plan <识别JSON> --output-dir <输出目录>
```

可选--stem指定输出名前缀，不能带路径分隔符。已有目标文件一律拒绝覆盖，换目录或文件前缀；禁止覆盖原文件。源散列变化、行号越界、原文依据不匹配或识别计划缺失时失败，不生成伪结果。

验收只证明输出合同与输入引用一致，不声称数据库执行通过或语义理解绝对正确。完成前由模型再核对主线顺序与原SQL一致。用户只要单一形式时遵照用户选择；默认仍双输出。
