# 取证与根因分流

## 连接与身份

从当前.envs/catalog.json和env_manager精确选连接，先核对完整性和驱动可用性。缺失报告连接/变量名，不输出值、不扫描旧路径回退。驱动协议与端口不匹配属于实现问题，不推断数据异常。

| 对象 | 当前登记连接示例 | 入口 |
|---|---|---|
| 平台监控/模型/调度元数据 | mysql.dataplatform.reader | C15只读路由、MySQL驱动 |
| Doris实体 | doris.prod.readonly | C02；DDL用C03 |
| PG实际源 | postgres.source.readonly | PG只读连接 |
| CK历史 | clickhouse.source.readonly | 对应协议/驱动 |
| SQL Server源 | sqlserver.saas.client / sqlserver.kd.client | 按实际源选，任务只读 |

这些是路由示例而非凭据，下次仍验证注册。“数仓”特指Doris，平台MySQL不是数仓。负责人重名需核对用户/租户/有效状态；同名模型结合引擎、库和连接唯一定位。

## 监控到实际加工

按 C15 核实schema。已实测关联线索如下，字段仍须现场确认：

- dmp_manage.dmp_govern_index及dmp_govern_index_monitor_record_r：监控SQL、阈值、关联模型、最新/历史质量值与时间。
- dap_application.dap_mart_dataset及dmp_manage.dmp_assets_table：平台模型与物理表。
- dap_mart_dataset_etl_log：源目标数量、实例与ETL时间。
- dolphinscheduler的process/task definition及历史版本、实例、relation、schedule：实际SQL、参数、DAG与调度。

质量值1可能是“不满足规则的行数”，不是业务总数。NULL计数先查统计采集链路，不能当成0。最新日志不能替代旧告警时点；读不到历史证据就记录限制。

## 数据比较

1. 回读源SELECT、writer/columns、主键模型、preSql/postSql、实际StartTime/EndTime与时区。先复现当次真实窗口，不能擅用业务日期替换采集日期。
2. 同窗数量与逐日分布定位范围，再比较主键集合/出现次数和共有键字段；同数异键也算差异。
3. 技术键变更时按业务身份和粒度追踪。业务键不一定唯一，不能DISTINCT或字典覆盖后宣称完整；先核对重复频次，必要时按多重集合比较。
4. 同一真实案例列出旧键、新键、业务标识、字段/金额、时间与当前源状态，再统计同类影响量。单样例解释机制，不代替全量范围。
5. 全量字段可按月/键分块读取指纹，核对每块及总行数、LIMIT/截断、完成标记、NULL日期和边界；源持续变化时选共同水位/稳定窗口。

指纹需防拼接歧义：区分NULL和空串，文本用长度前缀或可靠编码，数值/时间按已确认的目标实际类型转换。说明排除的生成审计字段；不得任意舍精度/字段来掩盖差异。报告“标准化字段核验”，不宣称原始字节全等。

## 根因分流

| 证据模式 | 继续确认 | 改法方向 |
|---|---|---|
| 源有、目标无 | 过滤、失败、映射、分区、迟到/水位 | 修同步或过滤后补齐 |
| 目标有、源无 | CK/归档、源删除换ID、业务身份、加载来源 | 保护合法历史，确认后清理残留 |
| 共有键字段不同 | 口径、更新条件、类型、源变化 | 修对应环节并重建 |
| 业务重复 | 技术/业务键、JOIN放大、重复版本 | 按证实机制改，不直接更换主键 |
| 计数NULL/时间陈旧 | 统计节点、权限、采集和规则时点 | 修采集监控链路，避免盲重载 |
| 当前正常、旧告警异常 | 历史日志和后续运行 | 区分已恢复与旧根因未证实 |

源更新换ID由用户/可靠证据确认后，可解释pkid upsert留旧键；仍核实本表writer和窗口。缺稳定业务键不自动要求改主键，可重建时考虑同窗重载。监控SQL确有错误可以修，但依据业务语义与独立数据，不以变绿为目标。
