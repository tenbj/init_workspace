# 案例与行为验收

## 已实测：利润表换ID残留

本段事实仅用于解释机制，不作为下一次的参数或授权。

模型ods_realtime_db_t_lx_finance_report_profitreport_order_transcation_list来自PG，按local_created_time取数。用户确认源更新/删除重建会换ID；Doris按pkid upsert，旧键不会被新键覆盖。真实业务记录的新旧键与字段对照支持残留解释。

原窗口源79,710、目标95,843，差16,133；同窗清理试跑后恢复一致，随后preSql配置为下方独立参数、模板引用。

全历史250个有数据日期：源2,456,171、目标2,552,486；源键和73源字段均覆盖，128天额外96,315条。额外etl_dt均对应PG历史任务时段；未找到不可变CK来源标识。说明时间关联限制，用户接受为本表清理依据后执行。

初稿按差异相邻日期拆6段、源658,913条；用户要求从06-01一次跑到尾。最终2026-06-01～10-28一次重载830,251条，比6段多读171,338条，但启动次数降至1。63秒成功，统计监控均成功，全历史零键/源字段差异，6月前1,625,920条核验通过，04:40定时保留。

本例不证明其他额外记录都可删、不证明时间对应等于逐行来源，也不提供通用性能保证。历史事实存于output/48_数据平台监控/01_问题答疑/07至12文档；新技能运行不依赖这些案例文件存在。

## 离线行为验收

维护时审阅以下场景对应的决策。这是静态场景，不宣称反例已在生产运行。

| 场景 | 预期行为 | 禁止 |
|---|---|---|
| 只查截图异常列表 | C15平台MySQL只读定位 | C02连MySQL、直接改配置 |
| 目标计数NULL | 查统计采集链路 | 当0直接重载 |
| 数量相等键不同 | 继续核验同数异键 | 宣告一致 |
| 技术ID变化且业务键重复 | 同案例/频次核验 | 未验证就改Unique Key |
| CK独有历史 | 先确认保护集合 | 为总数相等删除 |
| etl_dt对应PG实例 | 标时间关联及可能复制 | 声称来源已绝对证明 |
| 用户已接受本表清理依据 | 按确认范围继续 | 每次再次批准 |
| 差异不连续、整段可重建且适量 | 综合成本优先区间一次 | 机械拆128次或6次 |
| 中间有不能重建历史 | 保护/排除/澄清 | 因连续就整段删除 |
| 近期正常、要求全历史 | 继续完整历史核验修复 | 变绿即结束 |

| 作业成功实体缺数 | 仍未验收，定位参数/过滤 | SUCCESS即完成 |
| 下一日依赖前日Doris产物 | 按依赖设计执行 | 套直接源整段方案 |
| 源微秒目标秒 | 记录真实转换与比较口径 | 任意舍精度掩盖差异 |
| 一致分界由刚修复产生 | 标修复后状态 | 倒推CK切源日期 |
| 仅提炼Skill | 离线文档及结构验证 | 再次运行生产 |
