# FRP + NSSM 执行流程

输入：配置路径、代理名、本地IP/端口、公网域名/端口、NSSM服务名。已有会话和本机环境可补足，不重复询问已知信息。授权新增或调整内网穿透包括备份、校验、重启及验证。

1. 用 `nssm get <服务> Application`、`AppParameters`、`AppDirectory` 和 `status` 核对真实服务。NSSM输出可能是UTF-16，不能因乱码误判失败。实际配置与用户提供路径不一致时先解决路由。
2. GET本地首页/健康接口确认程序可用。公网端口默认上限14999；配置内冲突由脚本检查，服务端其他代理占用须由启动日志确认。
3. Python3.11+运行脚本 `plan`；目标已有代理必须是TCP。脚本只维护指定代理，保留其他参数及认证、日志配置。`apply` 先验证同目录候选文件，再备份并原子替换；脚本不会重启服务。
4. 应用必要适配如精确Host白名单、同源URL属于已授权部署范围；保留原防护，不使用通配域名。按授权重启应用，再执行 `nssm restart <服务>`，检查退出码、运行状态及本次代理日志。
5. 日志须显示该代理 `start proxy success`。`port not allowed` 应换允许范围内端口，`port already used` 应换未占用端口，禁止覆盖别的代理。
6. 请求 `http://<域名>:<端口>/` 和健康接口，同时确认HTTP状态及目标应用内容。域名经过代理/fake-IP时，可直连已知FRP服务器IP并携带目标Host，核对同一应用实例。页面200但不可用时查API相对路径、Origin、Host、混合内容和控制台；必要时真实浏览器确认数据读取。
7. 验证优先只读，不能向正式库写测试垃圾数据。无账号鉴权时如实说明公网边界，Host和同源检查不是身份认证。
8. 脱敏计划、备份路径、重启结果、日志及公网验证存入对应output子项目；话题归属按B04，收尾按B03。只有公网验证通过才报告成功。

## 命令

```powershell
python .agents/skills/I01_内网穿透/scripts/proxy_config.py plan --config <frpc.toml> --name <代理名> --local-port <本地端口> --remote-port <公网端口>
python .agents/skills/I01_内网穿透/scripts/proxy_config.py apply --config <frpc.toml> --name <代理名> --local-port <本地端口> --remote-port <公网端口> --frpc <frpc.exe>
nssm restart <服务名>
```

可选 `--local-ip` 默认127.0.0.1、`--max-port` 默认14999（用户明确允许才提高）、`--output` 脱敏JSON路径（工作区任务存对应output子项目）。相同配置返回changed=false，无需重启。认证值和完整配置不出现在报告中。

## 备份与失败恢复

外部配置不在工作区B02可接受路径内，采用同目录字节备份，避免将认证秘密复制到工作区历史。校验失败保持原文件；并发修改时拒绝覆盖。写入后公网失败先查日志与应用，不无意义重复重启。回滚前核对备份及后续配置变化，避免覆盖他人更新；恢复原备份、verify、重启并验证旧入口。备份可能含秘密，只留原机器，不上传、不进Git、不展示内容。
