# 数据平台模型与海豚工作流操作规则

本规则仅在数据平台建模、字段变更和工作流操作任务中由相关技能按需读取，服从当前工作区标准和任务授权，不是全局平台操作授权。

## 既有模型修改与代码合并

- 既有模型的修改与新模型创建分别判断，修改已有模型不将 GitLab 合并作为通用前置条件。已有授权范围内的字段调整、海豚节点更新及节点试跑，按当前开发代码和确认的字段合同推进，不把 MR 合并作为通用前置条件；新建模型仍按对应创建流程核验。
- 平台某个入口只展示已合并代码时，这是该入口的数据来源限制，应先寻找支持既有模型修改的正常操作入口，不能据此把整个任务改成等待合并，也不能伪造模型类型或绕过界面限制。
- 本规则不授予自动合并 MR 的权限；代码提交、MR 合并与平台变更分别按用户已有授权执行和记录。

## 平台登录与环境恢复

- 平台跳转登录页时，先按 B12 精确路由当前任务需要的连接，优先使用 `dataplatform.web.client` 登记的 `DATAPLATFORM_LOGIN_URL` 恢复登录；已有明确的平台账号密码配置也可按当前任务授权使用。不得未检查环境配置就要求用户手工登录。
- 登录入口真实值只保存在 `.envs/dataplatform.web.client.env`；规则、Skill、记忆和交付只记录连接ID、变量名和验证结果，不复制密钥、完整免登录URL或认证头。数据库连接账号不得推断为网页登录账号。
- 使用已登记入口后核验页面确已登录，再回到目标模型继续已授权操作。无可用配置时先检查用户是否已提供登录信息，已提供则补充私有环境文件、公开目录登记和空白模板；仅在配置缺失且无可用信息，或已验证失效/要求人工认证时向用户说明实际缺口。
- 恢复认证不得刷新、关闭或覆盖未保存的建模窗口；存在活动草稿时用辅助标签恢复认证，随后激活原窗口并核验草稿。免登录入口恢复认证不扩大发布、上线、执行等操作授权。

## 平台模型注释（备注）的内容标准

- 面向模型使用者，补充平台配置页面没有解释清楚的信息。保留调度时间及其推导依据、更新范围的业务含义、字段保留/新增/排除等加工逻辑；不因内容带技术字段就一概删除。
- 保留实际筛选字段和参数名，并翻译为可理解的业务含义，例如“按发货日期（ShipmentDate）增量重写，StartTime为两个月前月初，EndTime为明天，含首尾日期”。字段、参数、范围和边界以当前模型合同为准，不套用示例。
- 调度说明写清为什么安排该时间，例如有效非DIM上游计划时间顺延5分钟；区分计划与实际启用状态，不把时间推算写成依赖阻塞或执行成功。
- 不重复粘贴参数表达式、原始cron或整段SQL；这些保留在参数/周期配置和开发交付合同中。模型注释不写MR、提交、操作日志、开发过程或无信息增量的套话。
- 加工说明用紧凑句子表达。字段数量有助于解释构成时可以保留，但须与最终合同一致。例如“保留65个ODS业务字段（不含时间审计字段），新增unique_key、shop_id、msku_id，以及3个DWD时间审计字段，共71个字段”；数量和字段仅为案例，不是通用固定值。
- 填写前核对注释与SQL、字段合同、调度和范围一致；保存后回读实际文本。用户要求先核对时只交付候选文案，不写平台；已有相同内容确认及保存授权时不重复询问。
- 本节只约束平台模型备注，不替代字段COMMENT、代码注释或完整技术交付，也不改写平台自动生成的周期说明。

## 海豚工作流的正确入口

- 从数据平台的**目标模型记录**进入：按完整数据库和物理表名定位唯一模型 → 打开该模型行的“关联 ETL” → 选择“跳转工作流” → 在工作流详情确认完整名称、项目和工作流ID。具体控件以现场快照为准，不固定坐标或UID。
- 禁止默认从侧栏或独立海豚入口开始找目标工作流，也不凭裸URL、历史URL、旧标签页或名称猜测目标。只有明确任务本身不关联数据平台模型且用户指定其他入口时，才按该任务的已验证入口处理。
- 若误入独立入口并看到登录页，先停止输入凭据；回到数据平台目标模型记录，按“关联ETL→跳转工作流”恢复导航。登录页只说明当前入口未建立目标工作流上下文，不能据此推断用户掉线或要求重复登录。只有正确入口本身确实要求登录且当前会话无可用认证时，才按平台登录流程处理。
- 页面ID、浏览器标签和登录态属于当前执行代理的现场状态。子代理不得假设与主代理共享；每个执行代理必须在自己的浏览器会话中重新列出页面并取当前快照，不能直接复用其他代理读出的pageId、UID或标签状态。

## 浏览器窗口与辅助标签

- 每次浏览器操作前，把当前任务所用的页面/窗口置于最前（bringToFront）；切换到其他页面后，在下一次交互前重新置前并确认页面身份。
- 置前的目的包括让用户实时看到操作。通过浏览器读取同源接口、运行页面脚本也必须先置前相关工作页面；不要在后台隐藏标签中操作。工具仅确认标签激活但无法保证操作系统窗口在最前时，如实说明，不宣称用户已经能看到。页面操作与只读接口取数分别说明，不能把接口返回描述为可见点击。
- AI新开的辅助标签用完后，切回并置前保留的任务工作标签；可关闭已确认由AI打开且已用完的辅助标签。不得关闭用户原有标签，也不得关闭承载未保存配置的原窗口。
- “返回工作页”指激活仍保留的原工作标签，不是浏览器Back、重新导航URL或重开配置。C20建模期间仍遵守原配置页禁止Back、刷新、重导航和关闭的边界。

## 多行代码整块录入与双重回读

- SQL、DataX JSON、Shell等代码从已确认的源文件**整块复制粘贴**，不使用`type_text`、`keyboard.type`或其他逐字符模拟按键代替。首次录入前先确认当前工具的实际行为及可用停止方式；整块粘贴不可用时停在编辑前说明能力缺口，不自行降级为逐字输入。普通关键词、字段名等单行表单仍使用正常填表工具。
- 保留源文件真实换行、缩进、注释、大小写和末尾换行；比较时只允许CRLF/LF统一，不使用Trim、空白折叠、格式化或删除注释来掩盖差异。代码以`--`开头时，压成一行会使执行语句落入行注释，不能以“看起来内容都有”验收。
- **保存前回读编辑器全文**：粘贴完成后先将剪贴板置为本次唯一临时标识，再在目标编辑器全选复制；确认临时标识被替换，并与源文件全文比较。源内容原本留在剪贴板不能充当复制成功证据；虚拟编辑器textarea的局部窗口值也不能代替全文。记录比较结论、字符数、换行数或文本哈希，差异未清零不点节点确定或保存。
- **保存后回读持久化全文**：核对版本、代码与来源一致，必要参数及非授权配置未变，再进入上线、运行阶段。编辑器一致、保存成功、工作流ONLINE、定时ONLINE、实例SUCCESS、实体有数据分别验收，不能互相替代。
- 平台只读预览、自动拉取展示或接口返回若丢失换行，只作为展示异常记录；沿授权的实际代码编辑入口对齐文件，不把预览文本作为可执行来源，不绕过界面保存。本规则覆盖的具体节点步骤与Windows剪贴板操作见C22的操作流程。

## 停止、工具恢复与状态报告

- 用户要求停止时，**先停止实际动作，再分析和整理记录**；立即停止派发后续输入、确定、保存、上线和运行。不得让查源码、写备份或记忆、追加检查请求延误实际停止。
- 取消外层等待、工具超时、结束编排脚本、停止派发新动作，都不能单独证明浏览器输入已停。先使用可用取消手段；已知服务被长调用串行占用时，不依赖向同一队列追加读取实现紧急停止。没有执行层停止证据时只能报告“正在停止，尚未确认”，不得说“已停止”。
- 正常取消无效且需停止自动化进程时，先核对目标窗口、进程关系和本任务独占归属，仅停止准确对应的自动化；禁止按node/chrome进程名批量终止、硬编码旧PID或影响其他任务。不得为停止擅自杀浏览器、丢弃草稿或变更环境配置。归属无法确认时立即如实说明并采用用户可见的安全停止方式。
- 停止后核验自动化进程/实际输入状态，分别记录浏览器是否保留、草稿是否保存、是否已提交运行、工作流及原定时是否下线。未独立回读的状态标注“最后确认值”；下线后的待恢复项必须进入B08，不能把暂停记成完成。
- 用户授权继续后，自行使用现有可用启动/重连入口恢复因本任务停止的工具；不把正常恢复推给用户，也不把一次`Transport closed`直接当成必须改环境。恢复前仍不得擅自改配置、安装升级软件、改变权限或重启无关服务；如确需这些修改，先提供具体方案并按用户环境授权边界处理。确无可用恢复能力时说明真实阻塞。
- 连接恢复后重新列页、置前，按目标模型“关联ETL→跳转工作流”定位；先回读持久化版本、代码、原定时、草稿和活动实例，再决定补录、保存或运行。保留原执行策略及定时，不重复提交已经启动或成功的实例。

## 上游调度与 DIM 排除

- 维表（DIM）仍须纳入 SQL 直接依赖/数据血缘、平台注册身份、库表及字段匹配核验；**不把 DIM 调度时间、定时启停或运行批次纳入下游调度时间推算**，也不以 DIM 调度证据缺失阻止模型创建。DIM 上游的其他非调度核验仍按 C20 完成。
- 下游时间推算只使用参与该数据合同的有效、非 DIM 上游定时。已下线或确认停用的调度忽略时间贡献并记录，但保留依赖/血缘。文件导入、人工维护或无定时源不产生虚构的时间批次。
- 对应批次上取需等待的最晚有效非 DIM 上游计划启动时间，再加5分钟；多批次按实际对应关系分别推算，不把所有时间合并成全天单批或无对应依据的时间并集。跨午夜按日历进位。混合周期或批次映射存在歧义时，先给出候选及影响并核实，不强行推算。
- 只以最新可查的平台配置和调度器部署证据确认当前时刻、时区、批次、启停及参数；旧交付、案例或历史截图仅作历史证据。用户刚补充/修改的 ODS 调度信息必须重新读取并验证时间与来源，不能沿用先前缓存值；配置时间与实际运行时间分别记录。
