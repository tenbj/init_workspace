# E01 调用 SSOT 整改方案

## 1. 目标

本方案闭环 `E01_模型设计标准化` 在调用时不符合 SSOT 的问题：正式输出必须进入当前 `模型设计标准化` 子项目，而不是假设固定编号目录。

本方案同时回答根因归属：问题直接发生在 E01 的调用契约和脚本默认目录发现逻辑中；A01/A02 不是直接写出该缺陷的唯一原因，但它们的创建/安装校验缺少 SSOT 语义检查，属于复发防线缺口。

## 2. 问题背景

复核发现，当前 live 子项目是 `output/03_模型设计标准化_v1.9.0`，但 E01 的 `e01_common.py` 和 `references/input_contract.md` 曾写死 `output/01_模型设计标准化_v*`。这与 B04 的子项目编号规则冲突，因为编号由 `output/` 下现有最大编号自动递增生成，不具有业务含义。

E01 的 `SKILL.md` 只说“当前模型设计标准化子项目”，但没有把“先按话题归属定位或执行 B04 创建，再执行 B02 备份”写成明确步骤，导致调用者容易绕开工作区强制门。

## 3. 依据

| 事实源 | 采用方式 |
|---|---|
| `.system/standards/workspace-spec.json` | 以注册表和目录骨架为机器事实源；E01 注册名必须与 live Skill 文件夹和命令入口一致 |
| `.system/standards/Skills管理标准.md` | Skill 修改应按补丁升级，并同步注册表、YAML `name` 和 `.claude/commands/` |
| `.agents/rules/direction-rules.md` | 输出类任务必须完成话题归属，必要时执行 B04；`output/` 是 AI 输出唯一路径 |
| `B04` | 子项目编号是结构编号，不可由业务 Skill 写死 |
| `B02` | 修改文件前必须备份；正式写入 `output/` 前必须对整个子项目做 PROJECT 备份 |
| `A01` / `A02` | 当前只覆盖薄 Skill、骨架补齐和安装本地化，未形成“写 output 必须通过 B04/B02 且禁止固定编号”的硬校验 |

## 4. 最终判断

标准已经存在，问题不是 SSOT 缺失，而是执行层没有完全继承 SSOT。

直接缺陷在 E01：脚本默认目录发现写死 `01_模型设计标准化`，参考文档也给出了同样的正式输出路径，调用入口没有明确 B04/B02 顺序。

A01/A02 是间接原因：A01 的 `quick_validate.py` 只校验 frontmatter、标准段落、目录骨架和薄入口；A02 的本地化检查只要求“检查是否冲突”，但没有把 output 目录策略转成可执行校验。因此它们没有拦住 E01 这种“结构合格但 SSOT 语义不合格”的 Skill。

B01/B06 也有检查缺口：现有体检能发现命令注册、目录结构、BOM 和知识地图问题，但不会扫描 Skill 文档/脚本中是否硬编码 `output/NN_主题_v*`。

## 5. 最小整改清单

| 优先级 | 意图指向 | 具体落点 | 要做什么 | 验收标准 |
|---|---|---|---|---|
| P0 | `E01：修调用契约` | `.agents/skills/E01_模型设计标准化_v1.0.1/SKILL.md` | 写明正式输出前先定位/创建当前子项目，再做 B02 PROJECT 备份 | 调用 E01 时不会跳过 B04/B02 |
| P0 | `E01：修脚本默认目录` | `scripts/e01_common.py` | 将默认发现从 `output/01_模型设计标准化_v*` 改为 `output/*_模型设计标准化_v*`，并按版本选择当前 live 子项目 | 脚本可解析到 `output/03_模型设计标准化_v1.9.0` |
| P0 | `E01：同步注册入口` | `workspace-spec.json`、`.claude/commands/` | 将 E01 从 `v1.0.0` 升为 `v1.0.1` 并同步 slash command | B01 不报告 Claude 命令与注册表不一致 |
| P1 | `A01：补创建校验` | `A01` references 与 `quick_validate.py` | 对会写 `output/` 的 Skill 增加检查：必须提到 B04/B02，禁止硬编码 `output/NN_主题_v*` 作为正式路径 | 新建/薄化 Skill 时能拦住同类问题 |
| P1 | `A02：补安装后校验` | `A02` 本地化检查清单 | 迁入 Skill 后复用 A01 的 SSOT output 校验，不只做薄入口检查 | 外部 Skill 迁入后不会保留固定编号输出策略 |
| P1 | `B01/B06：补体检防线` | 体检/规范化脚本 | 扫描 live `.agents/skills/` 中的硬编码 output 子项目编号，至少 WARN；对正式路径强依赖固定编号的情况 FAIL | 批量体检能提前发现结构合格但 SSOT 语义漂移的 Skill |
| P1 | `初始化模板：防复发` | `00_系统治理` 代码程序模板 | 若初始化工具仍分发 E01 模板，则同步 E01 v1.0.1 并重建初始化产物 | 新工作区不会再生成旧 E01 |

## 6. 不做事项

- 不修改 SSOT 去允许固定编号目录；业务 Skill 必须向 B04 的动态编号规则收敛。
- 不把本方案反向当作标准源；标准仍以 `.system/standards/` 为准。
- 不把所有输出类 Skill 强制塞进 `模型设计标准化` 子项目；每个任务仍按话题归属判断。
- 不在本轮扩大到重构 A01/A02/B01/B06；这些属于后续治理项，按上表验收。

## 7. 执行顺序

1. 已按 B02 备份 E01 Skill、`.system/standards`、E01 command、系统治理子项目和全局知识地图。
2. 已修复 E01 live 文件，并升级为 `E01_模型设计标准化_v1.0.1`。
3. 已验证 A01 的 `quick_validate.py` 对 E01 通过，且 E01 默认目录发现能解析到当前 `output/03_模型设计标准化_v1.9.0`。
4. 本方案落盘后，更新系统治理目录、版本记录、全局知识地图和系统记忆。
5. 收尾复跑 B01；若仍有 FAIL，只处理与本轮直接相关的红项，其余作为独立治理项记录。

## 8. 验收口径

- `.agents/skills/E01_模型设计标准化_v1.0.1/SKILL.md` 的 YAML `name` 与文件夹版本一致。
- `.system/standards/workspace-spec.json` 注册的是 `E01_模型设计标准化_v1.0.1`。
- `.claude/commands/E01_模型设计标准化_v1.0.1.md` 指向同版本 Skill。
- `e01_common.latest_model_project()` 返回当前 `output/03_模型设计标准化_v1.9.0`。
- B01 不再报告知识地图中的系统治理目录版本漂移。
- 后续整改若实施 A01/A02/B01/B06，应能通过自动检查发现“正式输出路径写死 `output/NN_...`”的同类问题。

## 9. 结论

本轮最小闭环是先修 E01：它现在不再依赖固定编号目录，调用说明也回到 B04/B02 的强制门顺序。A01/A02 需要整改，但属于防线不足而不是唯一根因；后续应把“写 output 的 Skill 必须动态定位子项目”变成创建、安装、体检三层都能执行的检查。
