# 更新日志方案

## 分层

| 层级 | 文件或来源 | 用途 |
|------|------------|------|
| 提交层 | Git commit | 记录原子改动，支持追溯和自动归类 |
| 内部版本层 | `output/*/版本记录.md` | 记录工作区内部演进、Skill/规则/文档细节 |
| 公开日志层 | `CHANGELOG.md` | 面向 GitHub 用户的公开更新日志 SSOT |
| 发布层 | GitHub Release | 展示本次版本说明、资产、hash、升级提示和完整 diff |

## 核心判断

- `CHANGELOG.md` 是对外发布更新日志的唯一事实源。
- GitHub Release 正文从 `CHANGELOG.md` 对应版本段落生成或复制。
- GitHub 自动生成 Release Notes 只做草稿辅助，不替代人工整理。
- `output/*/版本记录.md` 只能作为 changelog 的输入材料，不应原样拼进 Release。

## 版本号

公开版本号使用 `vMAJOR.MINOR.PATCH`。

| 级别 | 触发条件 |
|------|----------|
| MAJOR | 旧工作区无法无感升级、入口规则或目录骨架出现不兼容变化 |
| MINOR | 新增兼容能力、新 Skill、新检查、新发布流程、新文档入口 |
| PATCH | 修 bug、安全脱敏、目录链接修正、构建修复、文档小修 |

当前项目的公开版本号优先跟用户下载的主要交付物一致，例如初始化工具 exe 版本，而不是跟某个 `output/` 子项目版本一致。

## `CHANGELOG.md` 推荐结构

```markdown
# Changelog

All notable changes to this project are documented here.

## [Unreleased]

### Added

### Changed

### Fixed

### Security

## [v2.8.0] - 2026-05-11

### Highlights

- ...

### Added

- ...

### Changed

- ...

### Fixed

- ...

### Security

- ...

### Upgrade Notes

- ...

### Assets

- `初始化工作区_v2.8.0.exe`
- SHA256: `...`

### Full Diff

- `v2.7.0...v2.8.0`
```

## 分类口径

| 分类 | 放什么 |
|------|--------|
| `Highlights` | 本次版本最值得用户知道的 1 到 3 条 |
| `Added` | 新功能、新 Skill、新命令、新文档入口 |
| `Changed` | 行为变化、目录结构变化、标准口径变化 |
| `Fixed` | bug、路径错误、构建问题、检查误报 |
| `Security` | 脱敏、密钥移除、权限和发布安全修复 |
| `Removed` | 删除或迁移的用户可见能力 |
| `Deprecated` | 仍可用但未来会移除的能力 |
| `Upgrade Notes` | 旧版本升级注意事项、兼容性说明 |
| `Assets` | Release 附件、hash、平台说明 |

## Commit 信息

建议使用 Conventional Commits：

```text
feat(skill): add B09 GitHub release workflow
fix(security): remove hardcoded connection defaults
docs(release): update changelog and release notes
chore(release): prepare v2.8.0
```

常用类型：

| 类型 | 进入 changelog 的位置 |
|------|-----------------------|
| `feat` | `Added` |
| `fix` | `Fixed` |
| `docs` | 视用户影响进入 `Changed` 或忽略 |
| `refactor` | 通常不进公开日志，除非改变行为 |
| `chore` | 通常不进公开日志，`chore(release)` 用于发布提交 |
| `fix(security)` | `Security` |
| `BREAKING CHANGE` | `Breaking Changes`，并触发 MAJOR |
