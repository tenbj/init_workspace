# E01 模型设计标准化输出物与目录结构

> 本文定义 `E01_模型设计标准化_v1.0.0` 每次运行的输出物、目录结构、文件命名和用户交互入口。  
> 设计前提：AI-first，脚本只做解析、任务打包、客观校验、回写和摘要，不维护复杂语义规则。

---

## 1. 总体输出分两层

`E01` 的输出分为两层：

1. **运行级产物**：每次处理一个模型设计 Excel 时生成，放在 `runs/{run_id}/` 下。
2. **最终交付物**：用户主要打开和评审的 Excel、摘要文档，放在本次 run 目录的 `deliverables/` 下。

完整结构：

```text
output/01_模型设计标准化_v{project_version}/
  03_代码程序_v{code_version}/
    runs/
      {run_id}/
        00_inputs/
        01_parse/
        02_ai_batches/
        03_ai_decisions/
        04_validation/
        05_writeback/
        06_deliverables/
        run_summary.md
        run_manifest.json
```

示例：

```text
output/01_模型设计标准化_v1.9.0/
  03_代码程序_v1.0.0/
    runs/
      20260511_171000_利润核算快报/
```

---

## 2. run_id 命名

每次运行创建一个唯一 `run_id`：

```text
YYYYMMDD_HHMMSS_{任务短名}
```

示例：

```text
20260511_171000_利润核算快报
20260511_174200_销售明细DWD
```

规则：

- 日期时间使用运行开始时间。
- 任务短名使用中文，取模型主题或文件名关键部分。
- 同一输入文件重复运行，也生成新 run，不覆盖旧 run。

---

## 3. 顶层文件

每个 run 根目录下有两个入口文件：

```text
run_manifest.json
run_summary.md
```

### 3.1 `run_manifest.json`

机器入口。记录本次运行的输入、输出、参数、状态。

示例：

```json
{
  "run_id": "20260511_171000_利润核算快报",
  "skill": "E01_模型设计标准化_v1.0.0",
  "mode": "review_only",
  "created_at": "2026-05-11 17:10:00",
  "inputs": {
    "standard_library": "input/标准库.xlsx",
    "model_design": "input/模型设计 - 利润核算（快报）.xlsx",
    "sample_design": null,
    "data_assets": null
  },
  "outputs": {
    "review_excel": "06_deliverables/模型设计标准化建议版.xlsx",
    "summary": "run_summary.md"
  },
  "status": "completed"
}
```

### 3.2 `run_summary.md`

人类入口。用户和 AI 换会话后优先读这个文件。

内容包括：

- 本次处理了哪个 Excel。
- 总字段数。
- AI 建议数。
- 需要人工确认数。
- 待沉淀标准数。
- 阻断问题数。
- 最终交付物链接。

## 4. `00_inputs/` 输入快照与清单

目录：

```text
00_inputs/
  input_manifest.json
  source_files.md
```

### 4.1 `input_manifest.json`

记录输入文件路径、大小、hash。

用途：

- 确认本次运行到底用了哪些输入。
- 防止同名文件被后续覆盖后无法追溯。

### 4.2 `source_files.md`

给人看的输入说明：

```markdown
# 输入文件

| 类型 | 路径 | 说明 |
|---|---|---|
| 标准库 | input/标准库.xlsx | 字段标准与映射标准 |
| 模型设计 | input/模型设计 - 利润核算（快报）.xlsx | 待标准化设计文档 |
```

说明：第一版不强制复制原始 Excel 到 run 目录，避免大文件重复；只记录路径和 hash。若后续需要严格归档，可增加 `source_copy/`。

## 5. `01_parse/` 解析产物

目录：

```text
01_parse/
  workbook_manifest.json
  template_check.json
  model_catalog.json
  dependency_raw.json
  entity_sheets.jsonl
  entity_fields.jsonl
  standard_library_raw.json
```

### 5.1 `workbook_manifest.json`

工作簿清单：

- sheet 数。
- sheet 名。
- sheet 类型识别。
- 行列统计。
- 是否可见。

用途：确认 Excel 是否完整读到。

### 5.2 `template_check.json`

固定模板检查结果：

- 是否缺列。
- 是否多列。
- 表头是否异常。
- 必填结构是否存在。

注意：这是结构检查，不做语义判断。

### 5.3 `model_catalog.json`

来自模型设计目录：

- 模型编号。
- 数据域。
- 专项。
- 分层。
- 模型名称。
- 实体表名。
- 当前状态。
- 单元格坐标。

用途：给 AI 提供模型上下文，也给回写定位。

### 5.4 `dependency_raw.json`

依赖说明原始结构化结果。

第一版不强制构建复杂图，只先把 Excel 数据流 sheet 转成可读 JSON；后续可扩展：

```text
dependency_graph.json
dependency_graph.mmd
```

### 5.5 `entity_sheets.jsonl`

一行一个实体 sheet：

```json
{
  "sheet_name": "管理快报-金额",
  "declared_table": "cbebg.dmt_profit_snapshot_amt_ilu_dd",
  "header_row": 2,
  "data_start_row": 3,
  "data_end_row": 113
}
```

### 5.6 `entity_fields.jsonl`

一行一个字段：

```json
{
  "sheet_name": "管理快报-金额",
  "row_number": 7,
  "field_order": 5,
  "field_name": "amt",
  "data_type": "decimal(18,6)",
  "field_desc": "金额",
  "reference_field": "amt",
  "reference_table": "cbebg.dws_fin_settlement_shop_msku_subject_ilu_dd",
  "is_primary_key": "否",
  "is_business_key": "否",
  "source_cell_map": {
    "field_name": "D7",
    "field_desc": "F7"
  }
}
```

这是 AI 字段评审的基础输入。

### 5.7 `standard_library_raw.json`

标准库原始结构化结果。

保留：

- `规则标准库` 原始行。
- `映射标准库` 原始行。

注意：不转成脚本语义规则，只作为 AI 权威参考资料。

## 6. `02_ai_batches/` AI 工作包

目录：

```text
02_ai_batches/
  ai_field_review_batches.jsonl
  batch_index.md
```

### 6.1 `ai_field_review_batches.jsonl`

一行一个实体 sheet 的 AI 评审任务：

```json
{
  "batch_id": "entity:管理快报-金额",
  "model_context": {
    "sheet_name": "管理快报-金额",
    "declared_table": "cbebg.dmt_profit_snapshot_amt_ilu_dd",
    "catalog": {},
    "dependency_rows": []
  },
  "standard_library_context": {
    "rules": [],
    "mappings": []
  },
  "fields": []
}
```

原则：

- 不筛“可疑字段”。
- 每个实体 sheet 的字段全量给 AI。
- AI 自己判断字段名是否合理、是否需要确认。

### 6.2 `batch_index.md`

给人看的批次清单：

```markdown
| batch_id | sheet | 字段数 | 状态 |
|---|---|---:|---|
| entity:管理快报-金额 | 管理快报-金额 | 111 | 待评审 |
```

## 7. `03_ai_decisions/` AI 决策产物

目录：

```text
03_ai_decisions/
  ai_field_review_decisions.jsonl
  ai_table_review_decisions.jsonl
  ai_standard_gaps.jsonl
  ai_decision_summary.md
```

### 7.1 `ai_field_review_decisions.jsonl`

一行一个字段决策：

```json
{
  "sheet_name": "管理快报-金额",
  "row_number": 7,
  "current_field_name": "amt",
  "recommended_field_name": "amt",
  "decision": "keep",
  "confidence": "high",
  "reason": "字段描述为金额，参考字段为 amt，当前字段名可保留。",
  "human_question": "",
  "writeback_allowed": false
}
```

决策枚举：

| 决策 | 说明 |
|---|---|
| `keep` | 保留当前字段名 |
| `fill_safe` | 高置信度可填字段名 |
| `suggest_with_review` | 有建议但需人工确认 |
| `replace_suggestion` | 建议替换但不自动替换 |
| `need_human_confirm` | 需要人工确认 |
| `cannot_decide` | 无法判断，阻断 |

### 7.2 `ai_table_review_decisions.jsonl`

一行一个表名/实体 sheet 决策：

```json
{
  "sheet_name": "管理快报-金额",
  "current_table_name": "cbebg.dmt_profit_snapshot_amt_ilu_dd",
  "recommended_table_name": "cbebg.dmt_profit_snapshot_amt_ilu_dd",
  "decision": "keep",
  "confidence": "high",
  "reason": "表名与模型目录一致，且符合 DMT 快报金额表语义。",
  "human_question": ""
}
```

### 7.3 `ai_standard_gaps.jsonl`

待沉淀标准：

```json
{
  "gap_type": "semantic_relation",
  "source_sheet": "管理快报-金额",
  "source_row": 4,
  "field_desc": "商品",
  "suggested_standard": "利润核算店铺MSKU粒度下，商品口语可映射为 MSKU",
  "reason": "AI 根据模型上下文判断需沉淀该语义关系。",
  "status": "待确认"
}
```

### 7.4 `ai_decision_summary.md`

给人看的 AI 决策摘要：

- 哪些字段高置信度。
- 哪些字段需确认。
- 哪些标准缺口频繁出现。
- 哪些表名可能有问题。

## 8. `04_validation/` 后验校验产物

目录：

```text
04_validation/
  validation_report.json
  review_items.jsonl
  validation_summary.md
```

### 8.1 `validation_report.json`

脚本对 AI 输出做客观校验：

- JSONL 是否可解析。
- 必填字段是否齐全。
- 推荐字段名是否小写下划线。
- 同一实体字段名是否重复。
- `writeback_allowed=true` 是否有推荐字段名和理由。

### 8.2 `review_items.jsonl`

综合评审项，来自 AI 决策和脚本校验：

```json
{
  "severity": "warning",
  "scope": "field",
  "sheet_name": "管理快报-金额",
  "row_number": 4,
  "issue_type": "need_human_confirm",
  "issue": "字段描述“商品”粒度不明确",
  "suggestion": "请确认是否指 MSKU 粒度"
}
```

### 8.3 `validation_summary.md`

给人看的校验摘要。

---

## 9. `05_writeback/` 回写计划和中间 Excel

目录：

```text
05_writeback/
  writeback_plan.json
  writeback_log.json
  workbook_draft.xlsx
```

### 9.1 `writeback_plan.json`

准备写入 Excel 的计划：

```json
{
  "mode": "review_only",
  "actions": [
    {
      "action": "append_review_row",
      "target_sheet": "AI字段建议",
      "source_sheet": "管理快报-金额",
      "source_row": 7
    }
  ]
}
```

第一版默认 `review_only`，不直接覆盖原字段名。

### 9.2 `writeback_log.json`

实际写入结果：

- 写入哪些 sheet。
- 新增多少行。
- 是否覆盖字段名单元格。
- 是否发生失败。

### 9.3 `workbook_draft.xlsx`

中间版本 Excel，可用于调试；最终用户主要看 `06_deliverables/` 下的正式交付版。

## 10. `06_deliverables/` 最终交付物

目录：

```text
06_deliverables/
  模型设计标准化建议版.xlsx
  模型设计标准化运行摘要.md
  待人工确认清单.csv
  待沉淀标准清单.csv
```

这是用户主要关注的目录。

### 10.1 `模型设计标准化建议版.xlsx`

最终 Excel 交付物。

建议包含：

| Sheet | 说明 |
|---|---|
| 原始模型设计各 sheet | 保持原结构 |
| `AI字段建议` | AI 对每个字段的建议 |
| `待人工确认` | 需要用户判断的问题 |
| `待沉淀标准` | 建议进入标准库治理的项 |
| `运行摘要` | 本次运行统计 |

第一版不覆盖原字段名，只追加评审 sheet。

### 10.2 `模型设计标准化运行摘要.md`

给人阅读的摘要，与根目录 `run_summary.md` 内容一致或更精简。

### 10.3 `待人工确认清单.csv`

从 Excel 中抽出的待确认清单，便于快速查看或导入其他工具。

### 10.4 `待沉淀标准清单.csv`

从 Excel 中抽出的待沉淀标准，便于后续标准库治理。

## 13. 最小第一版可只生成哪些

第一版只读原型可以先不生成 Excel。

最小产物：

```text
run_manifest.json
run_summary.md
01_parse/workbook_manifest.json
01_parse/template_check.json
01_parse/entity_fields.jsonl
02_ai_batches/ai_field_review_batches.jsonl
03_ai_decisions/ai_field_review_decisions.jsonl
04_validation/validation_report.json
```

第二版再补：

```text
06_deliverables/模型设计标准化建议版.xlsx
```

第三版再补可控回写。

## 14. 关键原则

1. 所有中间产物必须持久化，不能只存在对话上下文。
2. JSON/JSONL 是机器审计链路，Excel 是用户评审入口。
3. 第一版默认 `review_only`，不覆盖原字段名。
4. 每条 AI 建议必须能追溯到原 sheet 和原行号。
5. 每次运行生成独立 run 目录，不覆盖旧结果。
6. 标准库给 AI 看，不转成脚本语义规则。
7. 脚本只做客观检查，不判断字段业务语义。

---

## 15. 最终回答

`E01_模型设计标准化` 的输出物不是一个单独 Excel，而是一套可审计运行目录。

用户主要拿到：

```text
模型设计标准化建议版.xlsx
模型设计标准化运行摘要.md
待人工确认清单.csv
待沉淀标准清单.csv
```

系统内部保留：

```text
解析结果 JSON/JSONL
AI 工作包
AI 决策
后验校验报告
回写计划和日志
```

这样既能让用户在 Excel 中评审，也能让后续会话或脚本完整追溯“为什么生成这个字段建议”。
