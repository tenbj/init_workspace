# 同步权威资料

## 目标

只同步 `./input/data-assets` 的远端 `master` 最新状态。
始终优先远端版本，不保留本地冲突、本地未提交改动或本地未跟踪文件。

## 直接使用

从项目根目录运行下面这条相对路径命令：

```powershell
python ./.agent/skills/sync-authoritative-data-assets/scripts/sync_authoritative_data_assets.py
```

只检查当前状态而不执行同步时，运行：

```powershell
python ./.agent/skills/sync-authoritative-data-assets/scripts/sync_authoritative_data_assets.py --status-only
```

如果 GitLab SSH / 网络在沙箱里失败，申请提权后重跑同一条命令，不要改成绝对路径。

## 斜杠调用

前台展示名使用中文：`同步权威资料`。
如果界面支持 slash 技能菜单，优先使用中文名 `/同步权威资料`。
如果某些环境仍按内部技能名识别，则兜底使用 `$sync-authoritative-data-assets`。

## 执行规则

- 只针对 `./input/data-assets` 生效，不要改成别的仓库。
- 只允许拉取和覆盖本地，不要执行 `push`、`merge`、`rebase`。
- 每次运行都先把 `origin` 的 push 地址设置为 `DISABLED`。
- 冲突、脏工作区、未跟踪文件一律以远端 `master` 为准。
- 命令和脚本路径都使用项目相对路径，不要写死绝对路径。

## 同步流程

脚本会按下面的顺序执行：

1. 定位项目根目录，再定位 `./input/data-assets`。
2. 校验这个目录存在且是 Git 仓库。
3. 执行 `git remote set-url --push origin DISABLED`，禁止上传。
4. 执行 `git fetch origin master`。
5. 执行 `git reset --hard` 和 `git clean -fdx`，先清空本地改动。
6. 执行 `git checkout -B master origin/master`。
7. 再次执行 `git reset --hard origin/master` 和 `git clean -fdx`，确保本地完全对齐远端。
8. 输出远端配置、`git status --short --branch` 和最新提交信息。

## 脚本路径

脚本文件在这里：

`./.agent/skills/sync-authoritative-data-assets/scripts/sync_authoritative_data_assets.py`

## 判断结果

同步成功后，应当看到这些结果：

- `origin` 的 `(push)` 地址是 `DISABLED`
- `git status --short --branch` 显示 `## master...origin/master`
- 工作区没有残留改动
