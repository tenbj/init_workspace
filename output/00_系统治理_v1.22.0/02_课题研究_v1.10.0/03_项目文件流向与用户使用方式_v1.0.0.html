项目文件流向与用户使用方式

依据：workspace-spec.json v1.8.0 当前子项目：00_系统治理_v1.7.0 初始化工具：v2.6.1 体检状态：20 PASS / 0 FAIL / 1 WARN

一眼看懂总流向

1. 用户入口

AGENTS.md / CLAUDE.md 只写强制门和读取顺序。

2. SSOT 标准

.system/standards/ 决定骨架、命名、Skill 注册和历史规则。

3. 执行层

.agents/rules/ 常驻约束；.agents/skills/ 执行动作。

4. 当前产出

output/ 放完整成果；.memory/ 放当前态记忆。

5. 历史留痕

.history/ 只存备份快照；不作为 live 文件继续编辑。
input/资料 -> 入口强制门 -> SSOT 标准 -> Rule/Skill 执行 -> B02 备份 -> output 产出 -> B03 记忆 -> history 留痕

目录职责

input/

用户给的权威资料入口，只读参考。体检发现当前有一个治理类文档疑似误放：skills问题记录.md。

.system/standards/

机器和人共同遵守的标准源。冲突时，标准高于 Rule、Skill 和 output 过程稿。

.agents/rules/

常驻执行规则：方向归属、命名、记忆、版本控制。

.agents/skills/

可执行工作流：B01 体检、B02 备份、B03 记忆、B04 子项目、C 系列数仓等。

output/

唯一成果输出区。每个话题是一个子项目，内部固定为 01 问答、02 研究、03 代码。

.memory/

当前态记忆：对话记录、系统记录、知识提炼、全局知识地图。

.history/

备份区。由 B02 或初始化工具生成，手工不直接往里写。

.claude/commands/

Claude 斜杠命令包装，一条命令对应一个注册 Skill。

用户对话大致分 6 类

对话类型 用户常见说法 文件执行流向 主要落点
1. 问答解释 “这是什么意思？”“帮我判断一下” B01 -> 读 direction-rules -> 定位或创建子项目 -> B02 -> 写 01_问题答疑 -> B03 output/NN_主题/01_问题答疑/、.memory/对话记录/
2. 整理研究 “整理一下”“做个方案”“输出 HTML/Markdown” B01 -> 话题归属 -> B02 PROJECT -> 写 02_课题研究 -> 更新目录/版本记录 -> B03 output/NN_主题/02_课题研究/
3. 代码程序 “改脚本”“加功能”“构建 exe” B01 -> 读标准/规则 -> B02 -> 改 03_代码程序 或相关源码 -> 测试/构建 -> B03 output/NN_主题/03_代码程序/ 或受管源码目录
4. 系统治理 “改规则”“改 Skill”“调整入口/标准” B01 -> 读 SSOT/Skills 管理标准 -> B02 CONFIG/FOLDER/MEMORY -> 改 .system/.agents/.claude -> 记录到 output/00 和 .memory/系统记录 .system/、.agents/、.claude/、output/00_系统治理/
5. 数仓开发 “查表”“生成 DWD SQL”“出字段 Excel” C01 同步资料 -> C02/C03 只读查询 -> C05/C06/C07 生成产物 -> B03 input/data-assets、output/01_DWD开发产物/
6. 初始化升级 “初始化工作区”“升级骨架”“发布 exe” 运行 init_workspace -> 受管文件先备份到 .history -> 覆盖层更新 -> 必备层补缺 -> B01 复检 output/00_系统治理/03_代码程序/、目标工作区根目录

关键门

B01 先体检 会话开始先做只读健康检查；FAIL 先处理，WARN 可记录后继续。
B02 先备份再修改 改 live 文件前必须备份。output/ 用 PROJECT，Rule 用 CONFIG，Skill/.system 用 FOLDER，知识提炼用 MEMORY。
B03 先记忆再回复 有知识回答或文件操作就写记忆；涉及 output 产出时至少写项目对话记录。

最短判断法

如果用户要... 先看哪里 通常写哪里
理解、判断、说明 direction-rules.md 和现有 output/ 子项目 01_问题答疑
完整整理、研究、方案 .system/standards/、相关 Rule/Skill、现有产出 02_课题研究
生成脚本、SQL、工具 对应 Skill 和代码目录 03_代码程序
改框架规则或 Skill workspace-spec.json、Skills管理标准.md .system/、.agents/，并在 output/00 留过程说明
