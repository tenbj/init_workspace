# 目录链接规范最小整改方案（终版）

---

## 一、目标

让 `目录.md` 的文件列稳定生成并校验为可跳转 Markdown 链接，避免再次出现纯文本文件名。

本方案只处理**骨架层闭环**：标准如何被执行、体检如何发现问题、执行入口如何提醒。业务子项目里具体哪些目录项需要补链接，不在本文列清单；由 B01 检查结果在执行时给出。

---

## 二、问题背景

在新增和维护 `output/` 子项目文档时，`目录.md` 中曾出现文件列写成纯文本、不能直接跳转的情况。事后核对发现，链接格式不是新需求，`.system/standards/工作区骨架规格.md` 已经有明确规定；B04/B05 已回指该标准，B06 在规范化重建目录时也会生成链接。

问题不在标准缺失，而在执行闭环不足：日常落盘时容易漏写链接，B01 体检又没有检查这一项，因此“体检通过”不能证明目录链接一定合规。

所以本方案只补骨架层最小闭环：让执行入口提醒、让体检能够发现、让后续业务子项目修复由检查结果驱动。

---

## 三、依据

| 层级 | 事实源/入口 | 本方案采用方式 |
|------|-------------|----------------|
| 机器事实源 | `.system/standards/workspace-spec.json` | B01/B06 等脚本读取骨架标准时，以它为机器 SSOT |
| 人类可读标准 | `.system/standards/工作区骨架规格.md` | 目录链接格式以其中“固定文件”章节为准 |
| Skill 管理 SSOT | `.system/standards/Skills管理标准.md` | 跨 Skill 行动使用稳定编号，如 B01、B04、B05、B06 |
| 执行入口 | `.agents/rules/direction-rules.md`、对应 Skill | 只做提醒和执行，不反向定义新标准 |

核心规则：`目录.md` 的 `01_问题答疑` 与 `02_课题研究` 分节，文件列必须是 Markdown 链接；链接路径相对于 `目录.md` 所在目录。

---

## 四、最终判断

标准已经存在，不需要改标准。

B04、B05、B06 当前不是主要问题：B04/B05 已回指目录链接标准，B06 重建目录时已生成链接格式。

真正缺口只有两个：

1. **B01 缺自动检查**：体检不会发现 `目录.md` 文件列是纯文本还是链接。
2. **direction-rules 缺直写提醒**：只写“格式见 B04”，执行者只读 Rule 时容易漏掉链接要求。

---

## 五、最小整改清单

| 优先级 | 意图指向 | 具体落点 | 要做什么 | 验收标准 |
|--------|----------|----------|----------|----------|
| P0 | `B01：补目录链接检查` | B01 体检脚本 | 增加 `Catalog Link Format` 检查：遍历 `output/*/目录.md`，只检查 `01_问题答疑` 与 `02_课题研究` 分节，要求正式内容行的文件列为 Markdown 链接，且链接目标存在 | B01 能报告纯文本文件列和失效链接 |
| P0 | `B01：更新技能说明` | B01 `SKILL.md` | 在检查项中加入“目录链接格式” | Skill 说明与脚本实际检查项一致 |
| P1 | `direction-rules：补直写提醒` | `direction-rules.md` | 在 `目录.md` 维护规则中直接写明：`01/02` 分节文件列必须为 Markdown 链接，具体格式以 `工作区骨架规格.md` 固定文件节为准 | 执行者只读 Rule 也能知道必须写链接 |

---

## 六、不做事项

| 不做 | 原因 |
|------|------|
| 不修改 `工作区骨架规格.md` 来重新定义目录链接格式 | 现有标准已经明确，问题在执行和检查闭环 |
| 不把业务子项目缺链接条目列入本文整改清单 | 本文是骨架整改方案；业务内容修复由 B01 检查结果驱动 |
| 不继续追踪中文短名 Skill 入口 | 短名 Skill/命令已从 live 骨架移出，不再是当前主要风险 |
| 不把 B04/B05/B06 列为当前待改主项 | 当前复核显示它们已具备链接标准引用或链接生成能力 |
| 不把本文当标准源 | 本文只是一份执行方案；与 `.system/standards/` 冲突时，以标准为准 |

---

## 七、执行顺序

1. 执行 B02，对 B01 Skill 做 FOLDER 备份。
2. 修改 B01 体检脚本，新增 `Catalog Link Format` 检查；修改 B01 `SKILL.md`，同步检查项说明。
3. 执行 B02，对 `direction-rules.md` 做 CONFIG 备份。
4. 修改 `direction-rules.md`，补充目录文件列链接要求。
5. 运行 B01 体检。
6. 若 B01 报出业务子项目目录链接问题，再按 B02 对对应子项目做 PROJECT 备份后修复；该修复不属于本文骨架整改清单。

---

## 八、验收口径

整改完成后，应满足：

1. B01 体检包含目录链接格式检查。
2. B01 `SKILL.md` 的检查清单包含目录链接格式。
3. `direction-rules.md` 直接提醒 `目录.md` 的 `01/02` 文件列必须是 Markdown 链接。
4. `目录.md` 链接规则仍以 `工作区骨架规格.md` 为人类可读标准，不在 Rule 或 Skill 中另起一套格式标准。
5. 跨 Skill 行动描述使用稳定编号表达意图，具体路径只作为编辑落点。

---

## 九、结论

最终最小整改范围是：**B01 增加目录链接检查 + B01 Skill 说明同步 + direction-rules 直写链接提醒**。

这三项完成后，目录链接规范就从“标准里有”变成“执行时会提醒、体检时能发现”，形成最小闭环。
