# 字段命名规范

来源：新兔集团数据资产建设规范 v1.0

## 基本规则

- 全部小写，下划线分割
- 命名结构：`实体名_属性`，如 `emp_id`、`order_amt`
- 布尔字段以 `is_` 开头，如 `is_deleted`、`is_valid`
- 枚举描述字段以 `_desc` 结尾，如 `status_desc`

---

## 常用后缀缩写（命中时必须使用缩写）

| 含义 | 标准写法 | 常见原始写法 |
|------|---------|------------|
| 金额 | `_amt` | `_amount`, `_money`, `_value` |
| 计数 | `_cnt` | `_count`, `_num`, `_number` |
| 数量 | `_qty` | `_quantity` |
| 百分比（占整体） | `_pct` | `_percent`, `_percentage`, `_rate`（表示占比时） |
| 比率（部分对部分） | `_rto` | `_ratio`, `_rate`（表示比率时） |
| 日期时间 | `_dt` | `_time`, `_datetime`, `_timestamp` |
| 序号 | `_sn` | `_serial`, `_no`（序列号） |
| 代理键 | `_sk` | `_surrogate_key` |
| 单价/价格 | `_prc` | `_price` |
| 枚举描述 | `_desc` | `_description`, `_name`（枚举含义时） |

**注意**：`_name` 通常保留（如 `shop_name`、`product_name`），仅在明确表示枚举描述时才改为 `_desc`。

## 执行原则

### 第一步：单词拆分

ODS 字段名可能是全小写无分隔的拼接词，需先识别单词边界再处理：

- camelCase / PascalCase → Python 已处理，LLM 直接在 snake_case 初稿上操作
- **全小写拼接**（无大写、无下划线）→ LLM 依据英文词义拆分，确保见名知意：
  - `installationservicefee` → `installation_service_fee`
  - `cofundedcreatorbonusamount` → `cofunded_creator_bonus_amount`
  - `targetingtype` → `targeting_type`
- 拆分原则：优先拆出完整英文词，不强行切断词根

### 第二步：缩写替换

在拆分结果上，逐部分检查是否命中缩写规则：

- 命中则替换：`cofunded_creator_bonus_amount` → `cofunded_creator_bonus_amt`
- 不命中则保留（**不强行缩写规范外的词**）
- 缩写只替换对应语义部分，不改变其余部分

### 第三步：特殊处理

- 固定字段名（见上表）：**原样保留，跳过第一、二步**
- 有歧义（如 `_rate` 是 pct 还是 rto）：优先看语义；无法判断时保留原名，记入 .md 异常文件
- 不确定的拆分：保留 Python 初稿，记入 .md 异常文件，不猜
