# Skill 稳定 ID 依赖方案

> 简单说：别在其他 Skill 里到处写完整版本名。依赖用 `B04`、`C03` 这种稳定编号，真正当前版本由注册表决定。

---

## 1. 现在的问题

现在 Skill 的真实文件夹名是这样的：

```text
B04_子项目管理_v1.0.0
C03_Doris建表语句查询_v1.0.0
C05_1对1DWD单表SQL生成_v1.0.0
```

这对文件管理很好，因为一眼能看到编号、名字和版本。

但如果别的 Skill 也直接写完整名字：

```text
调用 B04_子项目管理_v1.0.0 Skill 创建子项目
```

以后 B04 升级成：

```text
B04_子项目管理_v1.1.0
```

那所有写过旧名字的地方都要改。很麻烦，也容易漏。

所以问题不是“完整名字不好”，而是：

```text
完整名字适合管文件，不适合做依赖引用。
```

---

## 2. 推荐方案

把 Skill 分成两种名字：

| 用途 | 写法 | 是否经常变化 |
|------|------|--------------|
| 依赖引用 | `B04` | 不变 |
| 落盘实现 | `B04_子项目管理_v1.0.0` | 会随版本变化 |

也就是说：

```text
B04 = 稳定编号
B04_子项目管理_v1.0.0 = 当前实现
```

以后其他 Skill 里写：

```text
调用 `B04`（子项目管理）Skill 创建子项目。
```

不要写：

```text
调用 `B04_子项目管理_v1.0.0` Skill 创建子项目。
```

---

## 3. 当前版本怎么找

当前版本从 `workspace-spec.json` 里的注册表找。

例如注册表里有：

```json
"registeredSkills": [
  "B04_子项目管理_v1.0.0",
  "C03_Doris建表语句查询_v1.0.0"
]
```

当正文写：

```text
调用 B04
```

执行时就按规则找：

```text
在 registeredSkills 里找唯一一个以 B04_ 开头的 Skill
```

找到：

```text
B04_子项目管理_v1.0.0
```

那它就是当前要用的 B04。

如果以后注册表改成：

```json
"B04_子项目管理_v1.1.0"
```

正文里的 `B04` 不用改。

---

## 4. 最简单的书写规则

以后跨 Skill 指引统一这样写：

```text
调用 `B04`（子项目管理）Skill 创建标准子项目。
调用 `C03`（Doris建表语句查询）Skill 获取建表语句。
调用 `C05`（1对1DWD单表SQL生成）Skill 生成 DWD SQL。
调用 `C06`（DWD字段信息Excel生成）Skill 生成字段 Excel。
```

规则很简单：

1. 正文第一次出现时写：`编号` + `中文名`
2. 后面可以只写编号
3. 不在普通依赖说明里写完整版本名
4. 路径示例、注册表、命令文件可以继续写完整版本名

---

## 5. 什么地方还要写完整名字

完整名字不是不用了，而是只放在适合它的地方。

| 场景 | 写完整名字吗 |
|------|--------------|
| `.agents/skills/` 文件夹名 | 写 |
| YAML `name` | 写 |
| `workspace-spec.json` 注册表 | 写 |
| `.claude/commands` 文件名 | 写 |
| 脚本路径示例 | 写 |
| 普通跨 Skill 调用说明 | 不写，用 `B04` |
| 历史版本说明 | 可以写 |

一句话：

```text
文件系统和注册表写完整名；依赖正文写稳定编号。
```

---

## 6. 版本升级时怎么办

### 情况一：只是功能增强

比如：

```text
B04_子项目管理_v1.0.0
升级为
B04_子项目管理_v1.1.0
```

但调用方式没变，还是“创建子项目”。

那只需要改：

- B04 文件夹名
- B04 的 YAML `name`
- `workspace-spec.json` 注册表
- `.claude/commands` 对应入口
- 初始化模板里的 B04

不用改：

- C05 里写的 `调用 B04`
- B05 里写的 `调用 B04`
- C07 里写的 `调用 B04`

因为它们引用的是稳定编号。

### 情况二：调用方式变了

比如 B04 创建子项目的参数、输出目录、返回结果都变了，旧调用方式不兼容。

这时才需要通知依赖方更新。

可以给这种调用方式起一个接口名：

```text
project.create@1
```

如果不兼容升级，就变成：

```text
project.create@2
```

只有接口版本变了，才需要检查依赖方。

## 7. 可选增强：写 dependencies

如果想让依赖更清楚，可以在 `SKILL.md` 头部加一小段：

```yaml
dependencies:
  - skill: B04
    name: 子项目管理
    interface: project.create@1
    when: 需要创建标准子项目
  - skill: C03
    name: Doris建表语句查询
    interface: doris.show_create_table@1
    when: 需要查询建表语句
```

这段的作用是：

```text
让人和脚本都知道：这个 Skill 依赖谁，依赖它做什么。
```

一开始可以不强制全量补齐，先从 C05、C06、C07 这些调用链明显的 Skill 开始。

---

## 8. 例子：C05 怎么写

现在可以写成：

```text
如果没有 DWD开发产物 子项目，调用 `B04`（子项目管理）Skill 创建。
```

不要写成：

```text
如果没有 DWD开发产物 子项目，调用 `B04_子项目管理_v1.0.0` Skill 创建。
```

如果加依赖声明：

```yaml
dependencies:
  - skill: B04
    name: 子项目管理
    interface: project.create@1
    when: DWD开发产物子项目不存在
```

---

## 9. 例子：C07 怎么写

C07 是编排 Skill，可以写：

```text
按顺序调用 `C03` -> `C05` -> `C06`。
如果 DWD开发产物 子项目不存在，先调用 `B04`。
```

依赖声明可以写：

```yaml
dependencies:
  - skill: B04
    name: 子项目管理
    interface: project.create@1
    when: DWD开发产物子项目不存在
  - skill: C03
    name: Doris建表语句查询
    interface: doris.show_create_table@1
    when: 查询 ODS/DIM 建表语句
  - skill: C05
    name: 1对1DWD单表SQL生成
    interface: dwd.generate_sql@1
    when: 生成 DWD SQL
  - skill: C06
    name: DWD字段信息Excel生成
    interface: dwd.generate_field_excel@1
    when: 生成字段信息 Excel
```

---

## 10. 最小落地版

如果现在只想先简单落地，不做接口系统，就先执行三条：

1. 跨 Skill 调用统一写 `B04`、`C03`、`C05` 这种稳定编号
2. 第一次出现时补中文名，例如 `B04`（子项目管理）
3. 完整版本名只留在注册表、路径、命令文件和历史说明里

这已经能解决大部分维护成本。

---

## 11. 一句话结论

推荐规则：

```text
依赖用稳定编号，版本交给注册表。
```

展开就是：

```text
B04 负责被依赖
B04_子项目管理_v1.0.0 负责落盘
registeredSkills 负责告诉我们当前 B04 是哪个版本
接口版本只在调用方式不兼容时才升级
```
