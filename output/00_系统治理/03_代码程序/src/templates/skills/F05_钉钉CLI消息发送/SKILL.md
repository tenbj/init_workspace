# F05_钉钉CLI消息发送

## 本地接入

执行前先读 `references/本地接入.md`，确认本项目规则、输入及授权。来源案例不授予本项目权限。

## 这项技能解决什么问题

- 通过官方 `dws` CLI 向已确认的钉钉收件人发送消息，复用授权，防止重复发送，并取得真实回执。
- 可独立调用，也可作为 C19 等已授权工作流的最后通知步骤；本技能不依赖桌面可见状态。

## 先读哪些本地知识

- 正常发送先读 `references/发送流程.md`、`references/输出契约.md`；模型合并通知同时遵循 F05 的 `references/通知规则.md`。
- 使用当前环境可用的官方 `dws` Skill 及对应 contact/chat 参考；实际命令参数以二进制 help/schema 为准。
- **仅当命令缺失、登录/权限失败、网络异常时读取 `references/环境与异常处理.md`；不把安装、扫码或代理配置放进正常流程。**

## 固定动作

1. 接收已授权的收件人、正文、稳定业务请求 ID 和回执路径；通知补齐精确标注 `（codex自动发送）`，不自行扩大收件人或消息数量。
2. 使用已配置 dws 路径与明确账号 profile；复用现有登录态，通过 CLI 查询联系人并核对唯一身份。
3. 检查本请求历史回执：成功则返回，已有 task 则只查状态，结果不明且无 task 则保留未知状态，禁止盲目重发。
4. 按 `scripts/send_message.py` 的预检/执行流程，以固定幂等键发送一次；记录服务器实际返回的任务 ID，查询至 SUCCESS、失败或有界等待结束。
5. 保存精简回执与恢复状态；回复已发送正文及结果，不将 pending 当成功、不将送达当已读。

## 什么时候再读本 skill 的 references

- 正常账号选择、联系人核对、调用与幂等恢复：`references/发送流程.md`。
- CLI 缺失、认证/权限、EOF/TLS、Clash 异常或锁屏条件：仅按异常读取 `references/环境与异常处理.md`。
- 参数、脚本动作和机器回执：`references/输出契约.md`、`assets/消息正文模板.txt`。
- 行为验收与能力落点：`references/行为验收.md`、`references/结构融合索引.md`。

## 边界

- **只允许 dws CLI 操作钉钉。禁止 Codex 视觉、截图识别、浏览器钉钉发送、客户端 UI、坐标点击、模拟按键、剪贴板与直接 curl/HTTP API 替代；CLI 失败也不回退。**
- 不主动发信；需用户明确指令或明确调用的上游技能授权。既有授权持续有效，不重复询问；同名身份不明时只问缺失识别信息。
- 不硬编码联系人 ID、令牌、窗口句柄或一次性配置 UID；测试收件人与正式收件人分开，独立调用没有默认收件人。
- 不读取/输出认证令牌，不每次重新扫码，不改动全局代理或 TUN；环境改动只在异常分支并限明确授权范围。
- 锁屏不影响 CLI 的操作机制，但机器睡眠、断网或授权过期仍会影响结果；未实测不得宣称锁屏发送已验收。
