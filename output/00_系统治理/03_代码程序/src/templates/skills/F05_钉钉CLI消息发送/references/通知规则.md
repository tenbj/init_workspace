
# 模型代码合并通知规则

适用范围：Codex 在用户授权下，为模型代码提交或合并请求发送钉钉通知。

1. 每条自动发送的通知必须包含精确标注 `（codex自动发送）`，不得省略；发送前同时核对正文、标注、收件人和真实合并请求链接。
2. 默认通知正文格式为 `帮合并代码：{合并请求链接}（codex自动发送）`；用户指定其他正文时仍保留自动发送标注，除非用户明确要求例外。
3. 只向用户本次授权的对象发送；测试对象与正式对象分开，不把测试联系人固化为默认收件人。既有明确授权不反复询问。
4. MR 创建后核对真实链接、提交、目标分支和未合并状态才发送；固定业务请求ID和回执，结果不明先通过CLI核查任务，禁止换键盲目重发。发送成功与对方已读、MR 已合并分别陈述。
5. 模型代码发布由 C19 编排，最后通知必须调用 F05，仅通过官方 dws CLI 完成联系人核对、发送与回执查询。
6. 明确禁止 Codex 视觉、截图识别、浏览器钉钉、客户端UI、坐标点击、模拟按键或剪贴板发信；不得以CLI不可用为由回退，也不得直接curl/HTTP API替代。
7. CLI缺失、认证/权限或网络异常只触发 F05 的环境与异常处理分册；不把安装、扫码、代理修改放进正常发布主流程。通知失败保留已创建MR，只恢复通知阶段。
8. 复用现有授权，不重复索要已授权操作的确认；不承诺永久授权。CLI无需桌面输入设备，但睡眠/断网/凭证失效仍会阻断，锁屏未实测时须明确边界。

C19 与 F05 引用本规则；历史客户端发送仅为过去事件，不再构成当前执行路径。

本规则按需由C19/F05读取，不是全局自动发信授权。无默认收件人。
