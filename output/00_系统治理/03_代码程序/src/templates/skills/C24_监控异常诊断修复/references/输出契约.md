# 输出契约

## 落点

复用业务子项目：最终报告放01_问题答疑或02_课题研究，中间SQL、脱敏JSON、完整差异数据、任务核验脚本放03_代码程序；维护目录、B08和B03。不把凭据带入结果或直写output根目录。

scripts仅保留骨架，不内置带本例表名/ID/日期的生产执行程序。复用 C15/C02 等查询能力；复杂核验可在任务目录创建带输出路径参数的只读脚本，先验证适配。

## 必需字段

| 类别 | 内容 |
|---|---|
| 身份 | 环境、监控、平台模型、物理表、真实源、流程/节点、用户终点 |
| 监控 | 完整SQL/阈值、质量值语义、告警时点与当前状态 |
| 加工 | 线上版本、实际SQL/参数、writer/key、日期边界、DAG、原定时 |
| 根因 | 同一真实案例、全量影响，事实/推断/用户确认分别标注 |
| 保护 | 历史来源依据、保护范围/键、证据限制、裁决与未定项 |
| 修复 | 修改前后、preSql参数、映射、保存前后回读 |
| 执行 | 当前计划及替代关系、实际参数、范围/节点/次数、每个实例终态 |
| 核验 | 日期覆盖、逐日数量、键/频次/字段、NULL/精度、全量或抽样 |
| 收尾 | 新监控时间/质量值、工作流/定时、保护集合变化、遗留与恢复入口 |

用户要完整数据/SQL时提供完整脱敏文件，不仅给截断片段。工具无法保存PNG如实说明，不把文本/数据库证据称为已保存截图。

## 完成条件

- 仅解释：因果链可复查，未知业务选择明确；不宣称已修生产。
- 修复：正确版本落地、必要节点成功、实际参数正确、实体符合目标、新监控符合正确口径、原定时恢复或明确不适用。
- 全历史：全部授权范围已处理、逐日完整性及保护范围通过；近期变绿不算结束。
- 合法保留历史可能使目标大于当前源，应按“当前源+确认保留历史”验收，不能为了总数相等删除；原规则不适用须另有证据和授权修订。
- 阻塞时交付已完成、精确缺口和恢复入口，批量逐项标状态，不让一个模型成功覆盖其他未完成项。
