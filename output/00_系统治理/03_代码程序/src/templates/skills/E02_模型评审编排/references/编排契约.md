# 编排契约

## 意图指向

使用 E02 的典型表达：

- “更新标准库后，对模型设计里待评审的模型做标准化”
- “从钉钉模型设计文档开始跑一轮待评审模型评审”
- “先锁定本次标准和模型设计，再只评审目录页标记待评审的 sheet”

E02 的工作对象是一次可追溯的评审编排，不是单一下载任务，也不是 E01 内部标准化算法。

## 反例路由

| 用户意图 | 应走 Skill | 原因 |
|------|------|------|
| 只下载钉钉/阿里文档或维护常用链接 | F01 | 下载、登录、导出、兜底由 F01 管 |
| 已有标准库和模型设计 Excel，只要生成建议版与清单 | E01 | 不需要输入锁定和待评审范围编排 |
| 只问工作区结构、备份、记忆或任务进度 | 对应 B 系列 | 系统治理规则不在 E02 重复维护 |
| 要生成 DWD SQL 或查询 Doris | 对应 C 系列 | 数仓开发链路与模型评审编排无关 |

## SSOT 边界

- Skill 注册、编号解析、版本映射以 `workspace-spec.json` 和 `Skills管理标准.md` 为准。
- 本 skill 只维护“输入锁定与待评审范围”的编排契约。
- F01 是钉钉/阿里文档下载的 SSOT；E01 是模型设计标准化执行的 SSOT。
- 原始 `input/10_模型设计标准化AI行动指南_v1.0.0.md` 只是本 skill 的来源材料，不作为运行时 SSOT 继续引用。

## 交付摘要

E02 完成一次编排后，对用户至少说明：

- 本次锁定的标准库快照路径。
- 本次锁定的模型设计文档快照路径。
- 待评审范围工作簿路径，以及识别到的待评审实体 sheet 数量。
- E01 输出的运行摘要和交付物路径。
