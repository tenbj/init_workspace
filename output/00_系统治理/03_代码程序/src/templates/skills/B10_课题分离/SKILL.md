# B10_课题分离

## 这项技能解决什么问题

- 把情绪化、多目标、混在一起的表达拆成可处理的信息层。
- 只负责“分清楚”：事实、感受、判断、假设、目标、约束、行动意图、风险信号和待澄清项。
- 适用于用户说“帮我拆清楚”“这里面混了哪些问题”“先不要给方案，只分离信息”等场景。

## 先读哪些本地知识

- 需要展开分类定义、输出模板、示例和自检清单时，读 `references/课题分离规则.md`。
- 若本轮还涉及正式课题研究，先执行本 Skill 做分离，再按需转交 `B05`。

## 固定动作

1. 中性复述原始表达，保留用户原意，不评价、不劝导、不急着解决。
2. 把混在一起的信息拆成类型表：事实、感受、判断、假设、目标、约束、行动意图、风险信号、待澄清项。
3. 把信息归到若干“课题层”或“问题域”，只命名边界，不设计实验和行动计划。
4. 标出哪些是已知信息、哪些只是推测、哪些需要用户补充。
5. 输出简洁 Markdown；如果用户要求结构化结果，可按 reference 中的字段给出 JSON 草案。

## 什么时候再读本 skill 的 references

- 需要精确定义分类口径时，读 `references/课题分离规则.md`。
- 需要套用标准输出模板或处理复杂、多段、强情绪文本时，读 `references/课题分离规则.md`。
- 需要判断“是否已经越界到实验/计划/内容化”时，读 `references/课题分离规则.md` 的边界清单。

## 边界

- 不把问题变成实验，不要求每个课题可观察、可验证、可行动。
- 不输出每日计划、下一步行动、指标体系、复盘表或执行清单。
- 不把拆解过程沉淀成小红书选题、内容结构、商业化路径或长期复盘素材。
- 不做医疗、心理、法律、财务等专业诊断；出现风险信号时只标记并建议寻求专业帮助。
- 不把假设写成事实，不把用户的感受道德化。
