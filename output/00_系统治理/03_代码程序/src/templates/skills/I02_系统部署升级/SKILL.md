# I02_系统部署升级

## 这项技能解决什么问题

把已经实现、通过验证的系统变更落实到实际运行服务，避免代码、发布包、数据库与运行进程版本脱节。由 H02 在系统更新完成后调用，也可单独执行；不限定拾序或某一种部署平台。

## 先读哪些本地知识

- 每次必读 `references/扩展说明.md`，确定触发、操作顺序和失败恢复。
- 读取目标项目部署说明、配置加载方式、备份/迁移/启动脚本与最近部署记录，识别真实服务。
- 目标为拾序时再读 `references/拾序部署适配.md`，示例须现场复核。
- 用 `assets/deployment-report.json` 记录部署计划与证据，输出放在对应子项目或项目私有运行目录。

## 固定动作

1. 用 B08 建立或恢复任务，识别机器、环境、服务管理器、数据源、目标提交/版本及已有授权。多个候选无法唯一确定时先完成只读核对。
2. 确认必要测试通过；按 B11/B09 完成本轮已授权的 Git 动作。读取项目维护脚本，Git 发布不能替代部署。
3. 按 B02 备份受影响工作文件及配置，停止或隔离全部相关写入者；确认停写后备份真实数据库并验证备份，再执行增量迁移。
4. 校验迁移结果与数据保留情况；失败立即按恢复规则处理，不启动不兼容版本。无数据变更须记录无需迁移的依据。
5. 使用原服务管理方式启动目标版本，保持必要配置、端口和运行环境；验证新实例就绪后恢复流量与写入。
6. 核对本地/公网版本、业务只读访问、MCP认证和接入分发一致性。可用 `scripts/verify_http.py` 留存公开端点证据，另补认证验证。
7. 回填报告及后续设备更新说明，按 B03 留档、B08 收尾。部署与必需验证都通过才声明运行服务升级完成。

## 什么时候再读本 skill 的 references

- 中断恢复、停写、备份、迁移失败或启动失败时，读 `references/扩展说明.md`。
- 拾序服务、MySQL迁移、FRP及AI接入验证，读 `references/拾序部署适配.md`。

## 边界

- 更新现有运行系统且目标和已有授权明确时继续完整部署，不重复索要授权；用户明确只改原型、只交代码/包或不重启时遵守限制，报告部署未执行。
- 触发是 AI 工作流编排，不是后台定时任务或开机自启。首次交付没有部署目标时明确部署条件，不凭空选择生产环境。
- 不把 Release、静态清单或 health 单独通过当成部署成功；不把服务端升级当成各设备 Skill 已更新。
- 不输出秘密、不清空真实库、不自动物理回滚数据库；保留失败现场，恢复须满足兼容与数据保护条件。
- 不改原型、无关服务、网络或启动策略；确需调整入口时转 I01。仅创建或修改本 Skill 不触发真实迁移重启。
