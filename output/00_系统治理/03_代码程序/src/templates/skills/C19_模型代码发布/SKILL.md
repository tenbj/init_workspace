# C19_模型代码发布

## 本地接入

执行前先读 `references/本地接入.md`，确认本项目规则、输入及授权。来源案例不授予本项目权限。

## 这项技能解决什么问题

- 将已确认的数仓加工 SQL 发布到 GitLab：更新主线、按库/域/分层落位、提交分支、创建并核对 MR、通知合并人。
- 消费 C18 等开发流程的正式加工文件；不重新开发 SQL，不发布数据平台模型或调度。

## 先读哪些本地知识

- 先读目标仓库的适用规范、`references/发布流程.md`、`references/输出契约.md`。
- 通知遵循 F05 的 `references/通知规则.md`，交给 F05 执行。
- 按工作区入口执行 B08；改动前按 B02 备份，收尾按 B03 留证。

## 固定动作

1. 确认正式 SQL、规范表名、业务库、域、分层、中文模型名及新增/修改；运行 `scripts/prepare_release.py` 生成只读发布计划。
2. 检查仓库状态和远端，在干净工作区回到已确认目标基线并快进拉取；保护已有修改，按发布流程处理分叉和同名分支。
3. 只将加工文件放入 `{库}/{域}/{分层小写}/{规范表名}/{规范表名}.sql`，保留模型目录，不复制建表或其他交付物。
4. 创建或核实本次分支 调用方已确认的工作分支（无其他约定时用`codex/`前缀）；核对并仅暂存本次路径，检查提交内容和来源一致性后提交。
5. 推送本次分支并创建/复用目标为已确认基线的 MR；回读真实链接、源/目标分支、提交号及状态，确认不是重复或过期 MR。
6. 将真实 MR 链接、已确认收件人、正文、稳定业务请求 ID 传给 F05；**最后通知只能用钉钉 CLI，禁止 Codex 视觉或任何桌面/浏览器发送回退。**
7. 分别记录代码、MR、通知结果；通知失败只恢复通知阶段，不重复提交、建 MR 或发送；交付精简发布回执。

## 什么时候再读本 skill 的 references

- 执行 Git、处理已有改动、分支冲突、MR 重复与恢复：`references/发布流程.md`。
- 核对输入、文件边界、提交消息与回执：`references/输出契约.md`、`assets/发布输入示例.json`。
- 检查行为或重放 SQP 案例：`references/行为验收.md`。
- 查找能力结构：`references/结构融合索引.md`。
- 钉钉环境或网络异常：交 F05 按其异常路由处理，不在此展开安装、扫码或 Clash 配置。

## 边界

- 本地发布仓库由调用方明确提供；不要把只读源码镜像 `input/data-assets` 当发布仓库，不调用 C01 的强制覆盖流程替代安全更新。
- 不 `git add .`，不自动 stash、丢弃改动、强推、直接推送 master 或合并 MR；不执行数据库 DDL/DML。
- 已授权的提交、推送、创建 MR 和通知连续完成，不对相同步骤反复索要许可；输入缺失、同名身份或未知差异才澄清。
- 发布没有默认收件人；正式或测试对象均从本任务明确授权读取，不同时扩大收件范围。
- 禁止把“推送成功”“MR 已建”“通知已送达”“对方已读”“MR 已合并”混为一个状态。
