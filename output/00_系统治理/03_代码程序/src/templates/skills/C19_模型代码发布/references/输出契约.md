# 输入与输出契约

输入必需：repo、source_sql、database、domain、layer、table、model_name、change_type、remote、base_branch。修改时必需 change_summary；远端和目标基线从目标仓库及本任务确认，不沿用来源默认值。branch和commit_message可按目标仓库规范显式传入；默认工作分支使用codex前缀，默认提交标题为中文类型化格式。库/域/层来自已确认模型元数据；不能用 active IDE 文件替换真实发布对象。

只读预检：

```text
python .agents/skills/C19_模型代码发布/scripts/prepare_release.py --input <发布输入.json> --output <任务目录>/发布计划.json
```

计划输出：源文件与 SHA256、唯一目标相对/绝对路径、分支、提交/MR标题、远端及目标分支。计划不是完成回执。

暂存后使用相同输入并加 `--check-staged`，校验暂存文件集合、`diff --cached --check` 与正式源内容（仅容许 CRLF/LF 转换）。成功后再提交；提交后还需回读实际提交对象，不能用计划或暂存校验冒充提交验收。

正式任务目录复用已定位子项目的 `03_代码程序/<本次发布目录>/`，只落：

- `发布回执.json`：基础提交、源哈希、目标文件、源/目标分支、提交SHA、远端SHA、MR URL/ID/状态、验证结果、通知回执路径、分阶段状态与恢复下一步。
- `发布说明.md`：结果和必要的未完成项，可更新项目已有实操报告而不制造重复文件。
- `通知回执.json`：由 F05 管理，发布技能仅引用。
- 必要中间件在 `过程材料/`，不得把其内容复制进 GitLab 仓库。

阶段状态应分开：code=prepared/committed/pushed/no_change，mr=unverified/opened/merged/failed，notification=not_requested/pending/unknown/failed/success。通知状态不覆盖代码状态。

所有输出脚本必须接收明确输出路径，不写 output 根目录、不写入凭证、代理完整配置或登录令牌。源码处理 SQL 中的中文注释保持原文，不在发布阶段清洗或改写 SQL。
