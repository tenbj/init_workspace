# 子项目管理技能（Sub-Project Management）

## 何时使用此技能

**每当以下情况发生时，必须先执行此技能**：
- 用户提出一个新的知识话题（无论是否要求输出文件、无论是否使用"研究"等措辞）
- 方向规则的话题归属判定结果显示，本提问不属任何已有子项目
- 尚未存在对应主题的子项目文件夹

---

## 命名规则

```
output\{编号}_{主题}
```

| 部分 | 说明 | 示例 |
|------|------|------|
| `编号` | 子项目顺序编号，由脚本按 `output\` 下现有最大编号自动递增生成，默认至少 2 位 | `01` |
| `_` | 固定分隔符 | `_` |
| `主题` | 用中文描述话题核心，简明扼要（3~10字） | `工作区初始化工具` |

**完整示例**：`output\05_工作区初始化工具\`

> 子项目 live 文件夹保持稳定，整体版本写入 `版本记录.md`，历史快照写入 `.history/output/{稳定子项目文件夹名}_v{x.y.z}_{yyyyMMddHHmmss}/`。
> 子项目内部固定分为 `01_问题答疑`、`02_课题研究`、`03_代码程序` 三个稳定子文件夹。

## 执行流程

### 第 1 步：确认主题名称

向用户确认（或根据上下文自行判断）本次研究的主题名称，例如：
- `睡眠优化`
- `投资心理学`
- `GTD时间管理`

### 第 2 步：调用创建脚本

使用 `run_command` 工具执行：

```powershell
powershell -ExecutionPolicy Bypass -File "e:\my_project\知识研究\.agents\skills\B04_子项目管理\scripts\new_project.ps1" -Topic "<主题名称>"
```

**示例**：
```powershell
powershell -ExecutionPolicy Bypass -File "e:\my_project\知识研究\.agents\skills\B04_子项目管理\scripts\new_project.ps1" -Topic "睡眠优化"
```

### 第 3 步：读取脚本输出，记录文件夹路径

脚本成功执行后，输出示例：
```
[OK] Created project folder: e:\my_project\知识研究\output\06_睡眠优化
[OK] Created sub-folder: 01_问题答疑
[OK] Created sub-folder: 02_课题研究
[OK] Created sub-folder: 03_代码程序
[OK] Created version record: 版本记录.md
[OK] Created catalog: 目录.md

==========================================
  New Sub-Project Created
==========================================
  Topic    : 睡眠优化
  Folder   : 06_睡眠优化
  Path     : e:\my_project\知识研究\output\06_睡眠优化
  Created  : 2026-05-04 02:30:15
==========================================
```

### 第 4 步：初始化 .memory 记忆目录

在 `.memory/对话记录/` 下初始化当前子项目对应的对话记录文件：

```
.memory\对话记录\{子项目文件夹名}.md
```

使用以下初始内容创建该文件：

```markdown
# 对话记录 · {主题名称}

> 记录本子项目所有对话的关键摘要，按时间追加。

---
```

> 说明：Rule、Skill、脚本、备份、Memory 治理等系统对话，不写入该文件，统一由 `B03` Skill 路由到 `.memory/系统记录/` 下的五个固定文件。

### 第 5 步：更新全局知识地图

`new_project.ps1` 会自动用 UTF-8 API 更新 `.memory/全局知识地图.md`：先把旧地图保存到 `.history/.memory/全局知识地图/`，再在表格中追加一行：

```
| {主题} | {子项目文件夹名} | {创建日期} | 进行中 | - |
```

若全局知识地图不存在，用以下模板创建 `.memory/全局知识地图.md`：

```markdown
<!-- memory-version: 1.0.0 -->
# 全局知识地图

> 所有研究子项目的总索引，新建子项目时自动更新。

| 话题 | 子项目文件夹 | 创建时间 | 状态 | 核心结论（一句话） |
|------|------------|---------|------|----------------|
| {主题} | {子项目文件夹名} | {创建日期} | 进行中 | - |
```

### 第 6 步：在对应子文件夹中开始输出文件

所有本次话题相关的输出文件，都必须放在刚创建子项目的三个分类子文件夹内，**不得直接放在 `output\` 根目录，也不得平铺在子项目根目录**。

新建内容文件时：
1. 先判断分类：问题答疑 → `01_问题答疑`；结构化研究 → `02_课题研究`；代码/程序 → `03_代码程序`
2. 调用 `next_number.ps1 -SubFolder "01|02|03"` 获取该分类内下一个可用编号
3. `01/02` 按 `{编号}_{标题}.{扩展名}` 格式创建文件，例如 `01_睡眠基础知识.md`；`03` 可保留代码/配置/构建产物原生命名
4. 同步更新 `目录.md` 对应分节，追加一行；文件列链接格式见 `工作区骨架规格.md` 固定文件节
5. 首次落盘日期与最近更新日期相同

## 往已有子项目添加新文件

```powershell
powershell -ExecutionPolicy Bypass -File "e:\my_project\知识研究\.agents\skills\B04_子项目管理\scripts\next_number.ps1" -ProjectPath "output\06_睡眠优化" -SubFolder "02"
# 返回: 04  （表示下一个可用编号是 04）
```

然后用返回的编号在目标子文件夹内创建文件、更新 `目录.md` 对应分节。

## 规范化老项目到新结构

```powershell
# 先预览（DryRun）
powershell -ExecutionPolicy Bypass -File "e:\my_project\知识研究\.agents\skills\B04_子项目管理\scripts\normalize_project.ps1" -ProjectPath "output\00_系统治理" -DryRun

# 确认无误后执行
powershell -ExecutionPolicy Bypass -File "e:\my_project\知识研究\.agents\skills\B04_子项目管理\scripts\normalize_project.ps1" -ProjectPath "output\00_系统治理"
```

规范化脚本会自动：
- 按创建时间排序内容文件，加上 `{NN}_` 编号前缀
- 生成 `目录.md`
- 在 `版本记录.md` 中追加规范化记录

### 子项目内部结构（固定）

| 路径 | 类型 | 命名规则 | 维护方式 |
|------|------|---------|---------|
| `目录.md` | 固定文件 | 名称不变 | 新建/更新内容文件时按三节同步维护 |
| `版本记录.md` | 固定文件 | 名称不变 | `B02` Skill 自动维护 |
| `01_问题答疑/` | 分类文件夹 | 稳定名称，不带版本号 | 存放问答型输出 |
| `02_课题研究/` | 分类文件夹 | 稳定名称，不带版本号 | 存放结构化研究输出 |
| `03_代码程序/` | 分类文件夹 | 稳定名称，不带版本号 | 存放代码、脚本、程序资产 |
| `01/02: {NN}_{标题}.{扩展名}` | 内部文件 | NN：两位编号，按所在分类内落盘顺序递增 | 问答/研究产出 |
| `03: 工具链原生命名` | 内部文件 | 保留工具链原生命名 | 代码、配置、构建产物 |

> `目录.md` 固定分为 `01_问题答疑`、`02_课题研究`、`03_代码程序` 三节，每节表格格式：`| # | 文件 | 说明 | 首次落盘 | 最近更新 |`；文件列链接格式见 `工作区骨架规格.md` 固定文件节。

## 禁止行为

- ❌ 未创建子项目文件夹，直接在 `output\` 根目录下输出文件
- ❌ 将内容文件平铺在子项目根目录（必须进入三个分类子文件夹之一）
- ❌ 手动指定或修改编号（必须由脚本自动按顺序生成）
- ❌ 在 live 子项目、分类文件夹或 01/02 内容文件名中写 `_v{x.y.z}` 版本号
- ❌ 把 `03_代码程序` 拆成大量强制文件级版本
- ❌ 手动指定 live 目录版本号（版本统一写入 `版本记录.md`，后续由备份脚本维护）
- ❌ 同一话题重复创建多个文件夹（先检查是否已存在）
- ❌ 使用英文或拼音命名主题（必须使用中文）
- ❌ 新建子项目后不同步初始化 .memory 和更新全局知识地图
- ❌ 用 Trae Write / SearchReplace 工具修改本 Skill 的 `new_project.ps1` 脚本（见下方编码约束）

---

## .ps1 脚本编码约束

> 本 Skill 下所有 `.ps1` 脚本（`new_project.ps1`、`next_number.ps1`、`normalize_project.ps1`）必须保持 UTF-8 with BOM。Trae Write/SearchReplace 会破坏 BOM，导致中文乱码。

修改脚本时，必须通过 ASCII-only 临时脚本或 RunCommand 调用 `[System.IO.File]::WriteAllText(path, content, [System.Text.UTF8Encoding]::new($true))` 写入。被破坏时通过读写 API 恢复 BOM。

详见 `version-control-rules.md` 中的「.ps1 脚本编码约束」章节。
