# C11_ODS表粒度主键核验

## 本地接入

执行前先读 `references/本地接入.md`，确认本项目规则、输入及授权。来源案例不授予本项目权限。

## 这项技能解决什么问题

- 面向 Doris / ODS 单表，识别业务粒度、核验业务主键是否存在，并确认技术唯一主键。
- 把候选组合、已确认业务键和不存在业务键严格区分：一个候选组合不唯一只否定该候选，必须继续探查其他有业务含义的字段。
- 输出可追溯的 SQL 证据、重复原因归属、清晰的结论总览及唯一性检验 SQL 配置。

## 先读哪些本地知识

- 涉及生产 Doris 查询时，先读并执行 C02；需要建表语句时，先读并执行 C03。
- 需要查 ODS 同步脚本或 data-assets 血缘时，按任务需要读取 C01；仅在注册表存在C09时使用其血缘Excel扩展。
- 需要输出完整报告结构时，再读 `references/报告口径.md` 和 `assets/核验报告模板.md`。
- 交付前读 `references/输出契约.md`，使用 `assets/唯一性检验模板.sql` 生成唯一性 SQL。

## 固定动作

1. 明确只核验用户指定的一张表；独立ODS任务不扩展下游。由C17指定非ODS实体时复用核验方法和模板，按真实层级及实际写入表报告，不混入ODS结论。
2. 读取表结构、源脚本和样例字段含义，先写清业务场景，再提出业务粒度字段组合。由C17治理的旧表/仓库代码与部署不一致时，按本任务已有明确授权从模型→关联ETL→海豚真实SQL节点取完整代码，以实际写入表及加工逻辑为准探查；保留登记表/实际表映射、节点版本及源码证据，不沿用旧表样本冒充新表结论。
3. 先在一个完整批次核验并探索唯一业务键组合：候选不唯一时查看组内完整业务字段差异，依据真实业务语义补充或替换字段再测。找到唯一候选后固定组合，逐批核验至全量；后续失败批继续诊断，若修订组合须回验已过批次。只有完整业务字段仍有重复等充分证据，才明确不存在可用业务键；单候选失败或证据不足不能写“无”。大表超时/内存取消后分批并细分失败批继续完成。
4. 唯一候选须继续做最小性核验：逐个剔除字段，在同一完整范围复核剩余组合的唯一性及业务身份含义；仍满足两者就删去冗余字段并继续，最终组合再次全量验证。保留每个字段不可删除的重复反例或业务身份依据；未完成此步不能称“已确认最小业务键”。最小指无可删除的冗余字段，不默认表示所有候选中字段数全局最少，详见核验流程。
5. 按 DDL 唯一键、空值数、`COUNT(DISTINCT 技术主键)` 核验技术唯一主键。
6. 如存在重复，把原因放入业务粒度或业务主键章节下说明；如需取最新，只说明当前态处理方式，不改写原始 ODS 主键结论。
7. 业务主键已确认且最小性核验完成时，按固定模板填入库表、业务键字段及范围，默认交付独立唯一性检验 `.sql`，并在报告中附完整 SQL 和配置口径。保留 `COUNT(*) AS cnt`，最终只返回重复组数 `quality_value`；主键无或证据不足时明确记录未生成原因。

## 边界

- 不把 `local_created_time`、`etl_dt`、`first_inserted_dt`、`last_updated_dt` 等采集/同步时间默认写进业务粒度。
- 不把“取最新后唯一”表述为“原始 ODS 表存在业务主键”。
- 不使用未解释的 SQL 占位概念；必须给字段组合补中文释义。
- 不为了 DWD 建模擅自扩大本表核验范围。
- 唯一性 SQL 只使用已确认业务键，不用技术键或取最新键替代；生成配置不代表已在平台配置或运行。
