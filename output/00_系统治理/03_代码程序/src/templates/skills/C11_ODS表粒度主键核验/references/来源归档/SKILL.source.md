# C11_ODS表粒度主键核验

## 这项技能解决什么问题

- 面向 Doris / ODS 单表，识别业务粒度、核验业务主键是否存在，并确认技术唯一主键。
- 把“业务粒度字段组合”和“业务主键”严格区分：字段组合不唯一时，结论必须写“业务主键：无”。
- 输出可追溯的 SQL 证据、重复原因归属、清晰的结论总览及唯一性检验 SQL 配置。

## 先读哪些本地知识

- 涉及生产 Doris 查询时，先读并执行 C02；需要建表语句时，先读并执行 C03。
- 需要查 ODS 同步脚本或 data-assets 血缘时，按任务需要读取 C01 / C09。
- 需要输出完整报告结构时，再读 `references/报告口径.md` 和 `assets/核验报告模板.md`。
- 交付前读 `references/输出契约.md`，使用 `assets/唯一性检验模板.sql` 生成唯一性 SQL。

## 固定动作

1. 明确只核验用户指定的一张表；不要把 DWD 建设结论混入 ODS 主键结论。
2. 读取表结构、源脚本和样例字段含义，先写清业务场景，再提出业务粒度字段组合。
3. 按 `COUNT(*)` 与 `COUNT(DISTINCT 粒度字段组合)` 核验业务主键；二者不等时，业务主键结论写“无”。
4. 按 DDL 唯一键、空值数、`COUNT(DISTINCT 技术主键)` 核验技术唯一主键。
5. 如存在重复，把原因放入业务粒度或业务主键章节下说明；如需取最新，只说明当前态处理方式，不改写原始 ODS 主键结论。
6. 业务主键已确认时，按固定模板填入库表、业务键字段及范围，默认交付独立唯一性检验 `.sql`，并在报告中附完整 SQL 和配置口径。保留 `COUNT(*) AS cnt`，最终只返回重复组数 `quality_value`；主键无或证据不足时明确记录未生成原因。

## 边界

- 不把 `local_created_time`、`etl_dt`、`first_inserted_dt`、`last_updated_dt` 等采集/同步时间默认写进业务粒度。
- 不把“取最新后唯一”表述为“原始 ODS 表存在业务主键”。
- 不使用未解释的 SQL 占位概念；必须给字段组合补中文释义。
- 不为了 DWD 建模擅自扩大本表核验范围。
- 唯一性 SQL 只使用已确认业务键，不用技术键或取最新键替代；生成配置不代表已在平台配置或运行。
