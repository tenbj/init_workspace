# 输出契约

运行后新增真实平台PNG及关联元数据，按`运行截图留证.md`接入HTML缩略图与页内放大弹窗。截图验收独立于SQL平台完成；批次交付由C17统一编排。

成果写入已定位的数仓质量子项目，每个目标保留独立目录。不将执行产生的证据写入 Skill 自身。

## 必须交付

1. 采用的原始 SQL 文件（可引用已有 C14 文件，不无意义复制）。
2. 新建/更新路径：保存回读的 SQL 全文与 platform_evidence.json，至少包含 assets 模板字段。快照/截图只保留相关页面并避免登录态和个人信息无关扩散。
3. 平台结论：正确模型的指标已保存SQL并回读一致，即C15已完成。通知、周期、运行结果另列，不作为平台完成门槛。
4. 未完成时保留具体卡点、已完成阶段、是否已提交、当前页面和待解问题，不能只写“失败”。

## 证据填写

复制 assets/平台证据模板.json 到本次成果目录并填写。evidence_refs 记录现场快照/截图路径或工具观察摘要，不能用历史案例伪装。model_identity_verified 等布尔值只有在对应证据成立时才能设 true。

- created/updated：平台需要保存回读SQL证据；updated仅限已授权更新。通知和运行证据独立，不要求已有执行结果才算平台完成。
- skipped_existing：需要精确同名同模型唯一存在证据；不虚构通知和执行验证，其他未读取字段保持 null。
- 尚未完成：保留 pending 和 blocker，脚本应报不完整；待问题解决后再次核验，不因此删除原始证据。
- model_key 是本次现场确认的技术表或平台模型标识，expected/actual 必须一致，不预置历史 ID。
- 时间使用带时区的 ISO 8601，按平台时钟记录；正常和异常都可通过交付一致性校验。脚本只检验证据字段之间是否自洽，不能代替浏览器真实取证。

## 交付核验脚本

```text
python <C15目录>/scripts/verify_delivery.py --evidence <成果目录>/platform_evidence.json --expected-sql <原始SQL> --saved-sql <回读SQL> --output <成果目录>/delivery_check.json
```

默认 --check platform，仅以模型、连接、策略/条件和SQL保存回读判定平台完成。--check notification 或 --check execution 分别追加检查通知或本次运行；报告分列platform_passed、notification_passed、execution_passed。默认平台passed为true不代表通知或运行通过。已有跳过时只传 --evidence 与 --output（只适用platform查重处理）。其他情况要求完整SQL参数。退出码0表示所填写的交付证据自洽，1表示不完整或不一致，2表示输入读取失败；禁止以脚本通过替代真实页面核验。

## 最终回复

用简短中文分别给出平台完成/跳过状态、通知配置状态和运行结果，另列业务线、周期及实际监控时间，附 SQL 和证据/报告链接。跳过时只报告核实过的内容。平台无法访问或操作不明时先提具体问题并保留进度，收到指导继续执行。
