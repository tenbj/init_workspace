# 生成与验收

## 生成

依赖 Python 3.10+ 与 `markdown-it-py`。优先使用已有解释器；缺失则使用任务虚拟环境，不擅自改系统环境。

```powershell
python -X utf8 '.agents/skills/C13_模型使用说明生成/scripts/build_manual.py' --input 'output/<子项目>/02_课题研究/01_模型使用说明.md' --output 'output/<子项目>/02_课题研究/01_模型使用说明.html' --status draft --check 'output/<子项目>/03_代码程序/模型使用说明/<模型>/生成校验.json'
```

替换路径，不照抄占位符。更新已有文件先按 B02 备份，再加 `--force`。脚本只渲染文档，不查询数据库，不执行文档中的 SQL。

Markdown 使用一个 H1、九个固定 H2 和按需 H3；模板二级内容可替换。支持表格、引用、代码块、列表和链接。H2/H3 按顺序生成 `section-N` 唯一锚点，正文若引用 `#section-N`，修改标题后重新核对。原始 HTML 按文字显示。

本地 PNG/JPEG/GIF/WebP 可内嵌；图片必须位于 Markdown 目录及其子目录，不能跨目录或使用远程图片、SVG。引用外部资料的普通链接允许保留，仅点击时联网。

## 三层验收

### 内容

1. 目标库表与环境明确；分层和模型类型判断有据，未知项不冒充结论。
2. 一行的业务含义与键分开；字段覆盖当前取得的结构；代码与生产差异可见。
3. 指标统计条件、币种单位、NULL含义、可加性和时间窗口不含推测默认值。
4. 关联给完整条件和版本/有效期，解释一对多与扩行；查询规则与形成规则不重复堆写。
5. 九章都存在；缺失、不适用、冲突分别标注；关键结论可沿证据ID追溯。
6. 示例 SQL 标状态、参数、预期粒度与校验方法；没有实际执行证据不能写已执行。
7. 首页状态与适用范围一致。草稿也可完整交付，不等于业务已全部确认。

### 生成文件

- `生成校验.json` 的 SHA-256 对应交付 Markdown；HTML 从同一源生成。
- 脚本验证单 H1、九章标题和顺序、目录锚点、图片内嵌；拒绝 `limited/final` 文档中的模板占位符。标题中的“待确认”不是占位符。
- 这些检查只能证明结构与渲染，不验证 SQL 或业务真相；状态仍需前述内容验收。
- 目录链接和 SQL 的 `<`、`>`、中文、长字段正确显示；没有自动加载的外部脚本、样式和图片。

### 浏览器

可用浏览器时检查桌面两栏、窄屏菜单、目录跳转/高亮、宽表格与 SQL 滚动、打印隐藏导航和按钮。无浏览器则做静态检查，并明确“未做浏览器验证”，不能把静态检查冒充交互验收。

## 简短行为核对案例

- 仅有源码：继续写有据草稿；调度和数据验证状态留白，不要求先人工填完字典。
- 日库存快照：必须提醒未确认时不能跨日累加；不能把余额套成交易流水。
- 映射模型：解释多对多与完整匹配条件，不仅罗列字段。
- DDL 与源码不同：第9章列双方版本及影响，不抹平冲突。
- 近30天估算额除30：说明估算日均，不写实际当日销售额。
