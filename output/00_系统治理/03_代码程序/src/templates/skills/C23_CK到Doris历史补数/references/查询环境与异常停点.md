# 查询环境与异常停点

## 数据库连接选择

先确认目标引擎与权限身份，再通过 `.envs/env_manager.py route <连接ID>` 定位当前工作区配置；实际查询时用 `run <连接ID> -- <命令>` 或 `load_connection` 在进程内读取，不输出凭据。已确认连接缺失或不完整时停止该连接，不扫描旧 input 凭据文件作为回退。

| 对象 | 连接 ID | 查询方式 |
|---|---|---|
| Doris 生产数仓 | `doris.prod.readonly` | C02；建表语句走 C03 |
| ClickHouse 历史源 | `clickhouse.source.readonly` | ClickHouse 驱动 |
| PostgreSQL 源 | `postgres.source.readonly` | PostgreSQL 驱动 |
| SAAS / KD SQL Server 源 | `sqlserver.saas.client` / `sqlserver.kd.client` | 按实际源选择，当前任务只读；登记的 client 不代表权限已核验 |
| 平台 MySQL 元数据 | `mysql.dataplatform.reader` | MySQL 驱动；不属于数仓，不调用 C02 |

这里只迁移数据库连接。网页登录入口不等同于数据库连接，仍按已授权入口恢复，禁止把令牌复制到本分册。

## 本次事故复盘

SBCR首例在执行 C03 时，`import pymysql` 报 ModuleNotFoundError，尚未连接数据库。此前成功脚本先把现有 `.deps` 加到 `sys.path`，再加载 C02；本次换成直接用 bundled Python 调用 C03，遗漏同一依赖路径。旧 `.deps/pymysql/__init__.py` 实际存在。

直接原因是启动方式不一致。流程缺口是 C23 仅要求使用 C02/C03，没有要求核对解释器、依赖位置和本次进程是否能实际导入；此前60项离线验证覆盖分段与参数，却未覆盖真实查询入口。由此得到两条教训：包存在不等于当前解释器可见，模板/参数检查通过不等于执行环境可用。

这不是已证实的 Doris 服务、账号、网络或数据异常。C02 报错里的“先 pip install”是通用提示，不应当成根因或必须执行的修复指令。

## 优先复用已验证方式

执行前先查看前一成功案例的真实调用记录，复用适用于当前工具和权限环境的解释器、依赖加载、查询入口、页面定位、参数读取及证据保存方式。文件存在本身不能证明当时使用了哪种工具。仅替换本例表名、工作流ID和输出路径，不照搬前例日期、数量或补数范围。确需更换方式时先说明原因、变化和验证方法；不得为省一步操作擅自换入口。

复用旧辅助脚本时，先通过实际文件清单或已核实路径定位，再读取；不得按命名习惯猜造文件名。文件未找到是本地定位问题，不据此推断数据库失败。按下方业务停点边界处理；已确认没有数据影响的本地定位问题自行恢复并校验。

SBCR第二次停点：SPPR先让浏览器返回筛选后的工作流参数，再由本地文件工具保存；SBCR改为浏览器 evaluate_script 带 filePath 直接保存，触发浏览器工具自身的workspace roots校验拒绝。这是证据落盘入口不一致，不是Doris连接、数据库权限或数据异常。

本流程优先沿用已验证方式：浏览器仅返回工作流标识及业务所需的 sql、columns、table、StartTime、EndTime、preSql 等参数；本地文件工具保存JSON并回读校验。不得返回完整连接配置、密码、带令牌的登录URL或不必要的taskParams。不得通过调整浏览器权限来绕过路径校验。

浏览器返回isError、命令非零退出码或业务响应失败时，立即中止后续依赖动作；即使工具调用本身正常返回，也必须检查内部状态。不得在同一编排中忽略错误继续计数、修改页面或运行工作流。先分类：常规操作与工具问题自行修复验证；涉及业务选择、执行范围或已发生数据影响时才报备确认。保存成功不代表源端核验或补数验收完成。

## 查询前的离线预检步骤

每次新会话、切换解释器、换脚本入口或恢复中断任务时，先检查本次实际运行环境。同一进程/解释器及依赖路径未变化时，可复用刚取得的预检结果。

1. 从此前成功调用或当前运行时配置确认 Python 可执行文件与依赖路径；不凭系统 `python`、不随意换解释器，不递归搜集用户电脑上的包。
2. 优先检查当前解释器的导入能力。若有明确、可信的既有依赖目录，显式传入它；不要把某个旧 output 路径写成所有任务的固定依赖。
3. 使用 `scripts/query_runtime.py --check-only`：记录解释器、实际 pymysql 文件位置和版本，导入 C02 类并检查 C03 入口；不实例化客户端、不读取凭证、不连接数据库。
4. 通过后，C03 查询沿同一个入口 `--ddl-table ... --output-dir ...` 执行。它在实际查询进程中再次预检，并在同一进程运行 C03，防止预检成功、另起进程又丢失 sys.path。
5. 其他 C02 查询脚本也必须显式复用同一解释器和依赖路径；单独进程不会继承上一脚本的 sys.path。不得仅凭另一终端的 import 成功宣称当前查询环境可用。

PowerShell 调用范式（变量须先设为本任务已核实路径；不在命令中传凭证）：

```powershell
& $queryPython $runtimeScript --deps-dir $verifiedDeps --check-only
# 只有预检通过且当前授权允许查询时才执行下一条。
& $queryPython $runtimeScript --deps-dir $verifiedDeps --ddl-table $qualifiedTable --output-dir $evidenceDir
```

`--check-only` 的 ready 仅表示本地加载通过，不代表网络连接成功、表存在、查询权限足够或数据验收通过。没有既有外置依赖需求时可不传 --deps-dir；预检失败返回退出码2，不自动安装、不回退重试。运行入口仅包装原 C03，不绕过 C02 只读守卫，也不构造新的数据库连接。

## 异常分类与可采取动作

| 分类 | 识别证据 | 下一步 |
|---|---|---|
| 模块当前不可见 | MODULE_NOT_VISIBLE；导入前失败 | 核对解释器、已知包路径和旧成功调用；不要声称包不存在 |
| 指定目录无包 | DEPENDENCY_PATH_INVALID | 核对路径；确认确无可用环境后再提出安装方案，不自动 pip install |
| 加载来源不一致 | DEPENDENCY_ORIGIN_MISMATCH | 新进程使用已核实路径；不原地替换已加载模块 |
| 导入/注册异常 | IMPORT_OR_REGISTRY_ERROR | 核查具体版本、传递依赖及稳定编号；不换账号碰运气 |
| 网络/认证/权限异常 | 实际连接或执行查询后返回相应错误 | 记录发生阶段与脱敏错误，不能由导入失败推断此类问题 |
| 数据/流程不适配 | 无日期可分段、粒度不一致、范围不可安全重写等 | 报出证据和方案差异，等待用户决定，不强套历史补数模板 |
| 写入阶段失败 | 已执行preSql或部分导入 | 按报错恢复分册核对数据影响；先遵守本批异常停点，不擅自修复重跑 |

## 停点与报备（2026-10-22用户确认边界）

判断标准：能否在已确认方案内修正，并确认没有造成数据影响。能做到的自行处理；涉及业务选择、范围变化或已发生/疑似数据影响的，停止后续批次，先只读诊断再报备确认。不要将代理自身操作失误转化为反复请求用户授权。

| 情况 | 处理 |
|---|---|
| 名称/描述填错、搜索词追加、复制粘贴不完整 | 自行修正并完整回读；保存前后均核对，不重复询问 |
| 浏览器卡顿、连接中断、依赖路径或证据保存问题 | 复用已验证方式恢复；先核实保存和提交状态，避免重复运行，不绕过权限 |
| 参数录入与已确认版不一致，尚未运行 | 自行恢复为已确认内容，逐项完整核验后继续 |
| 只读查询的语法/别名/路径等操作问题 | 在既有只读范围内自行修正验证，不改变查询口径，不把错误当业务结论 |
| 修复会改变已确认SQL逻辑、字段映射、补数基准或日期范围 | 停下列明具体改动和影响，用户确认后执行 |
| 已提交任务失败、实际运行参数不符、可能误删或部分导入 | 停止后续批次；先查日志和数据库影响，报备后等待修复重跑确认，不假设失败已回滚 |
| 验收出现缺失、重复、保护范围受影响、结果不符 | 停下列出实际差异与建议，等待用户判断 |
| 整表刷新、来源不同、模型不适配，或需改分区/表结构/日常任务 | 提供具体方案及影响，确认后执行 |

- 遇到真实业务/执行异常可自行完成必要只读诊断，不为每次查日志、查数量、定位根因重复提问；不擅自修复生产写入或提交后续批次。
- 报备包括当前表和步骤、预期与实际、已知原因与不确定项、数据库影响、实例状态及最小修复方案。
- 返回不明先核实状态，不再次点击运行。疑似超范围执行时先采取可用停止措施，再核对影响并报备。
- 名称、描述、搜索框先全选清空再录入，保存前核对全文，保存后回读名称、描述和六参数；不能只核对六参数。
- 不自动安装/升级依赖、修改全局环境、凭证或核心标准；无法在现有授权内恢复时说明具体阻塞。
- 每例验收回写后仍等待用户确认再进入下一例；本边界不解除逐例确认。
