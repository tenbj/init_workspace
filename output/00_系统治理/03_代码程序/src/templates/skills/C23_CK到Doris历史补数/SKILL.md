# C23_CK到Doris历史补数

## 本地接入

先遵循当前工作区规则；按 B12 精确路由所需连接，按 B04/B08/B03 管理产物与进度。来源案例、账号、路径、人员和历史授权均不自动继承。

## 这项技能解决什么问题

- 从 Excel 的 CK/Doris 对应清单出发，把 Doris 应保留的源端当前数据与 CK 独有历史补充完整。
- 覆盖探查、范围确认、分区、六参数、海豚工作流、逐段运行排错、验收和逐表回写。
- 适用于历史补数，不将数量相等当成数据完整，不直接把旧 CK 覆盖源端较新数据。

## 先读哪些本地知识

- 按工作区标准解析稳定编号，恢复 B08 任务与已有交付，定位对应子项目；避免重跑已验收批次。
- 优先复用此前已验证的执行方式（解释器、依赖加载、浏览器取数和本地保存）；先核对成功调用记录与当前适用性，不无故更换入口。具体要求见查询环境与异常停点。
- 先读 [三方探查与范围确认](references/三方探查与范围确认.md) 与 [报错教训与恢复](references/报错教训与恢复.md)。
- 查询前读 [查询环境与异常停点](references/查询环境与异常停点.md)，用 scripts/query_runtime.py 做本次解释器的离线导入预检；C03 通过同一入口运行。
- Doris 查询遵循 C02、DDL 读取遵循 C03；业务粒度不明时调用 C11；平台操作读取 C22。
- 数据库连接按查询环境分册从 `.envs/catalog.json` 精确选择；Doris 实际源必须从线上日常 ETL 确认，不以连接清单代替业务来源核验。不得输出凭证或登录链接中的令牌。
- 浏览器操作及同源接口读取前先将对应页面置前，让用户可见。若识别为日常整表刷新，先停下确认历史保留方案；不得补完即被日常整表替换。

## 固定动作

1. 锁定工作簿、工作表、行号、CK/Doris 对应关系和筛选范围；记录逐例确认与异常停点要求，完成本地查询环境预检后再逐表推进。
2. 按三方探查分册的“先适配、再总览、只深查决策缺口”推进：先核实两端来源、日常刷新和当前模型，再给同一时间口径的三方总览；只对影响补数范围/基准/安全重跑的差异深查，不把完整根因研究作为所有表的前置条件。
3. 先识别“CK 有而 Doris 的源没有”的候选历史，再扣除 Doris 已覆盖部分；检查历史内部断档及需保留的日期例外，列清实际重写窗口和删除命中量。
4. 按输出契约在回复窗口打印七列时间总览：时间分类、CK记录数、源记录数、Doris记录数、差异说明、补数基准、备注。先说明现状、原因及执行卡点，取得本表补数范围确认后再设计分段与参数；同一已确认计划不重复询问。
5. 读 [六参数与分段](references/六参数与分段.md)，先在回复窗口展示完整 sql、columns、table、StartTime、EndTime、preSql，再展示分段表，顺序固定；实际读取测试通过后再配置。
6. 读 [分区与工作流执行](references/分区与工作流执行.md)，核实分区和权限；分区/设置修改必须展示完整命令并确认，有无权限均适用。
7. 复用或从已有 His-Init 工作流复制，保存为 `[His-Init]{Doris表名}`；串行等待、上线定义、定时不上线；六参数整块录入与保存双回读。
8. 按 Doris 当前缺口规划约 500 万实际读取/重写行以内的批次。每次显式填写两个日期，通知策略选择“都不发”；一段一运行一提交。
9. 记录实例和实际启动参数，成功后独立查数据；操作失误和常规工具问题自行修正并核验；执行失败或业务/数据影响先只读诊断再报备确认，范围扩大重新确认。
10. 按 [输出契约](references/输出契约.md) 验收历史覆盖、近期保护和字段，完成一表即回写 Excel 数量、结论、分类与证据，保存 B08 checkpoint 和 B03 记忆。

## 什么时候再读本 skill 的 references

- 制作参数、时间分段或遇到 1925 占位日期：读六参数与分段、报错教训与恢复。
- 缺分区、权限不足、复制工作流、运行与保存参数不同：读分区与工作流执行。
- 需要完整成功样例：读 [SPPR完整实操案例](references/SPPR完整实操案例.md)，配套 SQL 在 assets/sppr_case/。
- 需要审查输入、产物和职责：读输出契约、[结构融合索引](references/结构融合索引.md)。

## 边界

- 仅执行用户授权的表和范围；无缺口不补数。样例日期、表名、实例号不是下次任务默认值。
- preSql 与导入不是一个原子事务；执行失败不代表删除回滚。不能无检查重复提交。
- 分区修改不能用只读查询工具绕过权限，也不能借工作流试探 ALTER 权限。
- 本场景按用户明确约定复制 His-Init；与 C22 一般不复制原则的差异仅限此流程。定时始终不上线。
- 不新增第七个工作流参数，不自动改主键模型、源端数据、动态保留策略或部署自动分区改造。
- 不把抽样当全量字段验收；不因 CK 历史多就断言源发生物理删除；未证实原因如实标注。
- 用户要求逐例确认时，本例完成后等待确认才能下一例；按查询环境分册区分自行修正与业务停点，不为没有数据影响的操作失误反复询问。离线环境预检通过不代表数据库已连接。
