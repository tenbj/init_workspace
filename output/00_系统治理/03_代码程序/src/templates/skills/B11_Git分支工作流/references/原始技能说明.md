# P03_Git分支工作流

## 这项技能解决什么问题

- 在当前工作区根目录不是 Git 仓库、真实应用仓库位于 `meal-manage-system-v2/` 的结构下，稳定执行分支优先流程。
- 保护 `main` / `master`，避免把未验收改动直接写入主分支或合并发布。
- 兼容旧入口 `git-branch-workflow` 的目标，但以当前项目路径、脚本和发布现状为准。

## 先读哪些本地知识

- 每次触发先读 `references/仓库定位与分支规则.md`。
- 需要决定跑哪些检查、是否更新版本或文档时，再读 `references/校验与发布规则.md`。
- 实现完成后等待验收、收到验收通过或合并指令时，再读 `references/验收与合并流程.md`。
- 需要确认最终汇报、失败边界或无 Git 场景说明时，再读 `references/输出契约.md`。
- 维护本 skill 结构时，再读 `references/结构融合索引.md`。

## 固定动作

1. 先定位本次要改的文件是否属于真实应用仓库；当前默认仓库是 `meal-manage-system-v2/`，工作区级 `.agents/` 文件不在该 Git 仓库内。
2. 对仓库内改动先检查分支和未提交状态；如果当前在 `main` 或 `master`，且即将修改仓库文件，先切到专用 `codex/<type>-<topic>-YYYYMMDD-HHmm` 分支。
3. 只在专用分支上修改请求范围内的文件，遇到无关脏改动时保留并绕开，不回滚用户工作。
4. 按影响面运行当前项目实际存在的检查；不要强制运行不存在的脚本或创建当前项目没有采用的发布文件。
5. 仓库内实现完成后提交并推送工作分支，汇报分支、提交、改动文件、校验结果，并明确进入 Isabel 验收阶段。
6. Isabel 明确验收通过、要求合并、发布或收尾时，再按验收与合并流程处理；未验收前不合并主分支。

## 什么时候再读本 skill 的 references

- 只要本次会改 `meal-manage-system-v2/` 内代码、测试、文档、脚本、依赖或配置，必须读 `references/仓库定位与分支规则.md` 和 `references/校验与发布规则.md`。
- 当本次只维护 `.agents/skills/`、`.ai-workspace/` 等工作区级文件时，读 `references/仓库定位与分支规则.md` 判断是否需要跳过 Git 分支。
- 当出现脏工作区、分支切换风险、缺失脚本、远端不可用、测试失败或 release/tag 诉求时，读对应 references 后再行动。
- 当用户说“确认无误”“验收通过”“OK”“可以合并”“发布”或同义表达时，读 `references/验收与合并流程.md`。

## 边界

- 不在 `main` / `master` 上直接修改真实应用仓库文件。
- 不把工作区根目录误认为 Git 仓库；根目录无 `.git` 时要继续定位真实仓库或说明不适用。
- 不强制使用旧规则里的 `npm run test:e2e`、`CHANGELOG.md`、`docs/版本管理.md` 或 `meal_manage_v*` 标签，除非当前项目后来显式补齐这些约定。
- 不提交 `.env`、密钥、登录态、数据库连接私密信息或无关用户改动。
- 不在 Isabel 验收前合并主分支、打 release tag 或删除远端分支。
