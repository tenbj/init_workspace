# 校验与发布规则

## 从仓库实际约定选择检查

先读目标仓库的入口规则、贡献说明、CI、构建配置与依赖清单。检查命令来自当前文件和可用环境，不从本技能推断项目使用 npm、Python 或其他固定技术栈。

| 修改范围 | 检查选择 |
|---|---|
| 业务代码、接口、数据结构 | 仓库现有单元测试、类型检查或对应集成测试，按影响面选择 |
| UI 与交互 | 相关前端测试；必要时启动现有服务做浏览器验收 |
| 配置、CI、脚本 | 对应语法、配置校验或可隔离的冒烟验证 |
| Skill、注册表、模板 | 对应 Skill 校验器与注册/命令/模板一致性检查 |
| 纯文档 | 链接、示例、格式及内容一致性；通常不要求完整应用测试 |

- 先验证命令存在；不运行项目不存在的 e2e、lint 或 build 脚本。
- 安装依赖、运行数据库迁移、播种数据或部署不是默认检查。必要时先确认目标环境和已有授权。
- 涉及外部服务时区分本地模拟、集成测试和生产操作；不把模拟结果描述成真实联调。
- B01 是可手动请求的全量框架体检，不作为本流程的默认检查或提交门槛。
- 本次引入的失败应修复并重跑；环境阻塞或已存在失败如实记录，不能宣称全部通过。
- 必要验证通过后停止重复扩大测试；没有运行的检查说明原因。

## 版本和发布边界

- 普通实现或文档改动不强制升级应用版本，不为形式补建 CHANGELOG、版本文档或 Release。
- 依赖更新按项目实际包管理器同步锁文件，不假设锁文件是 package-lock.json。
- 公共接口、运行、安装或部署方式变化时更新已有对应文档。
- 正式发版沿用仓库已采用的版本、标签、产物与签名约定；没有约定且发版确需决策时再询问。
- 本技能负责仓库、分支和交付状态。B09 负责当前骨架的 GitHub 发布、初始化工具封装、更新日志与 Release 资产；本地提交不触发该完整发布链路。
