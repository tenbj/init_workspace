# 输入、内容结构与标题

## 输入与定位

从对话和素材提取主题、主要读者、汇报目的、事实及待定状态，不要求用户先整理材料或重复提供已有信息。先判断读者看完需要知道或决定什么，再组织表格。多方参会时，以主要决策者和本次会议产出为主，技术依据按需下移。

只有缺口足以改变内容主次时才追问。普通版式选择自行完成，不强制审批表头。作者情绪用于理解表达策略，不原样写入业务汇报；用户要求保存的测试输入、原始材料则保留其原意。

先按[内容结构设计](内容结构设计.md)识别信息角色、选择同级分类主轴并确定阅读顺序，再使用下列行列和页签规则。主干不是素材清单：总体结论、事件、影响领域、地区属性与数据缺口不能混成一组平级编号。

## 列顺序与编号

1. 每张展示页的首个业务列固定为“编号”，使用中文大写序号“一、二、三……”；数字单独成格，不与名称或冒号混写。版式的空白 A 列不计业务列。
2. 第二列是内容主干，按主题命名为“模块”“场景”“议题”“事项”等。它决定分组、阅读顺序；目录页中它也是下级页主题，名称须对应。
3. 从左向右按编号、内容主干、展开信息组织总分关系。“安排”“优先级”“负责人”等只是属性时放在主干之后，不让属性分组冒充章节层级。
4. 主干之后只保留必要业务列，最右固定为“备注”。业务列通常 3–5 个，此范围不含编号与备注，也不是硬配额；删去语义重复列。
5. 非首列出现“编号：内容”式条目时，拆为“序号”和紧邻的内容列，序号用阿拉伯数字 1、2、3。主干编号、组内序号和页签层级编号各有作用，不混用，不无故增设第二套序号。
6. 不创建“对应章节”“输入章节”等专用指引列，也不将其改名挪入备注。通过目录内容主干、编号、页签名称和排序表达关系。

每个独立事项一行；共享编号与主干名称可按真实范围成组纵向合并，是否合并还应考虑后续修改，细则见[重点与分组](emphasis-and-grouping.md)。短字段通常 4–10 字，说明短句优先 8–18 字，但不能为凑字数删掉条件、对象、数字或状态。用户明确要求可复制的完整输入时，正文可更长，按语义拆行并留足空间，不压缩成不可复用的摘要。

同一张表内，每列保持一种稳定含义。以 A、B、C 方案为列时，单元格应分别描述对应方案，不能在这些列中横向合并公共目标、预算或待决事项。公共约束与方案差异需要不同表头时，按阅读任务拆成独立表或页签，不能靠合并掩盖结构不匹配。

## 工作表数量与总分层级

1. 先确定各部分分别回答什么问题，再决定工作表数量。单页能清楚表达且便于修改时用单页；需要不同字段体系、独立阅读任务或证据下钻时拆页。不要为制造层级增页，也不要为凑单页压缩必要条件。多页时首表命名为 `0 概览`。
2. 一级明细为 `1 主题`、`2 主题`；子表为 `2.1 子主题`、`2.2 子主题`。按父页、子页顺序排列，名称简短，符合 Excel 限制。
3. 概览只列真实一级模块：第二列名称与一级页主题逐一对应，顺序一致。一级页有几个，概览就列几个模块；不能把某模块内的“通过底线”等补充点再列为没有对应页的第四模块。补充点放到所属模块中。
4. 有下级页的目录按同样原则组织：第二列内容主干与直接下级页对应，属性列后移。普通明细行无需各自建页，不能为了凑对应关系生成空页。
5. 若以“阶段”作为目录主干，下级页就按阶段建；若按具体场景建下级页，目录主干就应是场景，“安排”等属性放后面。选定一种关系后，目录与页签必须一致。
6. 例如下级页为 `2.1 领导周报`、`2.2 受众切换`，目录应为“编号 / 场景 / 安排 / 验证能力 / 备注”，首两列分别填“一 / 领导周报”“二 / 受众切换”。若主干改成“现场主讲”“备用展示”，下级页应相应改为 `2.1 现场主讲`、`2.2 备用展示`；内部案例再用独立“序号 / 场景”展开。
7. 父页承担概括，子页承担展开依据，避免整段重复。不继承固定的建设背景、方案方向等业务章节，不强制每页增加结论。
8. “单页”可能指主阅读页、一个 sheet 或一张打印纸，三者分别设计。“优先单页”属于偏好，可按内容清晰度调整并简述原因；若用户明确限制只能一个 sheet 或一张纸，按该限制设计，不能自行突破或丢弃关键信息。
9. 方案选型可按“会议要点、待决问题、比较依据”组织，但不固定为三张表，也不默认每个方案单独建页。具体取舍见[方案对比与结构复核](方案对比与结构复核.md)。
10. 模块拆分后再检查阅读依赖。概览可先给结论，事件分析的明细通常先过程、后影响；不同任务不机械套用这一顺序。概览按报告模块组织，各明细表按自己的统一主轴组织，不能为对应页签而混合明细分类。
11. 来源需要独立核查时按[内容结构设计](内容结构设计.md)建立独立证据表或页签，不作为连续小字铺在主表尾部；少量简单引用不强制增页。重排须同步目录、编号、标题与引用。

## 页签与页内大标题

标题必须体现本页页签身份，补充说明只增加新信息。

- `0 概览` 的标题必须包含“概览”，可用“业务主题概览”或“0 概览 - 业务主题”。
- 后续页标题以完整页签名开头，保留编号与名称。默认直接用“1 演示安排”；确需说明用途或范围时用“页签名 - 补充说明”。
- 副标题不重复页签原词或已有含义。删除副标题后不影响理解，就不加；不得通过同义改写再讲一遍主标题。
- 例如“3 验收标准 - 生成结果质量验收”可用；“3 验收标准 - 生成结果质量验收标准”重复，不用。“1 演示安排 - 现场演示安排”重复，优先简化成“1 演示安排”。
- 单页也保持页签名与标题主题对应，不强制给单页添加编号层级。
- 页内大标题与各列的表头是两类对象，二者都必须居中；具体样式见[视觉与验收](visual-and-qa.md)。
- 标题默认合并第2行从B列至最右业务列并居中，不包含左右留白列；该例外仅适用于页内大标题。用户明确禁止标题合并时采用足够宽的单格标题。

## 信息必要性

对副标题、备注、页尾和跨页重复文字做删除检查：删除后是否影响理解、事实口径、决策或执行？若不影响则删去。项目名不作为每个 sheet 的固定页尾标识；需要识别项目时，可在概览标题中表达一次，独立分发的页面再按实际需要补充。

只在影响使用时保留来源、适用范围、版本或时间等元信息，不为留白补文字。预算约束、未验证状态、报价排除项和必要的待决请求即使简短或跨页概括，也不属于装饰性信息。

## 空白、未知与事实边界

- 备注无补充内容、不适用的时间或数值字段留空，不填“—”“-”等占位符。只为实际计时环节填写分钟。
- 未知、尚未确认但影响判断的信息，明确写“待确认”“待核实”等，不能用空白或破折号隐藏缺口。
- 合并区域非锚点留空代表共享，不是数据缺失。真实的零保留数值 0，不用空白替代。
- “观察”“建议”“暂定”“可能”必须与其内容一起可见，不编造事实、责任、日期、指标或承诺。重点样式见[重点与分组](emphasis-and-grouping.md)。
