# 固定视觉与验收

基础蓝白视觉保留自来源技能，以下本地规则为当前完整约定。用户明确的新要求优先。

## 默认参数

| 项目 | 固定参数 |
| --- | --- |
| 字体 | Microsoft YaHei（微软雅黑）；不可用时采用 Noto Sans CJK SC 并说明替代 |
| 页内大标题 | 30 pt、加粗、#3366CC、白底；水平与垂直居中，零缩进，无边框 |
| 全部表头 | 20 pt、加粗、白字、#3366CC 底色；每一列均水平与垂直居中，零缩进，白色细边框 |
| 正文 | 默认16 pt、白底；首两列黑字加粗，其余常规字重；重点用 #C00000 红字并写备注原因 |
| 正文边框 | #000000 黑色细线；合并区域只留真实外边框，内部不残留分隔线 |
| 表外留白 | A列宽10，第1行高16.5 pt；表右一列宽3，表下留一行 |
| 标题位置 | 第2行默认合并B列至最右业务列，不含左右留白列；标题水平与垂直居中、无边框；行高68 pt，可在64–72 pt内调整 |
| 表头区域 | B3起，默认行高52 pt，可在48–56 pt内调整；必要双层时每层同样处理 |
| 正文区域 | 单层表头从B4起，双层从B5起；单行行高可从40 pt、两行从56 pt起调，以渲染为准 |
| 首两列正文 | 编号与内容主干整列水平、垂直居中，零缩进，加粗 |
| 其他正文 | 按列统一选居中或左对齐；左对齐为一格原生缩进，居中为零缩进；垂直均居中 |
| 冻结窗口 | 所有工作表默认冻结前三行，从第4行开始滚动；概览和短表也必须设置，不额外冻结列 |
| 视图 | 隐藏网格线，检查时不选中单元格；100%看字体和留白，完整页看信息密度 |
| 页尾元信息 | 默认不添加；确有新增信息时用11 pt黑字，与表格间隔一行；核心请求不得藏在小字页尾 |

同一工作簿保持统一字号，默认标题/表头/正文为30/20/16 pt。确有阅读需要可统一用18 pt表头或14 pt正文，不能为个别拥挤格单独缩字。避免正文蓝底、装饰卡片、渐变、密集台账排版。

## 标题、表头与正文分开验收

“标题居中”同时检查页内大标题和各列表头，不能只检查标题格就声称全部居中。

- 大标题遵循[输入与内容要求](输入与内容要求.md)的页签对应规则，默认合并业务表宽并居中，文字保存在B2，其他被合并格应为空。用户明确禁止标题合并时使用单格标题。合并不得跨入表头、正文或左右留白列。
- 每一个表头都居中，包括长文本列、最右备注列和多层表头。正文左对齐不能传递到表头。
- 标题不画外框，表头用白框，正文用黑框。避免批量设黑色边框后覆盖标题和表头；检查共享边界处的实际显示。
- “同一列统一对齐”约束正文，同列中的短字、长句、数字、空白格和合并格都沿用该列设置。不能为单个短值临时居中，也不能把全部表头改成左对齐来追求形式一致。
- 短内容列如“分钟”“安排”宜整体居中，描述和原因列宜整体左对齐。混合长短文字时，以该列整体阅读需求选定一种对齐方式。

## 左右留白与列宽

正文左对齐采用一格缩进。右侧也应至少预留约一个汉字宽度，特别检查最长一行的末字与右边框，不能仅以“没有裁切”判定通过。

1. 列宽按内容角色分配，先保证主干简短，再把空间留给判断、行动和原因。不要固定套某次样例的列宽。
2. 右侧文字贴边时，优先适当加宽整列；加宽后重新核对标题覆盖范围、表头及该列所有行。
3. 整表已较宽时，让同一事项提前换行，必要时增加行高。可按语义设置换行；不得改变数字、日期、标识符和原始输入的含义。
4. 文字冗长时先提炼或拆独立事项，再调列宽与行高。不通过末尾补空格、缩小字体、无限加宽表格或虚构“右内边距”API解决。
5. 一格左缩进不保证右侧自动留白。右侧约一字是视觉验收标准，不是未经验证的固定列宽公式；每次以最终文件实际显示为准。

## 内容预检

先完成[内容结构设计](内容结构设计.md)的结构六检，再使用以下版面相关检查；格式合格不能替代分类、层级、阅读顺序和证据关系合格。

- 只读大标题、表头、首两列和红字，能否理解主题与本次判断？核心请求是否在主表可见？
- 首列是否为独立中文编号，第二列是否为内容主干，最右是否为备注？是否误加章节指引列？
- 目录主干与真实直接下级页是否一致，属性分组是否错误承担了层级？概览模块数与一级页数是否一致？
- 并列事项是否独立拆行，共享范围是否真实？不同原因与措施是否被强配？
- 各业务列是否有独立作用，事实、条件、数字和不确定性是否完整？空白是否代表无补充而非隐瞒未知？
- 每张表的列含义是否稳定？是否将公共说明塞入方案列，或依靠合并、字号和纸张掩盖结构问题？能否不解除合并就修改一项事实？
- 副标题、页尾和备注是否提供新增信息？去掉重复项目标识后，是否仍保留必要的业务限定？

## 制作、保存与验收

调用环境中的 spreadsheets 技能及其作者工具。只使用公开文档支持的接口，不猜测属性，不修改依赖。若必要原生样式没有公开接口，按环境允许的补充方式处理，并验证最终文件；不能用无效赋值或文本空格冒充成功。

完成修改后重算并检查需要的公式、日期和数字。逐页检查新增或改动的展示区域，保留未改区域的有效验收依据。验收至少包括：

1. **结构**：同级分类一致、主干与属性分开、阅读顺序符合理解依赖，独立证据结构可追溯；页签服务不同阅读任务，单页偏好未破坏字段含义或省略条件；多页概览、编号、主干、父子关系与实际排序一致，无空层级或悬空模块。
2. **标题**：每页标题体现页签身份，无重复副标题；标题完整可见、无边框、双向居中；默认合并范围为B2至最右业务列第2行，正文不存在未经授权的横向合并。
3. **表头**：逐列检查，全部双向居中、零缩进、白边框，不漏掉长字段及备注列。
4. **正文**：首两列居中加粗，其余无粗体；整列对齐一致，左对齐均一格缩进；重点红字及原因备注对应。
5. **留白**：左右不贴边，无裁切、孤字、过密文字或空洞大格；右侧约一字留白，必要换行有足够行高。
6. **内容**：原始事实与最终单元格逐项对应，无数据丢失；无无意义占位符和重复页尾标识；真实零值、待确认状态及必要限定词完整。合并区域满足用户限制，必要的纵向合并范围正确。
7. **视图**：每张工作表冻结前三行，滚动起点第4行，不能因概览较短而省略。
8. **最终件**：不能只相信内存模型或生成脚本。保存后核对原生对齐、缩进、字重、边框、合并及冻结设置。预览无法完整表现某项效果时，用目标 Excel 等环境验证；结构检查不等于视觉通过。

最终件与中间件路径见[输出契约](输出契约.md)。打印默认按一页宽、自动分页高度处理，不把 fitToHeight=1 当作固定要求。先解决阅读结构，再选择纸张和方向；不为塞进一张纸缩小至难读。删除页尾后收紧打印范围并保留必要留白。用户明确的单张打印要求优先；未要求时不额外交付模板、脚本或多种 Excel 版本。
