# 输出契约

## 输入

目标需求、来源及参考模型、引擎、已确认命名和口径、参数及输出子项目。缺失信息先从材料取证，只对影响结果且无法确定的事项提问。

## 默认正式交付：实体表四件

```text
模型工作目录/
├── 开发材料/                           # 或复用既有开发目录
└── 正式交付/
    ├── 交付说明.md
    ├── 01_SQL/
    │   └── {规范表名}/
    │       ├── create_{规范表名}.sql
    │       └── {规范表名}.sql
    └── 02_字段文档/
        └── {规范表名}_字段信息.xlsx
```

加工路径末两级必须是 `{规范表名}/{规范表名}.sql`，名称不含库名，不表达 delete_insert。

- 建表直接包含本版全部字段；加工为最终唯一运行入口，显式列出目标字段，中文分段注释。
- 首次参数及推导证据摘要写入说明，日常仍用同一 SQL；不单独生成 full_load.sql。
- 默认不含 add_scope_info.sql 等补列脚本。确有存量迁移需要时明确对象与授权，独立标注用途。
- 字段 Excel 从最终 DDL/投影生成或按 C06/E05 复用，至少含顺序、字段、类型、中文含义、来源/加工口径；键、可空及单位明确。
- 原始 DDL、查询、JSON、样例、生成器、回执、旧版留开发目录；不输出压缩包。
- 实际视图不强拆建表与插入，只交必需定义 SQL、字段文档及说明。额外文件须有明确用途或用户要求。

## 说明必须回答

库表及粒度；清单与相对链接；创建/运行顺序；参数含义、边界、首次实际值和核查日期；全量覆盖证据；日常参数；合并优先级；单位、跨年和审计时间；失败恢复、并发；完成验证范围、遗留和未执行项。

使用 `assets/交付说明模板.md` 并替换为真实证据。未查到全量参数须明确缺口，不能填合成日期。

## 本地检查

```text
python .agents/skills/C18_数据模型SQL开发/scripts/validate_delivery.py --delivery-dir <正式交付目录> --table <不含库名的规范表名> --output <开发目录/交付校验.json>
```

脚本只读交付目录，报告位于目录外；检查实体表四件清单、加工路径、SQL 中文注释和明显占位符，不删除文件、不连接数据库。视图或已确认扩展交付不适用默认契约时，按实际契约人工核对，不虚构文件凑数。

另须人工或已有生成器核对字段一致性、目标引用、参数语义和最终版本证据；目录/注释检查不能证明 SQL 可执行或业务正确。

白名单复制并核对哈希；若翻译注释或改名，保存前后差异证明，不能套用旧哈希宣称新文件已跑过数据库验证。

## 完成边界

说明、SQL、Excel 存在且一致才可声明交付完成。阻塞记录在开发材料及说明，不用占位件凑数。最后只给实际入口、验证范围与重要缺口。
