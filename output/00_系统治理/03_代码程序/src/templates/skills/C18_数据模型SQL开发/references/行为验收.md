# 行为验收与开发复盘

| 场景 | 正确行为 | 错误行为 |
|---|---|---|
| ODS技术源库编号进入DWD | 独立核查业务过程、来源标签和域，展示完整名称并保存明确确认 | 去掉ods前缀直接沿用源账套时间串，并把AI已有产物说成已确认 |
| 表名确认及频率 | 复用明确用户确认，记录dd每日依据与未配置的实际时刻；交给C19确认文件 | 因源名、粒度、全量SQL猜日频，或反复索要已有确认 |
| 已发布后改名 | 同步全部当前产物和生成器，保持源名及旧回执原貌；原MR追加改名提交 | 只改SQL别名、旧路径继续可运行、批量改历史证据或新建重复MR |
| 字段结构以旧源为准 | 分开确认结构与数据优先级，追踪主线 | 自动解释为旧源数据优先 |
| 索要逗号/百分号案例 | 单独取证SQL，没有则如实说明 | 用合成案例证明源存在异常 |
| 问空串能否直接写 | 核对源/目标/写入模式，区分SELECT与INSERT | 一问就删NULLIF，或无证据说一定不能写 |
| 跨年周且旧源须保留 | 仅确认的新源采用文本年周 | 重算所有来源 |
| 首次加载 | 同SQL按实际时间全范围，检查NULL范围覆盖 | 另复制full_load；误用业务日期 |
| 排名成员减少 | 删除变化范围再回读完整数据 | 只删新结果仍存在的键 |
| 要scope_info | 展示实际哈希输入并复算 | 另拼近似字符串称原文 |
| 表名缺后缀 | 查input规范，解释ilu/dd，确认后同步 | 沿用错误名，加工名带delete_insert |
| 交付目录混乱 | 仅必需文件，开发证据另存 | 压缩全部目录交付 |
| 中文SQL注释 | 检查中间行注释、块注释、表字段说明 | 只翻译文件头 |
| 无文件头注释 | 正式SQL直接以语句开始；行注释/块注释开头均拦截，内部业务注释和COMMENT可保留 | 为满足中文注释要求添加模型名/作者/日期头，或删除全部内部注释 |
| WITH子句格式 | 后续CTE使用逗号前置，注释放在逗号及CTE名称行之前 | 上一CTE右括号后挂逗号 |
| SQL连续排版 | 正式DDL/DML无空白行，段落以中文注释区分 | 只处理逗号位置，CTE和语句之间仍留空行 |
| 原脚本迁移 | 用E03、实际标准库和公式审核最终字段；保留计算不等于保留旧名 | 以兼容为由跳过字段命名，或仅做CamelCase转snake_case |
| 字段改名落地 | 同步DDL键、DELETE范围键、INSERT列、SELECT别名、Excel及生成器 | 只改SELECT别名或只改Excel，导致目标合同不一致 |
| DIM已有同义属性 | 核实实际结构和业务角色后沿用DIM完整字段名，如该DIM的msku_ctg_1st至msku_ctg_5th | 自造mat_ctg_1st_name等别名，或因不是DWD参考表而跳过 |
| 用户只举一列纠错 | 复核全部最终字段，逐列记录DIM同名、人工例外或无对应属性的依据，覆盖数等于最终字段数 | 只改示例，其他同义字段仍沿用自拟名称 |
| 最新人工命名例外 | 按最新确认执行，在模型开发材料独立记录来源、DIM默认名、最终名和确认依据 | 让旧建议或默认规则覆盖新要求，或反复询问已确认映射 |
| 例外作用范围 | 库存执行模型的ProductNo→sku_version_code、ASIN→asin只在该模型有效；ProductName→sku_name按实际DIM同义名核验 | 将案例中的源字段映射推广到所有模型，或把遵循DIM的字段也误列为例外 |
| 命名与取值分开 | 源字段沿用DIM同义名时保留已确认源表达式；不同角色的源版本编码和DIM SKU编码分别输出且别名唯一 | 改别名时偷偷换取DIM值，或用一个sku_code覆盖两个不同字段 |
| 相似字段语义不同 | 回到来源区分单据/订单、长宽高/尺码、销售组织/供应商，保留不同业务角色 | 看到相似英文或部分相同值便强制同名 |
| 去除维度属性冗余 | 核对已有源属性和用户范围，保留所需单份输出及其确认来源 | 把“不要额外DIM.msku”误解为删除原有源MSKU，或再次补出同义副本 |
| 网络异常暂停复验 | 停止连接，完成已授权离线修正，标明旧证据与新版本差异 | 反复查询或把旧版查询成功说成本版通过 |
| 不考虑分区替换 | 补齐CREATE及已确定的落表策略 | 擅自缩减为SELECT查询 |
| 带日期参数 | 根据删写范围判断更新语义 | 仅看到参数就断言增量 |
| 结果粒度与模型 | 按C11方法核验实际INSERT查询结果，证明业务键和技术键唯一后用主键模型 | 只看源键，或有重复便直接用明细模型 |
| 明细模型例外 | 证明无稳定唯一业务键且主键模型会归并丢行，附重复案例 | 用随机值、行号或新增DISTINCT伪造唯一性 |
| unique_key编码 | 参考真实表代码，以MD5和竖线拼接已确认业务键，检查NULL与分隔歧义 | 自作主张改SHA256/JSON或忽略拼接归并 |
| 小数类型 | 优先decimal(18,6)，范围与舍入画像支持必要的精度例外 | 因源类型或“保险”使用double/decimal(38,6) |
| 文本与可空 | 主键文本varchar(255) NOT NULL，其余文本string；全部非主键NULL | 用text、所有文本varchar，或把业务日期设为NOT NULL |
| 外层CAST | 根据实际表达式类型只保留必要转换 | 全列CAST或因质疑把必要精度转换一并删除 |
| 三个审计时间 | 补齐first_inserted_dt/etl_dt/last_updated_dt并说明范围重写重置含义 | 漏字段，或NOW重写却声称保留历史首次入库 |
| 新开一套交付 | 新目录及生成器独立，旧套清单/哈希保持不变 | 覆盖旧套或让生成器指回旧目录 |
| 确认SELECT能跑 | 从当前正式文件提取查询，真实参数、全部字段实跑并记录返回行列及范围 | 只跑COUNT/EXPLAIN，拿旧版或空结果证明全字段值可计算 |
| 查询通过范围 | 区分样例、完整单日、全范围；区分查询成功与落表成功 | 触及LIMIT仍称全量，SELECT通过即称INSERT通过 |
| 实跑版本指纹 | 按同一字节或规范化文本口径比较哈希 | 混用CRLF字节hash与LF文本hash误判文件漂移 |

SQP案例体现决策方法：初始通用防御清洗来自假设，实际查询后缩减；有证据的单位转换、空串处理保留。应在首次设计完成字段画像与必要性判断，而非等用户逐项追问。

自动验收覆盖白名单、命名、中文注释词法识别、字符串中注释符不误判、优化器提示排除、报告不得位于正式交付。语义仍需八类验证和项目测试。
