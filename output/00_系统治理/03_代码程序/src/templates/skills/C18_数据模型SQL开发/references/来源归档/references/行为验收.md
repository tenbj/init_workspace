# 行为验收与开发复盘

| 场景 | 正确行为 | 错误行为 |
|---|---|---|
| 字段结构以旧源为准 | 分开确认结构与数据优先级，追踪主线 | 自动解释为旧源数据优先 |
| 索要逗号/百分号案例 | 单独取证SQL，没有则如实说明 | 用合成案例证明源存在异常 |
| 问空串能否直接写 | 核对源/目标/写入模式，区分SELECT与INSERT | 一问就删NULLIF，或无证据说一定不能写 |
| 跨年周且旧源须保留 | 仅确认的新源采用文本年周 | 重算所有来源 |
| 首次加载 | 同SQL按实际时间全范围，检查NULL范围覆盖 | 另复制full_load；误用业务日期 |
| 排名成员减少 | 删除变化范围再回读完整数据 | 只删新结果仍存在的键 |
| 要scope_info | 展示实际哈希输入并复算 | 另拼近似字符串称原文 |
| 表名缺后缀 | 查input规范，解释ilu/dd，确认后同步 | 沿用错误名，加工名带delete_insert |
| 交付目录混乱 | 仅必需文件，开发证据另存 | 压缩全部目录交付 |
| 中文SQL注释 | 检查中间行注释、块注释、表字段说明 | 只翻译文件头 |

SQP案例体现决策方法：初始通用防御清洗来自假设，实际查询后缩减；有证据的单位转换、空串处理保留。应在首次设计完成字段画像与必要性判断，而非等用户逐项追问。

自动验收覆盖白名单、命名、中文注释词法识别、字符串中注释符不误判、优化器提示排除、报告不得位于正式交付。语义仍需八类验证和项目测试。
