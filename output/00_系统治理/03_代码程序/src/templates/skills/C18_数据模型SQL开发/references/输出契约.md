# 输出契约

## 输入

目标需求、来源及参考模型、引擎、已确认命名和口径、参数及输出子项目。缺失信息先从材料取证，只对影响结果且无法确定的事项提问。

## 默认正式交付：实体表五件

```text
模型工作目录/
├── 开发材料/                           # 或复用既有开发目录
└── 正式交付/
    ├── 交付说明.md
    ├── 01_SQL/
    │   └── {规范表名}/
    │       ├── create_{规范表名}.sql
    │       └── {规范表名}.sql
    └── 02_字段文档/
        ├── {规范表名}_字段信息.xlsx
        └── {规范表名}_平台字段信息.xlsx
```

加工路径末两级必须是 `{规范表名}/{规范表名}.sql`，名称不含库名，不表达 delete_insert。

- 建表直接包含本版全部字段；加工为最终唯一运行入口，显式列出目标字段，中文分段注释。
- 首次参数及推导证据摘要写入说明，日常仍用同一 SQL；不单独生成 full_load.sql。
- 默认不含 add_scope_info.sql 等补列脚本。确有存量迁移需要时明确对象与授权，独立标注用途。
- 字段 Excel 从最终 DDL/投影生成或按 C06 复用（E05 仅在注册表存在时按需使用），至少含顺序、字段、类型、中文含义、来源/加工口径；键、可空及单位明确。
- 原始 DDL、查询、JSON、样例、生成器、回执、旧版留开发目录；不输出压缩包。
- 实际视图不强拆建表与插入，只交必需定义 SQL、字段文档及说明。额外文件须有明确用途或用户要求。

“不考虑分区替换”只排除分区替换策略，不等于只要 SELECT，也不免除建表和落表加工交付。只有用户明确只要查询时，才采用查询交付契约。

## WITH / CTE 格式

正式建表及加工 SQL 文件不保留空白行，包括文件头、语句之间、CTE 之间、注释与代码之间；通过中文注释划分段落。不能只识别用户示例的逗号位置而遗漏连续排版要求。

从第二个 CTE 起，分隔逗号放在该 CTE 名称行的开头；上一个 CTE 的右括号后不带逗号。中文分段说明放在该 CTE 名称行之前。此规则仅约束 CTE 分隔符，不据此改动 SELECT 字段列表逗号。

```sql
with
-- 日期参数，包含起止两天。
params as (
    select cast('${StartTime}' as date) start_dt, cast('${EndTime}' as date) end_dt
)
-- 物料主干。
,material as (
    select * from source_table
)
select * from material;
```

参数本身不能证明更新策略为增量。依据实际写入语义确定：指定业务日期范围删除后完整回写、保留范围外数据属于范围增量重算；明确范围键、两步使用相同边界、空范围行为及失败恢复。没有生产写入授权时交付完整 DDL/DML 文件，验证仍遵循只读边界。

## 说明必须回答

库表及粒度；清单与相对链接；创建/运行顺序；参数含义、边界、首次实际值和核查日期；全量覆盖证据；日常参数；合并优先级；单位、跨年和审计时间；失败恢复、并发；完成验证范围、遗留和未执行项。

Doris 实体表还须写清结果业务键、技术键表达式、主键模型不丢行证据（或明细模型例外依据）、decimal 精度选择、非主键可空、三个审计时间含义，以及最终 SELECT 实跑的版本、范围和返回情况，详见 [Doris实体表设计与实跑验收](Doris实体表设计与实跑验收.md)。用户要求另开一套时，旧套保留，新套交付及生成器全部使用独立路径。

使用 `assets/交付说明模板.md` 并替换为真实证据。未查到全量参数须明确缺口，不能填合成日期。

## 本地检查

```text
python .agents/skills/C18_数据模型SQL开发/scripts/validate_delivery.py --delivery-dir <正式交付目录> --table <不含库名的规范表名> --output <开发目录/交付校验.json>
```

脚本只读交付目录，报告位于目录外；检查实体表五件清单、加工路径、SQL 中文注释、空白行、CTE 逗号前置、CREATE/INSERT 目标字段的小写下划线形式和明显占位符，不删除文件、不连接数据库。视图或已确认扩展交付不适用默认契约时，按实际契约人工核对，不虚构文件凑数。

另须按 E03 完成字段语义与标准词根审核，人工或已有生成器核对 DDL、DELETE 键、INSERT 列、SELECT 别名、字段 Excel 的一致性、目标引用、参数语义和最终版本证据；自动格式检查不能证明命名语义合规、SQL 可执行或业务正确。

白名单复制并核对哈希；若翻译注释或改名，保存前后差异证明，不能套用旧哈希宣称新文件已跑过数据库验证。

## 完成边界

说明、SQL、Excel 存在且一致才可声明交付完成。阻塞记录在开发材料及说明，不用占位件凑数。最后只给实际入口、验证范围与重要缺口。

## 平台建模交付接口

按[平台建模交接](平台建模交接.md)同时交付可直接导入的六列Excel：Type小写，审计前三行序号0，业务连续序号，中文和英文名称分别唯一，COMMENT来自DDL。首次内容未确认前停下确认；已有确认复用。原设计字段文档保留语义/血缘，不能当导入模板。

正式说明补齐上游库表/平台中文名/模型ID/树路径、有效调度、实际更新范围及证据日期；下游计划频率、默认参数合同和首次加载参数分别交付。未知项明确标记，建模前复核；平台操作路由 C20。默认24桶，四表级项及三方差异核对见平台交接分册。

完成目录校验后，再运行 `python .agents/skills/C18_数据模型SQL开发/scripts/validate_platform_fields.py --excel <六列文件> --output <开发目录/字段模板校验.json>`。输出放正式交付目录外。
