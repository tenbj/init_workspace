# SQL业务溯源与诊断

## 这项技能解决什么问题

- 用户指出数据不对时，结合已确认的业务目标，查清这条数据从来源到报表是怎样产生的，并主动检查修复会经过的相关环节。
- 自主查完整相关链路，用同一个案例有顺序地讲清楚；无需用户逐句指导下一条查询。
- 适用于字段缺失、串值、重复、排名或汇总口径异常，以及修改后的回验。

## 先读哪些本地知识

- 先看用户当前要求、连续对话中已确认的口径、指定SQL和对应业务资料，区分业务期望与代码现状。
- 开始诊断时读[调查方法](references/调查方法.md)；查询生产数据时使用 C02。
- 纯字段来源解释可以只读相关代码；需要解释实际数据异常时，再获取当前数据证据。

## 固定动作

1. **明确要保证什么。** 从上下文识别一行代表的对象、粒度和业务规则；能推导的自行推进，有关键歧义才集中询问。
2. **沿同一案例查完整。** 倒查字段来源和实际关联键，再正向检查分组、选行、汇总、周期取值及最终展示；不要在找到第一个断点后漏查相连环节。
3. **用证据定性。** 分清源缺失、关联失配、选行丢值、粒度不一致和业务规则未定；假设不能当成已证实的问题。
4. **按任务范围处理。** 解释、诊断、修复、重跑验收分别做到用户要求的深度；已授权修复要完成相互依赖的必要改动，并做同案例及相关边界验证。
5. **交付可复查的结论。** 先回答当前问题，用具体代码和实际值讲清因果，再给必要改法、验证结果与尚未确定的业务选择。按[输出契约](references/输出契约.md)保留证据。

## 什么时候再读本 skill 的 references

- 不确定该追多远、哪些问题该问用户时，读[调查方法](references/调查方法.md)。
- 要写诊断SQL、解释多行候选或组织回复时，读[单案例取证与解释](references/单案例取证与解释.md)。
- 交付诊断或修复结果时，读[输出契约](references/输出契约.md)；需要记录骨架时选用[证据卡](assets/诊断证据卡.md)。
- 维护或测试本Skill时，读[行为验收](references/行为验收.md)；查能力落点时读[结构融合索引](references/结构融合索引.md)。

## 边界

- 用户明确限定局部问题时尊重范围；普通语法问答、SQL格式整理不默认启动整条业务诊断。
- “分步骤解释”不等于每一步等待用户；“主动调查”也不等于替用户猜定业务口径、审计全库或修改无关模型。
- 区分本次实测、历史证据、模拟结果和待验证推断；本地代码正确、生产已部署、报表符合业务目标分别验收。
- 仅解释或检查时不改业务代码；本地修复不自动授权生产写入。具体项目口径保留在业务资料中，不固化为本Skill的普遍规则。
