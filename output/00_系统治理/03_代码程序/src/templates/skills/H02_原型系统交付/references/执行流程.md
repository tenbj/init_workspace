# 执行流程

本文件定义 H02 从原型到系统项目包的主流程。入口 `SKILL.md` 只保留骨架，本文件承接具体步骤。

## 输入判断

支持两类输入：

- 单个 HTML 原型：保留源文件，只读分析 DOM、脚本、数据结构、交互和路由。
- H01 原型能力包：优先读取包内 PRD、接口草案、数据模型、交互说明和验证记录。

第一步必须记录：

- 原型来源路径
- sha256
- 项目名
- 输出目录
- 用户要求保留、跳过或复用的内容

## 初始化

运行或参考：

```powershell
python scripts/init_project.py --prototype <原型路径> --project-name <项目名> --output-dir <输出目录>
```

该脚本只生成 `project-contract.json` 合同骨架，状态应为 `draft`。它不是系统实现，不得据此宣称交付完成。

## 实施顺序

1. 原型理解：抽取页面、视图、操作、筛选、状态、数据来源和异常提示。
2. 合同草拟：为本轮生成新的 delivery_id，补 `project-contract.json` 的操作、检查项、限制和验收证据。
3. 架构选择：优先复用已有技术栈；除非用户要求或现有架构明显不适合，不强制换框架。
4. 数据设计：区分真实数据库、合成数据、种子数据和 mock；公开包只能包含合成数据或脱敏样例。
5. 首次双图生成：调用 D04 生成架构图、G02 生成 ER 图；已有系统每次迭代必须维护两图并保存本轮核对记录，详见 架构与ER图维护.md。
6. API 实现：围绕业务能力设计可复用操作，不按每个自然语言任务复制一套 API。
7. MCP 实现：把可复用 API 暴露给 AI，提供清晰工具名、参数、返回、错误和副作用说明。
8. 前端联通：页面通过 API 读取和写入，不把真实业务状态长期写死在静态 HTML。
9. 文档和示例：交付中文 API 文档、HTML 调用示例、Python 调用示例、AI 安装与工具决策指南。
10. 验证：按最终实现同步两图，运行单元、接口、页面、MCP SDK 固定序列、架构与 ER 图和打包检查，保存证据。
11. 打包：生成脱敏 ZIP 项目包，明确许可证状态和未上传 GitHub。
12. 运行部署：系统实现和验证完成后调用 I02；已有提交、合并、发布授权时先按 B11/B09 完成相应动作，再部署核定版本。更新现有运行系统时，在明确目标及授权范围内完成备份、停写迁移、重启、本地/公网及MCP验证。仅交代码、原型、包或禁止重启时记未部署及原因；首次交付无目标时明确部署条件。调用 I02 不等于无条件重启所有环境。

## 并发工作建议

在父线程允许并发时，可以按文件所有权拆分：

- 页面与静态资源
- API 与数据库
- MCP 与 AI 接入
- 文档与示例
- 测试、验证和打包

共享合同 `project-contract.json` 必须串行合并，避免并发覆盖。

## 结束条件

只有同时满足以下条件才可说“系统交付完成”：

- 源原型未修改
- 合同 `status` 为 `ready`
- 页面、API、数据库、MCP、架构图、ER 图、文档、示例、测试、验证证据齐全
- 两图与当前实现一致，每张图有本轮 delivery_id、哈希、维护记录及通过的证据
- `scripts/validate_project.py --project-dir <目录> --report <报告>` 通过或已解释剩余缺口
- ZIP 包不含密钥、登录态、真实敏感数据
- 已调用 I02 判断并记录部署状态；本轮包含运行升级时，I02 必需验收通过才可说系统升级完成。代码/包通过而部署待办时分别汇报，不能把合同 ready 解释为生产已升级。
