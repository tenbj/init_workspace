# 验证与项目打包

H02 交付必须让用户能区分“看起来能跑”和“证据证明能跑”。

## 验证层级

| 层级 | 目标 | 证据 |
|---|---|---|
| 静态检查 | 文件、合同、OpenAPI、文档和示例存在 | validate 报告 |
| 单元测试 | 业务规则、幂等、版本冲突、证据必填 | pytest 或等价测试报告 |
| API 测试 | health、列表、详情、写入、错误码 | 请求响应记录 |
| 页面测试 | 首屏、筛选、详情、提交、移动端 | 浏览器截图和脚本报告 |
| MCP SDK 固定序列 | initialize、list_tools、只读、演示写入、回读 | MCP 验证报告 |
| 架构图 | D04 产物与实际组件/调用/部署一致，浏览器及离线检查 | 本轮架构核对、来源/产物hash、浏览器报告 |
| ER 图 | G02 产物与模型一致，双态几何与关键交互 | 本轮ER核对、来源/产物hash、G02报告 |
| AI 自主任务验收 | AI 按工具说明完成一段真实或演示任务 | 任务记录和人工复核 |

MCP SDK 固定序列只证明协议和工具链路可用，不等于 AI 已能自主完成复杂业务任务。

## mock 与真实测试

- mock 测试：可以验证 UI、数据结构和错误处理；不得声称已连接真实系统。
- 真实测试：必须说明真实连接范围、数据库或服务环境、写入对象和回滚或隔离方式。
- 混合测试：必须标注哪些步骤是真实，哪些步骤是 mock。

## 本地试运行与生产就绪

本地试运行通常只证明：

- 单机服务可启动
- 本地数据库或测试库可用
- 主要 API 和 MCP 链路可用
- 页面能完成核心路径

生产就绪还需要补充：

- 认证授权
- 审计和权限
- 高可用和备份
- 迁移脚本
- 部署流程
- 监控告警
- 数据保留和合规

没有这些证据时，不得把本地试运行说成生产就绪。

## validate 脚本

运行：

```powershell
python scripts/validate_project.py --project-dir <项目目录> --report <报告路径>
```

检查范围：

- `project-contract.json`
- OpenAPI 或等价 API 文档
- MCP 工具目录
- 中文安装和 AI 接入文档
- HTML/Python 示例
- 两图文件、来源哈希、维护记录、本轮 delivery_id、通过的JSON证据
- 测试与验证报告
- 脱敏和发布结构

## 打包规则

ZIP 包应包含：

- 系统源码
- 架构图、ER 图及生成材料、权威模型来源和本轮核对证据
- 合成 seed 数据
- 文档
- 示例
- 测试
- 验证报告
- 合同
- 启动停止脚本

ZIP 包不得包含：

- 密码、token、cookie、登录态
- 真实敏感数据
- 本机私有缓存
- 未脱敏日志
- 大型无关依赖目录

## GitHub 与许可证

H02 可以生成“可提交 GitHub”的项目结构，但不会自动上传 GitHub。许可证状态必须明示：

- 未选择许可证
- 内部使用
- 用户指定许可证

未获用户明确授权时，不添加开放许可证声明。

## 两图强制门

首次开发使用 D04/G02；每次更新遵循 架构与ER图维护.md。图存在不等于图已同步：报告、产物、来源均须属于本轮且哈希一致。结构检查不证明语义正确，须完成实际代码/模型核对和真实浏览器检查。图无语义变化也须有本轮复核说明与证据；任一图缺失、过期或失败，不能ready或宣称完整交付。
