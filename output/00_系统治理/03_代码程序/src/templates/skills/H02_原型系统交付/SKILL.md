# H02_原型系统交付

## 这项技能解决什么问题

把 HTML 原型或 H01 原型能力包继续落地成可运行系统：页面、后端 API、数据库、MCP、架构图、ER 图、示例、验证证据和可脱敏分发的项目包。

它适用于任意业务原型，不限定数仓治理领域；复用已有架构优先，不强制换框架。

## 先读哪些本地知识

- 本地编号、来源与兼容边界见 `references/本地迁入说明.md`。

- 按稳定编号解析 H01，读取其 `references/用户固定设计偏好.md` 与 `evaluation/checklist.md`，沿用同一份通用交互规则及适用边界，不另复制正文。
- 先读 `references/执行流程.md`
- 需要设计 API、数据库、MCP 或操作粒度时，读 `references/能力与接口设计.md`
- 需要生成中文 API、HTML、Python 示例和 AI 接入说明时，读 `references/文档与AI接入.md`
- 需要验证、测试、CI、脱敏和项目包时，读 `references/验证与项目打包.md`
- 需要确认最终输出字段、合同和验收口径时，读 `references/输出契约.md`

- 首次开发及每次迭代必读 references/架构与ER图维护.md。

## 固定动作

1. 确认输入是 HTML 原型还是 H01 包，记录源原型路径与 sha256；不得改源原型。
2. 运行或参考 `scripts/init_project.py --prototype --project-name --output-dir` 生成合同骨架；它只生成草稿，AI 必须继续实现后才能声明完成。
3. 从原型识别页面、状态、用户操作和外部系统边界，设计可复用 API 与 MCP 工具；不要按“一个任务一个 API”机械拆分。
4. 首次开发必须调用 D04 生成架构 HTML 页面、调用 G02 生成可交互 ER HTML 页面；每次更新都维护架构与 ER 两个 HTML 页面，按当前实现核对并保存本轮证据，详见 references/架构与ER图维护.md。
5. 实现或补齐真实系统页面、后端 API、数据库层、MCP 服务、架构与 ER 页面、示例、文档、启动停止脚本、测试和验证证据。
6. 运行 `scripts/validate_project.py --project-dir --report`，按报告修复缺口；只有合同、架构图、ER 图、文档、示例、验证和发布结构达标后，才交付脱敏 ZIP 项目包。
7. 系统实现和验证完成后调用 I02；更新已有运行系统且目标、授权明确时继续备份、停写迁移、重启及实际验收。明确只交代码/原型/包或不重启时按限制留档，不用代码发布代替部署，不重复询问已授权事项。

## 什么时候再读本 skill 的 references

- 工作流不清楚或需要并发拆任务时，读 `references/执行流程.md`
- 需要判断接口粒度、MCP 工具、数据库状态和凭据边界时，读 `references/能力与接口设计.md`
- 需要给用户或 AI 写接入说明、工具决策表和安装任务时，读 `references/文档与AI接入.md`
- 需要区分 mock/真实测试、本地试运行/生产就绪、SDK 固定验证/AI 自主验收时，读 `references/验证与项目打包.md`
- 需要输出结构、合同字段或质量门时，读 `references/输出契约.md`
- 需要核对 11 段结构落点时，读 `references/结构融合索引.md`

## 边界

- 两个 HTML 页面是必备交付物；缺图、与实现不一致或没有本轮核对证据时，不得标记 ready。
- 不修改源 HTML 原型或 H01 输入包。
- 不把凭据写入仓库、文档、示例、ZIP 或对话；凭据只从环境变量或用户授权的本地配置进入进程。
- 不把 mock 演示说成真实联调，不把本地试运行说成生产就绪。
- 不自动上传 GitHub，不默认声明开放许可证。
- 不把固定 MCP SDK 脚本验证等同于 AI 自主任务验收。
