# 输出契约

本文件定义 `A01_创建技能` 在新建、重写、薄化或补齐本地 Skill 时的输出物要求。它只约束交付结果，不替代 `SKILL.md` 的触发入口和固定动作。

## 一、输出类型

| 场景 | 输出物是否必须存在 | 必须交付 |
|------|--------------------|----------|
| 新建 Skill | 是 | `.agents/skills/{Skill名}/SKILL.md`、`agents/openai.yaml`、`references/`、`scripts/`、`assets/` |
| 重写或薄化 Skill | 是 | 薄入口 `SKILL.md`、承接长知识的 `references/*.md`、必要脚本和物料目录 |
| 补齐工作区本地骨架 | 是 | 缺失的基础目录或文件，以及更新后的 `agents/openai.yaml` |
| 只做方案判断或适装建议 | 否 | 对话回复中说明判断结论、建议路径和未写入原因 |

## 二、必须存在的文件与字段

1. Skill 目录名必须是 `{域代码}{编号}_{技能名}`，不得在目录名写版本号。
2. `SKILL.md` YAML `name` 必须等于目录名，`description` 必须能说明触发场景，正文保持薄入口。
3. `agents/openai.yaml` 必须存在，至少包含 `interface.display_name`。
4. `references/`、`scripts/`、`assets/` 目录必须存在；即使暂时没有物料，目录也要保留。
5. 当 Skill 有明确交付产物时，必须补 `references/输出契约.md` 或在既有分册中写清输出要求，并在 `references/结构融合索引.md` 的 `8. Output Schema` 指向它。

## 三、最终回复必须说明

- 本次是新建、重写、薄化、补骨架还是只判断不写入。
- 实际新增或修改了哪些文件。
- 版本号是否变化，变化后写在 `agents/openai.yaml` 的哪个字段。
- `scripts/quick_validate.py` 的校验结果。
- 如未产生文件，说明为什么本次输出物不需要落盘。

## 四、失败边界

- 基础骨架不完整时，不得声明 Skill 已创建完成。
- `quick_validate.py` 失败时，不得声明交付完成，必须说明失败项和待修复路径。
- 旧知识未迁入 `references/` 前，不得删除厚 `SKILL.md` 中的有效内容。
- 不生成 README、CHANGELOG、INSTALLATION_GUIDE 等噪音文件。
- 不把密钥、登录态或一次性环境变量写入 Skill 文档。
