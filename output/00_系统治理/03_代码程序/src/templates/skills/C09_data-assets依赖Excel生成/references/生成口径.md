# 生成口径

> 本地 CLI：默认只扫描已有仓库，不克隆/同步；仅显式 `--force-sync` 执行来源中的强制同步步骤，需符合当前 C01 授权。

## 扫描范围

- 默认仓库：`input/data-assets`
- 默认分支：`master`
- 默认文件范围：同步后的 `git ls-files` 中 tracked 的 `.sql` 与 `.py`
- 默认不包含未 tracked 文件、忽略文件和 `git status` 不展示的本地归档目录

## 表识别

数据表识别按以下优先级合并：

1. 文件名 stem 等于所在最小目录名，例如 `dwd_xxx/dwd_xxx.sql`
2. 脚本中出现明确目标表：`insert into`、`insert overwrite table`、`create table/view`、`truncate table`、`write.jdbc(table=...)`、`to_mysql(...)`
3. 仅识别到 staging 目标时，回落到路径/文件名推断

归一规则：

- `_cluster` 后缀按逻辑表归一，例如 `cbebg.xxx_cluster` 归为 `cbebg.xxx`
- 显式库名优先；缺失库名时按路径分层推断
- `cbebg/*` 默认库名为 `cbebg`
- `dw-data/dim/*` 默认库名为 `ck_dim_db`
- `dw-data/dws/*` 默认库名为 `ck_dws_db`
- `dw-data/ods/*` 默认库名为 `ck_ods_db`
- `dw-data/dmd/*` 默认库名为 `ck_dmd_db`
- `dw-data/ext/*` 默认库名为 `ck_extra_db`

## 依赖解析

- 只从 `from` 与 `join` 直接引用抽取上游表
- 能解析到本次数据表清单的引用，计入 repo 内直接依赖
- 无法解析到本次数据表清单的引用，进入“外部上游引用”sheet，不计入上下游数量
- 多目标 SQL 批处理按语句块绑定目标表和依赖
- 多目标 Python 若无法可靠匹配独立语句块，则依赖按空处理并写入异常清单，避免制造假依赖

## 必需 Sheet

1. `文件清单`：文件 id、文件名、文件路径、是否数据表、数据表名
2. `数据表清单`：数据表 id、数据表名、文件名、文件 id、上游依赖表数、下游依赖表数
3. `下游依赖明细`：数据表名、数据表库名、数据表 id、下游表名、下游表库名、下游数据表 id
4. `上游依赖明细`：数据表名、数据表库名、数据表 id、上游表名、上游表库名、上游数据表 id

## 补充 Sheet

- `汇总`：仓库、提交、范围和总体统计，并列出上下游 Top 表
- `外部上游引用`：无法映射到本次表清单的引用
- `异常清单`：非数据表文件、单文件多目标表、单目录多脚本、同名多库/多路径、语句块未匹配等
- `解析说明`：生成口径摘要

## 静态解析限制

- 不执行业务 SQL/Python
- 不解析运行时复杂拼接、调度平台配置和跨系统元数据
- 同名表跨库或跨路径时，以库名加表名作为表对象；需要人工复核业务语义
