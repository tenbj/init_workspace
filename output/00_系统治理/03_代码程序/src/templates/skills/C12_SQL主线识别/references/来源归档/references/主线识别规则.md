# 主线识别规则

## 仅完成主线识别

主线是从输入到最终结果的关键加工动作及其真实依赖顺序。用户确认固定表达：先给主线，再给表格；表头严格为“主线节点”“代码动作”。不自动加入粒度、字段等第三列或完整代码讲解。

## 四个动作

1. 沿最终SELECT或写入语句承载的查询逆追FROM/JOIN/子查询/CTE，找出实际参与输出的数据路径。忽略未使用CTE，不能按文件书写顺序推断依赖。
2. 从操作及下游用途判断动作：准备明细、关联、过滤、扩行、选行、汇总、合并、衍生计算等。保留决定主线的关键变化；一段可能有多个动作，不必须与CTE一一对应。
3. 合并同目的连续辅助步骤；参数和周期枚举通常归于使用方。分支在主线中明确表示“分支A… / 分支B… → 合并”，不能串成A先执行B的假顺序。
4. 从源到结果顺向核对，每个节点须能指回原SQL的行号与文本依据，再输出简洁箭头链。

## 防止机械套模板

- ROW_NUMBER只编号；若下游取rn=1，才能按用途概括为选行准备。窗口聚合一般不是GROUP BY降粒度。
- CROSS JOIN不必然是周月扩行，须确认右侧数据是什么；UNION ALL可能在日层或汇总后，不能只按关键字贴标签。
- JOIN可能补属性、过滤范围或扩成多行；唯一性未明时不要断言一对一。
- 汇总可不带GROUP BY；CASE可只是字段计算，不单独构成阶段。
- 有WITH不代表都参与最终结果；递归CTE须保留“递归/迭代”动作。
- 多条独立SQL分别识别；建表外壳与其查询区分。动态SQL无法展开时注明边界，不伪造内部主线。
- 简单SQL允许只有1或2个节点，不固定为本案例五步。

## 已确认的示例

主线：日明细 → 周/月扩行 → 统一选行 → 统一汇总 → 衍生指标

| 主线节点 | 代码动作 |
|---|---|
| 日明细 | 准备日期和源记录 |
| 周/月扩行 | 每条记录展开为W、M两份 |
| 统一选行 | 两种周期共用一套取值序号 |
| 统一汇总 | 按周期、链接统一聚合 |
| 衍生指标 | 基于周期结果计算占比、变化、趋势 |

这是一个SQL的实例，不是所有SQL的预设主线。识别表必须以实际SQL为准。
