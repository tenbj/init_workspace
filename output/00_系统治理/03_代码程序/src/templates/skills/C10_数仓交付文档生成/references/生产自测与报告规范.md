# 生产自测与报告规范

## 查询原则

- 只使用 C02 执行只读查询。
- 每次检查返回后先查看 `error`，再解释数据。
- 最新分区由目标表 `MAX(DATE(biz_dt))` 确定；及时性再与 SLA 比较。
- 命令包装失败与业务数据异常分开记录，修正包装后重跑。

## 自测矩阵

| 自测 | 必查证据 |
|---|---|
| 分支数量 | 源原始行数、源唯一键数、目标行数 |
| 键集合 | 源缺失目标、目标多出源 |
| 主键 | 目标重复键、公式复算差异 |
| 核心加工 | 关键源字段、枚举映射、窗口排名 |
| 派生指标 | 除法精度、聚合金额/数量、空值语义 |
| 边界 | 非法枚举、非正排名、评分越界、负销量/金额 |
| 调度 | 最新业务日期和 SLA 预期日期 |

目标使用 Doris Unique Key 时必须检查“源原始行数 → 源唯一键数 → 目标行数”。只看目标重复数无法识别写入前候选被合并。

## Excel 实际结果

- 写日期、范围、行数、差异数和 `quality_value`，不能只写“正常”。
- 结论只允许与证据一致：通过、部分通过、不通过。
- 非核心字段全空或上游延迟但不影响当前验收时，作为观察项披露。
- 代码已更新但生产未重跑，或生产已修复但本地代码未同步，必须拆开写状态。

## 独立报告结构

1. 目标表、SQL 来源、环境、执行日期、最新业务日期。
2. 总体结论。
3. 数据范围：最早/最新日期、总行数、日期数、分支行数。
4. 六维 DQC：业务阈值、实际质量值、结论。
5. 数据自测：数量、键、主要分支、派生指标和边界。
6. 风险控制和新增 DQC 的防护目的。
7. 验收结论：数据、代码、DQC 接口和交付状态分别判断。

## 必须重跑的时机

- 主键、字段列表、分支逻辑、JOIN、聚合或窗口函数变化。
- 目标表结构或 Key 模型变化。
- 质量维度映射或阈值变化。
- 实际结果日期过期且用户要求正式交付。

每次重跑都从最终落盘 SQL 提取 DQC 原文执行，防止临时查询与交付 SQL 漂移。
