# GitHub 发布

## 这项技能解决什么问题

- 把当前工作区按安全、可追溯、可发布的方式提交到 GitHub。
- 维护项目级 `CHANGELOG.md`、Release Notes、tag、Release 附件和校验信息。
- 将内部 `output/*/版本记录.md`、Git commit 和 GitHub Release 分层，避免把内部治理噪声直接发布给用户。

## “发布”的默认含义

用户要求发布当前项目/这次改动，且对象可从上下文确定时，即授权完整发布链：**本次新工作分支 → 按独立事项逐一提交 → 统一推送 → PR合并并保留分类提交 → 核验 → Tag → GitHub Release**。先清理本次交付并完成必要验证；不能只做push或上传Release就结束。多仓库分别执行并记录结果。同一次发布的恢复、返工复用已记录分支，不重复建分支；已有原始开发分支和隔离改动保留。

用户明确限定“只提交/只推送/暂不合并/只打Tag/只写发布说明”时按限定范围执行；单纯问“如何发布”不触发远端变更。对象无法确定时只澄清缺失信息，已有授权不重复询问。发布不隐含重新部署、删除旧分支或合并隔离的旧开发。

## 先读哪些本地知识

- 提交前读取 `.agents/rules/version-control-rules.md` 的“Git 提交描述语言”统一约束。
- 先读 `references/发布流程.md`，确认默认发布顺序。
- 涉及更新日志、版本号、Release Notes 时，读 `references/更新日志方案.md`。
- 涉及发布前验收、安全扫描、资产校验时，读 `references/发布前检查.md`。
- 需要执行命令或生成命令时，读 `references/GitHub命令模板.md`。

## 固定动作

环境模板只通过 `.envs/env_manager.py export-public` 的公共文件白名单生成，不整目录复制本机 `.envs/`。示例非空或分发目标混入私有文件时停止；真实凭据不进入模板、历史附件及发行包。初始化源码负责只补缺并保留已有清单与真实文件。

执行前先按 B11 核验当前工作分支与提交保护。**禁止在 main 上直接提交，包括发布准备提交。** 检查失败时先保留改动、切工作分支并恢复保护，再开始构建和提交；最终 tag 仍指向已核验的 PR 合并结果。

1. 先确认真实仓库、最新目标基线、正式变更范围、公开版本与交付物；区分核心骨架项目和普通应用，不能因都位于同一工作区就套用同一构建。
2. 按 B11 从已确认基线创建本次发布工作分支，保护原始改动与恢复点；按 B02/B03/B08 处理备份、任务进度和记忆。仅用户明确要求时调用 B01。
3. 仅核心骨架项目发布运行 `scripts/update_init_program.ps1`，成功后运行 `scripts/build_init_exe.ps1`，详见发布流程；普通应用执行其自身构建、测试和打包，不要求初始化程序或exe清单。
4. 整理有效脚本、文档和交付物，维护 CHANGELOG 与 Release Notes，按独立事项形成完整中文提交；具体命名回到Git标准。系统项目的测试管理按 H02，不能把一次性演练与私有材料一并打包。
5. 检查所有待公开新提交及blob、忽略规则、当前源码与产物及本轮验证证据；全部本次提交就绪后统一推送工作分支，按 B11 创建PR、等待检查并用merge commit保留分类提交。
6. 执行 PR 合并检查，核对合并目标与每条分类提交；通过后在该合并结果上创建并推送Tag，再创建GitHub Release及适用附件。明确限制或已存在标签/Release的冲突按发布流程处理。
7. 回读远端Tag、Release、资产及摘要，按发布前检查的完成证据清单逐项记录；未完成的阶段不能报告成功。

## 什么时候再读本 skill 的 references

- 只问“怎么设计更新日志”时，重点读 `references/更新日志方案.md`。
- 要真正发布或推送时，完整读 `references/发布流程.md` 与 `references/发布前检查.md`。
- 需要复制命令、改版本号、算 hash 或创建 Release 时，读 `references/GitHub命令模板.md`。
- 遇到 tag 已存在、Release 创建失败、远端不同步、敏感扫描失败时，回到 `references/发布流程.md` 的异常边界。

## 提交命名检查

生成消息及执行提交、合并或发布准备提交前，读取并执行 `.system/standards/Git版本控制标准.md` 的“提交命名”与“提交前核对”。命名规则和合格示例只在该标准维护，本 Skill 不另设口径。

## 边界

- 不在未完成敏感信息检查时推送公开仓库或创建 Release。
- 初始化程序更新与exe重封装只适用于核心骨架项目；普通应用不得被要求构建无关初始化程序。核心骨架发布仍不得跳过这两步。
- 更新核心骨架初始化程序时，不手工比对或零散复制模板；以当前 live 工作区为权威源，全量刷新已注册技能到最新。
- 不把 `.history/`、`.memory/`、`input/`、`.temp/`、本机私有配置或 `*.exe` 直接提交进 Git。
- 不把 GitHub 自动生成 Release Notes 当作唯一事实源；它只能作为草稿辅助。
- 不覆盖用户已有 Git 配置、远端、tag 或 Release；冲突时先报告并等待用户确认。
- 不在聊天、文档、脚本或命令历史中暴露 GitHub token。
