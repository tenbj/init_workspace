# 发布前检查

## 必须通过

1. `git status --short` 已理解：
   - 相关改动已纳入本次发布
   - 无关用户改动不被误提交

2. 忽略规则有效：
   - `.Claude.json` 不入库
   - `.claude/settings.local.json` 不入库
   - `input/` 只保留必要占位
   - `.temp/` 只保留必要占位
   - `.history/` 不提交历史快照
   - `*.exe` 不作为普通 Git 文件提交

3. 敏感信息扫描通过：
   - token / key / secret
   - 内部 URL
   - 数据库连接信息
   - 用户本机路径和私有配置

4. 发布文档一致：
   - `CHANGELOG.md` 最新版本在顶部
   - Release Notes 与 changelog 不冲突
   - README 当前版本正确
   - tag、Release 标题、资产文件名一致

5. 构建和校验按发布目标分流：
   - 仅核心骨架项目：初始化程序已通过 `scripts/update_init_program.ps1` 更新，更新清单与源码版本一致；随后通过 `scripts/build_init_exe.ps1` 重封装，构建清单记录资产路径、大小及SHA256。
   - 普通应用：通过项目自身构建与测试，检查对应交付物；不要求初始化程序、exe或上述清单。
   - H02系统：按H02的测试资产管理规则清理当前交付，核对源码、镜像、双图、合同与本轮证据一致；可复用测试集中管理，一次性旧脚本和私有演练不进入发布包。
   - 必要测试已通过，资产SHA256已计算；发布说明不能复用旧报告声称本轮已验证。

6. 本次发布记录完整：
   - 新发布任务有专用工作分支，续做能对应原记录；无关修改和旧开发有明确保留范围。
   - 每个独立事项有完整提交及验证，记录全部待保留SHA；全部就绪后统一推送。
   - 逐仓库执行，不因另一仓库成功就宣称两个系统都完成。

## 可选手动体检

仅在用户明确要求框架体检时调用 B01 并报告结果。未请求时不执行，也不作为发布准入条件。

## 建议命令

```powershell
git status --short
git diff --cached --name-only
git diff --cached
```

扫描全部待公开新增blob，而非仅最终工作树；在本工作区调用下列脚本，仓库和版本范围按本次发布替换：

```powershell
python .agents/skills/B09_GitHub发布/scripts/scan_release_history.py --repo-dir <目标仓库> --base <已确认基线SHA> --head <发布分支SHA> --asset <发布ZIP或文件>
```

`--asset`可重复，无附件时省略；可重复传`--secret-file <本机私有env文件>`，在内存提取非样例敏感值做精确匹配，不打印值、片段或私有文件路径。显式私有值只排除完整占位符或变量引用，不因包含`test_`、`sample`等子串而排除。Git和附件分别报告；两者中的ZIP递归读取、不落盘、不执行，共享各自类别的总字节与成员预算。退出码`0/1/2`分别表示范围内扫描完成且无发现/命中/未完成；对象或输入不可读、资源超限、加密或损坏ZIP均不能视为通过。默认上限：单文件16MiB、每类累计256MiB（含容器与展开内容）、Git对象10000、ZIP成员累计2000、嵌套3层、压缩比1000。该脚本仅为启发式辅助；不覆盖基线既有历史、外置LFS/子模块内容、非ZIP压缩内容及所有混淆秘密，仍须结合忽略规则、范围与人工判断。共享blob可能只报告一个代表路径；命中项不附源码片段。

如仓库中允许二进制 Release 附件只通过 GitHub Release 上传，则发布前检查暂存区：

```powershell
git diff --cached --name-only | Select-String -Pattern '\.exe$'
```

## 失败处理

- 检查失败时停止发布。
- 如果失败来自本轮改动，先修复并重新检查。
- 如果失败来自用户未说明的既有改动，只报告风险，不擅自删除或重置。
- 如果必须移除暂存项，先说明将移除哪个路径，再执行非破坏性取消暂存。


## 保留分类提交时的 PR 合并检查

在目标仓库根目录执行，先按注册表解析 B11 的路径：

```powershell
python .agents/skills/B11_Git分支工作流/scripts/verify_pr_merge.py --repo <owner/repo> --base main --commit <合并SHA> --expected-commit <分类提交SHA1> --expected-commit <分类提交SHA2>
```

- `--base` 按实际目标基线替换；把本次要求保留的每条提交都传入，不只传分支末尾一条。
- 提前 fetch 合并结果。检查命令只读取 Git 和 GitHub，不推送、不合并、不调整标签。
- 必须得到成功结果，再让 tag 指向该合并 SHA；回读远端 tag 和 Release 的目标，核对附件 SHA256。
- 单亲直接提交、未合并 PR、基线不符、PR head 不符或缺少分类提交均不能代替成功结果。
- 发生中间提交敏感问题，回到 B11 的分支净化步骤；不得在 main 重新压缩提交以绕过历史检查。

## 发布完成核对

依次核对远端PR已合并、分类提交全保留、Tag解析为已核验合并SHA、Release存在且不是未发布草稿、关联Tag正确、附件名和大小一致。适用附件下载回读并重新计算SHA256。报告各阶段真实结果与URL；缺少阶段就说明未完成，不能以“push成功”替代完整发布。恢复任务先回读现状，避免重复创建或覆盖已成功对象。
