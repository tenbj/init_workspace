# SQL 编写与验证

## 固定合同

- 查询数据：`query_data`；实体数据：`table_data`。
- 日期：`check_date`；两侧日计数：`query_count`、`table_count`。
- 两侧各自 `GROUP BY` 已识别的日粒度表达式，使用 `COUNT(*)`。
- 日期集合取两侧分组日期并集，或使用等价的保留两侧日期的关联。不可只用 INNER JOIN。
- 缺少某侧记录时其计数补0。NULL 日期保留并用空安全关联，避免NULL分组被丢失或重复。
- `dc` 仅包含 `query_count <> table_count` 的日期分组。
- 最终只返回 `SELECT COUNT(*) AS quality_value FROM dc;`，0一致、正数为数量不一致的日期分组数，不是相差行数。
- 两侧均空时 `dc` 为空，质量值自然为0；不补造异常行，不把NULL日期本身判为异常。
- CTE 分隔符写成上一行`)`、下一行`, 别名 AS (`；首个CTE前不加逗号，也不将逗号单独放一行。

## 模板使用

读取 `../assets/逐日数量核验模板.sql`。填入完整的数据CTE定义及两侧日期表达式，保留原查询依赖；原查询有WITH时将其CTE按依赖顺序放在query_data前，不丢弃嵌套逻辑。

模板占位符只用于制作，交付SQL必须全部替换。不要用不理解SQL结构的字符串截取破坏子查询、分号、字符串或注释。SQL前附日期映射、范围与选择理由。

诊断SQL复用主SQL中截至daily_comparison的CTE，末尾改为输出check_date、query_count、table_count、query_count-table_count AS row_difference。可加MATCH／COUNT_MISMATCH状态，优先展示差异日期。两侧全空时诊断结果零行是正常结果。

## 验证

1. 检查最终SQL只读且可独立执行，无模板占位符，所有上游JOIN和分支未遗漏，日期范围映射一致。
2. 用户要求实测时通过C02读取最终落盘文件执行，先检查error，保留实际SQL与时间；只生成时明确未执行。
3. 结果集不能被客户端默认上限静默截断。诊断有大量日期时采用覆盖范围的显式LIMIT或分页，并核对导出行数；质量值为单行聚合，不受明细输出上限影响。
4. 检查异常日期能直接定位。SQL错误与数据不一致分开报告，不修改业务口径以获得通过。

| 样例 | quality_value |
|---|---:|
| 每日两侧相等 | 0 |
| 总量相等、2个日期发生反向差异 | 2 |
| 某日仅一侧有数据 | 1 |
| 两侧全空 | 0 |
| 某日两侧都无记录 | 0 |
| NULL日期分组数量相等 | 0 |
| NULL日期分组数量不同 | 1 |

## 补充检查的范围

用户需要时可另交付两侧分支、唯一键数量或双向键集合比较，仍只判断两侧差异；不默认增加完整性、有效性、单侧重复检查或六维Excel交付。写入前行数与唯一键数的差额可作为诊断信息，不能混作主SQL异常条件。

数量和键集合一致均不证明所有属性值一致。需要字段值复算时应作为另一个明确范围处理。
