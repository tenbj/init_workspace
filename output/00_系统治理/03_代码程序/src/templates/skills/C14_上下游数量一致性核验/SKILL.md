# 上下游数量一致性核验

## 本地接入

执行前先读 `references/本地接入.md`，确认本项目规则、输入及授权。来源案例不授予本项目权限。

## 这项技能解决什么问题

将完整加工 SELECT 形成的“查询数据”与目标表的“实体数据”按日期逐日比较；全量更新表没有业务日期时使用其他可用的非审计时间，排除三个审计字段后没有时间字段时比较整表COUNT(*)。只判断两侧是否一致：两侧都没有数据时通过。

## 先读哪些本地知识

- 先读 `references/日期识别与范围.md`，从源码、参数和字段含义确定日期与可比较范围。
- 编写 SQL 前读 `references/扩展说明.md`；准备交付时读 `references/输出契约.md`。
- 需要生产实测时执行 C02；需要获取 DDL 时执行 C03。输出归属与备份遵循 B04、B02，进度和记忆按 B08、B03 收尾。

## 固定动作

0. 本次任务授权更新源码时，先拉取最新源码：独立新核验先检查 `input/data-assets` 为master、无本地改动，再fetch origin master并以 `merge --ff-only FETCH_HEAD` 快进，核对HEAD等于本次远端提交，记录北京时间及提交号后读取SQL。由C17调用时复用本批已同步并固定的提交，不重复拉取。分叉、改动、同步失败时保留现场并报告，不自动reset/clean，不以平台同步语句冒充仓库源码；第1步的海豚真实SQL优先分支单独记录部署基线。用户明确指定版本/不联网时记录例外。仓库缺失及明确授权强制对齐时按C01边界处理。
1. 根据用户给定表名或 SQL 定位完整加工代码和实体表，记录代码版本、写入方式及范围。旧表、仓库代码或部署不一致时，按本任务已有明确授权及C17的海豚真实SQL优先规则，从模型→关联ETL→跳转工作流读取实际SQL节点，以真实写入表及完整加工逻辑为基准；单列仓库维护异常、登记表与实际表映射及工作流/节点版本，不止于记录问题。仅在目标歧义等实质性缺口无法自行解决时询问。
2. 自行识别核验日期：优先参数日期对应字段，没有参数日期则按业务语义选择日期。全量更新表无业务日期时用其他可对应的非审计时间；first_inserted_dt、etl_dt、last_updated_dt不视为“其他日期”，排除后无时间字段则走整表COUNT(*)分支。说明两侧映射、日粒度转换、范围和理由；不把参数常量当作所有记录的分组日期。
3. 保留原加工逻辑形成 `query_data`，取同范围实体数据形成 `table_data`；总量超过1亿行的模型按用户规则只核验近六个自然月，具体边界及证据按日期识别与范围执行。逐日模式两侧按日期 GROUP BY 分别计算 `query_count`、`table_count`，日期并集对齐并将单侧缺失数量补0；整表模式分别COUNT(*)后将两侧单行聚合对齐。
4. 有可用非审计时间字段时参照 `assets/逐日数量核验模板.sql` 生成完整只读主 SQL；全量表排除三个审计字段后无时间字段时分别聚合整表COUNT(*)，保留真实模式为whole_table。异常集合 `dc` 只保留 `query_count <> table_count`；最终仅输出 `SELECT COUNT(*) AS quality_value FROM dc;`。整表模式值为0或1，逐日模式为不一致日期分组数。CTE 逗号放在下一子句别名前。
5. 用相同模式的比较 CTE 生成诊断 SQL，逐日模式输出日期、两侧计数和差额，整表模式输出两侧计数和差额。默认交付这两条 SQL；只在用户需要时增加分支、唯一键或双向键集合比较。
6. 用户要求核验结果时通过 C02 执行最终落盘 SQL，检查错误并保存结果；只要求生成时不强制连接生产。核对字段、范围、日期完整导出和接口，交付路径及执行状态。

## 边界

- 固定使用“查询数据”“实体数据”及 `query_count`、`table_count`；不混入非空、连续日期、字段有效性或单侧内部唯一性检查。
- 两侧全空、某日两侧均无记录均通过；NULL 日期保留并空安全对齐，只比数量。不补造空表异常，不使用 `COUNT(DISTINCT ...)` 替代主计数。
- 不把业务日期固定为广告组创建日期。有可用非审计日期时不以总量相等替代逐日相等；全量更新表排除三个审计字段后无时间字段时按用户确认走整表数量核验并明确标注。不得改变原 SQL 的 JOIN、过滤、聚合或去重以凑齐数量。
- 数量一致不等于字段值一致或业务正确。本 Skill 独立维护quality_value输出接口；C10仅为可选报告扩展，不启动其六维／Excel交付和空表异常规则。
- 生产只读；不执行写入、不修改正式 ETL／表结构／调度。按本任务已有明确授权先安全更新源码，但不自动重置或清理本地仓库；不保存凭据。
