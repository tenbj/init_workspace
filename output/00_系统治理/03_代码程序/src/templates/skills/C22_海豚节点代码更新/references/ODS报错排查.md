# ODS报错排查

## 先分阶段再行动

区分提交/调度、环境初始化、配置JSON解析、源查询、目标写入、后续统计。只取必要日志，过滤数据库密码、Cookie、访问密钥、连接串和含凭据的启动命令。HTTP 200/页面成功不代表作业成功。

## 已验证案例01：Common-00非法JSON

| 项目 | 实证 |
|---|---|
| 现象 | 约3秒失败，Common-00，配置信息不是合法JSON，TODO : F |
| 阶段 | ConfigParser.parseJobConfig / Configuration.from，尚未数据读写 |
| 触发 | 带原始双引号和换行的GitLab SQL直接填入嵌入JSON字符串的sql参数 |
| 根因 | 缺少模板所需转义，不是两个新增INT字段的转换错误 |
| 修复 | 对照成功版本，安全整理单行，四个PG大小写标识符的8个双引号转义；只改DataX sql |
| 检查 | 解码SQL与Git来源一致，59列和columns顺序一致，保存回读一致 |
| 验收 | 版本20实例610835成功19秒，DataX1216954/统计1216955成功，425条加载，失败/过滤0 |
| 边界 | 本模型PG→Doris自定义模板已验证，其他链路另核转义层数 |

寻找最早异常，不用末尾FAILURE代替根因。配置解析失败不能归因Doris类型；检查是否执行preSql/发生部分写入，不能把其他阶段失败也当无数据影响。

## 其他常见方向：排查指引，非本次实测修复案例

| 现象 | 先查证据 | 不可猜测执行的修复 |
|---|---|---|
| 源列不存在/大小写错误 | 保存后的SQL、源元数据、PG引号和大小写 | 删除引号、盲改字段名 |
| 写入列数/映射异常 | 输出别名顺序、columns、实体列 | 只凑列数不核位置 |
| 转换或过滤错误 | 加载回执、脱敏错误样例、真实值和类型 | 自动改类型、放宽过滤阈值 |
| 日期/数量异常 | 实际参数、源查询范围、preSql范围、两端计数 | 直接全表重跑或改日期 |
| DataX成功而流程失败 | 统计/后置日志、依赖和响应 | 仅据DataX报全流程成功 |
| 环境/权限/连接失败 | Worker、租户、节点环境和成功配置 | 更换凭据、覆盖连接、反复运行 |
| 零行成功 | 范围内源数据、读取和加载指标 | 宣称有数据验证通过 |

这些仅为对应故障的调查入口，不能提前实施修复或试探生产写入。

## 持续积累

用户要求后续ODS常见报错一起纳入Skill。每次实际遇到新问题用 [报错案例模板](../assets/报错案例模板.md) 补充：现象→阶段→证据→根因→最小修复→保存回读→真实运行→边界。推测单列，不混入已验证结论；维护Skill按 A01 和用户授权范围，不自动备份，不顺带大范围改规则。
