# C22_海豚节点代码更新

## 这项技能解决什么问题

- 更新已有DolphinScheduler工作流的模型加工代码，交付保存回读、运行结果与定时恢复证据。
- 适用于不同分层和节点类型；ODS/DataX、DWD/SQL已有实测，其他类型按实际代码承载位置处理。
- 仓库同步、GitLab发布、平台新增字段分别交给 C01、C19、C21，本技能不重复实现。

## 先读哪些本地知识

- 每次读 [操作流程](references/操作流程.md)、[输出契约](references/输出契约.md)，按 B08 恢复任务和授权边界。
- 读取 [数据平台模型与海豚工作流操作规则](../../rules/platform-modeling-rules.md)。关联工作流从目标模型行的“关联ETL→跳转工作流”进入；代码整块录入、保存前后双重回读、实际停止及恢复按该规则执行。
- DataX编辑前必读 [ODS与DataX参数](references/ODS与DataX参数.md)；失败时读 [ODS报错排查](references/ODS报错排查.md)。
- 按 B03 记录增量；本地修改不自动备份，用户明确例外优先。

## 固定动作

1. 锁定模型、环境、项目/工作流/节点及代码来源提交，记录工作流和原定时状态，确认本轮授权停点。
2. 将标签页置前，从模型关联工作流打开详情，复制完整名称。每次下线、编辑、上线或恢复定时前，必须在工作流定义页右上角搜索框输入完整名称并查询，核对结果中的完整名称、项目和目标ID，禁止在未筛选列表中按行序或旧坐标操作。
3. 下线后进入编辑；核对节点类型和代码承载位置。代码必须从已确认文件整块粘贴，禁止逐字输入；执行[操作流程第2.1节](references/操作流程.md#21-代码整块录入与保存前回读)，先置临时标识再复制编辑器全文，比较一致后才点节点确定。DataX同步核对sql、columns和运行时转义。
4. 已授权发布时，节点设置点击“确定”→编辑页顶部“保存”→“基本信息”保留原执行策略，底部勾选“是否上线工作流定义”→“确定”；返回列表后回读持久化代码全文、参数、版本和上线状态，与来源一致才运行。不能为补数并行而修改保存弹窗的执行策略；仅填写授权则停在草稿。
5. 试跑时完整名搜索定位→目标行“运行”→启动弹窗直接“确定”，保留现有默认配置；到左侧“工作流实例”定位本次实例并刷新观察到终态。整体成功直接进入下一步，不打开成功节点详情或日志；失败才打开失败节点日志，分析并反馈原因，按授权修复后再次试跑。
6. 试跑成功后恢复原本在线的定时；用户明确要求不试跑但上线并恢复定时时，跳过运行，保存回读通过后直接恢复原定时。回读工作流与定时状态，分别记录代码发布完成和运行未验证。
7. 已授权历史更新时，先检查实际DAG和各节点用途，判断跳过哪些依赖检查、保留哪些SQL后续节点，再选择执行方向；不能默认仅SQL，也不能不看节点就一律向后执行。时间区间参数运行用原工作流、填写起止启动参数、分批串行，不建副本；只有海豚“补数”模式才复制专用副本，删除副本依赖节点并核对剩余关系，副本定时不启用、补完下线留记录。无日期参数的整表重算也先判断节点范围，再运行一次。原工作流策略、依赖和定时保留。具体判断与实测边界见操作流程第6.1节。提交前在对话公布执行/跳过节点及理由、日期范围、批次、来源与预计输出量和失败处理；所需节点全部成功且数据核验通过后完成模型。

## 边界

- 仅封装/回顾时不操作生产；带教遵守停点。已有发布运行授权不在常规确认弹窗处重复询问。
- 不通过平台的同步语句确认更新修改代码；既有模型更新不套用新模型创建的MR合并门，来源仍须明确。
- 不擅自全量补数、清空表、删除字段、改变口径、放宽错误阈值或发消息；原无定时/有意停用的模型不擅自启用定时。
- 不硬编码目标ID、UID、凭据；不复制含密码的完整日志。无法确认目标或写入影响时先问，独立只读检查继续。
- 用户要求停止时先终止实际自动化动作，取得停止证据后才报告“已停止”；取消等待不算停止。停止及恢复按共用规则和操作流程“中断停止与恢复”执行，优先于分析和记录，保留未恢复的工作流/定时状态。
- 遵守指定次数和停点；用户明确授权修复至成功时，每次先查失败原因并作针对性调整再重试，不原样循环提交。无保存和运行证据不得宣称成功。
