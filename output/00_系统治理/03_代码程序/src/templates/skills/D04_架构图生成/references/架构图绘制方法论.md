# 架构图绘制方法论（通用）

> 本文件是本技能的核心资产。它先**复盘**本次"核心框架整体架构图"是怎么画出来的，再**抽象**成任意系统都可套用的通用流程，最后给出手写 SVG 的硬规则与质量自检清单。
> 配套：`assets/架构图模板.html`（空白骨架，绘制新图时从此出发）、`assets/示例-核心框架架构图.html`（已填充样本，画法复盘对照）、`references/配色与坐标速查.md`（色板与坐标）。

## 0. 这份方法论从哪来

本方法论源自本技能打包时依据的一次真实架构图绘制实践，经归纳沉淀为通用画法；其**已填充样本**随技能附在 `assets/示例-核心框架架构图.html`（即那次真实绘制的成品，自顶向下把"多 AI 接入 → SSOT → 执行层 → 治理机制 → 数据存储区 → 强制门时序"串成一张图），而**空白骨架**则是 `assets/架构图模板.html`（可直接克隆使用的分层带占位，含语义色板、图例与侧边说明卡）。下面的复盘与通用步骤均以该样本为对照、以模板为落点——你画任何系统时，都从这份内部模板出发，而非从零写起。

## 1. 样本是怎么画出来的（复盘）

> 下表以技能内附样本 `assets/示例-核心框架架构图.html` 为对照，逐步骤拆解那张图的实际画法；其结构骨架与 `assets/架构图模板.html` 一一对应，可直接套用到任何系统。

| 步骤 | 做法 | 样本中实例 |
|------|------|---------|
| ① 抽象层级 | 把系统拆成有限个**水平带**（band），每带一个主题；带内元素同色系 | 6 个带：多 AI 接入 / SSOT / 执行层 / 治理机制 / 数据存储区 / 强制门时序 |
| ② 定流向 | 带与带之间用**箭头**表达因果或依赖；支撑门与机制之间用细线/虚线表达"嵌入而非独立" | 接入层→SSOT→执行层→机制→存储区，自上而下实线箭头 |
| ③ 配语义色 | 每个带一种**主色**，用一组 CSS 变量定义色板；所有矩形/文字/箭头颜色引用变量；底部统一图例 | `--ai / --ssot / --exec / --mech / --gate / --store / --seq` 七色 |
| ④ 卡片化 | 每个实体画成圆角矩形**卡片**（标题行 + 要点行 + 落点行），统一网格尺寸保证对齐 | 治理机制 5 张卡 196×138，存储区 5 张卡 196×100 |
| ⑤ 坐标网格法 | 用 `viewBox` 建画布，所有元素绝对坐标定位；列锚点对齐多列；`text-anchor="middle"` 自动居中 | 列锚点 x=40/249/458/667/876（间距 209）；卡片中心 x=列锚点+98 |
| ⑥ 外围说明卡 | 图外 HTML 网格放文字卡片，补充图内放不下的细节，避免图过载 | 右侧两张卡："机制↔存储映射"、"强制门协同步骤" |
| ⑦ 自包含交付 | 单 HTML 文件内联 `<style>`+`<svg>`，无外部依赖；顶部标题+副标题标注生成时间 | 浏览器直接打开，副标题含"生成于 <时间>"占位 |

## 2. 通用化抽象（任意系统 → 这种图）

**输入三元组**：画任何架构图，先拿到这三样：
- **实体清单**：系统里有哪些"东西"（模块、机制、存储区、角色…）。
- **实体间关系**：谁指向谁、谁依赖谁、谁落点在哪。
- **分层主张**：自顶向下应该切成哪几层（通常 3–6 层）。

**可裁剪性**：
- 小系统 3–4 个带即可，不必硬凑 6 带。
- 颜色板可整体替换（改 CSS 变量），但**每带一色 + 图例**的约束不变。
- 卡片网格的"列数 × 行数"随实体数量变化，列锚点按 `起始x + i×间距` 推算。

**复用路径**：复制 `assets/架构图模板.html` → 改标题/副标题 → 按实体填卡片 → 按关系连箭头 → 补图例与侧边卡。

## 3. 标准工作流（5 步，与 SKILL.md 固定动作对应）

### 步骤 1 · 抽取结构
- 向用户确认或自行梳理"实体清单 + 关系 + 分层主张"。
- 输出一张草稿表：每层有哪些实体、实体间谁指向谁。
- 判定：若连实体都列不全，先回到梳理，不要急着画。

### 步骤 2 · 定分层与配色
- 把系统切成 3–6 个水平带，每带分配一种语义主色。
- 颜色必须有含义（如"接入=紫、标准=靛、机制=青、存储=蓝、时序=红"），不能随机。
- 带内实体用同色系的浅底 + 同色描边。

### 步骤 3 · 画卡片网格
- 每个实体 = 一个圆角矩形卡片：第一行标题（加粗）、中间要点、底部落点/注释。
- 用**固定列锚点**对齐多列卡片；`text-anchor="middle"` + 卡片中心 x 让文字自动居中。
- 卡片尺寸统一（如 196×138 或 196×100），行距留白充足。

### 步骤 4 · 连流向与图例
- 用 `<marker>` 定义箭头头，线条 `marker-end` 引用；实线=强依赖，虚线=参考/输入。
- 底部统一**图例**：每种颜色对应的含义一行。
- 关键关系（如"机制↔存储映射""协同步骤"）放到侧边 HTML 说明卡，避免图内过载。

### 步骤 5 · 交付自包含 HTML
- 内联 `<style>`（含 CSS 变量色板）+ 内联 `<svg viewBox>`。
- 单文件，浏览器直接打开；顶部标题 + 副标题（含生成时间）。
- 不引入外部 CDN / 字体 / 脚本。

## 4. 手写 SVG 的硬规则（避坑）

1. **画布建模**：`viewBox="0 0 W H"`，`svg{width:100%;height:auto}` 让图自适应宽度；W 一般 1120 左右，H 随带数增长。
2. **列锚点对齐**：多列卡片用固定 x 序列（如 40/249/458/667/876，间距 209）；卡片中心 x = 列锚点 + 宽度/2。
3. **文字居中**：`text-anchor="middle"` + 中心 x，避免手动算左偏移。
4. **箭头复用**：`<defs>` 里定义 `<marker id="ar">`，多条线 `marker-end="url(#ar)"` 共享，改色只改一处。
5. **长文本必须分行**：SVG `<text>` **不自动换行**；一行放不下就拆成多个 `<text y=...>`。
6. **颜色用变量**：所有 fill/stroke 引用 `var(--xxx)`，改主题色只改 `:root`。
7. **图例必带**：颜色语义必须有一处集中说明，否则看图人无法解码。
8. **侧边卡补细节**：图内只放"结构"，解释性文字放 HTML `.notes` 网格，防止图过载。

---

## 5. 质量自检清单

- [ ] 一眼能分清不同域（颜色是否语义化、是否有图例）。
- [ ] 流向清楚（箭头方向是否表达真实依赖，虚/实线区分是否到位）。
- [ ] 不超载（解释性内容是否已下沉到侧边说明卡）。
- [ ] 单文件可打开（是否内联 style+svg，无外部依赖）。
- [ ] 可维护（是否用 CSS 变量 + 列锚点，改色/加列是否只动少量坐标）。
- [ ] 不自动换行依赖（长文本是否已手动分行）。
