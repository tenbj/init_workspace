# 工作区骨架规格

> 版本：1.11.0  
> 数据源：`.system/standards/workspace-spec.json`  
> 消费者：`framework-check.ps1`（体检）、`normalize.ps1`（规范化）、`init_workspace.py`（exe 初始化）

本文档是 `workspace-spec.json` 的人类可读版本。标准以 JSON 为准，本文档辅助理解。

## 一、根目录结构（8 个）

```
{工作区根}/
├── .agents/          ← AI 行为配置（IDE 自动加载 rules + skills）
├── .claude/          ← Claude Code 本地接入层（settings + slash commands）
├── .history/         ← 版本控制备份
├── .memory/          ← 对话记忆
├── .system/          ← 项目基础设施（标准数据）
├── .temp/            ← 临时文件与规范化异常归档
├── input/            ← 用户参考资料
└── output/           ← 子项目产出
```

根目录固定文件还包括：

| 路径 | 说明 |
|------|------|
| `CLAUDE.md` | Claude Code 会话入口规则，必须保留强制门索引并指向工作区标准 |
| `AGENTS.md` | Codex 会话入口规则，必须保留强制门索引并指向工作区标准 |
| `.Claude.json` | Claude 本地私有环境配置；可能包含密钥，只补缺占位，不由模板覆盖真实值 |

#### `.system` 核心骨架

`.system/` 是工作区基础设施核心骨架，不属于可变层。`.system` 从文件夹到内部所有文件都视为必备核心项：缺失必须补齐，异常不得静默忽略。

| 路径 | 说明 |
|------|------|
| `.system/` | 项目基础设施根目录 |
| `.system/standards/` | 标准数据目录 |
| `.system/standards/workspace-spec.json` | 机器可读 SSOT |
| `.system/standards/工作区骨架规格.md` | 骨架人读标准 |
| `.system/standards/工作区命名规范.md` | 命名人读标准，包含子项目、`.system`、`.memory`、`.history` 命名 |
| `.system/standards/Skills管理标准.md` | Skill 人读标准，包含域分类、编号、注册和生命周期流程 |

`.history/` 内必须保留 `.system` 的历史镜像目录结构；`.memory/` 不再保留 `.system` 镜像。

| 路径 | 说明 |
|------|------|
| `.history/.system/` | `.system` 历史快照根目录 |
| `.history/.system/standards/` | `.system/standards/` 历史镜像结构 |

`.system` 的备份方式与 `.agents/skills/` 一致：按 `.system` 内部子文件夹做整文件夹快照，live 文件夹名称保持不变，历史快照写入 `.history/.system/{子文件夹名}_{yyyyMMddHHmmss}/`。

#### Claude 接入层

`.claude/` 是 Claude Code 在本工作区的本地接入层，必须纳入骨架检查，但其中的本机私有配置不得被模板覆盖。

| 路径 | 说明 |
|------|------|
| `CLAUDE.md` | Claude 会话自动加载的工作区规则入口 |
| `.claude/commands/` | 斜杠命令目录 |
| `.claude/commands/{Skill文件夹名}.md` | 每个注册 Skill 的命令包装文件 |
| `.claude/settings.local.json` | 本机权限设置；只补缺，不覆盖 |
| `.Claude.json` | 本机环境与模型配置；可能包含密钥，只补缺，不覆盖 |

命令文件必须与 `workspace-spec.json` 的 `skillsManagement.registeredSkills` 一一对应。命令文件名为 `{Skill文件夹名}.md`，正文固定为：

```text
请读取并执行 .agents/skills/{Skill文件夹名}/SKILL.md
```

新增、删除或版本 bump Skill 时，必须同步更新 `.claude/commands/`。`CLAUDE.md` 与命令文件可由初始化工具覆盖更新，`CLAUDE.md` 更新前写入 `.history/CLAUDE/`，命令文件更新前写入 `.history/.claude/commands/`；`.Claude.json` 和 `.claude/settings.local.json` 只补缺占位，不覆盖真实值。

#### Codex 接入层

`AGENTS.md` 是 Codex 在本工作区自动加载的会话入口。它属于强制门薄入口，只写必须先触发的门、SSOT 顺序和标准读取时机，不复制子项目、备份、记忆、Skill 生命周期等具体制度。

| 路径 | 说明 |
|------|------|
| `AGENTS.md` | Codex 会话自动加载的工作区规则入口 |
| `.system/standards/workspace-spec.json` | Codex 判断骨架与注册表时读取的机器标准 |
| `.system/standards/*.md` | Codex 判断具体规则时读取的人类可读标准 |

当 Codex 遇到 Skill 稳定编号、跨 Skill 依赖或命令包装问题时，必须转读 `.system/standards/Skills管理标准.md`；入口文件和单个 Skill 不重复维护完整路由规则。

`AGENTS.md` 更新前写入 `.history/AGENTS/`，历史文件名为 `AGENTS_{yyyyMMddHHmmss}.md`。

## 三、命名规范

### 子项目文件夹

```
{编号}_{主题}
```

| 部分 | 规则 |
|------|------|
| 编号 | 两位数字（01, 02…），脚本自动递增 |
| 主题 | 中文，3~10 字 |
| 版本号 | 写入 `版本记录.md`，不进入 live 目录名 |

正则：`^\d{2}_.+$`

### 三分类子文件夹

| 前缀 | 名称 | 正则 |
|------|------|------|
| 01 | 问题答疑 | `^01_问题答疑$` |
| 02 | 课题研究 | `^02_课题研究$` |
| 03 | 代码程序 | `^03_代码程序$` |

版本号规则：

- 三个分类 live 文件夹均保持稳定名称，不在目录名写版本号。
- 分类内容变化统一写入子项目根目录 `版本记录.md`；发布版本可由 Git tag、Release 或构建脚本记录。

### 内容文件

```
01_问题答疑/{两位编号}_{标题}.{扩展名}
02_课题研究/{两位编号}_{标题}.{扩展名}
03_代码程序/{工具链原生命名或按需编号的文件/目录}
```

- `01_问题答疑/` 与 `02_课题研究/` 内，内容文件必须带两位编号，例如 `01_项目骨架维护总览.md`。
- 内容文件版本不写入 live 文件名；需要时写入文件正文元数据或 `版本记录.md`。
- `03_代码程序/` 内部文件可保留源码、配置、构建产物的原生命名；不强制编号，也不强制带 `_v*` 文件版本。

### 固定文件

子项目根目录下两个固定文件，不带编号：

- `目录.md`
- `版本记录.md`

`目录.md` 中，`01_问题答疑` 与 `02_课题研究` 节的文件列必须为 Markdown 链接，格式：

```
[文件名](子文件夹/文件名)
```

路径相对于 `目录.md` 所在目录。文件尚未落盘时保留纯文本，落盘后立即补链接。`03_代码程序` 节若条目为文件夹，链接指向文件夹内主说明文件（如 `.md`）。

### 对话记录

```
{子项目文件夹名}.md
```

如：`09_项目检查标准_v1.4.2.md`

### 知识提炼

```
{话题名}.md
```

稳定文件名，不带 `_v*`。历史版本在 `.history/.memory/知识提炼/`。

### 系统记录

固定 5 个文件，不能多不能少：

| 文件名 | 内容 |
|--------|------|
| `规则变更记录.md` | Rule 增删改历史 |
| `技能变更记录.md` | Skill 增删改历史 |
| `脚本治理记录.md` | 脚本 bug/编码/编译 |
| `教训库.md` | 跨领域教训/根因分析 |
| `索引.md` | 各文件条目计数入口 |

旧版 `rules-skills.md` 是迁移源：读取内容按维度分发到 4 个正文文件 → 更新索引 → 归档原文件。

### 任务进度

```text
.memory/任务进度/
├── 索引.md
├── 进行中/
├── 已完成/
└── 已取消/
```

规则：

- `索引.md` 是任务恢复入口，只列出 `ACTIVE / PAUSED / BLOCKED / REVIEW / STALE` 等当前任务。
- 每个任务文件使用 `T{yyyyMMdd-HHmm}-{中文短题}.md` 命名，存放恢复卡片、事件日志、文件与产物、最终摘要。
- 任务进度是运行态记录，不替代 `output/` 成果文档和 B03 长期记忆。
- 任务完成或取消后，由 B08 移入 `已完成/` 或 `已取消/`，并更新 `索引.md`。
