# 工作区命名规范

> 版本：1.9.0  
> 提炼来源：`.system/standards/workspace-spec.json`、`.system/standards/Skills管理标准.md`、`.agents/rules/filename-rules.md`、`.agents/rules/memory-rules.md`、`.agents/rules/version-control-rules.md`、`.agents/skills/B04_子项目管理/SKILL.md`、`.agents/skills/B02_版本控制备份/SKILL.md`、`.agents/skills/B06_项目规范化/SKILL.md`  
> 定位：覆盖 `output/`、`.system/`、`.memory/`、`.history/` 与 AI 接入层（`AGENTS.md`、`CLAUDE.md`、`.claude/`）的命名口径。机器可读事实源仍以 `workspace-spec.json` 为准。

---

## 一、总原则

工作区命名分为三类：

| 区域 | 职责 | 核心命名原则 |
|------|------|-------------|
| `output/` | 当前研究与系统治理产出 | 子项目文件夹带编号与语义版本，内部内容进入三分类目录 |
| `.system/` | 工作区核心标准数据 | 文件夹和内部文件全部是核心骨架，名称固定，不进入可变层 |
| `AGENTS.md` / `.claude/` | AI 本地接入层 | 入口文件稳定命名并保留强制门索引；命令文件与注册 Skill 同名；本机私有配置稳定命名、不展示密钥 |
| `.memory/` | 当前态记忆 | live 文件名稳定，追加型记录不带版本，知识提炼与地图版本写在文件头；不保留 `.system` 镜像 |
| `.history/` | 历史快照与版本副本 | 历史项带时间戳或版本号，不作为当前态继续编辑；保留 `.system` 历史镜像结构 |

判断口径：

- 当前正在使用、会继续编辑的文件，留在 `output/` 或 `.memory/`。
- 已经被备份、归档、迁移的旧状态，进入 `.history/` 或 `.temp/`。
- `output/` 的历史用时间戳区分快照。
- `.memory/` 的历史用版本号区分副本。
- `.agents/` 的历史用时间戳区分规则文件与 Skill 文件夹。
- `.system/` 的历史按文件夹快照区分，规则与 `.agents/skills/` 一致。
- `AGENTS.md` 与 `CLAUDE.md` 是强制门薄入口，名称固定，不复制标准细则。
- `.claude/commands/` 的命令文件名必须与 Skill 文件夹名保持一致，正文只做 Skill 调用包装。

## 二、output 命名规范

### 子项目文件夹

```text
output/{编号}_{主题}/
```

| 部分 | 规则 |
|------|------|
| `编号` | 两位数字，按 `output/` 现有最大编号自动递增；`00` 保留给系统治理 |
| `主题` | 中文主题名，建议 3~10 字，表达话题核心；特定英文术语可保留 |
| `版本号` | 写入 `版本记录.md`，不进入 live 目录名；新建默认 `v1.0.0`，后续由备份脚本维护 |

正则：

```regex
^\d{2}_.+$
```

示例：

```text
00_系统治理/
05_工作区初始化工具/
09_项目检查标准/
```

### 子项目内部结构

```text
{编号}_{主题}/
├── 目录.md
├── 版本记录.md
├── 01_问题答疑/
├── 02_课题研究/
└── 03_代码程序/
```

| 项 | 规则 |
|----|------|
| `目录.md` | 固定文件名，不带编号，不带版本 |
| `版本记录.md` | 固定文件名，不带编号，不带版本 |
| `01_问题答疑` | 问答型输出；稳定目录名 |
| `02_课题研究` | 结构化研究、标准、方案、结论；稳定目录名 |
| `03_代码程序` | 代码、脚本、构建产物；稳定目录名 |

三分类目录不在 live 路径中写版本号。子项目整体版本、分类内容变化和文件变更统一记录到 `版本记录.md`，历史快照名携带备份时版本。

### 内容文件

```text
01_问题答疑/{两位编号}_{标题}.{扩展名}
02_课题研究/{两位编号}_{标题}.{扩展名}
03_代码程序/{工具链原生命名或按需编号的文件/目录}
```

规则：

- `01_问题答疑` 与 `02_课题研究` 内的内容文件必须使用两位编号。
- 01/02 内容文件版本不写入 live 文件名；需要版本时写入文件正文元数据或 `版本记录.md`。
- `03_代码程序` 内部源码、配置、构建产物和程序运行依赖可保留原生命名，如 `src/`、`dist/`、`package.json`、`初始化工作区.exe`，不强制文件级版本。

## 三、.system 命名规范

`.system/` 是工作区核心骨架，不属于可变层。当前结构：

```text
.system/
└── standards/
    ├── workspace-spec.json
    ├── 工作区骨架规格.md
    ├── 工作区命名规范.md
    └── Skills管理标准.md
```

规则：

- `.system/` 根目录名称固定。
- `.system/standards/` 名称固定。
- `.system/standards/workspace-spec.json` 是机器可读 SSOT，名称固定。
- `.system/standards/工作区骨架规格.md`、`.system/standards/工作区命名规范.md` 与 `.system/standards/Skills管理标准.md` 是人类可读标准，名称固定。
- `.system/standards/` 新增 Markdown 标准文件时使用稳定自然命名：中文为主，特定英文术语可保留原文，无编号，无版本号；版本写在文件头。
- `.system` 从文件夹到内部所有文件都属于核心骨架；缺失必须补齐，异常必须显式处理。
- `.system` 不按语义版本改 live 文件名，不在当前区堆 `_v*` 文件。

### .system 备份命名

`.system` 按与 `.agents/skills/` 相同的方式备份：整文件夹快照，live 文件夹保持原名不变。

```text
.history/.system/{.system子文件夹名}_{yyyyMMddHHmmss}/
```

示例：

```text
.history/.system/standards_20260505190640/
```

规则：

- 快照对象是 `.system` 内部子文件夹，例如 `standards/`。
- 历史快照名为 `{子文件夹名}_{14位时间戳}`。
- 快照内部保留被备份文件夹的完整文件结构。
- 不采用 `.memory` 的版本号历史命名，也不改 live 文件夹名。

## 四、.memory 命名规范

`.memory/` 只保存当前态记忆，不堆历史副本。允许结构如下：

```text
.memory/
├── 对话记录/
├── 系统记录/
├── 知识提炼/
├── 任务进度/
└── 全局知识地图.md
```

### 对话记录

```text
.memory/对话记录/{子项目文件夹名}.md
```

示例：

```text
.memory/对话记录/05_工作区初始化工具_v1.9.0.md
```

规则：

- 文件名与当前 live 子项目文件夹名保持一致。
- 子项目版本 bump 后，对话记录文件名同步更新。
- 追加写入，不做 `.history` 版本备份。
- 不写系统治理内容；系统治理进入 `.memory/系统记录/`。

### 系统记录

固定 5 个文件：

```text
.memory/系统记录/规则变更记录.md
.memory/系统记录/技能变更记录.md
.memory/系统记录/脚本治理记录.md
.memory/系统记录/教训库.md
.memory/系统记录/索引.md
```

规则：

- 文件名固定，不带编号，不带版本。
- 正文记录追加到前四个分类文件。
- `索引.md` 是入口与条目索引，不作为正文记录主文件。
- 旧版 `rules-skills.md` 只能作为迁移源，迁移后归档，不继续写入。
- 系统记录不做 `.history` 版本备份。

### 知识提炼

```text
.memory/知识提炼/{话题名}.md
```

示例：

```text
.memory/知识提炼/版本管理.md
.memory/知识提炼/PowerShell 编码陷阱.md
```

规则：

- 当前态文件名稳定，不带 `_v*`。
- 当前版本写在文件头隐藏注释中：

```markdown
<!-- memory-version: 1.2.0 -->
```

- 修改前使用 `MEMORY` 模式备份，历史版本进入 `.history/.memory/知识提炼/`。

### 全局知识地图

固定文件：

```text
.memory/全局知识地图.md
```

规则：

- 当前态文件名固定，不带版本。
- 当前版本写在文件头隐藏注释中。
- 新建子项目时由 `子项目管理` Skill 更新。
- 历史版本进入 `.history/.memory/全局知识地图/`。

### 任务进度

```text
.memory/任务进度/索引.md
.memory/任务进度/进行中/T{yyyyMMdd-HHmm}-{中文短题}.md
.memory/任务进度/已完成/T{yyyyMMdd-HHmm}-{中文短题}.md
.memory/任务进度/已取消/T{yyyyMMdd-HHmm}-{中文短题}.md
```

规则：

- `T{yyyyMMdd-HHmm}-{中文短题}` 是任务级运行态编号，由 B08 生成。
- `进行中/` 保存 `ACTIVE / PAUSED / BLOCKED / REVIEW / STALE` 任务。
- `DONE` 任务移入 `已完成/`，`CANCELED` 任务移入 `已取消/`。
- 任务进度文件不带语义版本号，不进入 `.history` 版本备份；最终摘要由 B03 压缩沉淀。

### .memory 禁止项

- 禁止在 `.memory/知识提炼/` 保留 `*_v1.0.0.md` 这类历史副本。
- 禁止在 `.memory/` 根目录保留 `全局知识地图_v*.md`。
- 禁止在 `.memory/` 下新增非标准目录；当前标准目录为 `对话记录/`、`系统记录/`、`知识提炼/`、`任务进度/`。
- 禁止在 `.memory/` 下保留 `.system/` 镜像目录。
- 禁止对 `.memory/` 做整目录快照。

## 五、AI 接入层命名规范

`AGENTS.md` 是 Codex 接入入口，`CLAUDE.md` 与 `.claude/` 是 Claude Code 接入层，当前结构：

```text
{工作区根}/
├── AGENTS.md
├── CLAUDE.md
├── .Claude.json
└── .claude/
    ├── settings.local.json
    └── commands/
        └── {Skill文件夹名}.md
```

规则：

- `AGENTS.md` 名称固定，作为 Codex 会话入口规则；只写强制门索引、SSOT 顺序和标准读取时机。
- `CLAUDE.md` 名称固定，作为 Claude 会话入口规则。
- `AGENTS.md` 与 `CLAUDE.md` 不承载子项目、备份、记忆、Skill 生命周期等完整制度，具体规则回到 `.system/standards/`、`.agents/rules/` 和对应 Skill。
- `.Claude.json` 名称固定，是本机私有环境配置；可能包含密钥，只补缺占位，不覆盖真实值。
- `.claude/settings.local.json` 名称固定，是本机权限设置；只补缺占位，不覆盖真实值。
- `.claude/commands/{Skill文件夹名}.md` 必须与 `workspace-spec.json` 的 `skillsManagement.registeredSkills` 一一对应。
- 命令正文固定为 `请读取并执行 .agents/skills/{Skill文件夹名}/SKILL.md`。
- 新增、删除或版本 bump Skill 时，同步新增、删除或重命名对应命令文件。

### AI 接入层历史命名

```text
.history/AGENTS/AGENTS_{yyyyMMddHHmmss}.md
.history/CLAUDE/CLAUDE_{yyyyMMddHHmmss}.md
.history/.claude/settings.local_{yyyyMMddHHmmss}.json
.history/.claude/commands/{命令文件名}_{yyyyMMddHHmmss}.md
```

规则：

- `AGENTS.md` 覆盖更新前按配置文件备份，历史副本写入 `.history/AGENTS/` 并带 14 位时间戳。
- `CLAUDE.md` 覆盖更新前按配置文件备份，历史副本写入 `.history/CLAUDE/` 并带 14 位时间戳。
- `.claude/commands/` 命令文件属于可由初始化工具维护的接入层资产，覆盖前进入 `.history/.claude/commands/`。
- `.Claude.json` 与 `.claude/settings.local.json` 是本机私有配置；常规初始化只补缺，不覆盖。确需修改时先备份到 `.history/.claude/`。
- 历史副本加 14 位时间戳，不作为 live 文件继续编辑。

## 六、.history 命名规范

`.history/` 是历史区，只保存备份与归档，不作为 live 文件继续编辑。允许根结构：

```text
.history/
├── AGENTS/
├── CLAUDE/
├── output/
├── .agents/
├── .claude/
├── .system/
└── .memory/
```

### output 历史快照

```text
.history/output/{稳定子项目文件夹名}_v{x.y.z}_{yyyyMMddHHmmss}/
```

示例：

```text
.history/output/05_工作区初始化工具_v1.8.2_20260505155637/
```

规则：

- 对 `output/` 子项目做 PROJECT 备份时生成。
- 快照名由“稳定 live 子项目文件夹名 + 备份时版本号 + 14 位时间戳”组成。
- 时间戳格式固定为 `yyyyMMddHHmmss`。
- `output/` 下单个文件不做 FILE 备份，必须对父级子项目整体备份。

### .agents 规则文件备份

```text
.history/.agents/rules/{rule文件名}_{yyyyMMddHHmmss}.md
```

示例：

```text
.history/.agents/rules/filename-rules_20260505105622.md
```

规则：

- 仅用于 `.agents/rules/*.md` 的 CONFIG 备份。
- live 规则文件名保持不变，历史副本加时间戳。

### .agents Skill 快照

```text
.history/.agents/skills/{Skill名}_{yyyyMMddHHmmss}/
```

示例：

```text
.history/.agents/skills/B04_子项目管理_20260505105617/
```

规则：

- 仅用于 `.agents/skills/{Skill名}/` 的 FOLDER 快照。
- live Skill 文件夹名保持不变，历史快照加时间戳。
- 快照内部保留原 Skill 目录结构。

### .system 文件夹快照

```text
.history/.system/{.system子文件夹名}_{yyyyMMddHHmmss}/
```

示例：

```text
.history/.system/standards_20260505190640/
```

规则：

- 与 `.agents/skills/` 的 FOLDER 快照同型。
- live `.system/{子文件夹名}/` 保持原名不变。
- 历史快照加 14 位时间戳。
- 快照内部保留 `.system` 子文件夹内的完整文件结构。

### AI 接入层历史

```text
.history/AGENTS/AGENTS_{yyyyMMddHHmmss}.md
.history/CLAUDE/CLAUDE_{yyyyMMddHHmmss}.md
.history/.claude/commands/{命令文件名}_{yyyyMMddHHmmss}.md
```

规则：

- `AGENTS.md` 覆盖更新前按文件备份，历史副本保留在 `.history/AGENTS/`。
- `CLAUDE.md` 覆盖更新前按文件备份，历史副本保留在 `.history/CLAUDE/`。
- `.claude/commands/*.md` 覆盖或重命名前按文件备份。
- `.Claude.json` 与 `.claude/settings.local.json` 仅在确需人工修改时备份，常规初始化不得覆盖。

### .memory 知识提炼历史

```text
.history/.memory/知识提炼/{话题名}_v{x.y.z}.md
```

示例：

```text
.history/.memory/知识提炼/版本管理_v1.2.0.md
```

规则：

- 来自 `.memory/知识提炼/{话题名}.md` 的 MEMORY 备份。
- 历史文件名带版本号，不带时间戳。
- live 文件仍保留稳定文件名。

### .memory 全局知识地图历史

```text
.history/.memory/全局知识地图/全局知识地图_v{x.y.z}.md
```

规则：

- 来自 `.memory/全局知识地图.md` 的 MEMORY 备份。
- 历史文件名带版本号，不带时间戳。
- live 文件仍固定为 `.memory/全局知识地图.md`。

### .memory 对话记录与系统记录历史目录

```text
.history/.memory/对话记录/
.history/.memory/系统记录/
```

规则：

- 这两个目录作为历史结构占位或迁移归档位置存在。
- 常规写入时，`.memory/对话记录/` 与 `.memory/系统记录/` 是追加型文件，不做版本备份。
- 不得为了普通追加记录而生成历史副本。

### .history 禁止项

- 禁止在 `.history/` 根目录堆放零散备份文件；入口历史副本必须进入 `.history/AGENTS/` 或 `.history/CLAUDE/`。
- 禁止把历史快照作为 live 文件继续编辑。
- 禁止保留不带时间戳的 `.agents` 或 `output` 历史快照。
- 禁止把 `.memory` 当前态文件复制到 `.history` 根目录。
- 禁止把 `.system` 文件平铺备份到 `.history/.system/`，必须按文件夹快照。

| `.memory/系统记录/{固定文件名}.md` | 常规不备份 | 追加写入 |

## 八、遗留命名判定

以下属于旧结构或待规范化残留：

- `output/` 子项目内部平铺内容文件。
- `output/` live 子项目或分类目录名仍携带 `_v{x.y.z}`。
- `output/01_问题答疑/` 与 `output/02_课题研究/` 内内容文件仍携带 `_v{x.y.z}` 文件版本号。
- `.memory/知识提炼/` 下出现 `*_v*.md`。
- `.memory/` 根目录出现 `全局知识地图_v*.md`。
- `.history/output/` 下快照缺少 14 位时间戳。
- `.history/.agents/skills/` 下快照缺少 14 位时间戳。
- `.history/.system/` 下 `.system` 快照缺少 14 位时间戳。
