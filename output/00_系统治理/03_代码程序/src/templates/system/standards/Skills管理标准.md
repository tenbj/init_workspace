# Skills 管理标准

> 版本：1.13.0  
> 定位：Skills 域分类、命名、注册、生命周期管理的正式 SSOT。  
> 适用范围：`.agents/skills/` 下所有项目级 Skill，以及 `workspace-spec.json`、体检脚本、规范化脚本中的 Skill 引用。

本文件是 Skill 管理规则的唯一事实源。`output/` 中的方案、问答和迁移清单只能作为设计过程记录；当它们与本文件冲突时，以本文件为准。

---

## 1. 域分类体系

### 域定义

| 域代码 | 域名称 | 职责边界 | 说明 |
|--------|-------|---------|------|
| `A` | 元技能 | 管理 Skill 与系统标准本身的 Skill | 创建、安装、迁移、技能模板、系统标准更新等 |
| `B` | 系统治理 | 工作区框架的运维与管控 | 体检、备份、记忆、子项目、研究、规范化 |
| `C` | 数仓开发 | 数据仓库开发全链路 | 建表、查询、SQL 生成、数据同步等 |
| `D` | 架构文档 | 架构图谱生成、查看与发布 | Mermaid / OMM 等架构可视化工作流 |
| `E` | 模型设计 | 模型设计标准化与评审 | Excel 模型设计解析、标准库评审、建议版输出 |
| `F` | 办公自动化 | 协作文档与办公平台自动化 | 钉钉文档下载、在线表格导出等 |
| `G` | HTML产物 | HTML报告、图示、互动编辑器与可视化决策产物 | 外部 HTML Skill 包的项目级本地化入口 |
| `H`~`Z` | 保留 | 按需扩展 | 新业务领域出现时启用下一个字母 |

### 域内编号规则

- 域代码 + 两位数字，如 `A01`、`B03`、`C07`
- 同一个域内编号连续递增，从 `01` 起步
- `A00` 是保留特例，只用于人工显式授权的超管模式，不参与常规递增编号
- 已删除的编号**不复用**（保留空位，防止混淆历史记录）

## 2. 命名规范

### 文件夹命名

```
{域代码}{编号}_{技能名}
```

**示例**：`B01_框架体检`

规则：
- 域代码：单字母大写（A、B、C…）
- 编号：两位数字（01~99）
- 技能名：中文为主，特定术语可用英文（如 `Doris`、`DWD`、`ODS`）
- 版本号：不得写入 live 文件夹名；只写入 `agents/openai.yaml` 的 `display_name`

### YAML name 命名

```yaml
name: {域代码}{编号}_{技能名}
```

**示例**：`name: B01_框架体检`

规则：
- 与文件夹名保持一致，**不得带版本号**
- 这是稳定 Skill ID，也是快速调用入口
- 用户输入 `/B01` 可按编号快速命中；输入 `/B01_框架体检` 可按稳定名称命中
- Skill 版本 bump 后，live 文件夹名、YAML `name`、`workspace-spec.json` 引用不变；只更新 `agents/openai.yaml` 的 `display_name`

### OpenAI display_name 命名

```yaml
interface:
  display_name: "{域代码}{编号}_{技能名}_v{MAJOR}.{MINOR}.{PATCH}"
```

**示例**：`display_name: "B01_框架体检"`

规则：
- `display_name` 是 Skill 唯一保留三段式版本号的位置。
- `display_name` 必须以稳定 Skill ID 为前缀，并追加 `_v{MAJOR}.{MINOR}.{PATCH}`。
- 版本升级只改 `display_name` 和必要的发布/历史记录，不改 live 文件夹名。

### YAML description

- 一句话描述技能职责，不超过 100 字
- 必须包含触发条件（何时用）和核心产出（做什么）

## 3. 新增 Skill 流程

### 第 1 步：域归属

判断新技能属于哪个域：
- 管理 Skill 或系统标准本身？→ A 域
- 工作区框架运维？→ B 域
- 数仓开发链路？→ C 域
- 都不是？→ 考虑启用新域

### 第 2 步：分配编号

在目标域的当前最大编号上 +1。

### 第 3 步：创建文件夹

```
.agents/skills/{域代码}{编号}_{技能名}/
├── SKILL.md              ← YAML frontmatter + 指引
├── scripts/              ← 脚本（如有）
├── references/           ← 参考文档（如有）
└── assets/               ← 资源文件（如有）
```

### 第 4 步：注册

在 `workspace-spec.json` 中更新：
- `skillsManagement.registeredSkills`：追加新 Skill 名称
- 若该 Skill 属于初始化覆盖层，再同步追加到 `overwriteLayer.skills`
- `bomCheck.files`：若有 `.ps1` 脚本，追加路径

在 `.claude/commands/` 中同步创建：
- 文件名：`{Skill文件夹名}.md`
- 正文：`请读取并执行 .agents/skills/{Skill文件夹名}/SKILL.md`

### 第 5 步：更新标准文件

在本文件的"当前完整映射表"中追加一行。

## 4. 修改 Skill 流程

### 修改内容（SKILL.md、scripts 等）

1. 执行版本控制备份（FOLDER 模式）
2. 修改内容
3. 按变更幅度判断是否需要 bump `agents/openai.yaml display_name` 中的版本号：
   - 不兼容变更 → MAJOR
   - 新增功能 → MINOR
   - 修复/微调 → PATCH
4. live 文件夹名、`SKILL.md name`、注册表和 `.claude/commands` 保持稳定
5. 若新增或删除脚本，同步更新 `workspace-spec.json` 中的 `bomCheck.files` 路径

### 移动 Skill 到新域

1. 备份原文件夹
2. 修改文件夹名的域代码和编号
3. 更新 YAML name（稳定 Skill ID，不带版本号）与 `display_name` 前缀
4. 更新 `workspace-spec.json` 中 `skillsManagement.registeredSkills`、`overwriteLayer.skills`（如适用）和 `bomCheck.files`
5. 同步重命名 `.claude/commands/` 下对应命令文件，并更新正文路径
6. 更新本文件的映射表

---

## 5. 删除 Skill 流程

1. 备份原文件夹到 .history
2. 删除 live 文件夹
3. 从 `workspace-spec.json` 的 `skillsManagement.registeredSkills`、`overwriteLayer.skills`（如适用）和 `bomCheck.files` 移除所有引用
4. 删除 `.claude/commands/` 下对应命令文件
5. **编号不复用**，在映射表中标记为"已删除"
6. 更新本文件

## 6. 版本号管理规则

| 变更类型 | 版本段 | 示例 | 适用场景 |
|---------|-------|------|---------|
| MAJOR | x+1.0.0 | 1.0.0 → 2.0.0 | SKILL.md 结构大改、脚本接口不兼容 |
| MINOR | x.y+1.0 | 1.2.0 → 1.3.0 | 新增功能、新增参数，向下兼容 |
| PATCH | x.y.z+1 | 1.2.0 → 1.2.1 | 修复 bug、调整描述、微调逻辑 |

## 7. 斜杠命令调用约定

`.claude/commands/` 是 Claude Code 的斜杠命令入口，命令集合必须由 `workspace-spec.json` 的 `skillsManagement.registeredSkills` 派生。每个注册 Skill 必须存在一个同名 `.md` 命令文件，正文只做一件事：读取并执行对应 `SKILL.md`。

| 输入方式 | 效果 | 示例 |
|---------|------|------|
| `/{编号}` | 快速命中当前稳定 Skill | `/B01` → B01_框架体检 |
| `/{完整名称}` | 精确命中稳定 Skill | `/B01_框架体检` → B01_框架体检 |
| `/{域代码}` | 列出整个域 | `/C` → 列出所有数仓 Skill |
| `/{中文关键词}` | 模糊匹配 | `/框架` → 命中 B01_框架体检 |

## 8. 跨 Skill 稳定编号引用规则

跨 Skill 意图指引只写稳定编号，例如 `B04`、`C03`、`C06`，不在业务说明里硬写完整 Skill 文件夹名。稳定名称保留在注册表、路径、命令文件和 YAML `name` 中；版本只保留在 `display_name` 中。

解析规则：

1. 读取 `.system/standards/workspace-spec.json` 的 `skillsManagement.registeredSkills`。
2. 查找唯一一个以 `{稳定编号}_` 开头的 Skill 名称。
3. 解析成功后读取 `.agents/skills/{稳定Skill名称}/SKILL.md`。
4. 找不到或匹配到多个目标时，停止执行并报告注册表异常，不猜测旧名称。

使用边界：

- Skill 的说明文档、依赖说明、编排步骤中优先写稳定编号。
- `.agents/rules/` 与 `.agents/skills/*/SKILL.md` 中的跨 Skill 意图指引必须使用稳定编号，例如 `执行 B04`、`按 B03 写入记忆`。
- `.agents/skills/` 真实目录、`.claude/commands/` 文件、YAML `name` 必须使用稳定 Skill 名称，不带版本号。
- 真实文件路径、脚本命令、注册表、历史快照示例中的稳定 Skill 文件夹名不得改成编号，否则会破坏可执行路径。
- Skill 版本 bump 后，只更新 `agents/openai.yaml display_name` 和必要的版本记录；引用方通常不需要改，因为引用的是稳定编号/稳定名称。
- 如果一个能力需要精确接口语义，可在稳定编号后补充业务意图，例如 `B04：创建 DWD 开发产物目录`，但解析仍以 `B04` 为准。
