# 默认读取编码治理方案

## 1. 目标

解决 AI 在 Windows PowerShell 中读取中文 Markdown、Rule、Skill、标准文件时出现乱码的问题。当前目标不是改变所有文件编码，而是先把默认读取命令收束为显式 UTF-8 读取，避免 `Get-Content -Raw` 在无 BOM 的 UTF-8 文件上按系统默认 ANSI 解码。

本方案只处理读取乱码治理；`.ps1` 写入时继续遵守现有 UTF-8 with BOM 约束，不把 PowerShell 脚本编码策略和 Markdown 读取策略混在一起。

## 2. 问题背景

用户指出 AI 经常执行类似命令：

```powershell
Get-Content -LiteralPath '.agents/skills/B05_课题研究_v1.0.0/SKILL.md' -Raw
```

在当前环境中，这类命令确实可能读出乱码。复核时确认：

| 项目 | 结果 |
|------|------|
| PowerShell 版本 | Windows PowerShell 5.1.26100.8115 |
| 控制台输出编码 | UTF-8 |
| 示例文件实际路径 | `.agents/skills/B05_课题研究/SKILL.md` |
| 用户示例中的 v1.0.0 路径 | 当前不存在 |
| 示例文件前 4 字节 | `2D 2D 2D 0D`，即无 UTF-8 BOM |
| 默认读取结果 | 中文字段出现 `璇鹃...` 等乱码 |
| `-Encoding UTF8` 读取结果 | 中文正常 |

因此，用户提出的调整方向成立：对 UTF-8 文本文件使用显式 `-Encoding UTF8` 可以规避当前乱码。

## 3. 依据

| 事实源 | 采用方式 |
|--------|----------|
| `.system/standards/workspace-spec.json` | 确认当前注册 Skill、`.ps1` BOM 检查清单和 Codex/Claude 入口定位 |
| `.system/standards/Skills管理标准.md` | 处理 Skill 编号引用时使用稳定编号，不猜测旧版本路径 |
| `.agents/skills/B02_版本控制备份/SKILL.md` | 修改文件前按目标类型执行备份；output 子项目使用 PROJECT 模式 |
| `.agents/skills/B07_系统治理方案沉淀/references/方案写作规范.md` | 本方案按系统治理终版结构收敛 |
| 本地验证命令 | 确认 `Get-Content -Raw` 与 `Get-Content -Encoding UTF8 -Raw` 的实际差异 |

## 4. 最终判断

`Get-Content -LiteralPath ... -Encoding UTF8 -Raw` 是当前最直接、最低风险、可执行的修复方式。它对 Markdown、JSON、YAML、Skill 说明、Rule 文件这类 UTF-8 文本读取有效。

单纯依赖 PowerShell 全局默认值不稳妥。AI 的每次命令可能在新进程中执行，不一定继承会话级 `$PSDefaultParameterValues`；修改用户 PowerShell Profile 又超出工作区边界，也不适合当作项目级治理方案。

最稳的做法是：在工作区入口和执行层文档中明确命令约束，让 AI 生成读取命令时默认带 `-Encoding UTF8`；同时补充 B01 检查，防止后续 Rule、Skill、模板里继续出现未声明编码的 `Get-Content` 示例。

## 5. 最小整改清单

| 优先级 | 意图指向 | 具体落点 | 要做什么 | 验收标准 |
|--------|----------|----------|----------|----------|
| P0 | 入口约束默认读取命令 | `AGENTS.md`、`CLAUDE.md` | 增加 PowerShell 文本读取约束：读取 UTF-8 文本必须使用 `Get-Content -Encoding UTF8 -Raw` | 新会话入口能直接告诉 AI 默认读取口径 |
| P0 | 执行层示例收敛 | `.agents/rules/`、`.agents/skills/*/SKILL.md` | 扫描并修正文档中的 `Get-Content ... -Raw` 示例，补齐 `-Encoding UTF8` | `rg "Get-Content" .agents AGENTS.md CLAUDE.md` 中的读取示例均显式带编码 |
| P0 | 模板同步 | `output/00_系统治理.../03_代码程序_v*/src/templates/` | 将入口和 Skill/Rule 模板同步改成显式 UTF-8 读取口径 | 初始化工具生成的新工作区也继承该约束 |
| P1 | B01：补自动检查 | `.agents/skills/B01_框架体检/scripts/framework-check.ps1` | 增加检查项：发现 `Get-Content` 读取文本但未出现 `-Encoding` 时报告 WARN 或 FAIL | 体检可以自动暴露新引入的未声明编码读取示例 |
| P1 | B06：补规范化提示 | `.agents/skills/B06_项目规范化/` | 项目规范化时提示或修复常见读取命令编码缺口 | 批量规范化后不会把旧命令继续扩散 |

## 6. 不做事项

不把所有 Markdown 文件批量改成 UTF-8 with BOM。当前问题是读取命令未声明编码，不是 Markdown 必须带 BOM。

不把 `.ps1` 脚本的 BOM 规则改掉。`workspace-spec.json` 已要求指定 `.ps1` 保持 UTF-8 with BOM，该规则继续有效。

不依赖用户本机 PowerShell Profile 作为主方案。Profile 可以作为个人习惯补充，但不能作为工作区可迁移规则。

## 7. 执行顺序

1. 对即将修改的 live 文件执行 B02 备份：入口文件用 CONFIG，Skill 文件夹用 FOLDER，output 初始化工具子项目用 PROJECT。
2. 在 `AGENTS.md` 和 `CLAUDE.md` 增加默认读取命令约束。
3. 用 `rg "Get-Content" .agents .system AGENTS.md CLAUDE.md` 扫描读取示例，把 UTF-8 文本读取统一改成 `-Encoding UTF8 -Raw`。
4. 同步初始化工具模板，必要时重建 EXE，避免新建工作区继续生成旧口径。
5. 给 B01 增加检查项，先按 WARN 上线；稳定后可视情况升为 FAIL。
6. 运行 B01 体检，并用 B05 Skill 文件做回归验证。

## 8. 验收口径

| 验收项 | 通过标准 |
|--------|----------|
| 实际读取 | `Get-Content -LiteralPath '.agents/skills/B05_课题研究/SKILL.md' -Encoding UTF8 -Raw` 输出中文正常 |
| 示例收敛 | 文档中用于读取 UTF-8 文本的 `Get-Content` 示例均带 `-Encoding UTF8` |
| 自动检查 | B01 能报告未声明编码的 `Get-Content` 读取示例 |
| 入口继承 | 新会话读到 `AGENTS.md` 后，应默认生成显式 UTF-8 读取命令 |
| 新工作区继承 | 初始化工具模板更新后，新生成工作区也包含同一约束 |

## 9. 结论

通过把默认读取命令从隐式编码改为显式 `-Encoding UTF8`，可以直接规避当前 AI 读取中文文件时的乱码问题。建议先改入口和执行层示例，再加 B01 检查，最后同步初始化工具模板；这样既能立即改善当前工作区，也能防止后续新工作区继续复发。
