## 2026-10-10 追加：禁止 main 直接提交的强制保护

用户明确提出“禁止从 main 直接提交”，要求已有约束仍犯错时继续加强。检查结果：核心 Git 标准已经要求独立任务在专用分支实现、提交；B11 已限制在受保护基线上开始实现，并要求 PR 合并。因此此前不是没有规则，而是 AI 未遵守；上轮新增的 verify_pr_merge.py 只在发布前调用，不能拦截创建错误提交的瞬间。检查时本仓库没有启用的提交 hooks，远端 main 未保护，rulesets 为空。

本次增强在 `codex/fix-main-commit-guard-20261010` 分支完成，不修改入口文件或核心标准，执行层落实既有标准及用户明确禁令：

1. version-control-rules、B11 和 B09 明写“禁止在 main 直接创建提交”，每次提交重新检查分支；发布准备、文档、小修复不能豁免，不能用底层 Git 命令或跳过 hooks 绕过。
2. 本地安装4个 Git hooks：pre-commit、prepare-commit-msg、pre-merge-commit、pre-push。拦截受保护基线上的普通提交、amend、合并提交及直接推送，prepare-commit-msg覆盖跳过pre-commit的路径；linked worktree共用保护。安装器拒绝覆盖不同内容的已有hooks和自定义hooksPath。
3. 远端 main 已设置必须 PR、管理员同样受约束、禁止强推及删除；所需审批人数为0，不额外要求另一位审核人。GitHub接口回读确认配置生效。
4. hooks属于客户端保护，不能防止任意改配置或底层写引用；远端PR保护负责拒绝其它未安装hooks客户端的直接推送。检查使用隔离仓库，不在真实main制造违规提交。

远端保护请求与回读记录保存在本地 `03_代码程序/main_guard/`。普通分支/PR检查代替重发旧版本，不以此次加固为由再次改写公开历史。
