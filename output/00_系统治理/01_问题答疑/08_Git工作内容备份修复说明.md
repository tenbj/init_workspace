# Git 工作内容备份修复说明

日期：2026-10-01。系统治理子项目：v1.31.2。B02/B06：v1.0.1。

## 原因与修复

B02 的 PROJECT/FOLDER 原先直接使用递归 Copy-Item，B06 规范化前置快照也递归复制目录。个人桌面的嵌套仓库因此把 `.git` 对象历史、索引和配置重复带入 `.history`。这不是七个独立业务项目；备份及测试入口也被统计为 Git 工作目录。

新增 `B02/scripts/content_snapshot.ps1`，由 B02、B06 共用。保留原来的子项目整体工作内容快照，在各层排除名为 `.git` 的目录/文件。不根据 `.gitignore` 排除文件，不跳过整座嵌套仓库，不采用只含已提交文件的 git archive。未提交、未跟踪、忽略、隐藏及中文/特殊名称文件和空目录仍受保护；`.gitignore`、`.gitattributes`、`.gitmodules` 仍保留。

目录枚举/复制失败立即报错；先写 `.incomplete-*`，成功后才发布正式快照并更新 live 版本。拒绝覆盖已有快照、把目标放入来源内部、错误 PROJECT 根路径、符号链接/junction 及链接祖先。已有历史快照全部保留。

## 最终流程

1. 定位真正需要修改的子项目/技能/规则。修改前按 B02 的 PROJECT、FOLDER、CONFIG、MEMORY 模式生成快照；PROJECT 仅允许 output 的直接子项目。
2. 快照保存工作文件；各层 `.git` 元数据留在 live 仓库。嵌套仓库、子模块和 linked worktree 仍保存各自实际工作文件。
3. 确认脚本成功后修改 live 文件。复制失败时停止修改；`.incomplete-*` 仅供人工检查，不视为可恢复的完整快照。
4. PROJECT 成功后填写版本记录。B06 的规范化前置快照使用同一复制函数，单次运行内避免重复快照。
5. 恢复时把工作文件与目录恢复到相应 live 工作区。Git 提交历史、暂存状态、stash、hooks 和本地 Git 配置由原仓库管理；本快照不替代 Git 灾备。

已同步 B02/B06、版本规则及说明到初始化源码模板，避免将来从这些源码生成骨架时覆盖回旧逻辑。初始化升级的目录备份同样排除各层 `.git`，沿用原有 `__pycache__` 排除；遇到链接停止。升级技能目录若包含 Git 入口，拒绝整目录替换，避免复制时排除元数据后又删除 live 仓库。

本次没有构建或发布 EXE。现有 EXE 内嵌旧模板可能重新带回旧逻辑；应在之后明确安排构建后再用新版 EXE升级。

## 实用边界

- **仍备份整个子项目的工作内容**，本次消除的是 Git 元数据重复复制，并未改为增量或仅脏文件备份。缓存/依赖也继续保护，避免误排业务资料。
- 暂存后又修改时，快照保存磁盘上的最新内容；此前仅存在于索引的版本、仅存在于 stash 的内容不在本快照内。需要保留这些状态时另做明确的 Git 灾备。
- 文件复制不提供应用级一致性锁；备份时避免其他进程持续写入。
- 快照会保留被忽略的本地文件，属于私有恢复材料，不应直接发布。

## 为什么本次仍保留全量工作文件

本修复保持原有恢复合同：单个子项目快照即可恢复该时刻的工作内容，不依赖远端、原仓库或一串历史补丁。仅备份 git diff 会漏掉未跟踪/忽略文件、其他嵌套仓库、二进制/空目录、删除和改名；只用 git archive 又会漏掉未提交内容。按 .gitignore 过滤可能把被忽略的私有资料一起排除。因此本次先修复 Git 元数据复制及错误成功问题，没有改变整个恢复模型。

## 仅备份变更文件的安全方案（仅分析，未实现）

可以采用“完整基线 + 带清单的增量包”：每个源目录维护稳定标识，以相对路径及文件哈希对比基线；增量包保存新增/变更文件的完整字节、删除墓碑、目录变化和必要属性。清单记录基线标识、父快照标识、文件哈希及可恢复性。每个嵌套仓库/worktree分别识别，但所有实际文件（含未跟踪/忽略文件）均参与比较；不把Git提交作为唯一事实源。定期生成完整基线以限制链长。

恢复必须获得正确完整基线和依序排列的所有增量包，先在空的隔离目录验证哈希再恢复；不能把一个增量包当完整快照直接覆盖live。删除墓碑需要明确生效，否则已删除文件会重新出现。清理旧备份前必须先验证没有后续包依赖它。只有Git提交可作基线时，必须保证对应提交及子模块提交本地可获得，并另保存全部未跟踪/忽略数据与删除状态；缺少该基线会无法恢复。

也可使用内容寻址存储：每次保存完整文件清单，按哈希去重存储字节，恢复仍依赖对象库完整性。这能减少重复体积，但增加索引、保留策略、对象校验和灾备要求，需要独立实现与恢复演练。

以上方案未在本次实现。当前修复不承诺增量、省去所有源码重复，或恢复Git暂存区/stash。
