# 课题研究 Skill 是否分析根因

## 用户问题

> 现在的课题研究skill，会分析根因吗？

## 简答

会分析“深层原因”和“机制链条”，但当前 B05 并没有把“根因分析”作为一个显式必做步骤。

更准确地说：B05 的通用流程要求按“问题 → 第一性原理 → 合理推导 → 结论 → 参考文献”展开。它会先寻找领域中的基础事实、基础机制或原典依据，再要求每一层推导都能追溯回第一性原理。因此，如果用户问的是“为什么会这样”“背后的原因是什么”，B05 会沿着第一性原理和推导链条分析到较底层的原因。

但它现在没有明确规定 RCA 式根因分析结构，例如“现象 → 直接原因 → 深层原因 → 系统性原因 → 验证证据 → 纠正措施”，也没有内置“五问法”“鱼骨图”“故障树”这类专门根因分析工具。

## 判断依据

1. `B05_课题研究_v1.0.0/SKILL.md` 的固定动作强调：
   - 把用户问题写入文档并正面回答；
   - 用第一性原理逐条论证每个主张；
   - 所有逻辑延伸标注为【合理推导】；
   - 在第一性原理基础上做合理推导，得出实践结论。

2. `references/研究方法论.md` 进一步要求：
   - 第一性原理是问题领域中不可再简化的基础事实或规律；
   - 每一条【合理推导】都必须能说清楚它从哪条第一性原理出发；
   - 推导不能跨层跳跃；
   - 多层推导可以用 `P1→D1→D2→C` 的链式标注。

这说明 B05 已经具备“追到基础机制”的能力，但它关注的是研究论证链，不是专门的问题治理 RCA 流程。

## 结论

当前 B05 可以回答原因，并能把原因追溯到第一性原理；但如果你想要它稳定地产出“根因分析”，需要在 B05 或其 reference 中新增一个显式章节或触发规则，例如：

```text
原因层级：
1. 表层现象
2. 直接原因
3. 深层机制
4. 根因判断
5. 可验证证据
6. 干预或修正建议
```

这样它才会从“能分析到根因”变成“默认必须做根因分析”。
