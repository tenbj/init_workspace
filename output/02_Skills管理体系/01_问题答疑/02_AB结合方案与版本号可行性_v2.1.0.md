# AB 结合方案 + 版本号可行性分析

> 用户需求两大目标：**好管理**（磁盘上分域排序+版本可追踪）+ **好调用**（输入 `/A01` 快速命中，也可在斜杠菜单中看到并调用完整版本号）。

---

## 用户需求拆解

### 目标一：好管理

| 需求 | 具体要求 |
|------|---------| 
| 分类可见 | 文件夹名带域前缀（如 A = 治理、B = 数仓） |
| 排序可控 | 文件夹名带编号（A01、A02、B01…） |
| 版本可追踪 | 文件夹名带版本号（如 `_v1.2.0`） |

**结论**：文件夹命名 `{域前缀}{编号}_{技能名}_v{版本}` 即可满足，与上一版分析一致。

### 目标二：好调用

| 需求 | 具体要求 |
|------|---------|
| 快速定位 | 用户输入 `/A01` 就能弹出目标 Skill |
| 打字效率 | 中文输入法切换慢，编号纯 ASCII，三键搞定 |
| 直觉映射 | 记住 A01 = 创建技能、B01 = 框架体检、C05 = DWD 单表 SQL，比记中文名更快 |
| 版本可见 | 斜杠命令候选项中直接显示当前 Skill 版本 |

**关键**：上一版方案把 YAML `name` 设计成 `[治理] 框架体检`——过滤"治理"两个字还得切中文输入法，违背了"好调用"的初衷。

**修正后的正确做法**：YAML `name` 同时带上编号前缀和版本后缀，例如 `A01_创建技能`。用户输入 `/A01` 仍可快速命中；需要确认版本时，也可以看到或输入完整的 `/A01_创建技能`。

---

## 设计方案

### 文件夹命名规则（磁盘上的真实名称）

```
{域前缀}{编号}_{技能名}_v{MAJOR}.{MINOR}.{PATCH}
```

域前缀定义：

| 域 | 前缀 | 说明 |
|----|------|------|
| 元技能 | `A` | 创建、安装、迁移、模板等管理 Skill 本身的能力 |
| 系统治理 | `B` | 框架管理、记忆、版本控制等 |
| 数仓开发 | `C` | SQL 生成、查询、数据同步等 |
| 未来扩展 | `D`、`E`... | 按需增加 |

### YAML name 命名规则（斜杠命令展示 & 搜索用）

```
{域前缀}{编号}_{技能名}_v{MAJOR}.{MINOR}.{PATCH}
```

**关键设计**：
- 保留 `A01`、`B05` 等编号前缀 → 用户输入 `/A01` 即可精确命中
- 保留 `_v{MAJOR}.{MINOR}.{PATCH}` 版本后缀 → 斜杠候选项直接显示当前版本
- 不带中文分类标签 → 不增加冗余字符，编号本身已隐含分类
- 版本变化时，YAML `name` 必须随文件夹版本同步更新

### 用户调用场景演示

#### 场景 1：精确调用（最常用）

```
用户输入：/A01
弹出列表：
  → A01_创建技能     ← 唯一命中，选中即可

用户输入：/C05
弹出列表：
  → C05_1对1DWD单表SQL生成
```

三键定位，无需切换中文输入法，**比输入 `/框架体检` 快 3-5 倍**。

#### 场景 1.5：完整版本调用

```
用户输入：/B02_版本控制备份
弹出列表：
  → B02_版本控制备份
```

这满足"斜杠调用时依然能带版本号"的要求。日常可以只记 `/B02`，需要版本确认时用完整项。

#### 场景 2：按域浏览

```
用户输入：/A
弹出列表：
  A01_创建技能
  A02_安装技能

用户输入：/B
弹出列表：
  B01_框架体检
  B02_版本控制备份
  B03_记忆管理
  B04_子项目管理
  B05_课题研究_v1.0.0
  B06_项目规范化
```

输入一个字母，列出整个域——比原来无序的长列表清晰得多。

#### 场景 3：中文搜索（依然可用）

```
用户输入：/框架
弹出列表：
  → B01_框架体检     ← name 里的中文名依然可匹配
```

编号不影响中文搜索能力，只是多了一种更快的调用方式。

## 实施成本分析

### 需要改什么

这是一次**大规模路径迁移**，影响面如下：

| 受影响位置 | 影响内容 | 数量估算 |
|-----------|---------|---------|
| `workspace-spec.json` | `bomCheck.files` 中的 7 个脚本路径 | 7 处 |
| `workspace-spec.json` | `overwriteLayer.skills` 中的 8 个 Skill 名 | 8 处 |
| Rules 文件 | `version-control-rules.md` 中引用 Skill 脚本路径 | ~10 处 |
| SKILL.md 交叉引用 | 记忆管理引用子项目管理、备份引用路径等 | ~15 处 |
| 脚本内部路径 | `backup.ps1`、`framework-check.ps1` 等 | 需逐个检查 |
| `.memory/系统记录/` | 历史记录中引用的路径 | 不改（历史记录） |

### 迁移策略

**推荐一次性批量迁移**，不要逐个改。具体方案：

#### 阶段 0：先验证（5 分钟）

在做任何批量改动之前，先对**一个** Skill 做最小验证：
1. 把 `框架体检` 的 YAML `name` 改为 `B01_框架体检`（不改文件夹名）
2. 在斜杠命令中输入 `/B01`，看能否命中
3. 确认斜杠命令搜索完整版本号 `/B01_框架体检` 能否命中

**如果验证失败**（斜杠命令不用 YAML `name`），则整个方案不可行，需要回退。

#### 阶段 1：编写迁移脚本

创建 `scripts/migrate_skills.ps1`，自动执行：
1. 读取所有 Skill 文件夹 → 按预定义映射表生成新名称
2. 批量备份所有 Skill 到 `.history`
3. 批量 rename 文件夹
4. 批量更新 `workspace-spec.json` 中的路径引用
5. 批量更新 Rules 文件中的路径引用
6. 批量更新 SKILL.md 中的 `name` 字段和交叉引用路径

#### 阶段 2：执行迁移

1. 跑一次框架体检（记录迁移前状态）
2. 执行迁移脚本
3. 再跑一次框架体检（验证迁移后状态）
4. 修复任何遗漏的路径引用

## 版本 bump 时的处理

文件夹名带版本号后，每次 Skill 升级都需要 rename 文件夹。需要升级现有的备份机制：

### 当前 FOLDER 模式

```
修改 Skill 时：
    1. backup.ps1 -Mode FOLDER → 快照到 .history（带时间戳）
    2. 手动修改 Skill 内容
    3. live 文件夹名称不变
```

### 改进后的 SKILL 模式（新增）

```
修改 Skill 时：
    1. backup.ps1 -Mode SKILL → 快照到 .history（带时间戳）
    2. 自动 bump 文件夹版本号（如 B01_框架体检_v1.2.0 → B01_框架体检_v1.3.0）
    3. 自动更新 workspace-spec.json 中的路径引用
    4. 自动更新 SKILL.md 中的 version 字段
    5. 手动修改 Skill 内容
```

这相当于把 PROJECT 模式的"自动 bump + 自动同步引用"能力扩展到 Skill 文件夹。

**核心差异**：PROJECT 模式只需同步 `.memory/对话记录/` 的文件名。SKILL 模式需要同步更多引用（workspace-spec、Rules、其他 SKILL.md），需要一个引用注册表。

### 引用注册表设计（可选）

在 `workspace-spec.json` 中增加一个 Skill 引用映射：

```json
{
  "skillRegistry": {
    "B01": {
      "name": "框架体检",
      "folder": "B01_框架体检_v1.2.0",
      "scripts": ["scripts/framework-check.ps1"]
    },
    "B05": {
      "name": "DWD 单表 SQL 生成",
      "folder": "B05_1对1DWD单表SQL生成_v1.2.0",
      "scripts": ["scripts/generate_dwd.ps1"]
    }
  }
}
```

其他文件引用 Skill 时，用稳定的 `A01`、`B05` 而非硬编码路径。备份脚本 bump 版本后只需更新 `skillRegistry` 一处。

## 与上一版方案的核心差异

| 维度 | 上一版（v1.0.0） | 本版（v2.0.0） |
|------|-----------------|---------------|
| "好调用"的理解 | 用中文分类标签 `[治理]`、`[数仓]` 在斜杠菜单过滤 | 用短编号 `A01`、`B05` 快速精确命中 |
| YAML name 格式 | `[治理] 框架体检` | `A01_创建技能` |
| 用户输入习惯 | 需切换中文输入法输入"治理" | 纯 ASCII 键入 `A01`，三键搞定 |
| 域浏览方式 | 输入中文域名过滤 | 输入单字母 `A` 或 `B` 过滤 |
| 中文搜索 | ✅ 可用 | ✅ 依然可用（name 里仍有中文名） |

**核心修正**：编号不只是"管理用的内部标识"，而是**面向用户的快速调用入口**。

## 风险与取舍

| 风险 | 严重程度 | 缓解方案 |
|------|---------|---------|
| 斜杠命令不用 YAML name | 🔴 致命 | 阶段 0 先验证 |
| 用户需记忆编号 | 🟡 中等 | 编号数量有限（<20），常用的记住即可；不常用的可用中文搜索兜底 |
| 迁移过程中遗漏路径引用 | 🟡 中等 | 迁移脚本 + 框架体检验证 |
| 每次 Skill 升级的 rename 成本 | 🟡 中等 | 扩展 backup.ps1 为 SKILL 模式 |
| 引用散布在多处，维护成本 | 🟡 中等 | 引入 skillRegistry 注册表 |

---

## 推荐行动顺序

1. **立即做**：阶段 0 验证（改一个 Skill 的 YAML name 为 `B01_框架体检`，测 `/B01` 与完整版本号能否命中）
2. **验证通过后**：编写迁移脚本 + 执行批量迁移
3. **迁移完成后**：扩展 backup.ps1 支持 SKILL 模式
4. **长期**：引入 skillRegistry 注册表，解决引用散布问题

---

## 结论

AB 结合方案满足两个核心诉求：

- **好管理**：文件夹名 = `{域前缀}{编号}_{技能名}_v{版本}` → 磁盘上分域排序 + 版本可追踪
- **好调用**：YAML name = `{域前缀}{编号}_{技能名}_v{版本}` → 输入 `/A01` 三键命中，同时斜杠候选项保留版本号

最大风险仍是"斜杠命令确实使用 YAML name"这一假设。建议先用一个 Skill 做最小验证。
