init_workspace 项目总览

这是一个把知识工作区、AI 强制门、Skill 注册、版本备份、任务进度、记忆沉淀和多领域自动化能力组织在一起的本地框架。它的核心不是单个脚本，而是一套围绕 SSOT 运转的工作区操作系统。

一屏结论

`init_workspace` 的定位可以概括成一句话：它用 `.system/standards` 做权威标准，用 `.agents` 与 `.claude` 接入 AI 执行，用 `output` 承载成果，用 `.history` 保留可回滚快照，用 `.memory` 沉淀上下文，再用一组编号 Skill 把这些动作编排成可恢复、可审计、可迁移的工作流。

8 根目录骨架：.agents、.claude、.history、.memory、.system、.temp、input、output
29 当前注册 Skill，覆盖 A 到 G 七个能力域
6 当前 output 子项目，包含系统治理、Skills 管理、模型设计标准化等主题
读法建议：先看 SSOT，再看 B01/B02/B03/B04/B08/B10 这些治理型 Skill。业务 Skill 只是能力枝叶，真正定义项目气质的是这几个强制门怎样保护目录、版本、记忆和任务连续性。

项目形态

这个仓库既是初始化工具的源码所在地，也是被这个工具管理的一个 live 工作区。它因此有两层身份：一层是“生产工作区骨架的工具”，另一层是“使用这套骨架进行治理和研究的样板工作区”。

区域 职责 当前规则口径
.system/standards/ 标准层，机器和人类共同读取的事实源。 workspace-spec.json 是机器 SSOT；三份 Markdown 是人读标准。
.agents/ Codex/AI 执行层，包含 rules、skills、脚本与 references。 执行层不能覆盖标准；冲突时向 `.system/standards` 收敛。
.claude/ Claude Code 接入层，主要是命令包装和本机设置。 命令文件与注册 Skill 一一对应，正文只指向对应 `SKILL.md`。
output/ 当前研究、方案、HTML 报告、代码程序的唯一正式输出区。 按子项目组织，每个子项目固定三分类：问题答疑、课题研究、代码程序。
.history/ 历史快照与备份区。 不手工拼路径；所有正式备份由 B02 脚本生成。
.memory/ 当前态记忆：对话记录、系统记录、知识提炼、任务进度、全局地图。 追加型记录不做历史备份；知识提炼和全局地图使用 MEMORY 模式。
input/ 用户资料输入区。 在方向规则中被视为权威参考资料来源。
.temp/ 临时文件、规范化异常和迁移过程材料。 不作为正式成果，也不替代 output。

三层资产模型

覆盖层

初始化工具每次运行会替换的受管模板，包括核心 rules、覆盖层 Skill、入口文件和标准模板。替换前需要进入 `.history`。

必备层

工作区运行必须存在的目录和文件。缺失时补齐，已有时不覆盖真实本机配置。

可变层

用户和 AI 按任务生成的产出、记忆、历史快照和本机私有配置。初始化工具原则上不重写这些内容。

SSOT 与标准层

项目的权威顺序非常明确：机器标准优先，人读标准解释，rules/skills 执行，output 只记录过程与产物。这个顺序解决的是“规则到底听谁的”这个基础问题。

SSOT 文件 承担的事实 主要消费者
workspace-spec.json 根目录、必备目录/文件、Skill 注册表、历史命名、BOM 检查、任务进度目录等机器可读约束。 B01 体检、B06 规范化、初始化工具、Codex 入口判断。
工作区骨架规格.md 解释根目录、覆盖层、必备层、可变层、AI 接入层和 `.system` 核心骨架。 人工理解、规则排查、系统治理方案。
工作区命名规范.md 解释 output、.memory、.history、.system、AGENTS/CLAUDE 的命名和历史态规则。 新增文件、备份、规范化、目录检查。
Skills管理标准.md Skill 域分类、稳定编号、文件夹命名、YAML name、注册、版本升级和跨 Skill 引用规则。 A01/A02/A03、B01、B06、Claude commands、所有跨 Skill 编排。

核心子模块

下面这些模块共同构成工作区的治理闭环。它们不是并列的散装规则，而是按“进入任务、定位话题、修改前备份、执行中记录、结束时沉淀”的顺序协作。

SSOT 管理

`.system/standards` 是项目的制度源头。`workspace-spec.json` 承担机器可读事实，三份 Markdown 承担人读解释。任何 Rule、Skill 或脚本和标准冲突时，不能反向修改标准来迁就执行层，必须让执行层向标准收敛。

.system 只读边界 A03 系统更新 B01 校验

版本管理

B02 是修改 live 文件前的门。`output` 子项目用 PROJECT 模式整项目快照并 bump 子项目版本；`.agents/skills` 与 `.system` 用 FOLDER 快照；规则和入口用 CONFIG 备份；知识提炼和全局地图用 MEMORY 模式。

.history 语义版本 版本记录.md

任务进度管理

B08 维护 `.memory/任务进度`，解决中断恢复问题。它记录任务 ID、状态、恢复卡片、事件日志、文件与产物。这里的“进程管理”更准确地说是任务过程管理，不是操作系统进程调度。

执行流程

工作区最重要的价值，是把 AI 的一次性回答变成有入口、有归属、有版本、有恢复点、有记忆的连续工作过程。

一次标准任务怎么走

1
进入工作区先体检

B01 执行 `framework-check.ps1`，检查 SSOT、骨架、对话记录、BOM、知识地图、目录链接和 Skill 注册。当前检查结果是 31 PASS、0 FAIL、0 WARN。

2
创建或恢复任务进度

B08 在 `.memory/任务进度` 下创建任务文件，记录目标、当前状态、下一步和后续 checkpoint。

3
知识回答先归属话题

direction-rules 扫描 `output/` 子项目。属于已有主题就定位子项目，不属于任何主题时用 B04 新建。

4
修改前先备份

B02 根据路径选择 PROJECT、CONFIG、FOLDER 或 MEMORY 模式。`output` 下只能对整个子项目做 PROJECT 备份，不能单文件备份。

5
执行并维护索引

新增内容文件时，更新分类文件夹版本、`目录.md` 和 `版本记录.md`。如果是 HTML 报告，G01 要输出单文件、响应式、可离线打开的 `.html`。

6
结束前写记忆并关闭任务

B03 写入项目对话记录或系统记录；B08 把任务关闭到已完成或保留在可恢复状态。

Skill 域体系

Skill 不是随意命名的提示词集合，而是带稳定编号、域分类、版本号、注册表和命令包装的一套能力目录。跨 Skill 引用优先写稳定编号，例如 B04；真实路径和注册表保留完整名称与版本。

域 数量 职责边界 代表 Skill
A 元技能 4 管理 Skill、系统标准和超管授权。 A00 超管模式、A01 创建技能、A02 安装技能、A03 系统更新
B 系统治理 10 维护工作区框架、备份、记忆、子项目、研究、规范化、进度、发布和课题分离。 B01、B02、B03、B04、B08、B10
C 数仓开发 7 Doris 查询、建表语句、临时数据、DWD SQL 和字段 Excel 的数据开发链路。 C02、C03、C05、C06、C07
D 架构文档 3 OMM 架构扫描、查看和云端推送。 D01、D02、D03
E 模型设计 3 模型设计 Excel 的 AI-first 标准化、评审编排和命名建议。 E01、E02、E03
F 办公自动化 1 钉钉在线文档或表格下载。 F01
G HTML产物 1 聚合 HTML 报告、图示、数据探索、路线图、互动编辑器等单文件产物模式。 G01
稳定编号的意义：文档和 Skill 编排写 B04、C03、G01 这样的稳定编号；解析时回到 `workspace-spec.json` 的 registeredSkills 找当前完整文件夹名。这样 Skill 版本升级时，引用方不必到处改路径。

注意点

README 与源码中的版本口径

当前 live SSOT 是 workspace-spec.json v1.20.0，B01 体检也以这个版本读取。README 和 `init_workspace.py` 中仍可看到 v1.19.0 相关元信息。解释项目现状时，应以 `.system/standards` 为准。

入口文件不可随意修改

`AGENTS.md` 和 `CLAUDE.md` 是入口控制区。普通任务不能修改，除非用户本轮明确授权相应动作；`.system` 修改也需要具体路径和动作授权。

output 不是随手落文件的地方

每个实质性回答都要归属子项目，文件必须进入三分类之一。新增文件还要同步 `目录.md`、分类版本和 `版本记录.md`。

记忆不是可选附加项

只要本轮产生知识回答、操作结论或系统治理信息，就必须在最终回复前写入 B03 记忆。B08 任务进度不能替代 B03 长期记忆。
