G01_HTML交互产物

把复杂说明变成可以打开、浏览、比较和操作的 HTML 产物

G01 不是“做网页”的泛用按钮。它是一个产物选择器：当信息需要视觉结构、交互选择或可分享审阅时，先选对 HTML 模式，再生成单文件、可离线打开的成果。

什么时候用 选择模式

一句话用法

  • 1先判断 HTML 是否真的比 Markdown 更清楚。
  • 2从 16 类模式中选一个主模式，不把所有规则一起展开。
  • 3输出单文件 HTML，CSS 和 JS 内联，默认离线可打开。
  • 4互动类结果走剪贴板回传，不依赖 Claude Code 监听器。

什么时候应该用 G01

核心判断不是“能不能写成 HTML”，而是“HTML 是否让理解、比较、操作或分享明显更省力”。

应该用

内容超过一屏，结构多层；需要看关系、时间线、矩阵、架构图、ERD、色板、数据表，或需要用户点选、排序、编辑后回传。

谨慎用

只是普通说明但要分享给别人、做评审、给团队同步，或 Markdown 会让读者在长段落里来回找重点。

不要用

短答、简单代码修改、命令输出摘要、普通规则更新、无需视觉布局的结论，直接用文本或修改目标文件更干净。

标准工作流

G01 本身仍服从当前工作区强制门：该落 output 的落 output，该备份的先备份，该写记忆的写记忆。

01

确认触发

判断任务是否需要视觉化、交互式或可分享 HTML 成果。

02

选择模式

从模式索引选一个主模式，例如报告、图示、矩阵、数据探索。

03

按需读原文

复杂边界才读取原始 skill，不一次展开全部 16 个说明。

04

生成 HTML

单文件、响应式、离线可打开；文本和图形节点不能溢出。

05

验证收尾

浏览器打开检查，再同步目录、版本记录、任务进度和记忆。

怎么向它下任务

最好的请求会同时说明目标读者、内容材料、希望用户能做什么，以及 HTML 是否需要交互。

请求模板

用 G01 做一个 HTML 产物，面向 {读者} 说明 {主题}。重点讲清 {3-5 个重点}。需要 {报告/图示/矩阵/编辑器/时间线} 形态，输出到当前子项目，并同步目录和版本记录。

本次请求的解释

“用这个 G01 将这个 skill 自己本身的使用方式介绍清楚”适合用 `html-spec-planning` 风格，因为目标是说明一个能力的定位、触发、流程、模式选择和边界。

  • 主模式：规格和使用说明。
  • 辅助结构：决策卡片、流程图、模式筛选器。
  • 产物形态：单文件 HTML，可直接浏览。

边界要记住

G01 的价值在“增强表达”，不是替代工作区制度，也不是把所有输出都变成网页。

保留的能力

HTML 报告、图示、数据探索、路线图、ERD、设计 token、互动编辑器、思维导图和决策矩阵。

  • 单文件 HTML。
  • 按需读取原始模式说明。
  • 互动结果默认剪贴板回传。

不做的事情

不启动 Claude Code 专属监听器，不注册 16 个常驻入口，不把短答、普通代码修改和规则补丁硬转成 HTML。

  • 不绕过 B01/B02/B03/B08。
  • 不把 HTML 当作唯一正确产物。
  • 不依赖外部 CDN 或网络资源。
