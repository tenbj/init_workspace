# 分类在斜杠命令中如何体现

> 用户追问：`[系统治理域]`、`[数仓开发域]` 是用什么形式呈现？人在斜杠命令调用时能否感知到分类？

---

## 直接回答

**我上一版方案中的 `category` 写在 YAML frontmatter 里，对用户斜杠命令调用完全不可见。这是方案的一个实际缺陷。**

斜杠命令（`/`）调用 Skill 时，用户看到的是 `.agents/skills/` 下的**文件夹名称**组成的扁平列表。YAML frontmatter 里的 `category: 系统治理` 只有 AI 能读到，人眼在斜杠菜单中看不到。

---

## 当前斜杠命令的工作机制

```
用户输入 "/" 
    ↓
IDE 扫描 .agents/skills/ 下的所有子文件夹
    ↓
以文件夹名称 + SKILL.md 的 description 组成列表展示
    ↓
用户看到的是一个扁平列表：
    
    01_同步代码仓库_v1.0
    1对1DWD单表SQL生成
    DWD字段信息Excel生成
    Doris建表语句查询
    ODS-DWD-一键生成
    临时数据存储
    创建技能
    子项目管理
    安装技能
    数仓生产库查询
    框架体检
    版本控制备份
    记忆管理
    课题研究
    项目规范化
```

**关键事实**：
- ❌ 斜杠命令不支持二级分组（没有"系统治理 >"子菜单）
- ❌ 斜杠命令不读取 YAML frontmatter 中的 category 字段
- ✅ 斜杠命令会显示文件夹名称
- ✅ 斜杠命令支持模糊搜索（输入关键词可以过滤）

## 让分类对人可见的方案对比

### 方案 A：文件夹名加域前缀

```
.agents/skills/
├── 治理_创建技能/
├── 治理_子项目管理/
├── 治理_版本控制备份/
├── 治理_记忆管理/
├── 治理_框架体检/
├── 治理_课题研究/
├── 治理_项目规范化/
├── 治理_安装技能/
├── 数仓_同步代码仓库/
├── 数仓_生产库查询/
├── 数仓_Doris建表语句查询/
├── 数仓_临时数据存储/
├── 数仓_1对1DWD单表SQL生成/
├── 数仓_DWD字段信息Excel生成/
└── 数仓_ODS-DWD-一键生成/
```

| 维度 | 评价 |
|------|------|
| 斜杠命令可见性 | ✅ 同域 Skill 排在一起，输入"治理"或"数仓"可过滤 |
| 实施成本 | ❌ **极高**：所有引用该 Skill 路径的地方都要改 |
| 受影响面 | Rules 文件、workspace-spec.json 的 bomCheck、其他 SKILL.md 的交叉引用、backup.ps1 的路径 |
| 未来维护 | ⚠️ 新增域时需要定义新前缀 |

**结论：能解决用户痛点，但迁移成本极高。**

### 方案 B：文件夹名加编号分段

```
.agents/skills/
├── A01_框架体检/
├── A02_版本控制备份/
├── A03_记忆管理/
├── A04_子项目管理/
├── A05_课题研究/
├── A06_项目规范化/
├── A07_创建技能/
├── A08_安装技能/
├── B01_同步代码仓库/
├── B02_生产库查询/
├── B03_Doris建表语句查询/
├── B04_临时数据存储/
├── B05_1对1DWD单表SQL生成/
├── B06_DWD字段信息Excel生成/
└── B07_ODS-DWD-一键生成/
```

| 维度 | 评价 |
|------|------|
| 斜杠命令可见性 | ✅ A 域和 B 域自然分组，但需要记住 A=治理、B=数仓 |
| 可读性 | ⚠️ 不如中文前缀直观，需要学习映射 |
| 实施成本 | ❌ 同方案 A，路径全变 |

**结论：和方案 A 成本相同，但可读性更差。**

### 方案 C：利用斜杠命令的模糊搜索（零成本方案）

不改文件夹名，而是在 SKILL.md 的 `name` 字段中加入域标签：

```yaml
---
name: "[治理] 子项目管理"
description: ...
---
```

或者在 `description` 开头加上分类标记：

```yaml
---
name: 子项目管理
description: "[治理] 子项目文件夹创建与管理技能..."
---
```

| 维度 | 评价 |
|------|------|
| 斜杠命令可见性 | ⚠️ 取决于 IDE 是否显示 name/description 而非纯文件夹名 |
| 实施成本 | ✅ **极低**：只改 SKILL.md 内部文本，不改文件夹名 |
| 路径影响 | ✅ 零影响，所有路径引用不变 |
| 模糊搜索 | ✅ 斜杠菜单中输入"治理"可能过滤出所有治理类 Skill |

**结论：成本最低，但效果取决于 IDE 斜杠命令的搜索范围是否包含 name/description。**

### 方案 D：仅维护索引文档（不改任何 Skill）

不改任何 Skill 的文件夹名或元数据，只维护 `.agents/skills/技能清单.md`：

| 维度 | 评价 |
|------|------|
| 斜杠命令可见性 | ❌ 零帮助，斜杠菜单还是扁平列表 |
| 实施成本 | ✅ 最低 |
| 实际价值 | ⚠️ 只有打开文档时才有帮助，不在调用流程中 |

**结论：是 AI 和人类事后查阅的索引，但不解决斜杠命令的效率问题。**

---

## 推荐策略

**短期（立即）**：方案 C + 方案 D 组合

1. 在每个 SKILL.md 的 `name` 字段前加域标签 `[治理]` / `[数仓]`
2. 测试斜杠命令中输入"治理"是否能过滤
3. 同时维护 `技能清单.md` 作为参考

**中期（如果方案 C 无效）**：方案 A

如果 IDE 斜杠命令的搜索不覆盖 YAML 字段，只看文件夹名，那就只能改文件夹名。此时建议：
1. 编写迁移脚本，一次性批量改名 + 更新所有引用
2. 统一改完，而非逐个改

**验证方法**：先对一个 Skill 改 name 字段为 `[治理] 框架体检`，在斜杠菜单中搜索"治理"，看是否能命中。结果决定后续路线。

## 核心认知

| 层级 | 谁能看到 | 怎么实现 |
|------|---------|---------|
| 文件夹名 | ✅ 人（斜杠命令）+ ✅ AI | 改文件夹名，成本高 |
| YAML name | ⚠️ 人（取决于 IDE）+ ✅ AI | 改 SKILL.md，成本低 |
| YAML category | ❌ 人 + ✅ AI | 改 SKILL.md，只对 AI 有用 |
| 索引文档 | ✅ 人（手动打开时）+ ✅ AI | 新建文件，不改现有 |

**分类标记的可见性由「它被放在哪一层」决定。放在文件夹名里成本高但人一定看得到；放在 YAML 里成本低但人不一定看得到。这就是取舍。**
