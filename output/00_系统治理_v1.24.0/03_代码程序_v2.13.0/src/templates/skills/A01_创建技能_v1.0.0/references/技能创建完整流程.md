# 技能创建完整流程

## 命名

- 当前工作区本地 Skill 目录名必须使用完整标准名：

```text
{域代码}{编号}_{技能名}_v{MAJOR}.{MINOR}.{PATCH}
```

- 新建 Skill 默认版本必须为 `v1.0.0`
- 目录名、`SKILL.md` YAML `name`、`agents/openai.yaml` 的 `display_name`、`workspace-spec.json` 注册项必须保持一致
- 技能名中文为主，特定术语可用英文
- 不用 `【】` 包裹
- 不把运行环境或时间戳写进目录名

## 创建步骤

1. 先明确使用场景和反例
2. 判断它该不该成为独立 skill
3. 按 `.system/standards/Skills管理标准.md` 分配域代码和编号
4. 规划哪些内容进 `SKILL.md`、哪些进 `references/`、哪些进 `scripts/`、哪些进 `assets/`
5. 用 `scripts/init_skill.py` 建骨架，传入完整标准名，例如 `F01_原子拆解技能_v1.0.0`
6. 补 `agents/openai.yaml`
7. 把 `SKILL.md` 收口成薄入口
8. 用 `scripts/quick_validate.py` 校验

## 建骨架时至少要交付

- `SKILL.md`
- `agents/openai.yaml`
- `references/`
- `scripts/`
- `assets/`

## 如果 skill 会写入 `output/`

额外检查：

- 是否说明最终件、中间件、日志分别是什么
- 是否遵守任务目录策略，而不是直写 `output/` 根目录
- 脚本是否支持 `--output` 或 `--output-dir`

## 反模式清单

- 只写一个厚 `SKILL.md`，没有 references
- 反过来只补脚本，不写触发和边界
- 生成 README、CHANGELOG、安装说明等噪音文件
- 名字过泛，导致触发范围失控
- 引用 references 却不在 `SKILL.md` 里写明何时去读

## 最低校验标准

至少确认下面几件事都成立：

- `SKILL.md` 有 frontmatter 的 `name` 和 `description`
- YAML `name` 与 Skill 文件夹名完全一致，且必须带三段式版本号
- `description` 不超过 100 字
- `SKILL.md` 有 5 个标准段落
- 已补齐 `agents/`、`references/`、`scripts/`、`assets/`
- `agents/openai.yaml` 至少有 `display_name` 和 `short_description`，且 `display_name` 必须与 Skill 文件夹名完全一致
- 没有多余噪音文件
