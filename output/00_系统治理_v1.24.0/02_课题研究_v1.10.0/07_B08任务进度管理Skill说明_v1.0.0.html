B08 任务进度管理 Skill 说明

B08 负责记录任务执行中的 live 状态：当前做到哪一步、下一步是什么、最近安全点在哪里、涉及哪些文件。它不替代成果文档，也不替代 B03 记忆；它补的是“任务没做完时如何接上”的那一层。

解决的问题

上下文压缩、工具中断、会话断开或模型切换后，下一次 AI 可以先读恢复入口，不必从聊天历史里猜进度。

不是用来做什么

不保存完整研究结论，不承载长期知识，不替代 output 成果区和 `.memory/系统记录`、`.memory/对话记录`。

核心入口

.memory/任务进度/索引.md 列出当前需要恢复的任务；具体任务文件保存恢复卡片、事件日志和最终摘要。

运行流程

Start

创建任务文件，写入用户目标、当前状态和下一步。

Checkpoint

关键动作后记录结果，比如 B02 备份、文件变更、验证结果。

UpdateNext

任务方向变化时更新下一步，避免恢复后跑偏。

Pause

遇到等待确认、阻塞或需要审阅时，改成可恢复状态。

Resume

新会话读取索引，列出可继续的任务和当前状态。

Close

任务完成后写最终摘要，移动到已完成或已取消目录。
开始任务 → 记录关键步骤 → 中断可恢复 → 完成后归档 → B03 沉淀摘要

文件结构

.memory/
  任务进度/
    索引.md
    进行中/
      T20260511-2202-B08说明HTML.md
    已完成/
    已取消/
索引.md

只放恢复入口：task-id、状态、更新时间、任务文件链接、当前状态。它让下一次接手时先知道读哪里。

任务文件

包含恢复卡片、执行计划、事件日志、文件与产物、恢复指令和最终摘要。重点是短、稳、可行动。

状态机

状态 含义 恢复动作
ACTIVE 正在执行 读恢复卡片，从“下一步”继续。
PAUSED 主动暂停或等待用户确认 先确认暂停原因，再继续或询问用户。
BLOCKED 遇到外部阻塞 先处理阻塞项，不要直接改文件。
REVIEW 主体完成，等待验证或审阅 先跑验证，再决定关闭或继续修改。
DONE 已完成并归档 默认不恢复；需要时读最终摘要。

常用命令

场景 命令
创建任务 task_progress.ps1 -Action Start -Title "任务名" -Goal "目标" -Next "下一步"
记录 checkpoint task_progress.ps1 -Action Checkpoint -TaskId "T..." -Message "已完成..."
更新下一步 task_progress.ps1 -Action UpdateNext -TaskId "T..." -Next "继续验证..."
暂停或阻塞 task_progress.ps1 -Action Pause -TaskId "T..." -Reason "等待确认"
恢复查看 task_progress.ps1 -Action Resume
关闭归档 task_progress.ps1 -Action Close -TaskId "T..." -Result "已完成..."

和其他强制门的分工

组件 职责 B08 如何配合
B01 框架体检 只读检查结构、BOM、目录、记忆和任务进度索引。 发现任务进度结构缺失、active 未索引或链接失效。
B02 版本控制备份 修改 live 文件前做安全备份。 B02 完成后，把快照路径、新 live 路径和版本变化写入 checkpoint。
B03 记忆管理 把最终摘要沉淀到对话记录、系统记录和知识提炼。 任务关闭后只把压缩摘要交给 B03，不复制整份事件日志。
B04 子项目管理 决定知识产出落到哪个 output 子项目。 B08 记录执行过程归属，但不替代 B04 的话题归属。
一句话记法： B08 不是“成果库”，而是“任务接力棒”。当任务还没结束时，它让下一次接手的人先知道从哪里继续；当任务结束后，它退场，把摘要交给 B03。
