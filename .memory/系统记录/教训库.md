## 2026-05-09 10:29

**用户问**：刚才改了文件内容好像没做文件级版本管理？
**根因分析**：PROJECT 级备份做了（子项目旧状态有快照），但后续修改文件内容时遗漏了文件级版本管理三步：①文件自身版本号没 bump（文件名的 `_v1.1.0` 没改成 `_v1.2.0`）；②分类文件夹版本号没 bump；③目录.md 没同步更新文件版本。根因是 PATCH 级 PROJECT 备份后，直接改内容就去更新版本记录了，跳过了文件级版本 bump 步骤。
**教训**：修改 `01_问题答疑` 或 `02_课题研究` 内的内容文件后，必须检查完整链条：PROJECT 备份 → 修改内容 → **文件名版本 bump** → **分类文件夹版本 bump** → 目录.md 同步 → 版本记录填写。不能因为 PROJECT 备份做了就跳过文件级版本管理。

## 2026-05-09 15:39

**用户问**：为什么没有版本管理？怎么才能让 AI 有这个习惯？
**根因分析**：AI 没有把项目规则内化为操作习惯，只响应用户直接指令，跳过了版本备份、子项目创建、记忆记录等强制步骤。规范分散写入多个 Skill 文件违反 SSOT，导致 AI 难以一致执行。
**教训**：① 修改任何框架组件（`.agents/`、`.system/`、`output/`）前必须先执行版本控制备份，不得事后补；② 规范只在权威来源（`工作区骨架规格.md`）定义一次，其他文件改为引用；③ `CLAUDE.md` 是让 AI 跨会话保持操作习惯的正确机制，项目规则应在此集中声明。
