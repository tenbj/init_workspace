## 2026-05-12 · 初始化工具对 memory/history 的边界

**核心观点**：
- 当前 `初始化工作区_v2.10.0.exe` 不会整体覆盖 `.memory/` 或 `.history/`。
- `.memory` 的初始化路径使用补缺逻辑：目录用 `mkdir(..., exist_ok=True)`，初始文件用 `write_if_missing()`，已有文件不改写。
- `.history` 的初始化路径只补建目录，并在覆盖受管骨架资产前追加备份；它会新增历史快照，但不清空、不整体替换。

**关键框架/模型**：
- 补缺层：`.memory/对话记录`、`.memory/知识提炼`、`.memory/系统记录`、`.memory/全局知识地图.md`。
- 追加历史层：`.history/.agents/*`、`.history/.system/standards`、`.history/AGENTS`、`.history/CLAUDE`、`.history/.claude/commands`。
- 覆盖层：`.agents/rules`、`.agents/skills`、`.system/standards`、`AGENTS.md`、`CLAUDE.md`、`.claude/commands`。

**与其他话题的关联**：
- → 工作区初始化工具：用户运行 exe 的主要风险不在记忆和历史被覆盖，而在受管骨架资产被模板替换。
- → 版本控制备份：`.history` 是追加式留痕区，受管资产覆盖前应先进入对应历史镜像路径。

## 2026-05-11 · PowerShell 默认读取编码

**核心观点**：
- Windows PowerShell 5.1 读取无 BOM 的 UTF-8 中文文件时，`Get-Content -Raw` 可能按系统默认 ANSI 解码并产生乱码。
- 对 Markdown、Rule、Skill、JSON、YAML 等 UTF-8 文本，默认读取命令应显式写成 `Get-Content -LiteralPath <path> -Encoding UTF8 -Raw`。
- 乱码治理应优先收敛读取命令和入口约束，而不是把所有 Markdown 批量改成 UTF-8 with BOM。

**关键框架/模型**：
- 读取治理：入口规则约束 AI 默认命令，执行层示例补齐 `-Encoding UTF8`，B01 增加未声明编码读取检查。
- 写入治理：`.ps1` 仍遵守 UTF-8 with BOM；Markdown 和普通文本不因读取问题强制加 BOM。
- 可迁移治理：不依赖用户 PowerShell Profile 或会话级 `$PSDefaultParameterValues`，因为 AI 命令可能在新进程执行。

**与其他话题的关联**：
- → 工作区初始化工具：模板也要同步入口和执行层读取约束，否则新工作区会复发。
- → 脚本治理：B01 可补检查项，自动暴露 `Get-Content` 读取文本但未声明 `-Encoding` 的示例。

## 2026-05-11 · 模糊问题原子化识别

**核心观点**：
- 用户给出一大片含糊、纠缠的问题时，AI 不应立刻进入建议模式，而应先完成课题识别。
- “原子课题”不是越小越好，而是要可命名、可判断边界、可单独推进、可沉淀产物。
- 案例本身可能只是样本，用户真正要验证的可能是“从混沌叙述到原子课题”的识别能力。

**关键框架/模型**：
- 识别流程：提取问题信号 → 按性质分层 → 判断依赖关系 → 压缩成少数主课题 → 确认用户关心的是内容答案还是拆题过程。
- 常见分层：状态层、目标层、路径层、表达层、商业层、风险层。
- 纠偏口径：遇到混杂诉求时，先显式说明“我先不急着给方案，这里需要先把混合问题拆成原子课题”。

**与其他话题的关联**：
- → 减脂内容计划：减脂案例被用作样本，真正沉淀的是课题识别方法。
- → 任务进度管理体系：原子课题识别完成后，才能进一步拆成可跟踪任务。

## 2026-05-10 · Claude 接入层骨架化

**核心观点**：
- Claude Code 的运行入口不应只是根目录里的附属文件；只要工作区依赖 Claude 执行规则和斜杠命令，`CLAUDE.md`、`.claude/commands/` 与相关本地配置就必须进入骨架标准。
- `.Claude.json` 可能包含密钥，标准只能识别其存在和私有属性，初始化工具只能补缺占位，不能覆盖真实值或在报告中展示内容。

**关键框架/模型**：
- `workspace-spec.json` 作为机器 SSOT 增加 `claudeIntegration`，统一定义命令目录、命令模板、命令来源和私有配置策略。
- Claude 命令文件由 `skillsManagement.registeredSkills` 派生：每个注册 Skill 对应 `.claude/commands/{Skill文件夹名}.md`，正文固定指向 `.agents/skills/{Skill文件夹名}/SKILL.md`。
- 体检脚本负责发现缺失或错误命令；规范化脚本负责在 `--Fix` 时补齐或重写命令。
- 初始化工具模板必须从当前 live 骨架同步 Rule、Skill、Standard 和 `CLAUDE.md`，否则新工作区会重新产生旧标准漂移。

**与其他话题的关联**：
- → Skills管理体系：新增、删除、版本 bump Skill 时，必须同步维护 `.claude/commands/`。
- → 工作区初始化工具：初始化工具需要生成 Claude 接入层，但对私有配置执行“只补缺不覆盖”。

## 2026-05-10 · AI 入口与 Skill 稳定编号

**核心观点**：
- `AGENTS.md` 和 `CLAUDE.md` 应是强制门薄入口，不应承载完整制度文本；入口只负责告诉 AI 什么时候读哪些 SSOT。
- 跨 Skill 的意图指引应写稳定编号（如 `B04`），不要写完整 Skill 文件夹名；完整名称只属于注册表、真实路径、脚本路径和产物目录。

**关键框架/模型**：
- 入口层：定义 SSOT 顺序、强制门索引、标准读取时机。
- 标准层：`Skills管理标准.md` 统一定义稳定 ID 解析规则，避免每个 Skill 重复写规则。
- 执行层：AI 在遇到编号时按标准和注册信息解析到当前 Skill；如果编号无法唯一解析，停止并要求修复注册关系。
- 初始化工具层：EXE 模板必须同步当前入口、规则、Skill 和标准，否则新工作区会带着旧规则启动。

**与其他话题的关联**：
- → Skills管理体系：Skill 升级版本时，意图依赖文本不再需要随完整文件夹名逐处修改。
- → 工作区初始化工具：初始化程序需要同时维护 `AGENTS.md`、`CLAUDE.md` 与对应历史目录。

## 2026-05-10 · 项目文件流向总览

**核心观点**：

**与其他话题的关联**：
