## 2026-05-10 · 初始化工具归属

**核心观点**：
- 工作区初始化工具属于系统治理能力，当前态应归入 `00_系统治理`，不再作为独立 `05` 子项目保留。
- 合并独立子项目时，内容迁入当前 live 目标子项目，迁移前状态保留在 `.history/output/` 快照中。

**关键框架/模型**：
- 问答型说明进入 `01_问题答疑_v*`，并按 `{NN}_{标题}_v{x.y.z}.md` 补齐内容文件版本号。
- 初始化工具源码、构建脚本、模板、EXE 进入 `03_代码程序_v*`，沿用工具整体代码版本。
- 迁移前子项目版本记录可作为治理历史材料归档到 `02_课题研究_v*`。
- 合并后同步 `目录.md`、`版本记录.md`、`.memory/全局知识地图.md`，再复跑 `normalize.ps1 --Check`。

**与其他话题的关联**：
- → Skills管理体系：初始化工具内置模板会影响 Rule、Skill 与 `.system/standards` 的落地形态。

## 2026-05-10 · Claude 接入层骨架化

**核心观点**：
- Claude Code 的运行入口不应只是根目录里的附属文件；只要工作区依赖 Claude 执行规则和斜杠命令，`CLAUDE.md`、`.claude/commands/` 与相关本地配置就必须进入骨架标准。
- `.Claude.json` 可能包含密钥，标准只能识别其存在和私有属性，初始化工具只能补缺占位，不能覆盖真实值或在报告中展示内容。

**关键框架/模型**：
- `workspace-spec.json` 作为机器 SSOT 增加 `claudeIntegration`，统一定义命令目录、命令模板、命令来源和私有配置策略。
- Claude 命令文件由 `skillsManagement.registeredSkills` 派生：每个注册 Skill 对应 `.claude/commands/{Skill文件夹名}.md`，正文固定指向 `.agents/skills/{Skill文件夹名}/SKILL.md`。
- 体检脚本负责发现缺失或错误命令；规范化脚本负责在 `--Fix` 时补齐或重写命令。
- 初始化工具模板必须从当前 live 骨架同步 Rule、Skill、Standard 和 `CLAUDE.md`，否则新工作区会重新产生旧标准漂移。

**与其他话题的关联**：
- → Skills管理体系：新增、删除、版本 bump Skill 时，必须同步维护 `.claude/commands/`。
- → 工作区初始化工具：初始化工具需要生成 Claude 接入层，但对私有配置执行“只补缺不覆盖”。

## 2026-05-10 · AI 入口与 Skill 稳定编号

**核心观点**：
- `AGENTS.md` 和 `CLAUDE.md` 应是强制门薄入口，不应承载完整制度文本；入口只负责告诉 AI 什么时候读哪些 SSOT。
- 跨 Skill 的意图指引应写稳定编号（如 `B04`），不要写完整 Skill 文件夹名；完整名称只属于注册表、真实路径、脚本路径和产物目录。

**关键框架/模型**：
- 入口层：定义 SSOT 顺序、强制门索引、标准读取时机。
- 标准层：`Skills管理标准.md` 统一定义稳定 ID 解析规则，避免每个 Skill 重复写规则。
- 执行层：AI 在遇到编号时按标准和注册信息解析到当前 Skill；如果编号无法唯一解析，停止并要求修复注册关系。
- 初始化工具层：EXE 模板必须同步当前入口、规则、Skill 和标准，否则新工作区会带着旧规则启动。

**与其他话题的关联**：
- → Skills管理体系：Skill 升级版本时，意图依赖文本不再需要随完整文件夹名逐处修改。
- → 工作区初始化工具：初始化程序需要同时维护 `AGENTS.md`、`CLAUDE.md` 与对应历史目录。
