# 环境与凭据管理

本目录按“服务、环境、权限身份”管理连接。`catalog.json` 只登记连接名称、用途、权限、相对文件名和变量名；真实值保存在本机 `*.env` 文件中。清单禁止填写真实账号、地址、密码或 token。

## 填写方式

1. 将 `examples/` 中需要的空白示例复制到本目录，并去掉 `.example` 后缀。例如 `doris.prod.readonly.env`。
2. 在本机编辑器中填写；无需把真实内容粘贴到对话中。可先用只读账号接入。
3. Windows 下通过文件属性的安全设置限制到本人和确需使用的服务账号；POSIX 下限制为本人读写。目录本身和外部备份也应限制访问。
4. 新服务在 `catalog.json` 中登记，并增加不含真实值的 `.env.example`。清单是公开元数据，模板每个值都必须为空。一个连接只包含本任务所需凭据。

## 模型与脚本如何使用

从工作区根目录运行：

```powershell
python .envs/env_manager.py list
python .envs/env_manager.py route doris.prod.readonly --variable DORIS_PASSWORD
python .envs/env_manager.py check doris.prod.readonly
python .envs/env_manager.py run doris.prod.readonly -- python path/to/query_script.py
```

`list` 只列连接 ID、环境、权限和文件是否存在；`check` 只校验配置，不连接远端服务。`run` 不通过 shell 执行命令，只把所选连接变量及必要的操作系统环境传给子进程，不永久修改系统环境。业务脚本通过环境变量读取凭据。

有明确连接ID时直接使用`route`，无需先列出其他环境。加`--variable`只返回所需变量及对应.env路径；加`--secret-file`只返回所需密钥文件路径，路由过程不读取任何真实凭据文件。主AI、agent、subagent均遵守同一范围，不将路由请求扩展为读值或联网测试。

凭据维护统一调用B12。键值凭据保存在本目录`<连接ID>.env`，私钥等文件按catalog中的secret_files保存在`keys/<连接ID>/`。B12可按明确本机源文件导入，Windows覆盖已有值前生成`.recovery/`中的当前用户DPAPI加密备份；维护操作只输出路由和状态。

Python 调用方也可通过本文件旁的 `env_manager.py` 中的 `load_connection(workspace, connection_id)` 获取字典，但不得打印返回值。优先使用 `run`，它对捕获的标准输出和错误输出替换凭据原值及常用 URL 编码形式；子程序自己写文件、主动发网络请求或转换后的秘密不在此保护范围内。

配置缺失、变量重复、未登记变量、非法路径、链接目录或既有环境变量冲突时均停止，不自动选择其他环境。生产只读和测试写入独立选择；存在凭据不会扩大任务的操作授权。

## 文件格式

每行 `变量名=值`；空白行与 `#` 注释可用，变量名使用大写字母、数字和下划线。含空格或 `#` 的值用单引号或双引号包住。引号内内容原样保存：不执行命令，不展开 `$VAR`、`${VAR}`、反引号、反斜线转义或多行值。需要其他格式时由对应服务的认证工具管理，不能把文件当脚本执行。

## 私有数据与恢复

- Git 只保留本说明、加载器、非秘密清单和经过校验的空白模板；本目录其他内容默认忽略。已经被跟踪的文件不会因忽略规则自动退出跟踪，填入真实值前必须检查。
- 本目录自带`.gitignore`，新建工作区也会补齐；真实.env、keys/、.recovery/和.locks/均默认忽略。
- 真实 `*.env`、令牌缓存、私钥不进入 `.history`、`.memory`、`output`、初始化模板和发行包。普通历史备份不提供凭据恢复能力。
- 更新凭据时由本人在本机编辑；需要恢复能力时，先使用独立且加密、受权限控制的凭据备份或服务方密钥管理工具。轮换完成后撤销旧值。
- 初始化只分发说明、加载器、空白模板与默认清单；已有清单、真实文件均保留，禁止把本机目录整体复制为分发模板。

`.env` 文件是明文。这里减少凭据进入模型上下文的机会；同一操作系统账号拥有文件读取权限时，目录和规则不能构成强制隔离。高保密场景需使用独立权限的凭据服务。
