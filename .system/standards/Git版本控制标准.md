# Git版本控制标准

本文件是工作区Git任务流程与提交命名的唯一事实源。规则和Skill只引用执行，不复制标准正文。

## 独立任务流程

每个独立改动任务必须在专用分支完成：新建分支 → 实现与验证 → 提交 → 合并到明确目标基线。同一任务内的连续调整复用分支；不同任务分开提交、验收与合并。已有未提交改动按任务分离，禁止混入无关内容。
用户确认采用此流程后，常规本地提交和合并属于该任务授权；优先仓库既有目标基线，本工作区为main。目标无法确定或验证失败时保留分支并报告。用户明确要求不提交、暂不合并等例外优先。推送、发布和删除分支仍需对应授权，不自动扩展。

## 提交命名

- 普通提交：`类型(范围): 中文描述`；类型使用feat、fix、docs、refactor、test、chore等，范围指明主要模块。
- 合并提交：`merge: 中文描述`；显式覆盖Git默认英文说明。
- 发布准备：`chore(release): 发布X.Y.Z`。
- squash按最终改动使用普通提交格式。
- 标题和正文用中文描述改动及原因，代码标识、类型、路径和版本号可保留原文。
- 不自动amend、rebase或强推改写已有历史。
