# 环境管理标准

> 版本：1.1.0
> 机器事实源：workspace-spec.json 的 environmentManagement。

## 目录与数据归属

- 根目录使用 .envs/，连接按服务、环境与权限身份拆分。catalog.json 只记录非秘密连接元数据与变量名，禁止真实值。
- README.md、env_manager.py、catalog.json 与空白 examples/*.env.example 可进入骨架；真实 *.env、私钥和登录缓存属于本机私有数据。
- Git 采用默认忽略与公共文件白名单；必须核对已跟踪状态，Git忽略不会移除已有跟踪。

## 使用与权限

- 模型读取非秘密索引并选择连接ID；脚本在本机按需加载，禁止把凭据原文、认证头、完整认证URL输出到对话、记忆、报告和普通快照。
- 凭据文件不作为脚本执行，不展开命令和变量。缺失配置、链接路径、重复或未登记变量、环境冲突时停止；不自动切换环境。
- 子进程仅获得所选连接变量与必要系统环境；不永久修改系统环境。输出脱敏不能替代子程序本身的安全约束。
- 凭据可用不表示获得额外业务操作授权；优先最小权限和既有登录态。同账号文件读取权限不受文件夹命名隔离。

## 初始化与发行

- 只分发 environmentManagement.publicFiles；模板变量必须全为空。
- 初始化及升级只补缺公共文件，保留已存在清单与真实凭据，禁止从本机.envs整目录复制到模板。
- 发行模板出现白名单外文件或非空模板时拒绝初始化；初始化前预检，不先复制污染文件。

## 备份、更新与恢复

- B02普通快照的完整工作文件保护原则不变；含私有凭据的.envs为受限来源，预检拒绝整个普通快照，不悄悄跳过私有文件后宣称完整。
- 直接备份.envs内真实文件、或包含这些文件的来源目录同样拒绝；全部为空白公共文件的分发目录可正常保护。
- 真实值更新前使用独立加密且受访问控制的凭据备份或服务方密钥管理能力。未配置安全恢复机制时不得把普通.history快照当凭据备份。
- 本机编辑、检查、验证新值后撤销旧值；轮换记录只保留连接ID、时间和结果。Windows使用文件ACL限制本人及必要服务，POSIX限制本人读写。

## 专用维护与精确路由

- B12负责账号密码、API key、token、密钥和secret维护。键值秘密写入`.envs/<连接ID>.env`；文件型私钥、证书等写入`.envs/keys/<连接ID>/<文件名>`，secret_files只登记名称与相对路径。
- 路由请求只读非秘密清单：返回明确所需变量对应的.env文件路径，或所需文件型密钥路径。主AI、agent与subagent适用同一协议；不多读、不少读，不返回未请求项。无唯一连接时只澄清缺失维度，不扫描真实文件。
- 路由不读取真实值，不自动校验全部凭据或连接远端。执行操作时脚本在本机按任务范围读取。
- `.envs/.gitignore`随公共模板补缺，私有.env、keys/、.recovery/及.locks/均默认忽略。初始化保留已有忽略规则。
- B12维护真实值走专用流程：首次写入前限制文件权限，覆盖前以Windows当前用户DPAPI生成`.envs/.recovery/<连接ID>/`加密快照，目标路径与内容同时受保护，收紧新文件ACL后原子替换。无需对真实值执行B02普通history备份；公共catalog变更仍先执行B02。
- DPAPI不使用LocalMachine共享解密标志，不能当跨机器通用备份。保护不可用时不覆盖原值、不降级明文备份。维护互斥锁避免多个agent并发写入，外部编辑器不得并发修改目标。
